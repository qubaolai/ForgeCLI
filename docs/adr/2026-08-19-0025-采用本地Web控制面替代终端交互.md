# ADR-0025：采用本地 Web 控制面替代终端交互

## 状态

Accepted

## 日期

2026-08-19

## 背景

Forge 的 AgentLoop、工具、安全裁决、恢复和 session 已由 application/domain 边界承载，
但用户入口仍由 Rich、prompt-toolkit、TTY 菜单和阻塞式审批组成。终端界面难以同时呈现项目、
历史会话、计划、工具时间线、配置和完整审批目标，也让业务组合根长期被 CLI 包裹。

本变更只替换控制面，不重新定义 Agent 行为。浏览器不能直接执行本地 Git、文件和 Shell，
所以本地 Python Runtime 继续拥有全部执行能力与安全边界。

## 决策

1. 裸 `forge` 启动只监听 loopback 的 FastAPI 服务并打印启动链接，默认不抢占浏览器；
   `--open` 可显式打开。端口默认固定（8765），`--port 0` 才取随机端口：端口漂移会让
   已经打开的页面在重启后失去目标。CLI 只保留版本、端口、是否打开浏览器和诊断参数。

   > **2026-08-21 修订**：终端入口以 `forge cli` 子命令保留，见下方「决策 1 修订」。
2. React/TypeScript 页面提供项目中心、会话、Agent 时间线、审批、计划评审、模式、模型、
   配置、工作区授权、学习规则和恢复点。**斜杠命令能改的每一项配置在 Web 都要有入口**：
   终端入口既然由本 ADR 取代，任何"只能回终端改"的配置都是这次替换没做完。对照清单见
   决策 33。
3. `AgentLoop`、`AgentTurnService`、ToolRuntime、PolicyEngine、审批绑定、沙箱、恢复与 session
   schema 的业务语义保持不变。LLM 和工具组合根移到 `interfaces/runtime`，CLI/Web 共用。
4. 运行通知继续使用 ADR-0016 的 `AgentRunEvent`，由 Web subscriber 放入有限缓冲，并通过
   SSE 发送。事件缓冲不是恢复真相源；过期后客户端重新读取 session 与运行状态。
5. Web 人类输入新增 `InputOrigin.WEB_USER`。它可以提交正常 turn，但不具备
   `TTY_USER` 的人工 Shell 特权；`#` 在 Web 中始终是普通文本。
6. Web 不提供 PTY 或任意命令入口。Agent 的 `shell.run` 保留，并继续经过能力分析、审批、
   恢复屏障、授权和沙箱。
7. Web 审批通过阻塞 broker 等待 `once/workspace/deny`，**不设等待超时**：正确的终止条件
   只有用户决定、用户停止这一轮、服务退出三个。挂钟到点就判成"没批准"，等于让用户离开
   座位的功夫决定这次调用的命运，而模型收到"未获授权"后整轮停摆，用户回来时既看不到
   审批卡片也没有补救入口。三种终止都只能返回 pending/deny，不能自动批准。计划评审继续
   调用 `PlanReviewService`。
8. 同一服务可列出多个项目，但同一时刻只激活一个 `ProjectRuntime`；项目锁和单活动 turn
   约束不变。
9. 服务仅监听 `127.0.0.1`，使用一次性启动 token、HttpOnly session cookie、CSRF、精确
   Origin/Host 校验和严格 CSP。session 与 CSRF 密钥以 0600 存在用户配置目录并跨重启复用，
   否则每次重启都会把已打开的页面踢下线；启动 token 仍然一次性。MVP 不提供远程监听配置。
10. 前端静态资源在构建时进入 Python wheel，最终用户不需要 Node.js。
11. 项目配置只持久化额外工作区路径，不持久化写授权；Runtime 重启后额外目录按只读恢复，
    需要写入时由用户在 Web 中重新显式升级，安全上 fail closed。
12. 用户消息先在浏览器本地即时上屏，再由 SSE 将同一 turn 的模型正文、模型用量、工具阶段和
    终态增量归并。过程按 turn 折叠，工具调用作为二级折叠；运行时展开、终态后默认收起。
13. 审批卡片位于输入框上方，不使用全局遮罩；它仍由同一阻塞 broker 控制，不改变批准语义。
    项目切换器可取消，并在活动 turn 期间禁止切换，以免丢失当前渲染上下文。
14. 对话滚动仅在距离底部不超过 140px 时自动跟随。计划栏可显隐、拖动调宽，并可通过只读
    loopback 接口在浏览器中打开当前 Markdown 派生视图；不再维护重复的“活动”侧栏。
15. 助手回复与计划正文共用安全的 Markdown 页面渲染；不执行原始 HTML。计划栏默认关闭并
    直接读取计划 Markdown，而不是用 todo 状态重组正文。运行过程采用无卡片边框的轻量时间线，
    中间模型正文、用量和工具调用按事件顺序显示，最终模型正文保留在正式回复区。
16. 项目选择保持项目中心式全屏布局，并通过右上角关闭按钮或 Esc 返回当前会话；打开选择器
    不卸载当前项目 Runtime，也不打断活动 turn 的事件渲染。
17. Forge 在主线程显式接管 SIGINT/SIGTERM，并把它们转换为 Uvicorn 协作式退出；不得依赖
    从 `make`/shell 继承的信号 disposition。浏览器自动打开线程为 daemon，不能阻止进程收尾。
18. 聊天 Markdown 在内容内部右上角与回复外部右下角都提供复制入口；复制的是原始 Markdown
    文本。行内代码统一使用浅色底与黑色文字，代码块继续跟随主题。活动 turn 的最终回复底部
    同步展示耗时、输入/输出/思考 token、模型/工具次数和本轮 token 总数。
19. 服务停止信号由启动器在"等待连接收尾"之前置位，SSE 流据此自己结束，并发出
    `server_stopping` 告知页面这是本地服务退出而非网络抖动。Uvicorn 的 lifespan shutdown
    排在等待之后，不能作为长连接的唤醒点；`timeout_graceful_shutdown` 只作兜底。
20. Host/会话/CSRF 校验与安全响应头由纯 ASGI 中间件承担。`BaseHTTPMiddleware` 会把响应体
    搬进内存流转发，长连接因此看不到客户端断连，退出时还会留下 `CancelledError` 栈。
21. SSE 只用 `run_event` 一个事件名承载全部运行事件，类型放在 `data.kind`；控制事件为
    `resync_required` 与 `server_stopping`。首次连接从当前游标开始，只有带 `Last-Event-ID`
    的断线重连才补发历史——已完成 turn 的正文来自 transcript，不靠重放事件缓冲拼装。
22. 页面顶栏展示真实事件流状态（连接中/已连接/重连中/已停止）；运行态以 `/turns/current`
    为准，刷新页面后仍能接上未完成的 turn 并保留停止入口。
23. SSE 重连节奏由页面自己控制：间隔从 1 秒起逐次翻倍，一旦下一次要等超过一小时就停止
    自动重试，只保留手动重连入口。断点续传改用显式 `after` 游标，不依赖 EventSource 实例
    内部状态。重连失败时先探测会话是否还有效：令牌换代导致的失效直接提示重开启动链接。
24. 用浏览器打开陈旧地址时返回可操作的失效说明页，而不是一行裸 `Unauthorized`。
25. 运行过程按步骤时间线呈现：模型、工具、计划与待办同处一条轨道，只用轨道圆点区分状态，
    不放类型图标——过程区是扫读区，图标只会分散注意力。turn 结束后自动折叠，也不再把没有
    终态事件的步骤显示成进行中。回复正文只在右下角保留一个复制入口，代码块自带复制按钮，
    最终用量以并列 chip 展示。
26. 处理过程可在刷新页面后重新展开：`/api/v1/runs` 按 turn 归档进程内缓冲，并把流式增量
    折叠成每次模型调用的一段正文。它仍然不是恢复真相源（ADR-0016 §9），服务重启后为空，
    会话正文继续由 transcript 提供。
27. 页面不提供手动重连按钮：端口与会话密钥都固定之后，重启 Forge 后已打开的窗口应当自己
    连回来。`server_stopping` 之后重置退避并继续重试；重连成功要重新对齐项目与工作区状态。
28. 流式增量不进前端的事件数组。每条增量都复制、排序、查重再重算分组，开销是事件数的平方，
    长回答会把页面卡死；正文按调用累加，事件数组只留结构性事件，并按帧合并落盘。
29. 入口 HTML 一律 `no-cache`，带内容哈希的构建产物 `immutable` 长缓存。入口被缓存意味着
    升级 Forge 之后浏览器还在跑上一版前端——代码改了、行为没改，而两边看起来都对。
30. 流式渲染的三条硬约束：解析器每轮必须推进游标；批量落盘用定时器而不是
    `requestAnimationFrame`（标签页切走时 rAF 完全不触发，事件会一直堆着不渲染也不释放）；
    受控 `<details>` 自己同步翻转开合，不依赖异步的 `toggle` 事件。
31. 模型与思考强度调得最勤，入口放在输入框旁边，不必进设置页；设置页里同一张表单的字段
    统一填写后一次保存——逐项保存每次都要重拉配置，会把同表单里其他没保存的输入冲掉。
32. 处理过程在运行时展开，答案落地即收起；工具调用按"做了哪一类事"（读取文件 / 修改文件 /
    执行命令 / 计划与待办）归并**时间线上相邻**的调用，不平铺。一次模型调用最后去调了
    工具，说明它说的是过程而不是答案。

    > 2026-08-20 修订: 上一版把交接点定在"模型表态要调工具的那一刻"，仍然不够早——中间
    > 输出还是先进了聊天区，闪一下再撤走。改成**只有确认这次调用不再要工具，正文才进
    > 聊天区**：流式过程中的正文只在处理过程里渲染一次，一次都不进聊天。代价是最终回答
    > 在这次调用收尾时才出现，所以处理过程运行期间必须默认展开——否则用户盯着一个折叠条
    > 等答案。答案到达时它自动收起（决策 32 的"生成最终答案即全部关闭"），用户手动开合
    > 过就一直听用户的。收起时连内容一起不渲染：一轮长任务有上百个节点，留在 DOM 里的话
    > 最终回答每流入一帧都要多走一遍这棵树。
    >
    > 归并要在**排好序的时间线上**判相邻，不能在只含工具的列表里判：隔着一次模型调用的
    > 两次读文件会被合起来，合出来的那一段还带着更早的 sequence，排到模型调用前面去，
    > 时间线就说了假话。派发前的 `DECISION_SUMMARY` 不再单独占一行——它夹在工具之间，让
    > 连着六次读文件没有一次是相邻的，聚合根本合不起来；改成挂在它解释的那一步上。
    >
    > 分类看的是**这次调用声明的能力**而不是工具名。写死的名字清单会悄悄过期：
    > `fs.search_text` 在清单里躺了很久而真名是 `search.text`，于是每次搜索都归进"其他
    > 工具"，没有任何东西会因此报错。连 `prepare` 都没走到的调用没有能力可看，才退回按
    > 名字认，而且只认确切认识的那些——模型编出来的 `fs.write_file` 也以 `fs.` 开头，
    > 猜成"读取文件"就是在替一次没发生过的写入洗白。
33. Web 覆盖 CLI 的全部配置面，逐条对应：`/mode` → 模式菜单；`/config` → 常规页；
    `/model` → 当前模型选择器（从已配置模型里选，并显示供应商密钥是否就绪）；
    `/config` 用途覆盖 → 用途模型覆盖区；`/thinking` → 当前模型的进程内 thinking 开关与
    强度（不落盘，与模型配置里的持久 thinking 分开）；`/tools` → 安全页的工具清单；
    `/rules --prune` → 清理按钮；`/checkpoints`、`/undo`、`/restore --preview`、
    `/recovery` → 恢复页；`/status` → 状态页；`/plan-doc list|use` → 计划栏的计划目录；
    `/todo` → 计划栏的待办清单。改运行配置与既有接口同一条边界：turn 运行期间一律 409。

## 决策 1 修订（2026-08-21）

**裸 `forge` 的默认不变**，仍是 Web 控制面。新增 `forge cli` 子命令进终端交互式会话，
走 `interfaces/cli/bootstrap.run()`。

### 为什么补这一条

本 ADR 的标题写的是「替代」，实现也照做了：`app.py` 把 `run_session` 换成了 `run_web`，
终端入口的整棵代码树（45 个文件、REPL、斜杠命令、TTY 审批）完好无损地留在仓库里，
**只是没有任何调用方**。一个既不删除也不可达的子系统是最坏的一种状态：它继续参与
`make ci`、继续被重构波及、继续让读代码的人以为它还在服役。

要么删掉它，要么给它一个入口。选后者，理由是终端会话在两类场景下仍不可替代：无法开
浏览器的远程会话（SSH、tmux），以及 `#` 人工 Shell 这条 Web 明确不提供的信任通道
（决策 5、决策 6）。

### 不变的部分

- **业务语义与组合根**：两条路径共用 `interfaces/runtime` 的 LLM 与工具组合根
  （决策 3），AgentLoop、裁决、审批绑定、恢复与 session schema 一字不改。
- **`InputOrigin` 的区分**（决策 5）：Web 提交的 turn 仍是 `WEB_USER`，不具备
  `TTY_USER` 的人工 Shell 特权；`forge cli` 里 `#` 仍然是人工 Shell 入口。
- **决策 2 仍然成立**：斜杠命令能改的每一项配置，Web 都必须有入口。`forge cli` 的
  存在不构成「这一项可以只留在终端」的理由——那正是本 ADR 要消除的状态。

### 两条路径不能同时对同一项目运行

CLI 与 Web 取的是同一把项目级 `forge.lock`。这不是限制，是前提：计划
（`fs_plan_store`）、会话事件与恢复点都不加文件锁，正因为这把进程锁保证了同一项目只有
一个 Forge 进程。后启动的一方以 `ExitCode.PROJECT_LOCKED`（6）退出并打印占用者 pid，
两条路径用同一个码——「另一个 Forge 在跑」与对方是哪种入口无关。

`ExitCode` 因此从 `interfaces/cli/` 移到 `interfaces/`：退出码是进程级契约，两条启动
路径共用。早先它在 cli 包下，web 那一侧只能自己写 `6` 与 `7` 两个裸数字。

### 验收

`tests/commands/test_entrypoint.py` 钉住入口分发：裸 `forge` 调 `run_web`、
`forge cli` 调 `run_session`、两者互不越界、退出码原样传出。加这组用例的直接原因是
这次回归本身——代码完好而没人调用，任何现有用例都发现不了。

## 兼容性

- `~/.forge/projects`、`events.jsonl`、`state.json`、计划、学习规则和恢复数据不迁移。
- `user_message.payload` 追加 `origin`；旧事件缺失时仍按既有读取逻辑处理。
- `forge --help`、`forge --version` 保留；原 REPL 和人工 Shell 不再是产品入口。
- ADR-0007 的终端主入口和 ADR-0017 的人工 Shell 产品入口由本 ADR 取代。
- ADR-0016 的领域运行事件协议继续有效，只有 `TerminalRunRenderer` 被 Web subscriber 替代。

## 验收标准

- `forge` 启动后打印可直接点击的启动链接，不自动打开浏览器；`--open` 时才打开项目中心。
- 未持有启动 session、CSRF 不匹配、非 loopback Host 或跨 Origin 的控制请求被拒绝。
- 相同输入、配置和工作区状态下，Web 入口产生与原入口相同的 Agent/tool/policy/session 结果。
- 工具审批与计划评审可在 Web 完成，断连不会放行。
- 用户输入即时显示，模型正文与工具阶段流式更新；终态保留耗时、模型/工具次数和 token 用量。
- 中文输入法组合态的 Enter 不发送消息；用户上滚超过阈值后增量渲染不强制拉回底部。
- 浏览器保持 SSE 连接时，一次 Ctrl-C 即可停止服务：进程退出码为 0，终端不打印异常栈。
- 服务停止后页面显示"服务已停止"并禁用输入，而不是无限重连；刷新页面能接回运行中的 turn。
- 服务异常退出后页面按退避节奏重连，超过一小时间隔即停手；重启 Forge 后已打开的窗口自愈。
- 一次数千增量的长回答不会卡住页面；刷新后仍能展开该 turn 的处理过程。
- 模型调工具之前说的话一次都不出现在聊天区；连着的同类工具调用在处理过程里合成一段。
- wheel 包含构建后的前端资源；Python 与 Web 类型检查、构建和测试进入 `make ci`。
