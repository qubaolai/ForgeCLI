# ADR-0027：采用单一安全事实链与执行前状态复核

## 状态

Accepted（2026-08-20 实现）

## 背景

ADR-0013/0014 建立了 Shell 解析、脚本分析、路径保护、审批、恢复和执行授权等多层防线。
层次本身有必要，但实现逐步出现了两类额外复杂度：

1. 同一事实被多次构造。Shell 与 ScriptAnalyzer 各解析一次命令；ShellAnalyzer 和
   WorkspacePathAnalyzer 各检查一次受保护路径；审批绑定与审批视图分别比较。
2. 类型名称声称“冻结”，实际只冻结 Python 对象。`ExecutionContext` 内仍可持有可变
   `dict`，`OsFileSystemView.version` 也不是文件系统快照；脚本或可执行文件在分析后被替换
   时，运行时没有统一复核。

这不是单纯的代码量问题。重复语义会产生口径漂移，而虚假的冻结保证会把 TOCTOU 缺陷藏在
类型名后面。

## 决策

### 1. 保留纵深防御，删除重复事实来源

安全链仍保留能力分析、Hard Deny、策略预算、人工审批、恢复层和运行时授权六个独立职责。
但一个事实只能有一个生产方：

- Shell 命令只由 `ShellCapabilityAnalyzer` 解析一次，`CommandPlan` 随
  `AnalysisFindings` 交给 `ScriptExecutionAnalyzer`。
- 受保护路径只由 `WorkspacePathAnalyzer` 按 realpath 检查；Shell 分析器只负责产出路径
  效果，不再维护第二套较弱的字面路径判断。
- 路径绝对化统一使用 `ExecutionContext.resolve`，不在 Shell 分析器内另写一套拼接规则。
- 审批视图哈希进入 `ApprovalBinding`，批准后只比较一份绑定对象。

“删除重复检查”不等于删除防线：路径保护仍在能力检查阶段，Hard Deny 和执行时复核均保留。

### 2. 不把普通文件系统观察入口称为快照

`FileSystemView.version` 只标识本次 `ExecutionContext` 的观察入口。它不证明目录内容在操作
系统层被冻结，也不进入可复用的 plan 身份。

真正需要执行一致性的文件，以 `FileStateBinding` 进入 `ToolPlan`：

```text
path / realpath / file_identity / size / mtime_ns / content_hash
```

当前绑定可执行文件与显式脚本文件。`ToolRuntime` 在调用 `perform` 前统一重读并比较；任一项
变化均返回 `execution_environment_changed`，要求重新 prepare、分析和裁决。

无法完整读取的脚本或可执行文件不提供“批准后继续”路径。内容超过分析上限、读取短缺或对象
不是普通文件时直接形成不可执行结论，因为审批界面没有展示完整内容，人工批准也不能补足这个
事实缺口。

### 3. 执行上下文递归冻结并在运行时核对

`ExecutionContext` 构造时复制环境映射并转为只读映射。运行时同时比较：

- cwd；
- 净化后环境哈希；
- 文件系统观察入口身份；
- toolchain id；
- ExecutionProfile hash。

因此“frozen dataclass 里装着可变 dict”的非法状态不再存在。

### 4. 审批响应也是不可信边界输入

`ApprovalService` 是界面适配器，不是授权签发者。协调器接受响应前必须验证：

- response.approval_id 与当前请求相同；
- scope 属于界面实际提供的 allowed_scopes；
- Mandatory Ask 只能使用 once。

审批绑定同时覆盖 plan、目标集合、目录快照、执行画像、策略、mode 和 presentation hash。
错误 id、扩大范围或视图错配一律不执行。

### 5. 环境净化使用“透传白名单 + 受控覆盖”

宿主变量仍先走显式 allowlist；之后仅允许 ExecutionProfile 中冻结的受控值覆盖。受控值关闭
常见隐式配置和代码加载入口，包括 Git system/global config、Python user site、pip/npm 用户
配置、curl/wget 用户配置。

HOME 从账户数据库获取，不接受可修改的宿主 HOME 重定向；PATH 只含绝对目录。用户显式加入
PATH 的工具链目录单独标记为可写 TOOLCHAIN，不能因为进入 PATH 就被误判成 SYSTEM。

净化规则和受控覆盖都进入 ExecutionProfile hash，变化会使旧授权失效。

## 影响

### 收益

- 命令解析、路径保护和审批重验各有一个事实来源。
- 脚本、可执行文件、PATH、HOME 或 cwd 在裁决后变化时，运行时 fail closed。
- 审批适配器不能串用响应或扩大授权范围。
- 类型与注释不再声称不存在的 OS 文件系统快照。

### 代价

- 执行前会重新读取已绑定的脚本和可执行文件，增加少量 I/O。
- 超过内容绑定上限的可执行文件或脚本会被拒绝，需要用户换成可分析的入口。
- 禁用隐式用户配置可能改变 git/pip/npm/curl/wget 的既有个人配置行为；需要的配置应在命令
  参数或 Forge 显式工具链配置中表达，不能隐藏在审批视图之外。

### 已知边界

- FileStateBinding 是 perform 前复核，不是把已打开 fd 直接交给 `execve`。复核结束到 Shell
  真正打开路径之间仍有很窄的宿主并发窗口；系统 PATH 不可由 Agent 写、可写工具链必须 ASK，
  后续系统沙箱仍是封住该窗口和任意脚本副作用的必要层。
- Raw Shell 的运行期 glob 会再次展开；本 ADR 不把分析期目标哈希伪装成结构化 argv。该限制仍
  按 ADR-0021 由恢复屏障兜底，彻底消除需要独立的 `process.run`/`script.run` 执行模型。

## 验收标准

- 环境映射不可变，原始 dict 后续修改不影响 ExecutionContext。
- cwd、环境哈希或观察入口变化时，ToolRuntime 在 perform 前拒绝。
- 脚本/可执行文件内容在分析后变化时，ToolRuntime 在 perform 前拒绝。
- 大于分析上限的显式脚本不可由普通审批绕过。
- 错误 approval_id 和未提供的 scope 不会执行。
- 显式工具链目录解析为 TOOLCHAIN，而不是 SYSTEM。
- 现有安全、工具、Web、恢复和 E2E 测试保持通过。
