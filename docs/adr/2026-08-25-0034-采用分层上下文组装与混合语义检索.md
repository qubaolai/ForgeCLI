# ADR-0034: 采用分层上下文组装与混合语义检索

## 状态

Proposed

## 日期

2026-08-25

## 背景

ADR-0032 已经让 Forge 不再等到供应商报上下文溢出才失败: 它按预算去重,
把较旧工具结果降级为 artifact 引用, 仍然放不下时再摘要旧消息. ADR-0033
也已经让跨会话记忆不再只增不改: 记忆是 `(scope, key) -> {value, provenance}`
的映射, 同 key 写入会覆盖旧值.

这两套机制解决的是“放不放得下”与“字面上是不是同一条”, 还没有解决更高层的
相关性与语义冲突.

### 1. 时间远近不等于与当前任务相关

`ContextManager` 今天的主要取舍依据是时间: 最旧工具结果先降级, 最近两条工具结果
保留原文, 摘要时保留最近六条消息. 这个降级方向确定, 可测, 且通常有效, 但它不能回答
“三轮前读到的架构约束是否正好与这次问题相关”.

### 2. 同 key 覆盖防不住语义别名与矛盾

以下两条在人看来是同一件事:

```text
test_command    = pytest
testing.command = uv run pytest
```

对今天的 `MemoryService` 来说它们是两个不同 key, 会同时进提示词. 反过来, 下面两条
向量很相似, 但不能直接合并:

```text
项目用 uv 管理依赖
项目的测试命令是 uv run pytest
```

embedding 能找出值得比较的候选, 不能证明两句话在说同一件事, 更不能判断谁真谁假.

### 3. “只保留语义相关内容”会删掉低相似度的必要约束

安全边界, 项目指令, 未闭合工具调用, 当前计划和用户刚刚给出的限制不一定与本次问题
有高向量相似度, 但不能被排名淘汰. 原始 transcript 还有时序和 assistant tool call /
tool result 配对约束; 从中任意抽几条“相关消息”会造出协议形状已坏的伪历史.

### 4. 全局用户记忆存在并发丢更新

`~/.forge/memory.json` 被所有项目共享, 而 `forge.lock` 是项目级的. 两个不同项目能同时
读到同一旧版本并各自整表写回. 临时文件 + `replace` 只防半截 JSON, 不防 last writer wins.

## 决策

### 决策 1: 上下文分成必须保留层与可检索层

Forge 不把全部上下文交给一个相似度排序器决定去留.

**必须保留层:**

- 系统规则, 安全边界与当前运行事实;
- 用户当前问题与本轮已给出的明确限制;
- `FORGE.md` 项目指令;
- 当前 plan / todo;
- 未闭合的 tool call / tool result 单元;
- 最近原始消息与正在被消费的工具结果;
- 未处理的审批, 评审与取消状态.

必须保留层不参与向量排名, 也不因为检索服务不可用而消失. 真的连必须层都放不下时,
按 ADR-0032 的 `CONTEXT_COMPACTION_REQUIRED` 停下, 不静默删约束.

**可检索层:**

- 跨会话项目记忆和用户偏好;
- 已被摘要的旧会话片段;
- 已归档的旧工具结果与 artifact 分块;
- 当前任务要求召回的已观测项目事实.

不对原始活跃 transcript 做逐条向量过滤. 会话历史先按 ADR-0032 的安全切点保持时序和
工具配对; 只有已摘要, 已归档或已提炼成独立事实的单元进可检索层.

### 决策 2: 检索采用确定性过滤 + 关键词 + 向量的混合路径

检索按以下顺序进行:

1. 按 `project_id`, `scope`, 内容类型, 权威级别, 生命周期和是否过期过滤;
2. 精确 key, 路径, 符号, 命令, 错误码与全文词项走词法检索;
3. 自然语言语义走 embedding 检索;
4. 合并候选, 按内容哈希去重并做多样性抑制;
5. 在 retrieval budget 内按相关性, token 成本, 权威和时效组装.

排序至少纳入:

```text
semantic_similarity
+ lexical_match
+ source_authority
+ freshness
+ active_task_relevance
- duplicate_penalty
- stale_penalty
```

分数是召回与排序依据, **不是真实性分数**, 不能用来覆盖记忆或解锁能力.

embedding 不可用或索引损坏时, 退化为确定性过滤 + 关键词 + 时间策略, 不阻断 turn,
不因为“没向量”就返回空上下文.

### 决策 3: 检索查询由当前任务快照确定性构造

query 不只包含用户最后一句话, 而是由本轮请求, 活跃 plan / todo, 最近出现的路径,
符号, 错误码, 工具名与当前未解决问题的短摘要拼成.

组装规则是纯函数并版本化. 默认不为“生成检索 query”额外调一次 LLM. 将来若引入
query rewrite, 必须是可配置的独立用途, 并保留原始 query 的检索分支.

### 决策 4: 记忆仍以稳定 key 为主键, 向量只产生冲突候选

ADR-0033 决策 6 保留: 同 `(scope, key)` 写入直接 upsert, 不需要 embedding 或语义模型.
只有新 key 被关键词或向量检索命中近似候选时, 才进入语义检查.

候选交给 `MemoryConflictResolver` 归一为封闭关系:

```text
SAME_FACT_SAME_VALUE
SAME_FACT_SUPERSEDES
SAME_FACT_CONTRADICTS
RELATED_DISTINCT
UNRELATED
UNCERTAIN
```

embedding 自己不得产生这个结论. resolver 通过规则和可选的结构化模型调用分类;
未配语义模型时不猜, 返回 `UNCERTAIN`.

处理规则:

- `SAME_FACT_SAME_VALUE`: 不新增, 刷新已有条目的来源与更新时间;
- `SAME_FACT_SUPERSEDES`: 只有新证据符合决策 5 时才更新 canonical key;
- `SAME_FACT_CONTRADICTS`: 不静默并存也不靠相似度选边, 返回冲突候选要求验证;
- `RELATED_DISTINCT` / `UNRELATED`: 允许新增;
- `UNCERTAIN`: 不把不确定内容静默写进长期记忆.

`memory_write` 的观测结果必须返回命中的 canonical key 与旧值摘要, 让模型能选择
用同 key 更新, 先验证, 或用 `memory_forget` 删除过期条目.

### 决策 5: 冲突按来源类型与当前证据处理

不使用“最新的一定对”这条粗暴全局顺序:

- **指令冲突:** 当前用户明确指令 > `FORGE.md` > Agent 记忆. 记忆从不覆盖指令;
- **项目事实冲突:** 当前受控工具观测到的文件状态优先于旧记忆. `FORGE.md`
  若与实际状态不一致, 向上层暴露冲突, 不静默改写人写指令;
- **用户偏好冲突:** 用户本轮明确表达的偏好更新旧用户记忆;
- **无法证实:** 保留原条目, 新写入返回 `memory_conflict` 或 `memory_uncertain`.

`derived_from` 只用于人类诊断, **不构成权威证据**. 新的 `source_kind` 与 `source_refs`
由系统绑定到当前 `session_id`, `turn_id`, 用户消息或已完成工具观测; 模型不能伪造
不在当前会话事件中的引用.

### 决策 6: 上下文冲突显式暴露, 不由排名分数静默选边

混合检索召回新旧两条矛盾事实时, 被 resolver 或确定性规则标记为一个有界冲突块:

```text
[已发现未解决的历史冲突; 不要据此执行不可逆动作]
- commands.test = pytest (session ..., turn ...)
- test_command = uv run pytest (session ..., turn ...)
```

如果冲突块超出检索预算, 保留 key, 来源和冲突类型, 内容降级为可取回引用;
不得只留一边.

### 决策 7: 上下文预算先保必须层, 剩余额度再分给检索层

`ContextBudget` 在总额度之下增加分层结果, 但不写死一组对所有模型都一样的百分比.

1. 计算 system prompt, 工具 schema, 当前用户请求与必须块的硬成本;
2. 为当前回复保留 `max_output_tokens`;
3. 对活跃 transcript 按 ADR-0032 去重, 降级和摘要, 不破坏安全切点;
4. 将剩余 token 作为 retrieval budget;
5. 按分数, 权威, 多样性和 token 成本选取检索单元;
6. 组装后再估算, 超出时只从检索层尾部退出.

“记忆全量注入”降为小数据 fallback: 全部有效记忆能放进 retrieval budget 时可以全量注入;
放不下时按本 ADR 检索.

### 决策 8: embedding 与索引是可替换端口, 原始 JSON 和事件仍是事实源

新增应用端口:

```text
EmbeddingGateway.embed(texts, purpose) -> vectors
SemanticIndex.upsert / remove / search / rebuild
MemoryConflictResolver.resolve(existing, proposed, evidence) -> relation
```

它们不让 `MemoryService` 直接 import 向量数据库 SDK. 记忆的事实源仍是 `memory.json`,
会话历史仍是 `events.jsonl` / `state.json`, 工具长输出仍是 `ArtifactStore`.
语义索引是可删除, 可重建的派生缓存.

MVP 索引按 ADR-0026 使用 JSON, 不落工作区:

```text
~/.forge/state/semantic-index/
  <embedding-model-hash>/
    user-memory.json
    projects/<project-id>/memory.json
    sessions/<session-id>/context.json
```

索引条目至少带 `record_id`, `source_type`, `source_id`, `content_hash`,
`embedding_model`, `embedding_dimensions`, `chunking_version`, `vector`.
模型, 维度, 分块版本或内容哈希不一致就重建. 索引写失败不回滚事实源;
只标 dirty, 下次重建.

若 JSON 平面索引实测不达标, 更换为 SQLite / HNSW 必须另立 ADR, 不提前引入向量数据库.

### 决策 9: embedding 必须显式配置, 不静默外发内容

embedding 是独立能力, 不复用 `LlmGateway.complete`. 目录显式声明 embedding 模型, 维度,
批量上限和供应商; 用户未配时语义分支关闭.

项目源码, `FORGE.md`, 工具输出, artifact, 会话历史与记忆, 不得被静默发给
未显式配置的远程 embedding 供应商. 凭证过滤在 embedding 之前继续生效.

### 决策 10: 索引只收录已经经过现有边界的内容

语义索引不得自己遍历工作区, 不得为了检索效果绕过 `fs_read`, `search_text`,
`ArtifactStore` 和会话事件存储. 只有已经工具管线读取并产生 provenance 的内容,
过滤后的记忆, 已落盘摘要与当前会话有权引用的 artifact 分块可以进索引.

召回后必须保留 provenance 与 trust. 工具输出即使经过重排仍是
`tool_output / untrusted`; 记忆仍然不参与安全裁决.

### 决策 11: 为全局用户记忆增加独立锁和存储 revision

`~/.forge/memory.json` 增加单调 `revision`. 写入走“加锁 -> 重读 -> 修改 -> 原子替换 ->
解锁”. 不同项目共用一把用户记忆锁; 项目记忆继续受项目级 `forge.lock` 保护.

`revision` 是并发控制字段, **不是版本历史**. 文件里仍只留最新表, 不保存 `r<N>.json`.
索引更新在事实源写成功之后发生, 且不持锁做远程 embedding 调用.

### 决策 12: 召回和冲突决策可观测, 但不记原文和向量

召回记录 `query_hash`, 策略版本, embedding 模型与索引版本, 候选数, 选中的 record ID,
分数, token 数和 fallback 原因. 冲突检查记录 proposed key, candidate key, relation,
resolver, evidence refs 和最终决定.

事件不记 query 原文, 记忆原文, embedding 向量或完整候选内容, 避免复制敏感面.

## 对 ADR-0032 / ADR-0033 的修订

- ADR-0032 的预算驱动, 确定性去重, artifact 降级, 安全切点与二级摘要保留;
  本 ADR 在它们之前增加分层组装, 不用向量抽取代 transcript 压缩.
- ADR-0033 的两级 scope, 静默写入, 同 key 覆盖, 凭证过滤, provenance 和记忆不参与
  安全裁决保留; 本 ADR 修订其全量注入和不检测语义冲突的取舍.
- 在本 ADR 被 Accepted 且实现前, ADR-0032 / ADR-0033 的已实现行为仍是当前事实.

## 备选方案

- **仅用向量相似度组装所有上下文:** 会删掉低相似度的必要约束并破坏工具配对,
  因决策 1 否决.
- **用 embedding 相似度直接覆盖旧记忆:** 相似度不能区分一致, 覆盖, 矛盾与相关,
  因决策 4 否决.
- **把向量数据库当事实源:** 更换模型, 维度或分块方法后无法从原始记录重建,
  因决策 8 否决.
- **每次请求全量注入所有记忆:** 小数据时作为 fallback, 不再是无条件不变式.
- **每次写记忆都调语义裁决模型:** 同 key 覆盖和无关新记忆无需额外调用,
  只在新 key 命中近似候选时调 resolver.

## 影响

- 上下文组装从“全量 + 按时间压缩”变成“必须层 + 可检索层 + 预算压缩”.
- 记忆扩展到能发现跨 key 的重复与冲突候选.
- 增加 embedding 成本, 延迟, 配置与数据出境面; 未配时保留确定性退化路径.
- 增加一份可重建索引, 不改变 JSON / JSONL / ArtifactStore 的事实源地位.
- 用户记忆写入收紧为带锁, revision 和事后索引刷新的事务边界.
- 语义检索不影响安全裁决, mode, 学习规则或审批.

## 分阶段落地

### 阶段 1: 先收紧记忆正确性, 不引入模型

- 建立保留命名空间与建议 key (`commands.*`, `preferences.*`, `architecture.*`);
- 增加 `source_kind`, `source_refs`, `updated_at`;
- 为用户记忆增加独立锁与 revision;
- 冻结记忆冲突结果的领域值.

### 阶段 2: 引入 embedding 端口与记忆候选召回

- 扩展模型配置与目录的 embedding 能力;
- 实现 `EmbeddingGateway` 与 JSON 平面索引;
- 只对新 key 查询语义近似记忆;
- 未配时保持今天的同 key upsert.

### 阶段 3: 引入语义冲突裁决与有界冲突块

- 实现 `MemoryConflictResolver` 的规则与结构化模型适配;
- 将冲突候选变成更新, 拒绝或可解释观测;
- 提示词组装显示未解决冲突, 但不将其变成指令.

### 阶段 4: 将检索接入上下文预算

- 增加必须层 / 可检索层的 DTO 与 token 计费;
- 先召回 memory 和已压缩会话, 再扩到有权 artifact 分块;
- 保留 ADR-0032 的去重, 降级, 摘要与超限停止;
- 用离线评测决定检索阈值, top-k 和分数权重, 不靠直觉写死.

## 验收标准

- embedding 未配, 不可用或索引损坏时, Agent turn 照常进行, 必须层完整.
- 必须保留块不因为向量相似度低而被删除.
- 原始 transcript 的 tool call / tool result 配对不被语义检索切断.
- 精确路径, 符号, 命令和错误码在向量分支不命中时仍能由词法分支召回.
- 同 `(scope, key)` 二次写入仍为覆盖, 不产生语义模型调用.
- 新 key 与已有 key 表达同一事实时, 不会静默并存为两条活跃记忆.
- 相似但表达不同维度的记忆不会被误合并.
- 矛盾且无法证实的内容不会由相似度静默选一条.
- `derived_from` 不能伪造权威; 不存在的会话引用不能进 `source_refs`.
- 项目指令, 记忆和工具事实矛盾时, 提示词显示来源与未解决状态.
- 两个不同项目并发写用户记忆时两条更新都保留, `revision` 单调递增.
- 索引可整目录删除并由 JSON / JSONL / ArtifactStore 重建.
- 切换 embedding 模型, 维度或分块版本后不读旧向量.
- 远程 embedding 未显式配置时不发出项目, 会话, artifact 或记忆内容.
- 召回的工具内容仍标记为不可信, 记忆仍不参与安全裁决.
- 相同输入, 索引版本与 embedding 响应下, 组装结果字节级一致.
- 现有 ADR-0032 / ADR-0033 测试在 fallback 模式下继续通过, `make ci` 全绿.
