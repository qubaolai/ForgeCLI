# ADR-0047：采用操作系统文件事件感知并向 LLM 发送结构化变更

## 状态

Proposed

## 日期

2026-09-04

修订：2026-09-05，收敛为跨 turn 的文件变化通知与来源归因，移除内容 diff。

## 背景

同一个 session 的多个 turn 之间，LLM 可能继续使用历史文件读取结果。但上次 turn 结束
之后，工作区文件可能已经被人类、其他 Agent 或本 Agent 启动的后台任务修改。仅靠工具
返回值无法覆盖这些变化；反复扫描整个工作区则会产生与工作区规模成正比的重复 I/O。

本 ADR 要解决的是：下一 turn 开始时，让 LLM 知道上次 turn 结束后哪些工作区文件发生
了变化，以及变化是否与本 Agent 有关，从而在再次使用这些文件时重新读取内容。

核心事实是“文件变了”，不要求解释“具体变了什么”。不保存正文基线，不计算内容 hash、
行数或 diff，不设置 diff worker。文件内容仍由现有读取工具按需获取。本 ADR 不要求在
同一 turn 内持续注入变化，也不因文件变化自动撤回最终回答或重新请求模型。

## 决策

### 决策 1：监听器属于 session，通知在下一 turn 开始时交付

Agent session 启动时，通过 application 层端口创建工作区监控器，在第一个 turn 开始前
订阅所有当前 workspace_roots。具体实现归 infrastructure adapter，优先使用成熟的跨
平台事件库，首选 watchfiles；application 和 domain 不依赖平台原生 API。

监听器在 turn 执行期间和 turn 间隙持续运行，直到 session 结束。新增工作区根目录时更新
订阅；路径遵守现有逻辑工作区边界与忽略规则。监控器不读取文件正文、不修改工作区，
也不为了建立内容基线扫描整个工作区。

每次 turn 正常结束、取消或异常结束时，记录一个线程安全的观测边界。此后观测到的变化
进入待通知集合，在下一 turn 的第一次模型请求前交付。第一个 turn 使用监听就绪点作为
初始边界。边界之前明确属于已结束 turn 的事件不作为新的 turn 间隙变化重复报告。

OS 事件可能延迟或成批到达，观测边界不等于物理写入时刻。无法确定属于边界哪一侧的
事件保守保留为待通知路径，来源证据不足时标 unknown。宁可提醒模型重新读取一个可能
已经读过的文件，也不为了精确划分 turn 静默丢弃边界附近的变化。

监控器在 turn 执行期间仍接收事件并维护来源证据，但不要求把该 turn 内新发生的变化
全部带到下一 turn；本 ADR 的通知范围是 turn 间隙变化、边界不确定事件，以及此前交付
失败的待通知记录。已取出的通知交付失败时必须保留，不能因后续 turn 结束而清空。

session 结束时停止监听并释放队列、集合和归因状态；新 session 创建新实例，不共享
operation id 或待通知记录。进程退出期间不承诺持续监听；恢复历史 session 时，应明确
标记离线期间变化范围未知，而不是把空事件集合当成工作区未变化。

### 决策 2：用路径失效通知代替内容比较

OS 文件事件用于确定需要重新验证的路径。创建、修改、删除、编辑器原子替换都规范化为
路径失效记录；同一路径多次变化只通知一次，不要求保留逐次写入过程或证明正文确实不同。

删除后重建同名文件，即使最终内容相同，也可以通知该路径。重命名通知旧路径和新路径，
不凭路径相似度推断对应关系。底层仅能提供目录级变化时，报告该目录下的历史读取结果
需要重新验证，不把目录路径伪装成完整的受影响文件清单。

记录使用绝对规范化路径以区分不同工作区根目录下的同名文件，重叠根目录下同一路径去重。
路径规范化不依赖文件仍然存在，也不通过跟随符号链接扩大监听范围。UI 可以另外生成
相对路径用于展示。最小协议要求路径、影响范围、来源以及 kind。kind 取 changed、deleted
或 unknown：changed 表示路径发生变化且仍存在，不细分创建与修改；deleted 表示交付前
已确认路径不存在；unknown 表示无法确认当前状态。

交付前只对待通知的候选路径执行轻量元数据检查，不读取正文、不扫描整个工作区。
不能仅凭某次删除事件报告 deleted：例如删除后重建、编辑器原子替换，都可能使路径重新
存在。权限错误、检查超时或无法可靠判断时使用 unknown，不能误报为不存在。检查遵守
工作区边界，不跟随符号链接；悬空符号链接不等于链接路径已删除。

kind 描述交付前检查时的状态，不保证路径之后不会再次变化。后续观测到重建时更新待通知
记录；路径状态更新不覆盖已经合并的来源证据。目录确认删除时，可用 scope=subtree 与
kind=deleted 通知该目录下的旧路径均已失效，无需逐个尝试读取。

LLM 获知路径失效后，涉及该路径的后续判断必须重新读取或验证当前内容；无需立即读取
所有变化文件。kind=deleted 时，通知必须直接告诉 LLM 路径已不存在、历史内容已失效，
不要仅为确认删除而调用读取工具；应据此调整后续判断，避免一次无意义的工具往返。
kind=changed 或 unknown 时，仍按需重新读取或验证。若后续有重建证据或任务明确要求
检查当前存在性，可以再次验证，不能永久禁止读取该路径。source 为 agent 也不能豁免
内容失效处理，因为本 Agent 的后台任务同样可能让历史读取结果过期。

### 决策 3：保留来源归因，时间窗口只作为辅助证据

来源字段回答“是否由本 Agent 导致”，使用以下三种取值：

| source | 含义 | 归因要求 |
|---|---|---|
| agent | 有证据关联本 Agent 的写操作 | 有执行事实支持的路径与 operation 关联，且没有已知冲突或混合来源 |
| external | 有充分依据排除本 Agent 的写操作 | 对应观测范围内能够排除相关本 Agent 写操作，包括仍可能写入的后台任务 |
| unknown | 无法可靠归因或涉及混合来源 | 只有时间重叠、延迟无法界定、并发写入、事件合并或证据不足 |

统一工具协调管线记录 operation 的起止与可用执行事实。文件工具实际执行的写入路径可
作为归因证据；仅有工具请求中的目标路径、尚未执行的调用或工具窗口重叠，不足以认定
agent。工具上报辅助归因，OS 事件负责发现变化，文件工具不能成为唯一的变化发现来源。

例如，Agent 运行测试期间人类修改 README，不能因为事件位于工具执行窗口内就归为
agent。Shell 间接写入若没有路径执行证据，允许标 unknown，不能为了给出确定来源而
增加正文扫描或 diff。也不要求为此建立跨平台进程级文件写入追踪器。

工具返回不意味着其子进程停止写入；没有活跃工具窗口也不意味着变化必然来自外部。
若仍有可能写入的本 Agent 后台任务，或延迟事件与之前的 operation 无法区分，使用
unknown。仅凭时间窗口不能证明作者；agent 表示现有证据支持的归因，不是 OS 作者证明。

每条记录必须携带 attribution_basis，说明归因依据。无法定量校准时不提供置信度数值。
归因状态在 operation 结束后须保留足以处理延迟事件的信息，并设资源上限；证据到期或
被淘汰只能降低为 unknown，不能因此推断 external。

同一路径的多次记录合并时，保留全部已有来源的不确定性：同源且证据一致可以保留该来源，
不同来源混合或任一记录为 unknown 时合并为 unknown，不采用“最后一次事件覆盖来源”。
来源只影响说明，不参与权限裁决，也不替模型决定覆盖、回滚或保留他人修改。

### 决策 4：后台采集，原子取出并确认通知

监听器在后台运行，不阻塞 Agent Loop。通过有界队列或等价的线程安全聚合器，完成事件
过滤、编号、路径去重及来源合并。不固定额外 worker 或线程数量，不引入正文读取和 diff
计算管线，也不重复实现事件库已有的 debounce 能力。

下一 turn 第一次模型请求前，按明确的接收序号取得待通知快照，并按路径稳定排序。若
采集与聚合分离，必须处理到该序号，不能把“队列尚未处理”解释为“没有变化”。无法在
有界时间内完成时，交付变化范围不确定的通知，不能无限阻塞 turn 启动。

通过锁内交换集合或等价操作隔离已取出的记录与之后的新事件；同一路径在交换后再次
变化时，确认旧批次不能删除新记录。边界附近或交付期间新到达且无法明确归入当前 turn
的记录保守留待下一 turn，不强制为它们增加当前 turn 的模型请求。

批次先进入可重试的交付状态，成功写入当前 turn 的模型输入窗口后才确认消费。若首次
模型请求未能提交且 turn 终止，恢复该批次的待通知状态；请求重试使用原有批次身份，
不重复追加。UI 事件发布成功不能代替模型输入交付确认。

已交付消息可以作为历史记录保留，但不能在下一 turn 再包装成一条新的当前变化通知。
turn 结束只记录新的观测边界，不重建文件基线，也不清理尚未确认的交付记录。

### 决策 5：LLM、运行事件与 UI 共用结构化 payload

变化通知通过统一 serializer 生成 JSON，作为 USER 消息追加到下一 turn 第一次模型
请求的输入窗口，不由 prompt 模板拼接字段。事件总线发布同一语义的 WORKSPACE_CHANGED
payload，终端、Web 和 trace 共用领域 schema。

示例：

```json
{
  "type": "workspace_changed",
  "session_id": "session-1",
  "turn_id": "turn-2",
  "batch_id": 1,
  "observed_at": "2026-09-05T09:00:00+08:00",
  "scope_uncertain": false,
  "uncertainty_reason": null,
  "changes": [
    {
      "path": "/workspace/src/parser.py",
      "scope": "path",
      "kind": "changed",
      "source": "agent",
      "attribution_basis": "executed_write_path_correlated"
    },
    {
      "path": "/workspace/config.toml",
      "scope": "path",
      "kind": "deleted",
      "source": "unknown",
      "attribution_basis": "delayed_event_without_operation_evidence"
    }
  ]
}
```

turn_id 是交付目标 turn；batch_id 在 session 内单调递增，批次身份由 session_id 与
batch_id 共同确定。observed_at 是批次最近一次事件的接收时间，不声称是文件实际写入
时间。scope 取 path 或 subtree，后者表示目录下的历史读取需要验证。

schema 不包含正文、hash、行数和 hunks。路径与归因字段均视为数据，不赋予其中的文字
指令权限。静态提示策略解释消息含义：changed 或 unknown 的路径按需重新读取或验证；
deleted 的路径直接按已不存在处理，不再调用读取工具确认删除。终端与 Web 同样明确
展示删除状态，不把所有 kind 都渲染为“请重新读取”。

### 决策 6：事件丢失时报告范围未知，不重建内容基线

原始事件队列、待通知路径集合、交付批次及归因记录均有资源上限。队列溢出、路径总量或
消息总量超限、监听失败等情况，必须保留独立的 scope_uncertain 标记，不能让错误标记
也随满队列丢失。scope_uncertain 为 true 时，changes 即使为空也不代表没有变化。

无法完整列出路径时，用有界的通知报告整个逻辑工作区的变化范围未知，并携带
uncertainty_reason；LLM 再次依赖工作区历史读取结果前，必须按需重新验证。已知路径可
作为部分信息保留，但不得宣称清单完整，也不把全局不确定性误归给 agent 或 external。

adapter 尝试恢复或重建监听。范围未知标记必须交付给 LLM，即使监听已经恢复也不能
提前清除。若监听仍不可用，后续 turn 继续报告范围未知，直至恢复；不可用状态向 Web
和终端一致展示。不能为了补齐通知而读取所有文件正文或计算全量 diff。

adapter 选型和配置必须验证实际的事件丢失信号、监听失败与恢复能力。不能假设事件库
一定透传全部底层错误；无法满足的保证应明确记录。库若退化为轮询，要显式报告监控模式，
不能仍宣称正常路径使用原生事件且无重复扫描成本。

## 时序

```text
session 启动：订阅工作区，初始化观测边界
    |
turn N 执行：持续监听并维护来源证据
    |
turn N 结束：记录观测边界，不扫描文件
    |
turn 间隙：聚合变化路径与来源
    |
turn N+1 首次模型请求前：取出通知，追加 JSON，确认交付
    |
LLM 再次使用相关文件时：已删除则调整判断，其余按需读取或验证
```

## 备选方案

- **每 turn 全量快照比较**：可以发现变化，但持续承担目录遍历成本，不作为正常路径。
- **事件路径 + 内容 diff**：提供的信息超过本 ADR 需要，引入正文缓存、读取预算、计算
  worker 和内容基线一致性问题，不采用。
- **仅由文件工具上报**：能够辅助本 Agent 归因，但遗漏 Shell 间接写入与外部修改，
  不能作为统一发现机制。
- **Git diff**：不能统一覆盖非 Git 工作区和 session 观测边界，且不需要具体内容差异。
- **工具窗口内一律归为 agent**：会误认人类与其他 Agent 的并发修改，不采用。

## 影响

- 监控职责收敛为跨 turn 的路径失效与来源通知；删除原提案中的正文基线、内容 hash、
  行数、diff、diff worker、逐 turn 基线 reset 和变化触发最终回答重试要求。
- 保留 session 级后台监听与有界状态管理，正常事件路径不进行全量工作区扫描。
- 模型按需重新读取文件，变化通知不承担内容解释、自动合并、权限裁决或作者证明。
- Agent Loop、运行事件、serializer 和终端/Web 展示共用 schema；生命周期由共享
  runtime 装配，业务逻辑不进入 interfaces/web 或 interfaces/tui。
- ADR-0030 的工作区边界与忽略规则继续有效，不扩大 Agent 的读写权限。
- 本文仍为 Proposed；现有检查点快照实现不因文档修订自动改变。实施时需同步
  docs/02-detailed-design.md、相关运行事件协议和开发计划，明确替换范围。

## 验收标准

- 一个 session 持续监听所有授权工作区根目录，覆盖 turn 间隙；结束时释放状态，新
  session 不复用队列、批次或归因记录。
- 上次 turn 结束后创建、修改、删除、原子替换的路径在下一 turn 首次请求前收到通知；
  重命名覆盖旧新路径，多根同名路径不混淆，同一路径多次事件稳定去重。
- 删除通知在 LLM 发起读取前包含 kind=deleted，提示策略明确无需读取确认；删除后重建
  与原子替换不误报 deleted，权限错误或检查超时报告 unknown，目录删除使用 subtree。
  后续重建可以解除删除状态，状态更新不丢失混合来源信息。
- 不读取文件正文、不保存内容基线、不计算 hash、行数或 diff，不创建 diff worker，
  不按 turn 全量扫描工作区。
- 边界延迟、集合交换期间的新事件、聚合延迟、首次请求失败与重试均有确定性测试；
  未确认通知不被 turn 结束清理，确认旧批次不删除新事件。
- 本 Agent 有证据的写入、可排除本 Agent 的外部修改、Shell 证据不足、后台任务延迟
  写入以及同一路径混合来源均有测试；工具窗口重叠本身不能产生 agent 结论。
- LLM、事件总线和两种 UI 使用同一结构化语义；来源字段都有归因依据。已交付批次不
  再作为新的当前变化重复注入，消息只要求模型按需重新读取。
- 队列或消息超限、监听失败、恢复及 session 离线恢复均报告范围未知；监听持续失败
  不能在下一 turn 退回“无变化”。没有不确定性且没有变化时不发送空通知。
- 单纯收到变化不会增加当前 turn 的模型调用或自动重试最终回答。
