# ADR-0031: 把模型可读正文收进单一目录并纳入版本管辖

## 状态

Accepted (2026-08-24 实现)

## 背景

ForgeCLI 写给模型读的文字, 原先散在四个文件里:

| 位置 | 内容 | 受什么管 |
|---|---|---|
| `application/prompt/system_prompt_builder.py` | 系统提示词的五个块 | `MAIN_AGENT_PROMPT_VERSION` + 指纹快照 |
| `application/agent_loop/builtin_loop.py` | 回合中注入 transcript 的 7 段引导 + 6 处内联 f-string | 无 |
| `application/agent_turn/agent_turn_service.py` | 6 段收摊文字 | 无 |
| `application/llm/gateway/default_gateway.py` | 结构化输出的 schema 指令 | 无 |

ADR-0018 §15.3 立过一条规矩: **改内置提示词必须同时升版本并更新快照测试**. 但这条规矩
只覆盖了上表第一行. 后面三行的文字同样会进模型上下文, 同样会改变模型行为, 却既没有版本
也没有快照 —— 改一个字, 全库没有任何一处会说话.

### 散着的真正代价不是难找, 是看不出彼此矛盾

把四处正文收到一屏之内通读, **第一次就查出三处**, 而它们在散着的状态下都不可能被发现:

1. **我们要求模型做的事, 自己在同一段对话里反着做.**
   回答契约写着"标点用半角", 而我们注入的六段文字用的是全角:
   `"上一次请求未获授权, 本轮已停止执行工具。"`,
   `"模型连续 {count} 次产出无法使用的工具调用，本轮中止。"`,
   `"本轮工具调用已达上限 {limit}。"`, `"（本轮回复已被用户取消）"`,
   `"循环步数超出安全上限，本轮中止。"`, 以及 schema 指令.

2. **同一条规则三处各写一遍措辞.** "不要绕过刚被拒的决定"在回答契约,
   `_HALT_NOTICE` 和 `_BLOCKED_NOTICE` 里各有一个版本, 谁是准的说不清.

3. **一处手写的格式副本.** `agent_turn_service` 直接拼
   `"[tool_unavailable] 当前会话未装配工具系统"`, 形状照抄 `ToolObservation.render()`
   的 `[{kind}] {message}` 但不走它. render() 改了, 这一处不会跟着变.

三处都不是任何一层会报错的缺陷: 提示词照常渲染, 890 个测试照常绿, 指纹照常稳定 ——
只是模型读到的东西开始互相拆台.

### 为什么测试没挡住

改完全部标点之后**一个测试都没红**. 唯一沾边的断言是
`tests/agent_run/test_barren_progress.py` 里的 `_NUDGE = "没有带回新信息"` ——
一段七个字的正文副本, 而不是对常量的引用.

## 决策

### 1. 一处目录, 两个模块

> 2026-08-26 修订 (ADR-0039): **正文全部搬去 `application/prompt/templates/`,
> `text.py` 已删除.** 两条理由: 块有骨架 —— 哪几节, 什么条件下出现 —— 而骨架当时只存在于
> builder 的控制流里, 收进一个模块解决不了它; 而且这个模块坐在 domain 却没有一个 domain
> 消费方, 八个消费方全在 application, 下面"只有 domain 能被它们全部 import"那句不成立
> (SIBLING_BANS 里没有任何一条涉及 `application.prompt`). 下面这一节按"正文在
> application/prompt/templates, domain/prompt 只剩 blocks.py"读.

新建 `domain/prompt/`:

- `blocks.py`: `PromptBlock` / `PromptBlockId` / `PromptSnapshot` (由 `domain/agent/prompt.py` 迁入)
- `text.py`: Forge 撰写的**全部**模型可读正文

拆成两个模块是因为改动理由不同: `blocks.py` 是不变量 (缓存划分, 派生指纹), 改它要动测试;
`text.py` 是措辞, 改它会改变模型行为, 所以要升版本.

放 `domain/` 而不是 `application/`: 正文是无依赖的值, 而四个消费方分属
`application/prompt`, `application/agent_loop`, `application/agent_turn`,
`application/llm/gateway` —— 只有 domain 能被它们全部 import 而不撞任何一条
`SIBLING_BANS`, 也不制造新的 import 环 (ADR-0028 规则 A1 守的那些边界).

### 2. 收进来的判据

**这段文字如果改了, 改的是"我们想让模型怎么做", 还是"某个事实是什么"?**

- 前者进 `text.py`: 指令, 引导, 拒绝说明, 收摊通知, 人类可读的标签.
- 后者留在算出它的地方: 工具用途取自 `ToolSpec.title`, 拒绝原因取自
  `AuthorizationDecision.message`, 计划正文取自 `PlanDocument`, 工具输出取自 `ToolResult`.

**这条判据的第二半和第一半一样重要.** 把 `ToolSpec.title` 抄一份进 `text.py` 会得到一个
"统一管理"的假象, 实际是 ADR-0028 规则 B 说的第二份会漂的真相 —— 而且漂了不报错.
`system_prompt_builder` 的模块说明里早就写了这一点, 本 ADR 不推翻它。

同理不收: `plan_template.py` 的模板 (它是 `PlanDocument` 的渲染器, 已有
`PLAN_TEMPLATE_VERSION` 自管), 以及终端与 Web 的人机界面文案 (读者是人不是模型).

### 3. 一个版本号, 一个指纹

`PROMPT_TEXT_VERSION` 顶替 `MAIN_AGENT_PROMPT_VERSION`, 从 6 起 (接原来的 5 往下数:
两者数的是同一件事, 只是原来只覆盖一块). `PromptSnapshot.version` 直接用它 ——
一个事实一处 (规则 B).

`fingerprint()` 反射遍历本模块的公开大写常量, **不维护第二份清单**: 手写的清单会漏,
而漏掉的那一条恰恰是没人复核的那一条.

### 4. 四条自动断言

`tests/prompt/test_prompt_text.py`:

| 断言 | 挡住什么 |
|---|---|
| 指纹钉死 | 改任何一个字不升版本 |
| 每个常量都有消费方 | 一段没人引用的提示词, 读起来像生效实际模型看不到 (规则 C) |
| 无全角标点 | 我们要求模型做的事自己先做到 |
| 带占位符的模板必须有人 `.format` | 漏一个占位符, 模型读到的就是 `{count}` 本身 |

> 2026-08-26 修订 (ADR-0039): 四条改成五条, 判据全部按模板目录写 —— 指纹算全目录 (不含
> `{# #}` 注释), 半角标点按文件参数化, 无孤儿从"每个常量有人引用"改成"每个 notices 宏有人
> `render_notice`", 再加"每个块都有正文与标题", "模板经 importlib.resources 读得到",
> "渲染结果里不残留花括号".

### 5. 归属检查进 `make ci`

`scripts/check_prompt_text.py`: 送进模型上下文的参数里不得出现含中文的字符串字面量.

"送进模型上下文"由一张 SINKS 表列举 (`TextBlock`, `ToolResultBlock`, `LoopObservation`,
`PromptBlock`, 以及 `system_prompt=` 关键字), 都是机器认得出的构造类型, 不靠命名习惯猜.

> 2026-08-26 修订 (ADR-0039): SINKS 增加 `render_block` / `render_notice` /
> `render_heading` —— 模板渲染的 context 是一条新的进上下文的路, 在那里写一句中文和在
> `PromptBlock(body=...)` 里写, 后果完全一样. 同时**取消例外目录**: 原先要给 `text.py`
> 放行 (它自己全是中文字面量), 正文改成模板之后任何一个 .py 里都不该再有, 这条闸因此比
> 本节原来的版本严.

为什么需要它: 往 transcript 里加一句话是**最容易**的改动 —— 一个 f-string 就完事,
而且没有任何一层会说话. 没有这个闸, 本 ADR 的收敛会在三个月内重新散开.

### 6. 标点一次性改半角

按回答契约自己的要求. 这是一次真实的正文变更, 因此走版本号 —— 那正是这套机制的用途.

## 备选方案

**维持现状, 只在文档里写一条约定.** 否决: ADR-0018 §15.3 已经是这么一条约定了,
它守住了它明确点名的那一个文件, 没守住其余三个. 约定挡不住"顺手加一句"。

**只加检查不搬文字.** 否决: 检查能挡住新增, 挡不住已经存在的三处矛盾 —— 那三处只有
在正文并排放着的时候才看得见.

**把工具描述也搬进来.** 否决: 见决策 2. 那会把一个真实的单一真相 (`ToolSpec.title`)
变成两份.

## 影响

**收益**: 全部模型可读正文在一处, 一个版本号, 一个指纹, 四条自动断言, 一个 `make ci` 闸门.
消灭三处已存在的矛盾.

**代价**: 读 `builtin_loop._weigh()` 时看不到措辞原文, 要跳到 `text.py`. 这是真实的代价,
换来的是"全部正文能被一次通读"—— 而那是唯一能发现彼此矛盾的办法.

**不变**: 系统提示词的渲染结果逐字未变 (以旧版本号 5 重算指纹, 与旧值完全相同, 证明
搬迁没有夹带任何措辞改动); 块顺序, 缓存划分, `PromptSnapshot` 的全部不变量不变.

## 验收

- `domain/prompt/text.py` 之外, `src/` 中没有任何中文字面量进入 SINKS 表列出的构造.
- `PROMPT_TEXT_VERSION` 与 `fingerprint()` 被快照钉死.
- 每个正文常量都有消费方; 每个带占位符的模板都有人 `.format`.
- 全部正文无全角标点.
- `make ci` 全绿.

## 关联

- ADR-0018 (分层且按 Turn 冻结的系统提示词编译): §15.3 的改动纪律由本 ADR 扩到全部正文;
  `MAIN_AGENT_PROMPT_VERSION` 由 `PROMPT_TEXT_VERSION` 顶替.
- ADR-0028 (轻量 DDD 结构收敛判据): 规则 B (一个事实存一次) 是决策 2 后半的依据;
  规则 C (字段要有生产方与消费方) 是"无孤儿"断言的依据.
- ADR-0010 (受控 ReAct 主循环): 回合中注入的引导由它产生.
- ADR-0022 (计划与待办): `plan_template.py` 明确不在本 ADR 收编范围内.

## 已知限制

`SCHEMA_INSTRUCTION` 会**追加在 `PromptSnapshot.text` 之后**再发给供应商, 因此供应商
实际收到的 system prompt 比 `PromptSnapshot.fingerprint` 覆盖的多一段. 当前
`complete_structured` 全库没有调用方 (Agent 主循环走原生 tool calling, 见
`domain/model/request.py`), 所以这个偏差没有真实影响. 真要用起来, 得让这一段也进指纹 ——
记在这里而不是现在就改, 是因为改一个没有调用方的路径无从验证.
