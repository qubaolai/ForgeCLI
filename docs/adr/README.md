# ADR 决策记录

ADR 是 Architecture Decision Record，用来记录已经做出的重要架构决策。它回答的是“为什么这样设计”，不是替代概要设计或详细设计。

## 命名规范

文件名采用：

```text
YYYY-MM-DD-四位编号-中文决策标题.md
```

示例：

```text
2026-06-17-0001-采用jsonl-state作为本地会话存储.md
```

规则：

- 日期使用决策提出或接受日期。
- 编号全局递增，不按日期重置。
- 中文标题保持短句，避免过长。
- 文件名使用 `-` 分隔，不使用空格。

## 状态

- `Proposed`：已提出，尚未接受。
- `Accepted`：已接受，需要同步概要设计、详细设计或工程规范。
- `Superseded`：被新的 ADR 替代。
- `Rejected`：明确拒绝，保留原因。

## 使用方式

- 重要设计先写 ADR。
- ADR 接受后，再同步修改相关设计文档。
- PR 或每日验收中引用 ADR 编号，例如 `ADR-0003`。
