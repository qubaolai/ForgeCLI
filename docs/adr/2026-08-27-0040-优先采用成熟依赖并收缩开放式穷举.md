# ADR-0040：优先采用成熟依赖并收缩开放式穷举

## 状态

Proposed

## 日期

2026-08-27

## 摘要

ForgeCLI 不再为已有成熟实现的通用机制编写和维护自有版本。对 HTTP 协议、数据校验与
序列化、终端输入、Git 对象读取、跨平台路径、文件锁、SSE、缓存容器、熔断器、代码与
Shell 语法解析、秘密检测等能力，默认选择官方 SDK、标准库或维护活跃的社区包；Forge
只保留自己的领域模型、统一调用边界、安全裁决、工作区授权、运行期围栏、恢复事务和
用户交互语义。

本 ADR 同时规定：开放世界中的命令名、供应商名、路径名、环境变量名、凭证格式、脚本
解释器和 CLI 参数不能通过穷举获得“完整性”。这类表若无法从权威运行时或用户配置派生，
就不得承担自动放行或默认授权责任。它们只能是：

1. 失败向安全的提示增强；
2. 性能优化；
3. 受审计的小型强制 ASK 覆盖层；
4. 或由运行期隔离、显式能力声明和默认拒绝取代。

本 ADR 是一份待评审的依赖与穷举治理决策，不直接授权一次性改写全部模块。每个迁移切片
仍须独立测试、独立提交，并满足本文给出的退出条件。

## 背景

### 1. 审计范围与基线

2026-08-27 对以下范围进行了只读扫描：

- `src/forgecli/**/*.py` 的通用机制、自定义解析器、注册表和语义常量；
- `tests/` 中与上述机制直接相关的验收用例；
- `pyproject.toml` 与 `poetry.lock` 中的直接依赖；
- ADR-0011、ADR-0012、ADR-0013、ADR-0028、ADR-0030、ADR-0035 中已经冻结的边界；
- 源码中所有 `Enum` / `IntEnum`，以及有授权、放行、路由或路径含义的集合、元组和映射。

审计时的验证基线：

- Ruff：通过；
- Mypy：358 个源码文件通过；
- Pytest：1111 passed、4 skipped、4 failed；
- 三个失败由受限运行环境直接造成：`ps` 无权限、终端没有 `poetry`、端口监听无权限；
- 另一个失败是应单独修复的裁决回归：`ls -a . 2>/dev/null` 被判为需要审批。

该基线只用于记录提出决策时的事实，不代表本 ADR 已经实现。

### 2. 当前问题不是“代码多”，而是知识所有权错误

扫描发现两类问题。

第一类是通用机制被 Forge 自己拥有：

- OpenAI-compatible 请求、SSE 解析、流式增量合并、超时和错误映射；
- 类型校验、JSON 编解码、JSON Schema 与 UI 字段元数据；
- POSIX/Windows 原始终端按键读取；
- Git CLI 只读子命令和选项白名单；
- POSIX/Windows 文件锁与应用目录；
- SSE ping、断连、发送超时；
- TTL/LRU、熔断状态机、结构化日志渲染；
- Shell lexer、代码定义解析、秘密格式识别。

这些能力有成熟实现。Forge 自己维护它们，会承担协议演进、平台差异、边界条件、安全修复、
类型桩和兼容性测试，却不会形成产品差异。

第二类是开放集合被写成封闭表：

- “所有会写文件的命令”；
- “所有会执行代码的命令”；
- “所有网络工具”；
- “所有不可逆外部操作”；
- “所有解释器、wrapper 和脚本后缀”；
- “所有敏感目录和凭证路径”；
- “所有危险环境变量”；
- “所有供应商”；
- “所有 Git 只读参数”。

这类表永远不完整。若表外默认放行，漏项就是安全缺陷；若表外默认拒绝，漏项只是体验问题。
ADR-0030 已经把大部分命令知识从安全路径降级到性能与展示路径，但当前实现仍有重复表和一张
承重的不可逆操作表，需要进一步约束。

### 3. “不造轮子”不能破坏已有分层

ADR-0002 与 `scripts/check_arch.py` 要求：

- `domain` 不依赖 application、infrastructure、interfaces；
- application 不依赖 infrastructure、interfaces；
- Rich、prompt-toolkit、HTTP 客户端和供应商 SDK 不进入 domain/application；
- provider、终端、文件系统和协议细节停留在 infrastructure/interfaces。

因此，“采用依赖”不等于“把第三方类型传遍所有层”。正确形式是：第三方包在最外层承担
通用机制，转换成 Forge 已有的领域值对象或 application 端口。SDK 类型、Pydantic model、
Tree-sitter node、pygit2 object、prompt-toolkit event 都不能穿过边界。

### 4. 已有 ADR 对本决策的约束

- ADR-0010：受控 ReAct 与 Agent 主循环由 Forge 拥有；第三方 agent framework 不得隐式
  接管循环、工具授权或恢复。
- ADR-0011：所有模型调用继续经过 `LlmGateway`；SDK 是 provider adapter 的实现细节。
- ADR-0012：缓存、重试、熔断、token 估算和观测仍由统一网关治理，但通用算法可委托依赖。
- ADR-0013：Shell 必须先形成结构化 `CommandPlan`，不能按命令名直接放行。
- ADR-0028：一个事实只存一次；新抽象必须满足依赖倒置、多实现或开放扩展点之一。
- ADR-0030：运行期围栏与快照是主要安全边界；静态命令知识不能重新升级为主要证明。
- ADR-0035：本地日志的产品格式与诊断入口已有 Proposed 设计，不能因为换日志库而改变
  事件名、文件生命周期或敏感信息约束。

## 术语与判据

### 通用机制

不包含 Forge 产品语义、在其他 Python 项目中也会以相同方式实现的能力。例如 HTTP 重试、
JSON Schema 校验、LRU 淘汰、文件锁、终端 key binding、SSE framing。

### 产品语义

决定 Forge 是什么、用户批准了什么、哪些事实进入恢复或审计的能力。例如 `LlmGateway`
边界、`ToolPlan`、`AuthorizationDecision`、workspace grant、approval binding、recovery
checkpoint、mode policy、Agent event。

### 封闭集合

成员由 Forge 的协议或状态机定义，新增成员必须修改调用者。例如 `ToolResultStatus`、
`Decision`、`RunPhase`、patch envelope verb。显式枚举是正确做法。

### 开放集合

成员由操作系统、外部生态、用户配置或未来软件决定，Forge 无法预先列全。例如命令名、
供应商、凭证格式、环境变量、包管理器、云 CLI、用户目录。

### 承重表

漏掉一个条目会让本应拒绝或 ASK 的动作自动放行。承重表必须极少、逐条可审计，并有明确
退出计划；能用运行期机制取代时必须取代。

### 非承重表

漏项只会导致多打一次快照、少一行提示或多问一次用户。允许存在，但不能被描述为完整集合。

## 决策

### 决策 1：建立“标准库 → 官方 SDK → 社区包 → 自实现”的选择顺序

新增通用机制时按以下顺序评估：

1. Python 标准库是否已经提供足够正确的原语；
2. 协议或服务的官方 SDK 是否覆盖；
3. 是否有维护活跃、许可证兼容、支持 Python 3.13+、具有类型信息和测试的社区包；
4. 只有前三项都不满足 Forge 的硬约束时，才允许自实现。

选择社区依赖必须记录：

- 维护者与发布活跃度；
- 许可证；
- Python 3.13+ 与 Windows/macOS/Linux 支持；
- 是否有类型注解或可维护的 types 包；
- 是否允许注入 clock、transport、filesystem 等以离线测试；
- 是否把第三方类型泄漏到 domain/application；
- 失败时能否失败向安全；
- 替换和回滚成本；
- 直接依赖和传递依赖体量。

“只有几十行”不是拒绝依赖的充分理由；“这是 Forge 的安全/恢复/审计语义”是。

### 决策 2：采用依赖时保留 Forge 控制面

第三方包只接管机制，不接管以下控制面：

- provider/model 选择；
- mode 与工具目录；
- tool schema 的 Forge 归一化表示；
- capability、target、workspace boundary 与 protected path；
- ASK/DENY/ALLOW 顺序；
- 人工审批绑定、批准后重验和 learned rule；
- 运行期围栏与 execution profile；
- checkpoint、mutation、undo/resume；
- session event、AgentRunEvent 与 usage 落盘；
- 日志事件名、诊断读模型和敏感信息规则。

任何候选框架若要求这些语义迁入其专有对象、回调或持久化格式，默认不采用。

### 决策 3：第三方类型不得跨越分层边界

依赖放置规则如下：

| 依赖类别 | 允许位置 | 输出边界 |
|---|---|---|
| 供应商 SDK、HTTP、Git、OS integration | `infrastructure` | 转换成 domain/application 定义的值对象或异常 |
| 终端、Web transport、SSE | `interfaces` | 调用 application service，消费 application event |
| Pydantic | `interfaces`、`infrastructure`；application 仅允许无 IO 的配置/DTO schema | 不进入 `domain`，不成为端口方法的必需类型 |
| Tree-sitter、秘密扫描器 | `infrastructure` adapter | 输出 Forge `CommandPlan`、symbol record 或 secret finding |
| cachetools、pybreaker | 优先 `infrastructure` 实现 application port | 对上只暴露 Forge cache/health 契约 |
| prompt-toolkit | `interfaces/cli` | 不进入 intent、application service 或 domain enum |

若为了一个依赖新增端口，该端口必须满足 ADR-0028 A1：它确实阻止上层依赖外层包。不得为
测试方便或未来想象新增空抽象。

### 决策 4：接受的高优先级依赖迁移

#### 4.1 官方 OpenAI Python SDK 替代自有 OpenAI-compatible 传输栈 —— 不采用

**2026-08-28 评审结论：撤回本条，保留现有传输栈。**

原提案要用官方 SDK 换掉 `infrastructure/llm/adapters/openai_compatible.py`。逐段核算之后，
这笔账不成立：

| 现有代码 | SDK 能否接管 |
|---|---|
| httpx client 生命周期、timeout、传输错误（约 60 行） | 能 |
| SSE 分帧（约 15 行） | 能 |
| HTTP 状态码分派骨架（约 20 行） | 能 |
| `_payload` / `_messages` / `_thinking_fields`（约 120 行） | 不能。只是改成 kwargs；而 `thinking`、`provider_options` 是非标字段，仍要走 `extra_body` |
| `_parse_usage` 读 `prompt_tokens_details.cached_tokens` 等（约 110 行） | 不能。SDK 的强类型响应模型还可能**丢掉**兼容端点返回的非标字段 |
| 400 按措辞分流到 `ModelContextOverflowError`（约 40 行） | 不能，全部保留 |
| url / status / elapsed / first_chunk_ms 结构化日志（约 50 行） | 不能。非流式还要改用 `.with_raw_response` 才拿得到响应对象 |

净删约 100–130 行，代价是：新增依赖、SDK 类型模型可能吞掉兼容端点字段、`base_url` 语义
变更波及内置注册表默认值与所有已存用户配置、以及与网关重试的归属重排。

根本原因是这个 adapter 的工作对象：**它面对的是 OpenAI-兼容端点，不是 OpenAI。** 官方
SDK 的价值在服务端就是 OpenAI 时最高；这里是 DeepSeek、GLM、Ollama、vLLM 四种，而它们
各自的协议偏差正是这份手写解析在吸收的东西（`tests/llm/test_provider_error_mapping.py`
钉着 GLM 的 1261 错误码与 DeepSeek 的具体措辞）。

这不推翻决策 1 的选择顺序：它说的是"有成熟实现时优先采用"，而这里的判断是这个成熟实现
覆盖不到本 adapter 的实际问题域。将来若 Forge 主要面对官方 OpenAI 端点，可重新评估。

#### 4.2 Pydantic 作为边界校验、序列化与 Schema 的单一事实来源

目标模块：

- `application/llm/config/llm_config.py` 的 `_KNOWN_FIELDS`、`STANDARD_FIELDS`、手写 coercion；
- application/infrastructure 中各 JSON store 的 `to_dict/from_dict`；
- recovery、planning、session snapshot/event 的持久化 DTO；
- Web request/response model 和 `interfaces/web/serialization.py`；
- 工具参数 JSON Schema 的边界校验元数据。

规则：

- domain 实体和值对象继续使用 dataclass/Enum，不改成 Pydantic；
- Pydantic model 是 boundary DTO，不拥有业务方法；
- `model_validate`/`TypeAdapter` 负责外部数据进入系统；
- `model_dump` 负责边界输出；
- `model_json_schema` 与 `Field` metadata 生成配置 UI 和 Web schema；
- 未知字段策略必须逐格式明确，不能默认在 ignore/forbid 间漂移；
- 持久化兼容必须有 fixture 覆盖旧 JSON；
- 错误文案可由适配层翻译，不把 Pydantic `ValidationError` 直接展示给最终用户。

源码已经直接导入 Pydantic，但 `pyproject.toml` 没有直接声明。本 ADR 接受后，Pydantic 必须
成为直接运行时依赖，不能依赖 FastAPI 的传递依赖。

**2026-08-28 实施说明：目标清单按决策 3 收缩。**

已完成：`ModelParams` 与 `ProviderConfig` 改为 Pydantic model。`_KNOWN_FIELDS`、
`STANDARD_FIELDS`、`_FIELD_KIND`、`_PROVIDER_STR_FIELDS`、`_PROVIDER_INT_FIELDS`，以及
`llm_menu.py` 里第四份 (标签, 字段名) 表全部改为从模型声明派生；菜单标签写在
`json_schema_extra` 上。范围校验从手写 `_as_*` 函数改为 `Field` 约束，`strict=True`
复刻原有语义（int 拒 bool/str/float，float 收 int）。

不做，以及原因：

| 原目标 | 结论 |
|---|---|
| 各 JSON store 的 `to_dict/from_dict` | 全库只有 `domain/session/snapshot.py` 与 `domain/session/events.py` 两处，都在 `domain`。决策 3 明写"Pydantic 不进入 domain"，本条与决策 3 冲突 |
| recovery / planning / session 持久化 DTO | 同上。`fs_recovery_store.py` 的 `_to_json/_from_json` 确在 infrastructure，可用 `TypeAdapter`，但它的落盘形状与 dataclass 形状不同（`mutations` 落成数组，字段是 `MutationSet`），直接替换会改变已存 checkpoint 的格式；要保形就得再引入一层镜像 DTO，是平移不是收敛 |
| `interfaces/web/serialization.py` | `to_jsonable` 的 26 行里有一条安全性质："只展开值对象、枚举和基础容器，不调用任意对象的 `__dict__`"，未知类型直接抛。它有 28 个调用点，输入是异构的 domain dataclass；换成 `TypeAdapter` 要么逐类型登记，要么退化成 `Any` 而丢掉这条性质 |
| Web request/response model | 已经是 Pydantic（`interfaces/web/app.py`），无事可做 |
| 工具参数 JSON Schema 的边界校验元数据 | 未做。工具的 `input_schema` 是手写 JSON Schema dict，由 `jsonschema` 校验；改成 Pydantic 会改动 `ToolSpec` 契约与 `spec_hash`，超出本条范围，应单独评估 |

#### 4.3 prompt-toolkit 替代自有 TTY 与菜单输入状态机

目标模块：

- `interfaces/cli/tty/_tty_posix.py`；
- `interfaces/cli/tty/_tty_windows.py`；
- `interfaces/cli/tty/keys.py`；
- `interfaces/cli/menu_presenter.py` 中输入、光标、搜索、编辑和键绑定机制。

保留菜单项、业务动作、application service 调用以及 Ctrl-C 的产品语义。删除 termios raw
mode、UTF-8 首字节判断、ESC/CSI 解析、Windows `msvcrt` key map 和无其他消费者的 `Key`。

#### 4.4 pygit2 替代 `git_read` 的 CLI 参数白名单

目标模块：`application/tools/builtin/git_read.py`。

将 status、diff、log、show、blame、branch/reference、remote URL、stash list/show 改成
结构化工具参数和 pygit2 API。这样不再枚举 Git CLI 选项，不再启动任意 `git` 子进程，
也不再需要工具层与安全层维护两份只读知识。

pygit2 不覆盖或语义差异过大的能力，不扩大 `git_read`，而是明确返回 unsupported；用户确实
需要原生 Git CLI 时走 `shell_run` 和既有策略。项目已经使用 pygit2 的
`Repository.path_is_ignored()`，该依赖保留。

#### 4.5 filelock 替代跨平台进程锁

目标模块：`infrastructure/project/process_lock.py`。

采用 native `FileLock` 和稳定锁文件语义；Forge 只保留锁文件路径、project identity、
holder metadata 产品字段、冲突文案和退出码。必须覆盖同进程重入、另一进程占用、陈旧
metadata、Windows 打开文件、进程异常退出和多个项目同时运行。

#### 4.6 platformdirs 替代应用目录计算 —— 不采用

**2026-08-28 评审结论：撤回本条。**

原提案是"只接 API，不切默认数据路径"。实施时发现这两句互相矛盾：没有任何 platformdirs
调用能在不改路径的前提下产出 `~/.forge`（`user_config_path` 在 Linux 上给的是
`~/.config/...`）。照字面执行只能新增一个没有调用方的函数，那正是决策 3 与 ADR-0028
禁止的"为未来想象新增抽象"。

唯一的候选消费者 `infrastructure/platform_paths.py` 要的是 Program Files / ProgramData /
Windows 目录，platformdirs 的公开 API 不覆盖它们（只有内部的 `get_win_folder` 沾边，依赖
它比现有的 ctypes 调用更差）。

因此 platformdirs 不进依赖表——它会成为一个无消费者的直接依赖，而这正是决策 11 与
`scripts/check_deps.py` 要拦的东西。未决问题 1（`~/.forge` 是否迁移到平台标准目录）仍然
未决，但那是一个数据迁移决策，与是否引入这个包无关。

#### 4.7 sse-starlette 替代手写 SSE framing

目标模块：`interfaces/web/app.py` 与 `interfaces/web/events.py` 的 transport 部分。

`EventSourceResponse` 负责 SSE frame、ping、disconnect、send timeout 和 shutdown
cancellation。Forge 保留单调 event sequence、replay ring、cursor/Last-Event-ID、session
authorization，以及 AgentRunEvent 到 Web payload 的投影。

#### 4.8 Tree-sitter 替代手写 Shell lexer/parser —— 实测后改期

现有 `tree-sitter-language-pack` 已用于代码定义。原提案是新增 infrastructure shell parser
adapter，优先覆盖 POSIX/Bash 与 PowerShell，输出已有 `CommandPlan`。

**2026-08-28 实测结论：语法可用，但换掉的理由不成立，改期并单独立 ADR。**

可行性没问题：`bash` 与 `powershell` 语法都在 language pack 里（`cmd` 没有，只有不对口的
`batch`，所以 `cmd.py` 无论如何都留着）。写了一个 tree-sitter → `ParsedPosix` 的映射原型，
十条命令里三条与手写解析器一致，另外七条的差异全是机械映射缺口（引号未剥、`2>` 的 fd 落在
argv 里、`$(...)` 的 `\x00subN\x00` 占位协议、`for` 循环的连接符），逐条可补。

不成立的是**换掉它的理由**。原提案的论据是手写解析器不完整。用九条对抗性输入实测了它的
不完整之处，结论是**每一处都失败向安全**：

| 输入 | 手写解析器 | 后果 |
|---|---|---|
| `$'\x72\x6d' -rf /tmp/x` (ANSI-C 引用) | 解出可执行文件 `x6d` | 受控 PATH 上找不到 → `EXECUTABLE_NOT_FOUND` → **DENY** |
| `sh -c "$(printf 'rm -rf /tmp/x')"` | `parse_error` | → UNPROVEN → **ASK** |
| `sh -c "rm -rf $(echo /tmp/x)"` | `parse_error` | → **ASK** |
| `sh -c 'echo \'; rm ...; echo \''` | `parse_error`，零单元 | → **ASK** |
| 反斜杠续行 / 算术展开 / 大括号展开 | 正确解出 `rm` | —— |
| `<<'EOF'` 带引号的 heredoc | 正文捕获为 `ScriptPayload` | 进脚本分析 |
| `echo 'a; rm -rf x'` | 只解出 `echo` | 正确 |

没有一处是绕过。按本 ADR 决策 7 自己的判据，这份解析器已经处在可接受状态：它的漏洞产生
UNPROVEN/ASK 或 DENY，不产生静默放行。

所以真实收益是**可用性**而不是安全性：九条里三条 `parse_error` 意味着三次本不必要的打断，
而 `sh -c "rm -rf $(echo /tmp/x)"` 是正常写法。这是个值得做的改进，但它的论证、优先级与
验收标准都与本 ADR 给的不同，且风险集中在全项目安全用例最密的模块（`tests/security` 276 例）。

改期条件（下一份 ADR 应先写清）：

1. 先把 `CommandPlan` 的隐性约定写成用例——原型暴露了两条没有文档的：重定向的 fd 会落进
   `argv`，命令替换用 `\x00subN\x00` 占位。任何替代实现都要复刻它们。
2. 明确 `cmd` 方言留手写，以及它与另外两种方言共存时的一致性判据。
3. 明确解析器从 `domain` 移到 `infrastructure` 之后的端口形状——tree-sitter 是 C 扩展，
   按本 ADR 决策 3 不能留在 domain。

#### 4.9 detect-secrets 替代自有凭证格式检测 —— 实测后不采用

**2026-08-28 评审结论：撤回本条，保留 `domain/memory/secrets.py`。**

原提案要启用 detect-secrets 的 provider-specific、high entropy 与 keyword detector。
装了 1.5.0 实测两种配置，都不如现状：

| 配置 | 十种真凭证 | 正常项目事实 |
|---|---|---|
| 开熵检测器 | 全抓到 | **文件路径、40 位 commit sha、构建产物名 `index-JwK66ukq.js`、驼峰标识符全部误报** |
| 只开厂商 + 关键词 | 只抓到六种（漏 OpenAI、Anthropic、Google API key、npm token） | 零误报 |
| 现有实现 | 全抓到 | 两处误报（已修，见下） |

第一行是决定性的。记忆是**静默写入**（ADR-0033 决策 2），误报的表现是"它记不住东西"，
而且没有人会看到原因——一个记不住文件路径的记忆系统，用户会在第三次的时候关掉它。
`secrets.py` 的 docstring 早就写明它"刻意不查熵"，正是为了这个。

第二行说明厂商检测器也没有覆盖优势：漏掉的四种前缀表都认得。

它还会带进 `requests` 与 `pyyaml` 两个传递依赖，进一个安全敏感路径。

**那次实测有真实产出**：它暴露了现有实现的两个真误报，已修——`_TOKEN` 的字符集去掉 `/`
（否则一条绝对路径就是一个"大小写数字齐全的长串"），`_is_random_token` 增加"没有八个以上
同类字符连排"（否则 `ToolAuthorizationServiceRegistryBuilderFactoryImpl2026` 这种类名被
判成凭证，而这个仓库里到处都是）。配套用例见 `tests/memory/test_secret_shapes.py`，
两个方向各钉一半。

### 决策 5：有条件采用的依赖

| 能力 | 候选 | 采用条件 | 不采用条件 |
|---|---|---|---|
| TTL/LRU | `cachetools` | response cache 继续保留，且能隐藏在已有边界后 | 新增 adapter 比现机制更复杂 |
| 熔断 | `pybreaker` | 能按 provider/model 隔离、注入 clock | SDK/router 已是唯一所有者，或 half-open 语义不符 |
| 精确分词 | `tiktoken` | OpenAI 模型或明确 tokenizer mapping | 未知模型必须保守 fallback |
| 多供应商 token | LiteLLM tokenizer API | 只用 tokenizer/cost registry，依赖体量可接受 | 为分词引入完整 router/proxy |
| async/thread bridge | AnyIO 或 `janus` | Web event bridge 真正改为异步队列 | replay/cursor 状态机没有减少 |

采用 PR 必须证明删除的机制多于新增适配层，并明确唯一的重试、缓存、熔断或指标所有者。

### 决策 6：明确不采用的框架与依赖

#### 6.1 不采用完整 Agent Framework 替换 Forge 主循环

本 ADR 不采用 Pydantic AI、OpenAI Agents SDK、LangChain、LangGraph 或 LiteLLM Router
接管 AgentLoop。它们会与 ADR-0010、ADR-0011、ADR-0013、ADR-0027、ADR-0030 的控制面
重叠。后续若采用，必须单独 ADR 证明批准后重验、授权绑定、围栏、checkpoint、resume、
mode catalog、事件顺序和 usage 落盘不丢失。

#### 6.2 不叠加 Tenacity 到官方 SDK 默认重试

SDK retry 与 Tenacity 叠加会造成乘法重试和 timeout 预算失真。只有 SDK retry 被显式关闭，
且 gateway 仍有 SDK 不覆盖的单一策略时，才能重新评估。

#### 6.3 不为 atomic write 引入维护状态不明确的包

JSON 原子写继续使用一个共享标准库 primitive：唯一临时文件、flush、`fsync`、`os.replace`、
必要时父目录 `fsync`。不得在每个 store 各写一份。

#### 6.4 本 ADR 不推翻 ADR-0035 的日志格式决策

`structlog` 可减少 contextvars 和 renderer 机制代码，但 ADR-0035 已把事件名、单行格式、
本地文件生命周期、诊断模型和 credential redaction 定义为产品契约，现阶段不迁移。

若后续仍出现 renderer/context 缺陷，可用 structlog 作为 `shared/observability` 内部实现；
不能让其类型进入调用点，也不能同时保留两套 context/renderer。

#### 6.5 不采用 keyring 扩大 MVP 凭证来源

ADR-0011 已把个人版凭证收敛为环境变量。使用依赖不能偷偷恢复已否决的 keychain scheme。

### 决策 7：开放式穷举分为四类处理

#### A 类：可由权威来源派生——删除手工表

示例：Git ignore/object、配置 schema、平台目录、provider plugin。权威来源是 Git/libgit2、
Pydantic、OS API、用户配置或 package entry point，不再维护第二份手工清单。

#### B 类：无法列全但可以失败向安全——允许非承重表

示例：命令效果、解释器、script suffix、低价值目录。表外必须走 UNPROVEN/ASK、保守快照
或正常搜索；命中只能改善提示或性能，不能扩大权限。

#### C 类：可由运行期边界取代——删除授权表

示例：网络工具、文件写命令、危险环境变量 denylist。使用 network/file/PID sandbox、正向
环境 allowlist、workspace grants 和受控 PATH；命令名只作提示。

#### D 类：围栏仍无法覆盖——保留最小承重表并默认 ASK

当前只有 ADR-0030 §7.3 的“围栏外不可回滚操作表”：远端发布/部署/推送与宿主进程操作。

该表增加两条约束：

1. raw shell 获得不受限网络或宿主进程控制能力时，不能因为命令不在表中自动判定安全；
2. 可迁移到专用工具的动作，应显式声明不可逆外部能力，并逐步从命令表删除。

在专用工具或更强运行时拦截完成前，该表不能直接删除。

**2026-08-28 补充：它的承重范围收窄了。** full_access 那一档已改为"只剩 Hard Deny 兜底"
（ADR-0030 决策 4 修订），该表在那一档不再产生 ASK。它仍然在 plan / accept_edits / auto
三档承重，因此上面两条约束继续成立——只是"表外默认放行"的后果现在被限制在用户显式选择
了最宽一档的场景里。

### 决策 10：注册表的扩展方式统一

注册表分为：

1. 内置封闭注册表：内置 tool、slash command、event handler，显式注册并测试名称唯一；
2. 外部开放注册表：provider adapter、interpreter strategy、未来 secret plugin，使用
   `importlib.metadata.entry_points()`，不扫描目录、不依赖 import side effect。

entry point 必须延迟加载；失败产生诊断而不阻止核心启动；同名冲突拒绝；插件 capability
只是上界，仍经过 Forge policy；未知插件不自动获得 workspace/network/credential 权限。

### 决策 11：依赖清单必须与真实 import 一致

直接依赖是 `src/forgecli` 直接 import，或正常运行时直接调用其 entry point 的包。

提出本 ADR 时：

- `pathspec` 没有任何源码或测试 import：删除；
- `watchfiles` 只为读取 `DefaultFilter.ignore_dirs`：删除，真正文件监控时再引入；
- `tree-sitter` 没有直接 import，只有 `tree_sitter_language_pack`：检查 metadata，若后者已声明
  依赖则删除冗余直接声明；
- `pydantic` 已被 Web 源码直接 import：补成直接依赖；
- `starlette` 同样被 `interfaces/web/app.py` 直接 import，只靠 FastAPI 传递引入：补成直接依赖；
- `jsonschema`、`regex`、`rapidfuzz`、`wcmatch`、`charset-normalizer`、
  `tree-sitter-language-pack`、`pygit2` 有真实消费者：保留。

CI 增加依赖卫生检查：直接 import 必须有直接依赖；无消费者依赖要求 allowlist 理由；可选依赖
只能在边界模块延迟 import；lockfile 与 pyproject 同步；架构检查继续禁止 SDK 进入核心层。

### 决策 12：迁移顺序与退出条件

迁移遵循“小切片、双写最短、旧实现可删除才完成”。

- Pydantic 声明为直接依赖；
- 修复 GLM key/id；
- 增加依赖卫生脚本。

退出条件：行为测试不变，lockfile 与 architecture checks 通过。

#### Phase 1：低耦合基础设施

- filelock；
- prompt-toolkit；
- sse-starlette。

（platformdirs 见 4.6：已撤回。）

退出条件：旧实现删除；TTY、锁、SSE 的目标平台契约测试通过。

#### Phase 2：数据边界单一化

- Pydantic 配置 DTO、persistence DTO、Web serialization、UI schema。

退出条件：字段只有一个 schema 来源；旧 JSON fixture 可读；手写字段表和递归 serializer 删除。

#### Phase 3：Git

- pygit2 `git_read`。

（官方 OpenAI SDK adapter 见 4.1：已撤回，传输栈保持现状。）

退出条件：第三方对象不泄漏；Git read 安全用例通过；Git CLI 参数白名单删除，`git_read`
不再声明 SPAWN_PROCESS。

#### Phase 4：解析与安全穷举降级

**2026-08-28 状态**：

| 项 | 结论 |
|---|---|
| 网络表退出授权路径 | **已做**。`NETWORK_ACCESS` 移进 `budget._NEEDS_FENCE`：围栏立起来就自动放行，没立起来时 `EXECUTE_SHELL` 本来就落回 ASK。批准一次网络访问并不会放宽围栏（围栏由 mode 编译，授权信封里没有它），所以那次 ASK 问的是一个答案不起作用的问题 |
| 合并 interpreter/wrapper | **已做**。`command_plan.py` 的两份私有副本（解释器名字表、5 条的网络工具表）删除，改用 `wrappers._INTERPRETERS` 这一份登记与 `commands.NETWORK_TOOLS` 这一份表。合并顺带补上了红线覆盖：`nc … \| sh` 与 `ssh … \| bash` 原先不命中 Hard Deny，因为那份副本比风险摘要用的窄 |
| detect-secrets adapter | **不采用**，见 4.9（实测数据在那里） |
| Tree-sitter Shell adapter | **改期**，见 4.8（实测数据在那里） |
| 不可逆动作迁入专用 capability | **无事可做**。这一条以"存在专用工具"为前提，而目前没有任何写侧 git/云工具可迁。`git_read` 是只读的。真要做就是新增产品能力，超出本 ADR |
| 开放表标注分类与漏项方向 | **已做**。39 张表全部标注，并由 `scripts/check_open_tables.py` 守住（接进 `make arch`）。方向性用例见 `tests/security/test_open_table_directions.py` |

退出条件：未知命令、解析错误、未知脚本不会扩大权限；命令表错误只影响性能/展示；唯一承重表
有明确审计测试。

#### Phase 5：可选治理件

- cachetools、pybreaker、精确 tokenizer；
- 只在真实使用和删码收益成立时实施。

**2026-08-28 状态：不实施。** 决策 5 的采用条件是"证明删除的机制多于新增适配层"。
现有实现都藏在已有边界后面（响应缓存与熔断在 `LlmGateway` 内，token 估算在
`token_estimator.py`），换成依赖要新增 adapter 把第三方类型挡在 infrastructure，
净增代码。这一条按 ADR 原文就是条件不成立时不做，不是遗留项。

退出条件：每类机制只有一个所有者，不存在双重重试、缓存、熔断或指标。每个 Phase 可独立停止；
不得先删除安全/兼容实现，再等待依赖接入。

## 备选方案

### 方案 A：维持现状，只规定以后不再新增自实现

零迁移风险，但现有 HTTP parser、TTY、Git flags、文件锁、字段 schema 和开放表继续承担成本。
不采用。

### 方案 B：一次性引入完整 Agent Framework

能同时得到 provider、tools、streaming、HITL 和 tracing，但会与 Forge 控制面重叠，无法小步
验证。不采用。

### 方案 C：依赖优先，但允许第三方类型穿透所有层

适配代码少，但 domain/application 被具体版本和对象模型绑定，违反分层。不采用。

### 方案 D：只替换通用机制，不处理开放式穷举

迁移清晰，但命令、网络、路径、环境和 provider 表仍可能被误认为完整集合。不采用。

### 方案 E：删除所有表，完全依赖 sandbox

实现最小，但 sandbox 关不住进程内工具、环境变量、macOS 宿主进程操作，也无法在放开网络后
区分 fetch/push，违反 ADR-0030。不采用。

## 影响

### 收益

- 协议和平台 bug 交给维护对应标准/SDK的项目；
- Forge 代码集中在领域、安全、恢复和交互差异；
- 配置 UI、Web schema、持久化校验收敛到单一来源；
- Git 读取不再有任意 CLI 参数和外部执行入口；
- TTY、SSE、锁和应用目录获得成熟跨平台行为；
- Shell 解析升级为语法树；
- 开放表的漏项不再默认变成授权缺陷；
- 依赖声明与真实 import 一致。

### 代价

- 运行时依赖、安装体积、供应链审查和 lockfile 成本上升；
- SDK/社区包升级可能改变协议或类型；
- Pydantic 可能影响配置错误文案；
- pygit2 与 Git CLI 在 diff/config/attributes 等细节上可能不同；
- Tree-sitter grammar 不等于执行语义，仍需 fail-closed adapter；
- 部分开放表在 macOS/full_access 下仍暂时保留。

### 供应链与性能影响

- 依赖必须锁定并审查许可证、来源和 telemetry 默认值；
- 原生扩展须验证目标平台 wheel，不在启动时下载 grammar/binary/model；
- 插件不得自动获得权限；
- Tree-sitter/libgit2/RapidFuzz 可减少纯 Python CPU；
- SDK client 必须复用并测量连接池；
- detect-secrets 只检查即将写入的有限文本，不作为每轮全仓扫描前置。

### 兼容性影响

- 旧 JSON 必须可读；
- 本 ADR 不直接改变应用默认目录；
- LLM base URL 兼容完整 endpoint 与 protocol root；
- CLI 快捷键、Ctrl-C、非 TTY fallback 保持；
- SSE id/replay/鉴权保持；
- Git tool result 字段语义保持，不承诺逐字符复刻 CLI；
- 只有安全 plan/hash/vocabulary 改变时才失效 learned rules。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 依赖弃用或供应链受损 | lockfile、审计、adapter、可回退版本 |
| SDK 与兼容供应商不一致 | recorded fixtures；保留 provider dialect adapter |
| Pydantic 改变持久化输出 | golden fixture、双读单写、格式版本 |
| pygit2 不支持查询 | 返回 unsupported，不回退任意 shell |
| Tree-sitter 转换漏项 | error/unknown node 进入 UNPROVEN，sandbox 仍为主边界 |
| 开放表重新被当作完整集合 | 静态检查、注释和表外行为测试 |
| 重试/缓存/熔断重复 | 每类机制声明唯一 owner，测试请求次数和 deadline |
| pygit2 与 git CLI 输出不同 | 渲染由 Forge 拥有并有用例钉住；覆盖不到的查询返回 unsupported |

## 测试策略

### 1. Contract test 优先于库内部测试

不测试依赖自己的算法，测试 Forge 与依赖之间的输入映射、输出/异常归一化、取消/超时、第三方
对象泄漏、失败方向和旧格式兼容。

每个 adapter 至少覆盖正常路径、非法输入、主要异常、timeout/cancel、可选依赖缺失、版本边界、
日志无 secret，以及 domain/application API 不出现第三方类型。

### 2. 穷举表的方向性测试

每张开放表必须有“表外成员”测试：表外命令不自动放行；表外网络客户端受 fence；表外环境变量
不进入子进程；未知 secret 可被 entropy/keyword 捕获；非 Git 未知目录不默认忽略；未知兼容
provider 可配置，否则明确 unsupported；未知 irreversible raw shell 不得被宣称安全。

### 3. 红蓝对抗回归

至少覆盖 `bash -lc`、命令替换、heredoc、nested interpreter、Git ext-diff/pager/textconv、
PATH 劫持、环境变量写入工作区、未知云 CLI、`2>/dev/null`、parser error node、乱码和超长输入。

## 验收标准

### ADR 接受前

- 确认不改变 ADR-0010/0011 的主循环和网关所有权；
- 确认 ADR-0030 运行期边界不被依赖绕过；
- ~~明确 full_access raw network shell 对未知不可逆操作的默认处理~~（2026-08-28 已定，见未决问题 3）；
- 核实高优先级依赖的许可证、Python 3.13+ 和目标平台 wheel；
- 对 conditional dependencies 逐项记录采用/拒绝。

### 全部迁移完成后

- 不再手写边界字段校验/序列化、TTY key parser、Git CLI 白名单、project native lock 和
  Web SSE framing（OpenAI HTTP/SSE 栈按 4.1 保留，POSIX/PowerShell lexer 按 4.8 改期）；
- ~~secret scanner 不再以 credential prefix 为主要检测~~（按 4.9 撤回：实测显示前缀表在真凭证覆盖上优于 detect-secrets 的厂商检测器）；
- `pathspec`、借目录名的 `watchfiles` 等无消费者依赖删除，Pydantic 是直接依赖；
- 每种 retry/cache/circuit/metrics 只有一个 owner；
- ~~开放表全部标注分类、默认方向和漏项后果~~（2026-08-28 完成：39 张表，由 `scripts/check_open_tables.py` 守住）；
- 除记录的 D 类外，没有表外默认放行的承重穷举（2026-08-28：仅剩 `_IRREVERSIBLE`，且承重范围已收窄到 plan / accept_edits / auto 三档）；
- Ruff、Mypy、架构检查、全量测试和安全红蓝对抗通过；
- 设计文档、roadmap 和依赖说明同步。

## 回滚策略

- adapter 切换使用仅迁移期存在的装配 flag，完成后删除 flag 和旧实现；
- 持久化先双读旧/新、只写选定格式，回滚版本仍能读；
- 应用目录若将来切换，切换前保留 legacy discovery；
- SDK/pygit2/Tree-sitter 回滚只替换 infrastructure adapter，不改 domain contract；
- 安全表只能在运行期替代机制通过红蓝测试后删除；
- dependency downgrade 通过 lockfile，不在运行时动态安装。
