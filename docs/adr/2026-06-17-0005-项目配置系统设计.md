# ADR-0005：项目配置系统设计

## 状态

Accepted

## 日期

2026-06-17

## 背景

ForgeCLI 虽然是本地化 CLI 工具，但仍需要让用户和企业控制模型、模式、权限、MCP、存储、上下文预算、工具开关和 UI 行为。配置系统需要兼顾可读性、可测试性、安全边界和多 workspace 场景。

## 决策

1. 配置文件采用 TOML。项目配置的物理存储位置已由 ADR-0008 调整为用户级 Forge home 下的 `projects/<project-id>/forge.toml`；用户全局配置默认路径为 `~/.forge/config.toml`。

2. LLM API key、token、secret 等敏感配置只从环境变量或系统凭证读取，不写入项目配置文件。模型供应商、模型名、base URL、超时、上下文预算等非敏感配置可以写入 `config.toml`。

3. 配置系统按领域分块，例如 `model`、`policy`、`tools`、`mcp`、`storage`、`context`、`ui`。

4. 项目不使用可变全局配置单例。应用启动时由 `ConfigService` 加载和合并配置，生成不可变 `EffectiveConfig`，并在 session/turn 编排时显式注入。`ConfigService` 可以作为应用生命周期内单例，但领域层不得直接读取全局配置。

5. 配置示例：

   ```toml
   # 进入交互式会话后的默认工作模式，可在会话内临时切换。
   default_mode = "chat"

   # 当前运行时默认使用的模型配置。
   # 该配置块不表示可用模型目录，也不表示动态 provider registry。
   # 可用模型列表和能力元数据由 ModelCatalogService 管理。
   # API key、token 等敏感凭证不得写入本文件。
   [model]
   provider = "openai"
   model = "gpt-5"
   timeout_seconds = 60

   # 本 workspace 的本地会话和产物存储位置。
   # 相对当前项目的 Forge home 目录：~/.forge/projects/<project-id>/
   [storage]
   sessions_dir = "sessions"
   artifacts_dir = "artifacts"

   # 工具调用和外部副作用的默认审批策略。
   [policy]
   network = "ask"
   write = "ask_in_chat_allow_in_act"
   destructive = "ask"
   external = "ask"

   # 单次会话上下文预算和自动压缩阈值。
   [context]
   max_tokens = 120000
   auto_compact_threshold = 0.8
   ```

## 备选方案

- JSON 配置：机器友好，但不支持注释，人工编辑体验较差。
- YAML 配置：表达力强，但解析规则复杂，需要额外依赖，MVP 没有必要。
- 全局可变配置单例：调用方便，但测试困难，也不利于多 session、多 workspace 和后台任务。

## 影响

TOML 配置让用户可读可编辑，并与 Python 项目的 `pyproject.toml` 保持一致。`ConfigService + EffectiveConfig` 提高测试性和可控性。代价是调用链需要显式传递配置视图，不能在任意模块中直接读取全局配置。

## 验收标准

- 详细设计中的配置文件路径更新为 `.forge/config.toml` 和 `~/.forge/config.toml`。
- 敏感凭证不出现在配置示例中。
- `ConfigService` 合并配置后输出不可变 `EffectiveConfig`。
- 领域层不直接读取环境变量、配置文件或全局配置对象。
- 配置合并、优先级和企业只读策略有测试覆盖。
