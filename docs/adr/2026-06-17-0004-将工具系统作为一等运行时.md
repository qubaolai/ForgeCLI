# ADR-0004：将工具系统作为一等运行时

## 状态

Accepted

## 日期

2026-06-17

## 背景

工具是 CLI Agent 执行真实动作的核心入口，涉及文件、shell、git、测试、MCP 和外部系统。如果工具仅作为 infrastructure 细节，会削弱权限控制、审计和统一扩展能力。

## 决策

将工具系统设计为独立的 `tools` 运行时，包含 `ToolRegistry`、`ToolRuntime`、内置工具、MCP tool adapter、风险分级、结果归一化和 artifact 管理。`infrastructure` 只提供 shell、git、filesystem、MCP client 等底层适配。

## 备选方案

- 把工具放入 infrastructure：实现简单，但权限和审计边界不清晰。
- 每个 Agent 自带工具：灵活，但难以统一治理。
- 直接使用框架工具协议：接入快，但容易绕过 ForgeCLI 的安全模型。

## 影响

该方案让工具成为可审计、可配置、可治理的能力层。代价是工具调用链路更长，需要严格定义 ToolSpec、ToolResult 和审批流程。

## 验收标准

- 所有工具必须通过 Tool Registry 暴露。
- 工具执行必须经过 ModePolicy 和 ApprovalService。
- 工具结果统一归一化为 ToolResult。
- MCP 工具不能绕过 ForgeCLI Tool Runtime。
