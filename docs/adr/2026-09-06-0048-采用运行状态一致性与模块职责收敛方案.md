# ADR-0048：采用运行状态一致性与模块职责收敛方案

## 状态

Proposed

本文记录总体优化方案，不代表下述问题已经修复，也不代表当前版本已通过完整验收。

## 日期

2026-09-06

## 背景

ForgeCLI 已形成领域层、应用层、基础设施层及 Web / TUI 两个入口。工具裁决、LLM
网关、会话存储和人机交互均已有实现；两个入口经 `interfaces/runtime` 装配。
当前需要解决的是这些组件共同运行时的状态边界与维护成本。

本次分析基于 2026-09-06 工作区，包括尚未提交的 `human_interaction` 功能包迁移。
该迁移改善了文件归属，但不能单独解决上下文丢失、事件混入和取消后继续等待的问题。
本文保留现有轻量 DDD 和单一组合根，按“修复状态一致性、恢复质量门禁、收敛模块职责、
测量并优化性能”的顺序推进，不以全面重写作为优化手段。

### 现状与证据

“已复现”指使用真实相关类和内存替身完成最小复现，不等同于生产环境端到端验证。
“代码确认”指可从当前调用链确认的行为；“待测量”不作为已发生的性能故障。

| 方向 | 当前现状及问题 | 证据强度 |
| --- | --- | --- |
| 会话与模型重载 | `reload_llm()` 重建 `AgentTurnService`，窗口重建、轮次归零；最小复现中轮次从 7 变为 0 | 已复现 |
| 事件重连 | 新服务游标为 1、客户端携带旧游标 100 时，`after(100)` 返回 `(False, ())`，既无事件也不要求重新同步 | 已复现 |
| 会话隔离 | 新建会话未清理共享事件缓冲；`/runs` 合并全缓冲并仅按 `turn_id` 分组，不同会话的轮次编号可以相同 | 代码确认，需补完整跨会话回归 |
| 取消与人机等待 | 取消先释放队列，随后 `ask_user` 入队，取消标记已为真但工具仍等待 | 已复现 |
| 模块职责 | `web/src/App.tsx` 为 1877 行，承担查询、SSE、状态和多个界面；后端 `interfaces/web/app.py` 为 1195 行，运行时也承担用例操作 | 代码确认，行数只用于定位，不作为拆分阈值 |
| 两入口一致性 | TUI 支持配置来源与恢复默认；Web 通用设置接口只有有效值查询和修改，未提供相应重置能力 | 代码确认 |
| 性能 | 工作区检查多次执行全量遍历；历史过程查询读取整份 JSONL | 代码确认调用方式，实际性能影响待测量 |

检查时 Python 测试为 308 通过、9 失败，失败集中在 `--mock-llm` 入口契约；Web
测试 67 通过，生产构建通过。mypy 和依赖方向检查通过，`make ci` 被 4 个未使用导入
阻断。抽象检查对 `WorkspaceSnapshotProvider` 报“无实现”，但基础设施中的
`OsWorkspaceSnapshotProvider` 已通过结构化类型实现该 Protocol；检测器仅看显式继承，
因此这一项属于检查器误报。

这些数字是分析时的快照，不能替代实施后的重新验收。启动检查因本机 8765 端口被占用
未完成，该环境条件不计为产品缺陷。

## 决策

### 决策 1：分离会话状态与可重载的模型依赖（P1）

**现状。** `ProjectRuntime.reload_llm()` 重建网关、工具栈及 AgentTurnService。
后者的构造函数将 `_turns` 置零、创建新窗口；这条路径没有恢复原服务的完整状态。

**问题。** 更换模型或模型覆盖时，用户仍处于同一个会话，模型却可能失去上下文，
轮次编号也可能重复。配置操作因此改变了会话身份和记忆，超出其应有的职责。

**优化方案。**

- 会话状态由应用层长期持有，至少包括当前窗口、轮次身份以及已累积的上下文维护状态；
  网关、模型选择、计量与预算依赖可在空闲边界重新配置。
- 优先保留现有会话服务，通过明确的重配置入口更换依赖。需要替换服务实例时，必须
  显式迁移完整状态，不能只复制轮次计数，也不能退化为只恢复用户和助手的文本。
- 将空闲检查、候选配置校验和依赖切换作为受控操作。新依赖构造失败时，旧运行配置
  仍可用；配置文件与生效状态不得静默分离。多个相关配置键应整体校验、整体提交。
- 新模型上下文容量不足时，走已有窗口预算和压缩机制，不通过重置会话解决。

**优化后的好处。** 用户可在同一任务中切换模型而保留上下文；配置失败可恢复；
会话状态的测试不再依赖整个运行时重新装配。

证据：[模型重载](../../src/forgecli/interfaces/runtime/project_runtime.py)、
[会话服务初始化与恢复](../../src/forgecli/application/agent_turn/agent_turn_service.py)。

### 决策 2：建立带会话归属和实例标识的事件协议（P1）

**现状。** 运行事件按 `turn_id` 编号，SSE 游标是进程内递增整数；会话切换后仍共享
缓冲。客户端重连继续发送旧游标，后端只处理“游标过旧”，不处理“游标超前”。

**问题。** 服务重启后可能跳过新事件；旧会话过程可能混入新会话；单独的
`turn_0001` 无法表达它属于哪个会话。简单刷新 UI 不能修复这些身份歧义。

**优化方案。**

- 领域运行事件显式携带 `session_id`，轮次至少由 `(session_id, turn_id)` 唯一定位。
  后台调度的 `run_id` 与会话轮次 `turn_id` 保持明确映射，不能互相代用。
- 事件 hub 每次创建生成新的 `stream_id`。SSE 续传标识包含实例和游标，两者共同
  表示续传位置；事件身份由调用链显式提供，不从日志上下文反推业务归属。
- 实例不匹配、游标超前或缓冲过期时，统一要求 `resync_required`。客户端同步当前
  会话快照并使用新的续传位置，不能等待事件计数追上旧值。
- 快照携带事件水位，客户端先应用快照，再应用水位之后的事件；重复事件幂等处理，
  避免“读取快照”和“接入事件流”之间丢事件。
- `/runs` 和历史查询按会话过滤；切换会话时释放或切换相应订阅、草稿和缓存。
  可保留不同会话的缓存，但必须分别索引，不能把清空全局状态作为唯一隔离方式。

**优化后的好处。** 重启与断线恢复可预测，跨会话展示不会串数据，前端能可靠地
合并快照和增量事件，问题卡片和普通模型流式输出使用同一套恢复规则。

证据：[事件缓冲](../../src/forgecli/interfaces/runtime/event_hub.py)、
[历史过程合并](../../src/forgecli/interfaces/web/app.py)、
[Web 续传](../../web/src/App.tsx)。

### 决策 3：将取消纳入轮次生命周期，原子管理人机等待（P1）

**现状。** `cancel()` 设置取消标记并释放已在队列中的提示；`ask()` 随后仍可入队。
`ask_user.perform()` 在进入等待之前没有与取消状态建立原子关联。

**问题。** 取消与入队交错时，停止按钮可能已经返回成功，后台却新增一个永久等待。
只在 `perform()` 开头检查一次标记，仍存在检查之后、入队之前的竞态。

**优化方案。**

- 在后台线程启动前创建并绑定轮次生命周期，至少区分运行、取消中和结束；取消状态
  在本轮内不可逆，下一轮以新的轮次身份开始。
- 每条待答提示绑定轮次。通道在同一个同步边界内检查轮次状态并登记等待者；取消既
  释放已有等待者，也阻止该轮后续入队，不能仅遍历一次当前队列。
- 回答、取消、关闭之间只允许一个终态。用户主动跳过、取消整轮、无人可答继续保留
  不同结果语义；审批不得通过跳过取得授权。
- 保留“回答持久化成功后才继续执行”的顺序。需要避免慢磁盘占用队列全局锁时，应
  引入按提示的提交状态或等价机制；不能先唤醒模型再异步补写回答。提交期间的取消
  也必须有唯一终态，持久化失败应允许重试。

**优化后的好处。** 停止任务不依赖时序运气；不再留下取消后的孤立等待者；多端作答、
磁盘失败和关闭流程都有可测试的结果。

证据：[取消入口](../../src/forgecli/interfaces/runtime/project_runtime.py)、
[等待队列](../../src/forgecli/interfaces/runtime/human_interaction/broker.py)、
[提问工具](../../src/forgecli/application/tools/builtin/ask_user.py)。

### 决策 4：恢复可信门禁，以场景测试覆盖状态边界（P1）

**现状。** 静态类型检查与局部测试通过，但完整 CI 未通过。入口实现、mock 相关测试
和部分说明存在不同步；抽象检测器不能正确识别 Protocol 的结构化实现。

**问题。** 长期存在的失败会掩盖新回归；单纯调整类型或只跑局部测试不能证明整个任务
可以完成。错误的架构检查还可能推动开发者删除合理的依赖倒置端口。

**优化方案。**

- 清理未使用导入，明确 mock CLI 参数的保留或退役契约，再统一入口实现、测试和文档。
  本 ADR 不直接决定恢复某个已移除参数，也不允许以跳过失败测试代替契约修正。
- 结构化 Protocol 的实现归属通过可验证的绑定检查或显式且可核验的实现登记识别，
  保留跨层端口；不能仅按类名白名单豁免，也不能只比较方法名便认定实现。
- 将最小复现固化为回归测试，再增加使用真实装配的集成测试。用内存替身替换模型与
  外部副作用，保留真实事件总线、等待通道、路由和会话状态。
- 前端保留渲染测试，补充挂载后的交互测试：单选互斥、多选增删、跳过、失败保留
  草稿、重复提交、切换会话和 SSE 重连。跨入口契约测试验证同一个输入得到等价结果。
- CI 报告明确区分产品失败、检测器误报和端口占用等环境限制；发布前所有必需门禁
  必须通过，不能把环境限制记成成功。

**优化后的好处。** 失败重新具有诊断价值；重构时能检验行为不变；竞态和协议回归可在
合并之前发现，降低依赖人工重启页面排查的频率。

证据：[质量门禁](../../Makefile)、[入口测试](../../tests/test_entrypoint.py)、
[抽象检查器](../../scripts/check_abstractions.py)、
[工作区 Protocol](../../src/forgecli/application/workspace/monitor.py)、
[具体实现](../../src/forgecli/infrastructure/workspace/snapshot_provider.py)。

### 决策 5：按功能和职责拆分界面，统一异步状态管理（P2）

**现状。** Web 根组件集中持有会话、模型、设置、运行事件等状态；后端单个 app 工厂
包含大量资源路由；`ProjectRuntime` 兼有装配和用例操作。问题查询已有请求版本保护，
历史、模型等查询缺少一致的迟到响应处理。

**问题。** 修改一个功能容易触碰多个无关状态；切换会话后，旧请求可能覆盖新页面；
把所有查询绑在一个 `Promise.all` 中，也会让一个慢查询延迟其他数据展示。

**优化方案。**

- Web 按 conversation、human interaction、settings、run events 等功能拆分组件与
  状态逻辑。`App` 保留外壳与功能装配，SSE 连接和请求客户端独立维护。
- 后端使用按资源组织的 router。路由承担参数、身份和响应映射；配置修改、回答审计、
  会话切换等规则通过应用层用例执行；`interfaces/runtime` 负责装配与运行资源管理。
- 延续 `human_interaction` 功能包，与负责 LLM 提示词的 `prompt` 包分别组织。
  不为每个方法新增 service、manager 或通用转发层。
- 查询按项目、会话和请求代次定位。切换作用域时取消旧请求，并在写入状态前校验
  作用域和版本；取消请求不能代替响应身份校验。
- 各资源独立维护加载、错误与有效数据，关键交互不等待无关查询。草稿以
  `(session_id, prompt_id)` 绑定，重连保留、切换作用域隔离、问题结束后清理。
- `BuiltinAgentLoop`、LLM gateway 等大型模块也按稳定职责逐步提取协作者；主循环
  仍负责控制流，网关仍是统一调用入口。文件长度不构成引入新抽象的充分理由。

**优化后的好处。** 一个功能的状态和交互可以单独测试；迟到请求不会污染当前页面；
路由与终端共享用例，减少修复一端后另一端仍保留旧逻辑的情况。

证据：[Web 根组件](../../web/src/App.tsx)、[API 路由](../../src/forgecli/interfaces/web/app.py)、
[组合根](../../src/forgecli/interfaces/runtime/project_runtime.py)。

### 决策 6：两入口共用配置视图和操作契约（P2）

**现状。** 配置键已来自 `config_keys.SCHEMA`，但 TUI 与 Web 暴露的操作和信息仍不
完全一致。TUI 能恢复默认并显示来源；Web 通用设置界面缺少对应重置能力。

**问题。** 共用字段名称只能避免部分重复，无法保证用户在两个入口完成相同操作。
界面各自推导来源、生效时机或重置含义，还会产生第二套业务规则。

**优化方案。**

- 应用层输出统一配置视图，包含键声明、有效值、来源、是否覆盖、作用域和生效时机。
  模型标准字段和会话权限姿态继续分别由 `STANDARD_FIELDS`、`domain/intents` 声明。
- Web 与 TUI 调用相同的设置、取消覆盖、校验和应用入口。重置表示删除覆盖、重新
  继承默认值，不等于把当前默认值写成永久覆盖。
- 操作是否允许、生效是否需要下一轮或重载，由共享用例和声明提供，界面只展示结果。
- 增加能力清单测试，逐项比较两个入口能否查询、修改和重置对应设置。

**优化后的好处。** 使用者可以自由切换入口；新配置项只维护一份声明和用例；修改
默认值后，未覆盖的用户能正确继承新默认值。

证据：[配置声明](../../src/forgecli/domain/config/config_keys.py)、
[TUI 配置操作](../../src/forgecli/interfaces/tui/commands/config.py)、
[Web 设置路由](../../src/forgecli/interfaces/web/app.py)。

### 决策 7：先建立性能基线，再采用增量监测和分页（P2）

**现状。** `OsWorkspaceSnapshotProvider.snapshot()` 遍历工作区，主循环在多个
检查点调用它；`JsonlRunStore.read()` 读取整份会话过程文件，前端加载历史缺少分页。

**问题。** 工作区文件数与会话长度增长会增加重复 I/O、解析和渲染开销。目前没有
压测数据，不能把这些路径直接宣称为已证实瓶颈，也不能承诺未经验证的加速倍数。

**优化方案。**

- 用固定环境和样本测量 1 千、1 万、10 万文件，以及 100、1000、1 万轮历史，记录
  扫描次数、读取字节、耗时分布、内存和页面可交互时间；报告硬件、缓存冷热和样本大小。
- 工作区增量监测遵循 ADR-0047 的独立决策：session 生命周期、OS 文件事件、下一轮
  通知及有限恢复扫描。本 ADR 不改变其通知时机、不新增内容 diff，也不把当前轮内
  反复扫描作为目标实现。ADR-0047 尚为 Proposed，相关语义以其接受后的版本为准。
- 历史 API 增加稳定游标和有界页大小。仅限制返回条数但每次仍读取整个文件不算完成；
  采用可从原日志重建的偏移索引或等价方案，JSONL 仍作为既有事实来源。
- 前端按需加载历史，根据测量结果引入列表虚拟化；滚动位置、当前待答卡片和输入
  草稿不得因窗口化而丢失。分页索引和缓存均有失效与资源上限策略。
- 在同一环境复测，记录收益和代价后决定是否继续投入；不因这一轮优化迁移数据库。

**优化后的好处。** 页面加载和检查成本可随实际变更量或当前页大小控制；性能结果
可重复比较，避免引入复杂机制却没有改善用户体验。

证据：[工作区扫描](../../src/forgecli/infrastructure/workspace/snapshot_provider.py)、
[历史读取](../../src/forgecli/infrastructure/session/jsonl_run_store.py)。

## 实施顺序

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| A：恢复门禁 | 校准入口契约、清理 lint、修复 Protocol 检查 | 必需检查可正常运行且基线通过 |
| B：状态修复 | 会话与模型依赖分离、事件身份与续传、原子取消/等待 | 三类最小复现转为通过的回归；跨会话和真实装配集成通过 |
| C：职责收敛 | 界面功能拆分、共享用例、请求作用域、配置操作一致性 | 两入口契约一致；拆分前后行为测试不退化 |
| D：性能治理 | 建立基线、历史分页、按 ADR-0047 推进监测 | 同环境对照数据可复现，状态正确性和资源上限验证通过 |

阶段 A、B 优先于新增功能；C 按单个功能逐步迁移，每批改动可独立审查和回退。
性能基线采集可提前进行，但 D 的机制改造不得替代 B 的正确性修复。

## 备选方案

- **只整理目录或按行数拆文件。** 变更较小，但保留原有状态耦合与竞态，不作为总体方案。
- **只增加轮询、强制刷新或重新创建会话。** 可以缓解部分界面症状，但会掩盖事件身份
  问题，且无法保证上下文和用户回答不丢失，不采用为主恢复机制。
- **整体切换 Agent 框架、数据库或前端状态库。** 迁移成本高，现有证据不足以证明必须
  替换这些基础选择。保留成熟依赖的使用空间，但先明确状态和契约边界。
- **只在提问之前检查一次取消标记。** 改动最小，仍有检查与入队之间的窗口，不采用。
- **按功能逐步收敛并补行为测试。** 采用；优先修复已复现问题，再决定结构和性能投入。

## 影响

### 收益

- 同一会话更换模型后保持上下文；服务重启、断线和会话切换有统一身份与恢复规则。
- 取消、回答和关闭拥有唯一终态，减少“按钮已点但后台仍等待”的问题。
- Web 与 TUI 的能力、声明和用例保持一致，功能修改更容易定位和验证。
- CI 能区分真实回归和检测器局限，性能优化有可重复的基线。

### 代价与兼容性

- 会话状态分离、应用用例迁移及事件字段扩展涉及多个层，需要分批实施和契约测试。
- 新事件建议增加 schema 版本。旧记录缺少 `session_id` 时，只能在所属会话文件提供
  可靠归属时补全；不能把无法归属的全局缓冲默认标为当前会话。历史 `turn_id` 可保留，
  由会话身份补足唯一性，不要求重写所有事件文件。
- 旧版纯数字 SSE 游标无法证明实例一致，升级时按需要全量同步处理。前后端随包升级，
  旧页面遇到不兼容协议应明确要求重新加载，不能继续静默消费。
- 现有 `ask_user` 的单选、多选、唯一推荐、自由文字和逐题跳过契约继续有效；调整等待
  生命周期不产生新的权限，不改变审批服务的授权语义。
- 性能索引和缓存增加失效处理成本；必须可重建、有界，并与会话事实存储分离。
- 不新增一套业务恢复日志。现有事件存储、快照与窗口机制继续承担各自职责。

## 验收标准

1. 同一会话连续对话后切换模型，窗口内容和轮次身份保留；配置校验或依赖构造失败
   不破坏当前会话，下一次请求仍可正常执行。
2. 覆盖同实例重连、服务重启、游标超前、缓冲过期，以及读取快照时产生新事件；
   新事件不遗漏，重复事件不重复应用。
3. 两个会话均存在 `turn_0001` 时，历史查询、事件续传和 UI 展示不混合；切换回原会话
   后仍能正确读取属于它的记录。
4. 用受控线程屏障覆盖取消早于入队、晚于入队、与回答并发及关闭时序；不存在遗留
   等待线程。跳过只结束本题，取消结束本轮，审批未答不放行。
5. 回答持久化失败时不唤醒模型；重试不会重复记账或重复恢复工具；多端竞争只能产生
   一个有效结果。
6. 会话 A 的慢请求晚于会话 B 的请求返回时，不能覆盖 B 的状态；问题查询失败可以
   重试，草稿不丢失，切换作用域后不携带旧回答。
7. Web 与 TUI 对同一配置声明提供等价查询、设置和取消覆盖能力，来源与生效时机一致。
8. `make ci` 通过，包括 Python/Web 测试、类型和架构检查；新增集成用例不调用真实
   模型、不执行未经授权的外部副作用。启动验收使用可用端口，环境限制单独记录。
9. 性能报告包含固定样本和对照结果；历史查询不为每页重读全文件，监测和缓存资源
   有界，未改变状态正确性及 ADR-0047 的通知约束。
10. 接受和实施时同步详细设计、工程/验收规范、代码阅读指南及 roadmap，清除已过时
    的入口路径和“尚未实现”描述；逐项记录完成情况，不将本 ADR 自动视为实现证明。
