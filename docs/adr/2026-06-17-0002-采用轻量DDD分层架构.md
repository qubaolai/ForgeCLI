# ADR-0002：采用轻量 DDD 分层架构

## 状态

Accepted

## 日期

2026-06-17

## 背景

ForgeCLI 需要长期演进 Agent、工具、MCP、配置、记忆、审批和会话存储。如果按技术组件随意堆目录，后续很容易出现领域逻辑散落、测试困难和框架绑定。

## 决策

采用轻量 DDD 分层：`interfaces`、`application`、`domain`、`tools`、`infrastructure`、`shared`。核心领域模型不依赖 CLI、LLM SDK、MCP SDK、文件系统或第三方 Agent 框架。

## 备选方案

- 按技术模块平铺：上手快，但边界容易失控。
- 重型 DDD：约束强，但 MVP 成本过高。
- 框架驱动目录：初期快，但容易绑定某个 Agent 框架。

## 影响

该方案让核心模型更稳定，便于测试和替换基础设施。代价是前期需要维护清晰的依赖方向，不能为了速度把业务规则写入 CLI 或适配器。

## 验收标准

- `domain` 不依赖基础设施和 CLI。
- `application` 负责编排用例。
- `infrastructure` 只实现外部适配。
- 领域逻辑具备独立单元测试。
