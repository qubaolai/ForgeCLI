# ADR-0012：完善统一 LLM 网关运行时自身能力

## 状态

Accepted

## 日期

2026-07-12

## 背景

ADR-0011 定义的统一 LLM 网关 MVP 已落地：complete / stream / complete_structured
三类调用共用一条治理管线，凭证解析、错误归一化、usage/cost 计量草稿、响应缓存与
治理端口（限流 / 熔断 / 预算）均已存在，OpenAI-compatible adapter 可发起真实调用。

但盘点网关**自身能力**（不含 AgentLoop / REPL 等调用方接入），仍有一批实现停留在
近似、单一来源或 no-op：

- stream 路径没有凭证级重试；429 只会冷却换凭证，单 key 用户无法"短等重试"。
- 响应缓存无 TTL、无容量上限、无配置开关，生产装配不可达；native 结构化输出未纳入。
- thinking 只翻译 effort 型方言（`reasoning_effort`），effort -> budget_tokens 的
  映射（ADR-0011 §3.5 要求）缺失。
- 凭证只支持 `env:NAME` 一种来源；lease 的 `expires_at` / `release` 无实际语义。
- token 估算只有字符近似，无精确分词器接入点。
- 价格元数据缺 cached / reasoning 单价，成本口径不完整。
- RateLimiter / ProviderHealthRegistry / BudgetGuard 仅有 no-op；可观测性（§15）
  除重试计数外基本未产出。
- `DefaultLlmGateway` 仍保留 06-30 的"无 resolver 兼容路径"与 `validate_model`
  参数，生产装配永远不会走到，属于应清理的遗留占位。

本 ADR 定义补齐上述能力的架构决策。**范围主要覆盖网关自身**；REPL 流式渲染、
Ctrl-C 取消接线、工具执行闭环、context compact 联动属于 ADR-0009 / 0010 及
接入切片，不在本文范围。2026-07-20 增补的配置归属与状态展示只负责让用户可观察、
可编辑本 ADR 的运行时策略，不改变网关调用边界。

## 决策

1. **重试环统一**：流式与非流式共用同一凭证级重试环；stream 仅在**首个 chunk
   产出之前**允许重试（auth / 429 换凭证、超时 / 连接同凭证），首包之后的错误
   一律按中断收尾，不重试、不重放。
2. **429 短等重试**：`retry_after` 小于等于配置阈值时，本地等待后用**同一凭证**
   重试；超过阈值时进入冷却并换下一凭证。等待经注入的 sleeper 完成（可测），
   计入 latency，不计 provider 计费。
3. **响应缓存完备化**：`InMemoryResponseCache` 增加 TTL、容量上限（LRU）与
   注入时钟；缓存开关、TTL、origin 白名单由应用级配置驱动装配；native
   结构化输出纳入缓存（指纹并入 schema 摘要）。chat / act 硬排除不变。
4. **Prompt 缓存标注定性**：`CacheHint` 保留为统一请求侧抽象；OpenAI-compatible
   自动前缀缓存下"静默忽略 + 归一化命中信息"即为其正确翻译，不再视为占位；
   显式 cache breakpoint 翻译随首个需要它的 provider adapter 落地。
5. **thinking 方言翻译补全**：adapter 按 provider 声明 thinking 方言（effort 型 /
   budget 型）；budget 型供应商由 adapter 把 effort 映射为 budget_tokens
   （固定档位表，受模型 max_output_tokens 截断）。mode/effort 来自具体模型配置，
   不接受请求级显式 thinking（修订 ADR-0011 §3.5）。
6. **凭证来源扩展（已回退，凭证保持 env-only）**：本决策原以**封闭 scheme
   注册**扩展 credential ref 为 `env:` / `dotenv:` / `keychain:` 三种来源，由
   `ChainedCredentialResolver` 按 scheme 分发。2026-07-17 复核后判定：ForgeCLI
   是个人单用户 CLI，环境变量足以覆盖本地使用——dotenv 相对直接 `export` 无
   实质收益、keychain 增加平台耦合与实现面，两者均不需要。`dotenv:` / `keychain:`
   resolver、`ChainedCredentialResolver`、`[llm.credentials].allow_dotenv` 配置
   已整体移除，`CredentialResolver` 回到 env-only（`EnvCredentialResolver`）；
   来源单一后 `env:` scheme 前缀也无消歧义作用，一并去除——credential reference
   就是裸环境变量名（如 `DEEPSEEK_API_KEY`）。
   `Credential.expires_at` 字段与池的过期检查也一并移除（唯一来源 env 恒不过期，
   过期分支永不触发）——凭证回到**可用 / 冷却两态**：`mark_failed` 进入冷却
   （401/429），`mark_succeeded` 或冷却到期后恢复，无其他不可用状态。凭证不被
   独占：`CredentialPool.get_credential` 直接返回 `Credential`，不做租借 / 占用，
   无需配对的 acquire/release（原 lease 生命周期与在途计数只服务于 ADR-0011 §13
   的凭证并发闸设想，已随决策 9 一并移除）。
7. **精确分词器接入点**：新增 `TokenizerRegistry`，按 provider/model 选精确
   分词器（作为**可选依赖**接入）；无映射或依赖缺失时回落字符近似。估算接口不变。
8. **价格口径补全**：配置标准字段增加 cached input 与 reasoning 单价，目录与
   `CostEstimator` 消费；reasoning 无专价时并入 output 计价（现行为）。
9. **治理能力实裁决**：提供滑动窗口熔断 `SlidingWindowHealthRegistry`、快照比对
   `SnapshotBudgetGuard` 两个真实实现；**配置未启用时维持 no-op 装配**，行为渐进
   切换，不破坏既有调用链。不含客户端主动限流（RateLimiter，原计划中的第三件）：
   ForgeCLI 定位为个人单用户 CLI，本地按配置猜测的限流阈值相对 provider 真实
   429 响应没有信息优势，对交互 origin（chat/act）的快速失败只会拒绝掉 provider
   本可能接受的请求，是纯粹的可用性损失；单 key 429 已由第 2 条的短等重试环与
   凭证冷却处理，属于用户自行判断是否需要升级配额的范畴，不需要网关代为限速
   （2026-07-16 复核后从本 ADR 范围移除，不再保留 RateLimiter 端口与占位实现）。
10. **可观测性产出**：新增 `GatewayObserver` 端口与进程内聚合实现；网关在每次
    调用收尾统一产出安全摘要样本（provider / model / origin / finish_reason /
    latency / retry / cache_hit / estimated / 错误分类），供 /status 与未来
    trace 导出消费；网关自身仍不落盘。
11. **遗留占位清理**：删除 `DefaultLlmGateway` 的无 resolver 兼容路径与
    `validate_model` 参数，resolver 成为必备协作件；受影响的 06-30 契约测试
    同步迁移为注入 resolver。
12. **配置归属与 CLI 可见性收口（2026-07-20 增补）**：cache、circuit breaker、
    retry 全部是跨项目共享的应用级策略，统一保存到 Forge home 的 `llm.toml`，
    并由 `/config` 经 `LlmConfigService` 编辑。thinking mode/effort 跟随同一文件中的
    具体模型条目；`ModelRequest` 不得显式覆盖。当前模型与用途覆盖仍属项目级
    `forge.toml`。CLI 输入框下方右侧持续显示“当前模型 + 该模型的 thinking”。

LLM 仍不能决定 provider / model / 重试 / 缓存 / 预算，任何重试与降级均不切换
provider/model（ADR-0011 不变量全部保持）。

## 备选方案

- **换用 LiteLLM 等现成网关库补齐能力**：限流 / 重试 / 缓存开箱即用，但审计、
  凭证与预算控制被外置到第三方抽象之后，违背 ADR-0011 的自有控制面初衷。
- **治理能力放到外部 sidecar / 代理进程**：与企业网关方案兼容，但对单机 CLI
  部署过重，且进程内熔断 / 限流已足够。
- **一次性全部启用真实现（无配置开关）**：实现最省，但限流与熔断会改变既有
  调用行为，回归风险不可控。选择配置驱动的渐进启用。

## 影响

- 收益：单 key 用户 429 可自动恢复；stream 与 complete 可靠性一致；响应缓存
  可真正启用；成本口径覆盖 cached / reasoning；/status 有真实数据来源。
  （凭证多来源扩展已回退，见决策 6：个人 CLI 只需环境变量。）
- 代价：`llm.toml` 配置面扩大（cache / circuit_breaker / retry 段）；精确分词器
  引入可选依赖；治理实裁决需要配置迁移说明。
- 兼容性：所有新能力默认关闭或回落到现行为；唯一破坏性变更是清理 06-30 兼容
  路径，仅影响旧契约测试（同步迁移），不影响生产装配。

## 设计细节

## 1. 目标与非目标

目标：把网关自身能力从"接口完整、实现近似"推进到"真实调用可依赖"。

非目标（本 ADR 不做）：

- 调用方接入：REPL 流式渲染、Ctrl-C -> cancel_token、AgentLoop / ToolRuntime
  工具闭环、`complete_structured` 的内部任务调用方（title / summary 等）。
- context overflow 后触发 compact 重试（依赖 ContextManager，ADR-0010 侧）。
- 企业托管凭证、企业 allowlist / 插件 provider、embeddings / rerank、多模态。
- usage 独立落盘（usage.jsonl / sqlite）——写入边界仍归 AgentTurnService。

## 2. 统一重试环与 429 等待策略

```text
RetryPolicy（每 provider，源自 ProviderRuntimeSettings + [llm.retry]）
  max_retries            # 既有：总尝试上限
  wait_threshold_seconds # 新增：retry_after <= 阈值时本地等待，默认 5.0
```

规则：

- `_invoke_with_retries` 提升为 complete 与 stream 共用：stream 在拿到首个
  provider chunk 前的失败按同一分类处理（auth/429 换凭证、timeout/连接同凭证），
  首包之后的错误只做中断收尾（§9 语义），不重试。
- 429 处理顺序：有 `retry_after` 且 `<= wait_threshold_seconds` -> 经注入
  sleeper 等待后**同凭证**重试；否则 `mark_failed(retry_after)` 冷却换下一凭证。
  两类都计入 `max_retries` 预算与 raw_metadata 重试摘要（新增 `wait_retries`）。
- sleeper 为 `Callable[[float], None]` 注入（默认 `time.sleep`），测试钉死。
- 等待时间计入 latency_ms；任何等待 / 重试不切换 provider/model。

## 3. 响应缓存完备化（§14 补全）

```text
InMemoryResponseCache
  ttl_seconds: float | None      # None = 不过期（现行为）
  max_entries: int               # LRU 淘汰上限
  allowed_origins: set[origin]   # chat / act 永远硬排除
  clock: Callable[[], float]     # 注入，可测
```

- 惰性过期：lookup 时校验写入时间；容量满时淘汰最久未命中项。
- native 结构化输出纳入：指纹函数增加可选 schema 摘要维度
  （`schema_name` + schema 的 sha256），`complete_structured` 的 native 路径
  与降级路径都可缓存；两条路径指纹天然不同，不会串味。
- 配置形态（应用级 `llm.toml`）：

```toml
[llm.cache]
enabled = false          # 默认关闭
ttl_seconds = 600
max_entries = 256
origins = ["title", "summary", "structured_classification"]
```

- wiring 按配置装配：`enabled=false` 或缺省 -> Noop（现行为）；配置读取属
  LlmConfigService 面，网关不解析 TOML（§4 边界不变）。
- `/config -> 网关运行时配置 -> 响应缓存` 可编辑 `enabled`、`ttl_seconds`、
  `max_entries`、`origins`；菜单只调用 application service，不直接写 `llm.toml`。

## 4. thinking 方言翻译（§3.5 补全）

```text
ThinkingDialect = effort | budget | none    # provider 级声明，代码内注册

effort -> budget_tokens 档位表（budget 型供应商）：
  low    -> 1024
  medium -> 4096
  high   -> 16384
  （均受该模型 max_output_tokens 截断；catalog 缺失时不截断）
```

- OpenAICompatibleProvider 构造时接受 dialect 参数（wiring 按 provider 注册表
  给定）；effort 型发 `reasoning_effort`，budget 型把模型配置的 effort 映射为
  provider budget 字段。
- `thinking_mode` / `thinking_effort` 是 `[llm.providers.<provider>.models.<model>]`
  的标准字段。gateway 在选择解析后从 `ModelCatalogEntry` 读取，完成能力校验和 auto
  解析，再通过内部 `ProviderRequest.thinking` 下发 adapter。
- `ModelRequest.ModelParams` 不含 thinking，从类型上禁止调用方按请求覆盖；配置优先级
  只有“具体模型字段 > 内置 `auto/none` 默认”。
- 当前模型是项目级配置。CLI 在输入框下方右侧组合展示当前模型与该模型的 thinking；
  状态提供器每次渲染现读模型目录，`/model` 或 `/config` 修改后无需重启即可刷新。

## 5. 凭证来源（§7 补全；scheme 扩展已回退为 env-only）

本节原以封闭 scheme 注册扩展 `env:` / `dotenv:` / `keychain:` 三种来源，由
`ChainedCredentialResolver` 分发。**2026-07-17 复核后整体回退**：ForgeCLI 是
个人单用户 CLI，环境变量足以覆盖本地使用，dotenv / keychain 判定不需要（见
决策 6）。当前凭证来源与 ADR-0011 §7 一致——只支持环境变量，且 credential
reference 就是**裸环境变量名**（前缀原本是多来源分发键，来源单一后无消歧义
作用，一并去除）：

```text
DEEPSEEK_API_KEY         # 环境变量名，无前缀；EnvCredentialResolver 直接读取
```

- 已移除：`DotenvCredentialResolver`、`KeychainCredentialResolver`、
  `ChainedCredentialResolver`、`build_default_resolver`、`[llm.credentials]`
  配置段（含 `allow_dotenv` 开关）、`Credential.expires_at` 字段与池的过期
  检查分支，以及 credential reference 的 `env:` scheme 前缀。
- 凭证只有**可用 / 冷却两态**：`mark_failed` 使其进入冷却（401/429），
  `mark_succeeded` 或冷却到期后恢复，没有其他不可用状态。原 `expires_at`
  过期态只服务于 keychain 的过期语义，keychain 移除后 env 恒不过期、该分支
  永不触发，故一并删除。
- 凭证不被独占（2026-07-17 复核）：`CredentialPool.get_credential` 直接返回
  `Credential`，不经 acquire/release 配对；并发调用可同时拿到同一凭证的值，
  网关不做凭证维度并发限制。原设计里 `release` 维护的在途计数只服务于
  ADR-0011 §13 设想的凭证并发闸，该设想连同 §13 整节已判定对个人单用户 CLI
  无实际价值一并移除（见决策 9、ADR-0011 §13 修订说明）。
- 安全不变量不变：明文 key 永不入 TOML / 事件 / 异常 / fixture。

## 6. 精确分词器接入（§11.4 补全）

```text
TokenizerRegistry
  register(provider, model_prefix, tokenizer_factory)
  estimator_for(ref) -> TokenEstimator   # 无匹配 -> ApproximateTokenEstimator
```

- 精确分词器作为**可选依赖**（extras，如 `tokenizers`）；import 失败静默回落
  近似估算，不影响默认安装的无网络测试。
- 估算端口（`TokenEstimator`）不变；gateway 经 registry 按已解析 ref 取估算器。

## 7. 价格口径补全（§11.2）

- 配置标准字段（`STANDARD_FIELDS`）新增：`cost_per_1k_cached_input`、
  `cost_per_1k_reasoning`；/config 模型编辑菜单随 SCHEMA 自动获得两行。
- `ModelCatalogEntry` 增 `reasoning_price_per_1k`（cached 单价字段已存在），
  catalog builder 合并；`CostEstimator` 口径：reasoning 有专价用专价，缺失并入
  output 价（现行为）；cached 缺失回落 input 价（现行为）。

## 8. 治理能力实裁决（§12.1 / §13）

两者端口不变（已织入管线），新增真实实现，**配置驱动启用**：

```toml
[llm.circuit_breaker]
enabled = false
failure_threshold = 5         # 连续 连接/超时/5xx 达阈值 -> open
cooldown_seconds = 30

[llm.retry]
wait_threshold_seconds = 5    # 429 retry_after 小于等于该值时同凭证等待重试
```

- `SlidingWindowHealthRegistry`：连续失败达阈值 -> open（冷却）；冷却到期 ->
  half-open 放行 1 个探测请求；成功 -> closed，失败 -> 继续 open。状态仅进程内。
  open 时 `check()` 抛 `ModelUnavailableError`（消息标注熔断与剩余冷却）。
- `SnapshotBudgetGuard`：`estimated_input + 已用量 > 上限` 时抛
  `ModelBudgetExceededError`，不发起 provider 调用；快照缺失直通。预算规则与
  已用量状态仍归 AgentTurnService（BudgetPolicy / BudgetTracker，本 ADR 不实现）。
- 可选扩展（P2）：流式过程中按 usage delta 提前停止（§11.3 检查点 2），在
  BudgetGuard 端口上增加流式检查方法后实现。
- `/config -> 网关运行时配置` 暴露响应缓存、熔断器和重试策略三个应用级子菜单；
  所有输入由 `LlmConfigService` 做封闭字段校验，再 round-trip 写入 `llm.toml`。

不实现客户端主动限流（原 §13 RateLimiter/TokenBucketRateLimiter）：见决策 9
的复核说明——本地限流阈值只是对 provider 真实配额的猜测，没有信息优势；provider
返回的真实 429 + `retry_after`（本 ADR §2 短等重试环）是更准确的反应式处理，
而对交互 origin 的快速失败只会误伤 provider 本可能接受的请求。单 key 429 是
用户需要自行处理的问题（升级配额 / 更换模型 / 减少并发），不属于网关代为解决
的范畴。

## 9. 可观测性产出（§15 落地第一步）

```text
GatewayCallSample（安全摘要，不含凭证与 prompt/response 原文）
  provider, model, origin, finish_reason
  latency_ms, credential_retries, transport_retries, wait_retries
  cache_hit, estimated, error_type?

GatewayObserver
  on_call(sample)                  # complete / stream 收尾统一上报

InProcessGatewayMetrics(GatewayObserver)
  按 provider/model 聚合：调用数、错误分类计数、延迟分桶、cache 命中数
  snapshot() -> 只读视图            # 供 /status 消费（接入属调用方切片）
```

- 网关在 complete 返回、stream 收尾 chunk、错误抛出三个位置统一上报。
- 默认装配 `InProcessGatewayMetrics`（纯内存，无 IO），不设开关——它无副作用。
- trace span 导出、审计落盘形态留后续；样本字段本 ADR 先冻结。

## 10. 遗留占位清理

- 删除 `DefaultLlmGateway` 的 `validate_model` 参数与"未注入 resolver 仅支持
  explicit selection"兼容路径；`resolver` 变为必填构造参数。
- `tests/2026_06_30` 中依赖旧路径的用例迁移为注入
  `DefaultModelSelectionResolver`（断言语义不变）。
- `AgentTurnService` 的 `_stub_reply` 回调路径保留（未配置模型时的兜底与测试
  替身价值仍在），不属网关，本 ADR 不动。

## 11. 实现切片建议

1. 重试环统一 + 429 短等重试（改动小、真实调用收益最大）。
2. 响应缓存 TTL / 容量 / 配置开关 + native structured 纳入。
3. 价格字段与 CostEstimator 口径补全。
4. thinking effort -> budget 映射。
5. ~~凭证 scheme 扩展（dotenv / keychain）~~——已回退，凭证保持 env-only（见决策 6）。
6. TokenizerRegistry 与可选精确分词器。
7. 治理实裁决按熔断 -> BudgetGuard 逐个落地（各自带配置开关）。
8. GatewayObserver / 进程内聚合 + 兼容路径清理收尾。

## 12. 测试策略

每个切片必须覆盖（延续 ADR-0011 §18 风格，全部离线确定性）：

- 429 带小 retry_after：同凭证等待重试成功；超阈值：换凭证；等待经注入 sleeper
  断言，不真实 sleep。
- stream 首包前 auth 失败可换凭证重试；首包后错误只产出中断收尾，不重试。
- 缓存：TTL 过期未命中、LRU 淘汰、配置关闭时零缓存、native structured 命中且
  不同 schema 不串味、chat/act 永不缓存。
- thinking：模型字段进入 catalog；budget 型方言收到由 effort 映射后的 budget_tokens
  且受 max_output 截断；effort 型行为不回归；请求 DTO 拒绝显式 thinking。
- 凭证：裸环境变量名可解析且值不泄露到 repr/str/异常；空引用报错；
  凭证只有可用 / 冷却两态（无过期态）；凭证不被独占，
  并发获取互不阻塞。
- 分词器：有映射用精确值、无映射回落近似、可选依赖缺失不影响导入。
- 熔断：连续失败进入 open 且不再调用 provider、half-open 探测成功恢复、
  状态不落盘。
- 预算：快照超限请求前拒绝且 provider 零调用、缺失快照直通。
- 观测：成功 / 失败 / 缓存命中样本字段齐全且不含凭证与原文。
- 清理：resolver 必填后全量测试仍绿。
- 配置归属：thinking 只写具体模型的 `llm.toml` 条目；当前模型只写项目级
  `forge.toml`；cache / circuit breaker / retry 只写应用级 `llm.toml`。
- `/config`：三类网关运行时配置均可查看和修改，非法布尔、范围、origin 被拒绝。
- CLI 状态行：持续显示当前模型和 thinking，配置变更后重新渲染即可看到新值。

## 13. 验收标准

- stream 与 complete 的凭证级重试语义一致（首包前），重试摘要可见。
- 单 key 用户遇 429（retry_after 小）不需人工干预即可恢复。
- 响应缓存可经配置真实启用，且默认行为与启用前完全一致。
- effort 型与 budget 型 thinking 供应商都能被同一 ThinkingConfig 驱动。
- 凭证 ref 只支持环境变量名（无前缀，scheme 扩展已回退，见决策 6），明文 key
  仍不出现在任何持久化面。
- 精确分词器缺失时系统行为与今日一致（回落近似）。
- 治理能力在配置关闭时为 no-op（行为回归零），开启后各自约束生效且有测试。
- 每次调用产出结构化样本，/status 可基于 snapshot() 展示（展示接入不在本文）。
- `DefaultLlmGateway` 不再有生产不可达的兼容分支。
- `/config` 可编辑应用级 cache / circuit breaker / retry，以及具体模型的 thinking；
  thinking 在 ADR、schema、catalog、gateway 和测试中统一为模型级，并与当前模型一起
  持续显示在输入框下方右侧。
- 默认无网络测试全绿；LLM 仍不能影响 provider / model / 重试 / 缓存 / 预算决策。
