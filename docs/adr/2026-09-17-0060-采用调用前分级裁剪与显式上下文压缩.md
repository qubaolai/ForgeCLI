# ADR-0060：采用调用前分级裁剪与显式上下文压缩

## 状态

Proposed

本文细化 ADR-0056 的窗口维护。接受后，替代 ADR-0032 的压缩与去重策略，以及
ADR-0056 决策 9、决策 13 中“不做 microcompact，因为正文不进窗口”的条款；
ADR-0056 的提示词分层、通知通道、刷新点与恢复规则继续有效。
ADR-0037 的用量计量继续有效。本文不代表实现已完成，不提前修改旧 ADR 的状态。

## 日期

2026-09-17

## 背景

### 当前实现与设计前提的差距

`tools/result_storage.py` 已经实现单条结果超过 `min(tool.max_result_size_chars, 50000)`
时落盘，返回前 2000 字节预览与路径；未超限的结果仍然全文内联，Read 声明无穷上限，
通过自身读取预算限制输出。因此，“超长结果会落盘”不等于“窗口没有旧正文可清”。
多个各自未超限的并行结果，也可能在一次请求中合计占用大量上下文。

`conversation/window_manager.py` 目前按整条请求估算 token，撞高水位后在合法工具配对
边界淘汰，并由 `summarize.py` 生成交接摘要。缺少的是新结果合计预算、缓存感知的旧结果
清理，以及对这些变化的稳定回放。每次调用都重写旧消息会破坏前缀缓存，只等整段摘要又
会让可重新读取的工具正文长期占用窗口。

### Claude Code 的可确认机制

以本地 `claude-code-analysis` 源码为依据，不把实验分支视为所有发行版本的默认行为：

| 机制 | 可确认行为 | 源码位置（相对参考仓库 `src/`） |
|---|---|---|
| 调用前整理 | compact boundary → 结果合计预算 → 可选 snip → microcompact → 可选 collapse → autocompact | `query.ts` |
| 新结果预算 | 同一 API user 消息默认 200000 字符；优先将最大的新结果落盘；历史替换决定冻结 | `utils/toolResultStorage.ts`、`constants/toolLimits.ts` |
| 时间触发清理 | 默认关闭；配置默认间隔 60 分钟、保留最近 5 个；旧工具结果正文替换为占位符 | `services/compact/microCompact.ts`、`timeBasedMCConfig.ts` |
| 自动摘要 | 有效窗口减 13000 token 为默认阈值；有效窗口预留 `min(max_output, 20000)` | `services/compact/autoCompact.ts` |
| 手动摘要 | `/compact [instructions]`；无自定义说明时优先尝试已有 Session Memory | `commands/compact/compact.ts` |
| 会话摘要复用 | 等待进行中的提取，按已覆盖消息边界复用摘要，保留未覆盖尾部和完整工具配对 | `services/compact/sessionMemoryCompact.ts` |

本地缺少 `cachedMicrocompact.ts`、`snipCompact.ts` 和 `contextCollapse/` 的实现。
只能确认其调用入口，不据此规定阈值或复制未知算法。传统 `compactConversation` 与
Session Memory 压缩也不具有完全相同的尾部保留行为；下面的统一规则是 Forge 的选择。

## 决策

### 1. 每次请求检查，条件满足才变更

主 Agent 的每次模型调用前执行以下顺序，包括同一用户回合中的工具循环：

1. 从最近一次已提交的 compact boundary 建立有效窗口，回放已记录的内容替换。
2. 对尚未发送的新工具结果执行单条与同批合计预算。
3. 检查时间触发的旧工具结果清理；没有满足条件就原样返回。
4. 加入本次应发送的通知，按最终请求的 system、tools、messages 重新估算预算。
5. 达到自动压缩条件时尝试 Session Memory 复用或传统摘要。
6. 重建必要通知与会话段，再次检查最终请求预算，通过后调用 LLM。

单条落盘仍发生在工具结果生成时；调用前只补合计检查，避免对同一正文重复落盘。
轻量裁剪不调 LLM，不是每次检查都要减少内容。底层网络重试复用同一请求，
不在每次 HTTP 重试时重新裁剪或发起摘要。

`WindowManager` 负责窗口判断与变换，返回消息视图、变换草稿和用量草稿；
`AgentTurnService` 负责持久化、材料读取和刷新。Agent loop 不直接读取记忆、文件或配置。
compact、session_memory、memory_extract 等内部调用不递归启动这些后台任务。

### 2. 新工具结果按 API 消息分组控制体积

沿用单条 50000 字符上限与 2000 字节预览，增加同批默认 200000 字符合计预算。
这两个字符限制用于防止异常大输出；最终是否放得下仍由 token 预算判断。

- 分组与 adapter 最终合并消息的语义一致：一次 assistant 的并行工具结果算一组，
  不能因为内部拆成多条消息就分别规避预算。
- 只对首次发送的新结果作决定，按正文大小降序落盘，直到候选合计降到预算内。
  替换后按真实预览长度复算；不能只减原文长度就宣称达标。
- 结果替换为稳定的路径、大小、预览；保留工具名、调用 ID、成功/错误状态和必要结构。
- Read 的无穷上限声明继续豁免通用落盘，避免“读取 → 落盘 → 再读取”的循环。
  含图片等非文本块的结果不直接套用文本落盘；其实际体积仍进入总 token 预算。
- 落盘失败保留原结果并标记失败，再由总预算决定是否压缩或暂停，不生成失效路径。

按 `tool_call_id` 记录 seen 状态和精确 replacement 文本。已发送结果的决定不再变化；
后续调用和恢复直接复用记录。模型已经看过的旧结果不为满足本次合计预算而重新截短。
若已有结果或豁免结果使请求仍然超限，转入正式预算处理，不谎报“已满足上限”。

### 3. 旧结果清理以缓存状态和时间为条件

增加可配置的 time-based microcompact，首版默认关闭，候选配置为间隔 60 分钟、保留
最近 5 个可清理结果。只检查主会话；内部摘要、提取和上下文查看命令不触发。

供应商支持缓存时，等待间隔至少覆盖其已知 TTL；TTL 未知时不宣称缓存已失效，默认
跳过时间清理。显式配置可以选择承担缓存失效成本，日志记录该选择。
不支持缓存的供应商也只按明确配置触发，不自动退化成“每次调用都清”。

候选为 Read、Bash、Grep、Glob、Edit、Write 等可重新获取正文的工具结果；后续增加
Web 工具时显式登记。不清普通用户文本、助手文本、工具入参、未配对调用、人工回答、
当前任务约束和未决交互。排除豁免项后保留最近 N 个实际结果，N 至少为 1。

其余候选只替换 `tool_result` 正文为明确的“旧结果正文已清理”占位，保留 ID 和状态。
已有可读取的落盘引用保留引用；没有保存的正文不承诺可通过路径找回，必要时重新执行
只读查询。文件编辑前仍需按文件状态校验规则重新读取，清理不构成写入授权。

清理发生在请求视图，不覆盖原始 transcript。记录被替换 ID、原因、占位文本和窗口
版本，使恢复得到相同视图。这是对 ADR-0056“绝不改写已发送窗口”的有限修订：
热缓存期间保持稳定，仅在明确清理点创建新视图并记录预期缓存变化。

首版不实现供应商专用 `cache_edits`、未知 snip 或 context collapse。以后增加时由
adapter 声明支持，并另行规定服务端与本地视图的一致性，不能向通用 API 发送专用字段。

### 4. 自动压缩按完整请求预算触发

沿用 Forge `ContextBudget` 的现有策略，参数集中配置：

```text
allowance = context_window - reserved_output_tokens
high_water = min(effective_context_tokens（若已知）, allowance × compact_ratio)
low_water = high_water × low_water_ratio

初始 compact_ratio = 0.80；low_water_ratio = 0.40
```

窗口未知时不猜测容量并主动丢弃历史；输出预留非法或不可满足时返回配置/预算错误。
`effective_context_tokens` 只能来自模型配置或验证结果，不推断所有模型都有统一的
“可靠注意力长度”。Claude 的 13000/20000 是参考实现参数，不直接移植到多供应商 Forge。

估算包含 system、工具 schema、用户与助手历史、工具调用参数、结果、通知和多模态
占用；能取得供应商输入计数时用于校准。命中缓存的 token 仍占上下文，不能从容量扣除。
字符启发式不保证永远高估，必须保留供应商溢出后的处理路径。

轻量处理后达到高水位才自动 compact。目标是低水位，若受必要尾部与通知限制无法达到，
明确记录实际值；最终超过 allowance 就暂停为 `CONTEXT_COMPACTION_REQUIRED`。
摘要请求自身按所选模型单独计算输入、输出和指令预算，不能假设历史子集一定放得下。

### 5. 自动和手动共用压缩提交路径

自动触发且有有效 Session Memory 时先复用已有摘要；`/compact` 不带自定义要求时也
可走此路径。有自定义要求的 `/compact [instructions]` 直接生成对应摘要。
Session Memory 缺失、过期或覆盖边界无效时退回传统摘要，不临时强制先提取一次记忆。

手动调用跳过高水位判断。摘要只允许处理合法配对边界以前的历史；保留当前用户请求、
尚未完成的工具链与人工交互，保留近期消息。压缩摘要包含任务、约束、已完成工作、
证据、失败尝试、待办与下一步，历史用户关键约束另按预算逐字保留。

候选结果形状为：

```text
compact boundary 元数据
历史摘要（明确标注模型生成）与必要用户原话
未被摘要覆盖/必须保留的近期消息
当前状态通知
```

边界记录来源窗口版本、覆盖消息 ID、摘要版本和 trigger（auto/manual/overflow）。
摘要及替换内容完整落盘。先生成候选、验证配对、复算预算，再提交新窗口；空摘要、
取消、落盘失败或未达到有效缩减时保留原窗口，不先删历史再等待模型补摘要。

`/summary` 仅更新会话记忆，不剪掉历史，定义见 ADR-0061。正式 compact 不触发长期
记忆提取，也不把历史摘要升格成权限、用户指令或系统策略。

### 6. 压缩后重建状态，但重注入也必须服从预算

沿用 ADR-0056 的会话段刷新与通知通道，按运行时事实恢复当前模式、计划、待办、
必要的工具目录变化，再按剩余预算补最近读取文件。未来实现 skill/MCP/agent 后才增加
对应通知，不为不存在的功能预建注入内容。

最近文件最多 5 个、单个最多 5000 token；同时受剩余总预算限制。5 个各 5000 的实际
理论上限是 25000 token，不把参考实现的另一个合计上限误当成必须预留的额度。
可选文件正文可降为路径/短预览，不能让重注入马上再次触发同一轮自动压缩。

刷新使用权威运行态，不从摘要推断当前模式或权限。刷新后的 system 和全部通知都进入
最终容量检查。不会因为摘要声称“已经获批”就恢复某项授权。

### 7. 溢出恢复与失败熔断有界

供应商返回上下文超限时，即使本地估算未超高水位，也允许一次强制整理并重试模型请求。
模型/权限/凭证错误不归类为上下文溢出。未产生更小合法视图时不原样重复请求。

同一主请求链连续自动压缩失败达到 3 次后停止自动尝试，返回可恢复暂停；成功后清零。
手动 `/compact` 可在失败后重试，但不清除失败事实。摘要或记忆提取调用不再启动自动
摘要，避免递归消耗。上下文变更失败和模型请求失败分别记因，便于恢复和排查。

### 8. 恢复、缓存与费用使用同一事实记录

原始 transcript、有效窗口和请求视图分别有清晰身份：原始记录保留发生过什么；
压缩边界与替换记录决定发什么；UI 可继续显示原始历史，不据此推断模型仍能看见全文。
恢复读取最后完整提交的变换，忽略未完成候选，已有 replacement 保持字节相同。

工具输出文件按会话资源生命周期管理，不在仍有有效引用时独立回收；文件确实缺失时
返回“历史正文不可用”，不伪造空结果。请求清理本身不等于删除磁盘原件。

日志记录触发原因、命中阶段、工具结果数、输入估算前后、摘要版本和预期缓存失效，
默认不记录原文。轻量裁剪产生变换事件但没有模型用量；传统摘要的输入/输出/缓存用量
沿用 ADR-0037，含空摘要和失败前已产生的用量。复用 Session Memory 不重复计费，
生成该记忆的费用已由 ADR-0061 单独记录。

## 备选方案

- 只限制单条工具结果，撞水位再摘要：实现最少，但不能限制并行结果合计和旧正文积累。
- 每次都按新旧或重要性裁剪历史：能及时缩短输入，但改变热缓存前缀且难以稳定回放。
- 直接复制 Claude 的缓存编辑和所有实验分支：可能减少缓存失效，但源码不完整且供应商
  协议不同，不能作为通用方案的前提。
- 只保留最终用户/助手文本：体积小，但丢失工具证据与失败信息，导致跨回合重复劳动。

## 影响

收益是以无模型调用的方式控制新增输出，在明确时机清理旧正文，并保留自动/手动摘要
作为上下文压力兜底。代价是增加少量会话级替换状态和恢复记录，清理后可能需要重读文件，
摘要仍然存在信息损失，后台会话记忆的费用也不会因后续复用而消失。

迁移分三步：先接新结果合计预算与稳定回放；再统一自动/手动压缩的候选提交、重注入与
用量路径；最后接 ADR-0061 会话记忆复用和默认关闭的时间清理。旧会话没有替换记录时
将既有结果冻结，只对新结果执行预算；没有会话记忆时保留传统摘要路径。
接受后同步 ADR-0056 相关条款及详细设计，不改其余提示词组装与权限架构。

## 验收标准

- 普通未超限请求不改消息正文、不发摘要调用；工具循环中的每次模型调用均有预算检查。
- 多个单条未超限的结果合计超限时，最大的新结果优先落盘，替换后再次测量；Read、
  图片结果及失败落盘走明确分支，仍参与总容量检查。
- 相同有效窗口重复组装和恢复后的 replacement 字节一致，历史 seen 结果不被重新裁剪。
- 时间清理关闭、TTL 未知或间隔不足时无变化；启用且满足条件时只清理候选旧正文，
  保留最近 N 个、原消息 ID、工具配对、人工输入和状态。
- 自动高水位、手动自定义 compact、已有 Session Memory 复用、供应商超限恢复都有用例。
- 摘要空白、取消、文件写入失败和边界失效不提交半成品窗口；连续失败可熔断、可手动恢复。
- system、tools、多模态、通知和压缩后重注入均计入最终预算；缓存 token 不从容量扣除。
- 接近容量上限时减少可选重注入，仍放不下则可恢复暂停，不无限摘要或静默删用户目标。
- UI 保留原始历史不影响请求裁剪；恢复可重放边界与替换，文件缺失有明确标记。
- 正式摘要费用含失败/空结果，轻量裁剪不记成 LLM 调用，复用摘要不重复记费用。
- 实现阶段同步设计文档并完成相关单元、集成及多供应商消息配对测试。
