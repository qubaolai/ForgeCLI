# ADR-0032: 采用预算驱动的上下文压缩与回合内内容去重

## 状态

Accepted (2026-08-25 实现)

## 日期

2026-08-24

## 背景

到 ADR-0031 为止, Forge 没有任何一处代码在管上下文长度. 这不是一个缺口, 是两个,
它们的失效方式完全不同, 而且互相掩盖.

### 1. 回合内溢出会直接打死这一轮, 且没有补救路径

`BuiltinAgentLoop._messages` 从 `context_package.messages` 起步
(`builtin_loop.py:290`), 之后每派发一次工具就追加一条 assistant 消息和一条 tool
result, 正文**全文内联**. 没有任何一处会在中途看一眼它有多长.

到了网关, `_pre_call_checks` 判 `estimated_input + expected_output >
context_window` 就抛 `ModelContextOverflowError`
(`default_gateway.py:817`). 循环把它当普通 `ModelGatewayError` 接住, `_stop(
MODEL_ERROR_BLOCKING)`, `AgentTurnService` 落一条 FAILED. **这一轮跑过的全部工作
就没了.**

这条边界比想象中近得多. `fs.read` 单次内联上限 16 KiB
(`fs_read.py:80`), 按 `ApproximateTokenEstimator` 的 4 字符/token 折约 4096
token. 用户没在 `llm.json` 里写 `context_window` 时默认取 32768
(`catalog_builder.py:34`). **读六七个文件就到顶.** 这不是长任务才碰得到的天花板,
是日常.

### 2. 回合之间彻底失忆

`AgentTurnService._remember_turn` (`agent_turn_service.py:488`) 只往 `_history`
里塞两条: 用户原文, 和最终回答文本. 本轮跑过的所有工具调用, 所有工具结果, 所有安全
裁决, 在 turn 边界**全部丢弃**. `_rebuild_transcript` (resume 路径) 同理, 只重放
成对文本.

后果不是崩溃, 是静默的质量塌陷: 第二轮模型不知道第一轮读过哪些文件, grep 出过什么,
哪条命令被拒过. 循环里那三道防打转的闸 (`_MAX_IDENTICAL_CALLS`,
`_MAX_BARREN_OBSERVATIONS`, `_MAX_BLOCKED_CALLS`) 拦的全是**回合内**的原地打转,
回合间的重复劳动一道都拦不住.

### 3. 两个缺陷互相掩盖

正因为第 2 条把历史砍成纯文本, 第 1 条才没有在多轮会话里更早爆. 反过来说,
**任何"让模型记住上一轮做过什么"的改动都会让溢出更早发生**. 所以这两件事不能分开
设计, 只能分开落地.

### 4. 零件早就冻好了, 只是没有生产方

| 零件 | 位置 | 状态 |
|---|---|---|
| `LoopStopReason.CONTEXT_COMPACTION_REQUIRED` | `domain/agent/stop.py:27` | 枚举值冻了, 分类为 `RESUMABLE_PAUSE`, 全库零生产方 |
| `RequestOrigin.COMPACT` / `SUMMARY` | `domain/model/origin.py` | 枚举值冻了, 零使用 |
| `ApproximateTokenEstimator` | `application/llm/gateway/token_estimator.py` | 已接线, 但只服务于网关的溢出预检 |
| `ArtifactStore` | `application/tools/artifact_store.py` | 超阈值输出已经落盘并只回填引用; 但 `read()` 全库零调用方, 落下去取不回来 |
| `path_state_token` | `application/tools/builtin/base.py:125` | ADR-0027 的执行前复核在用 |
| `last_compaction_event_id` | `docs/02-detailed-design.md:572` | 设计文档画过, `SessionSnapshot` 里没有 |

`docs/02-detailed-design.md` §6/§7 那份十字段 `ContextPackage` 加百分比预算的草稿,
写于 ADR-0018 的块结构与 ADR-0026 的 JSON 决策之前, **本 ADR 取代它**.

### 5. 一个顺带暴露的已有缺陷: artifact 永不回收

`FsArtifactStore` 按内容哈希寻址, 全文没有一处 `unlink`
(`infrastructure/tools/fs_artifact_store.py`). `~/.forge/state/artifacts/`
今天是**无限增长**的. 本 ADR 要往里写更多东西, 所以必须先把这个漏补上.

## 决策

### 决策 1: 压缩由循环发起, 由驱动方落盘

循环持有一个 `ContextManager` 端口 (上下文管理对外的**唯一**入口), 在每次
`_build_request` 之前调它一次. 预算经 `LoopInput` 带进去, **循环不认识
`ModelCatalogEntry`** —— `SIBLING_BANS` 已经禁了
`application.agent_loop -> application.llm.gateway.default_gateway`, 让循环去查
模型目录等于绕过那条禁令.

压缩不写事件. `ContextManager` 返回 `CompactionDraft`, 循环攒着, 由
`AgentTurnService` 统一落盘 —— **和 `usage_drafts` 完全同构**
(`agent_turn_service.py:176` 那段 `for draft in outcome.usage_drafts`).
这样 ADR-0010 那条"`AgentLoop` 不能写事件"仍然成立, 而循环获得了它需要的能力.

**本决策修订 ADR-0010 §设计细节里 `LoopAction.request_compaction?` 的草稿, 该字段
不实现.** 原草稿把压缩做成一个交给驱动方执行的意图, 而压缩发生在**一次模型调用
之前**, 走意图意味着循环要么把内部状态 (`_pending_calls`, `_tools_closed`, 三个
计数器) 全部交出去再重建, 要么让驱动方重启循环而丢掉这些状态 —— 而这些状态正是三道
防打转闸的全部依据. 端口调用不动它们.

`LoopStopReason.CONTEXT_COMPACTION_REQUIRED` 保留, 但含义收窄成**压缩之后仍然放不下**
的兜底停止 (例如单条工具结果本身就超过窗口). 网关的
`ModelContextOverflowError` 同样保留为最后一道兜底.

### 决策 2: 两级压缩, 先降级后摘要

**一级: 降级 (3 天内可回取, 无 LLM).**
把靠前的 tool result 正文换成一行引用: `[已归档 9f2c3a1b5e7d0446, 12.4 KB, 用
artifact.read 取回]`. 内容仍在 `ArtifactStore` 里; 取回路径见决策 6.2, 过期回收
见决策 6.1.

**二级: 摘要 (有损, 不可复现, 走 LLM).**
一级降到底仍然超预算时, 用 `RequestOrigin.COMPACT` 调一次模型, 把一批消息换成
一段结构化摘要.

顺序不可颠倒. 一级是确定性的, 可单测, 不花钱, 且 3 天内可逆; 二级引入不可复现性.
**能用一级解决的绝不用二级.**

一个前提: 一级要求内容有 artifact 文件可指. 今天只有**超**过 `max_inline_bytes`
的部分才会落盘, 内联的那 16 KiB 没有. 因此决策 6 把落盘规则改成**每次工具调用的
完整输出都落**, 内联与否只决定回填多少, 不决定存不存.

### 决策 3: 回合内内容去重

同一份**未变更**的内容, 在一次 transcript 里只出现一次全文.

去重键是 `(realpath, path_state_token)`. 第二次及以后的命中回一行引用:
`[与第 N 步读到的内容相同, 未变更]`.

**判据复用 `path_state_token` (`application/tools/builtin/base.py:125`), 不新造.**
它摘要 `exists / realpath / kind / is_symlink / link_target / file_identity /
size / mtime_ns / mode`, ADR-0027 的执行前复核已经在用同一个函数. 两套判据意味着
安全层说"没变"而去重层说"变了" (或者反过来), 而这种分歧不会报错.

**这里省的是 token, 不是 IO.** 文件照读, `stat` 照做 —— 省掉的是把同一份 16 KiB
再塞一遍进上下文. 明确不做"有缓存就不读文件"的免读复用: 读一次是几毫秒加一次已经
被 ADR-0024 快速放行的裁决, 省下的 IO 不值得换来一份可能陈旧的当前状态.

### 决策 4: 文件变更主动通知, 不等模型来问

`path_state_token` 不同时, **不是**去修改历史里那条旧记录 —— 那条记录陈述的是
"我在第 N 步读到的内容是 X", 这在此刻依然为真, 它是历史.

做两件事:

1. 正常读一次新内容, 全文回填.
2. 把旧的那条降级掉, 占位文本明写: `[第 N 步读到的内容已归档 9f2c3a1b5e7d0446;
   该文件此后被修改过]`.

第二条是**主动**的: 模型不需要想起来去问"这个文件变了吗". 而变更来源是谁并不重要 ——
也无法知道: `fs.apply_patch` 有 mutation 记录, `shell.run` 里的 `sed -i` 只能给出
`workspace_mutated=None` (`domain/tool/result.py` 明写"无法证明"), 人工 Shell 模式
Forge **有意**不捕获内容 (ADR-0017 §9), 用户在自己编辑器里改则完全观察不到.

**所以判据只能是使用时重新 `stat` 并比对, 不能是"谁改了就去失效".** 后一条路会漏掉
最后两行, 而漏掉是静默的.

### 决策 5: 去重不存表, 因此不需要失效钩子

**2026-08-25 实现时修订.** 本条原文是"去重表必须注册进 `ManualMutationBarrier`",
理由是屏障的注释写着*"任何想跨人工 Shell 复用事实的地方都可以拿 generation 当键"*.

实现时发现那个前提不成立: **去重根本不需要存表.** 判据的两个输入 —— 两条工具结果
各自记下的 `path_state_token` —— 都是它们**在自己执行的那一刻**算出来的, 而每次整理
都从 transcript 重新扫一遍. 人工 Shell 在两次读之间改了文件, 后一次读必然拿到不同的
token, 于是去重不命中, 变更通知照常发出.

无状态实现**靠构造**具备了屏障要提供的那个性质, 而不是靠记得注册. 反过来说, 注册一个
无表可清的钩子正是 ADR-0028 规则 C 说的不生效的安全阀 —— 读代码的人会以为这里有一道
闸, 而它什么都没关住.

**这条修订只对无状态实现成立.** 将来若为省一次 `stat` 而把 token 缓存起来, 屏障注册
立刻变成必需 —— 那时它守的是一份真实存在的旧事实.

### 决策 6: 工具输出全量落盘, 按最后引用时间过期回收

1. **每次工具调用的完整输出都写进 `ArtifactStore`**, 不再只写超阈值的部分.
   `max_inline_bytes` 从"存不存的开关"降级成"回填多少的开关".
2. **保持内容寻址**, 引用信息并进 artifact 文件本身: 每次被引用时 `touch` 一下,
   文件 mtime 就是"最后一次被引用的时间". 不另存 sidecar, 不记会话归属 ——
   归属需要时从 `events.jsonl` 里的 `artifact_id` 反查得到.
3. 启动时扫一遍 `~/.forge/state/artifacts/`, 删掉 mtime 早于 **3 天**的文件.
4. **归档只进 `ResultProvenance`, 不进 `ToolResult.artifacts`** (2026-08-25 实现时
   补充). 两者说的不是同一件事: `artifacts` 的意思是"你看到的输出被切了, 剩下的在
   这里", 它进审计 payload, 也进终端那行"N 个产物"; 而 `provenance.artifact_id` 的
   意思是"完整内容留了一份, 压缩时可以拿它顶替正文", 只有 `application/context`
   读它. 混为一谈的后果是读一个 20 行的文件也显示"1 个产物" —— 而用户看那个数字,
   要的正是"有没有东西被切掉"这个答案.

**不做引用计数, 也不挂在会话生命周期上.** 用户不会记得归档会话, 挂在"会话结束"上的
回收等于不回收. 而一份独立的 `artifacts/refs.json` 必须和 artifact 写入成对原子完成,
否则漏算会删掉还在用的文件, 多算会永远删不掉 —— 两种错都是静默的, 都得靠测试兜住.
把这份状态并进文件的 mtime, 那两类错根本不存在.

内容寻址仍然保留 (同一段输出被两个会话引用只占一份空间), 而 `touch` 让还在被用的
内容自动续期, 所以共享不会导致误删.

### 决策 6.1: 过了 3 天, 一级降级就是有损的

`FsArtifactStore.write` 在文件已存在时跳过写入, 所以 mtime 不会自己刷新 ——
决策 6 的 `touch` 是它唯一的续期来源. 反过来说, **超过 3 天没被碰过的内容会消失**,
而 transcript 里那条降级占位仍然指着它.

这个取舍是明确接受的: artifact 大多是一次文件读取的内容, 删了最多重读一次, 比让磁盘
无限涨好. 但有两类内容重读不回来, 必须说清楚:

- `shell.run` 的输出. 重跑 `pytest` 不等于取回三天前那次的输出, 而且重跑会再执行
  一次子进程.
- 已经被二级摘要吃掉的那一段原文.

因此:

1. 降级占位文本**区分两种状态**: 未过期的写"用 `artifact.read` 取回", 已回收的写
   "内容已过期回收". 让模型去取一个不存在的 id, 它拿回的是 `KeyError`, 而模型读不出
   这到底是"清理机制"还是"我 id 写错了" —— 后一种理解会让它反复重试.
2. `ArtifactStore.read` 对缺失 id 返回明确结论, 不把异常抛穿到循环.

### 决策 6.2: 新增 `artifact.read`, 这是一级降级唯一的取回路径

**没有它, 决策 2 的一级降级是句空话.** 今天 `ArtifactStore.read` 全库零调用方, 它的
docstring 写着"供 /artifact 查看", 而那个斜杠命令并不存在 —— 落盘的 artifact 只写不读.

模型也够不着. `build_protected_path_policy` 把 `state_dir()` 注册成
`ProtectedCategory.FORGE_STATE` 且 **`deny_read=True`**, 而
`application/security/analyzers/workspace_analyzer.py:67` 命中 `deny_read` 直接走
`result.denied(HARD_DENY_CREDENTIAL_ACCESS)`. 所以 `fs.read ~/.forge/state/artifacts/...`
与 `shell.run cat ...` 都是 **Hard Deny** —— 不是 ASK, 既不能批准, 也不能用 `/add-dir`
豁免 (`build_protected_path_policy` 的 docstring 明写豁免不适用于 Forge 自己的状态目录).

**这不只是"缺一个功能", 现状是负的.** `ToolResult.text` 已经在截断时告诉模型"完整内容
见产物 9f2c3a1b5e7d0446", 而模型追这个 id 的每一次尝试都撞 Hard Deny —— 按
`_MAX_BLOCKED_CALLS = 3`, 三次就把本轮的工具目录整个收掉. 一个取不到的引用比没有引用
更坏.

**工具形状照 `plan.read` 抄.** 那批工具的 `_spec` 注释
(`application/tools/builtin/planning_tools.py:78`) 已经把理由写清楚了:
`additionalProperties: False` 连同"没有路径字段", 构成这批工具目标集合在**机制上**
封闭的证明.

- 入参 `{artifact_id, offset?, limit?}`, `additionalProperties: False`,
  **没有路径字段**.
- `prepare()` 产出的 `ToolPlan` 不声明任何路径 target, 因此 `workspace_analyzer`
  没有东西可判. 这**不是绕过** Hard Deny, 是根本不产生受它管辖的路径.
- 能力闭集新增 `ARTIFACT_READ`, 不进 `MUTATING_CAPABILITIES`, 与 `PLAN_ONLY` 同侧 ——
  它读的是 Forge 自己的状态目录, 碰不到用户文件, 所以不触发审批. 按 ADR-0033 决策 9,
  这是增量扩词汇: `CAPABILITY_VOCABULARY_VERSION` 不升, 已有 `always` 规则不失效.
- `offset` / `limit` 同时解决"一份 32 MB 的 artifact 只能整份 `read_text` 读回内存".

**`artifact_id` 必须先校验 `^[0-9a-f]{16}$` 再进 `_path_of`.**

```python
def _path_of(self, artifact_id: str) -> Path:
    return self._root / artifact_id[:2] / f"{artifact_id}.txt"
```

传 `../../../../etc/passwd` 时 `[:2]` 是 `..`, 直接穿越出 artifacts 目录. **今天不可达**
(`read()` 零调用方, `write()` 的 id 是自己算的 sha256 截断), 但本决策一落地, 这个参数
就变成**模型可控**, 穿越随之可达 —— 而它绕开的恰好是上面那道 Hard Deny, 因为工具内部
走 `ArtifactStore`, 不经 `workspace_analyzer`. 上一条"目标集合在机制上封闭"的证明,
前提就是 id 不能表达路径.

`/artifact` 斜杠命令另外做, 供人排查时看完整内容. 它与模型那条路是两个通道, 不能互相
替代 —— 本 ADR 上一版把占位文本写成"用 `/artifact` 取回", 错的就是这一点.

### 决策 7: 回合间保留工具调用的结论行

`_remember_turn` 改成: 除了成对文本, 再为本轮每次工具调用追加一条**结论行**:

```
[第 3 步] fs.read src/main.py -> 读到 412 行 (art_9f2c)
[第 4 步] shell.run "pytest -q" -> 退出码 1, 3 个用例失败 (art_1a7e)
[第 5 步] fs.apply_patch src/main.py -> 已写入, 2 处改动
```

不保留全文: 全文进跨轮历史等于把决策 1 要防的溢出提前到第二轮. 结论行加 artifact
引用足以让模型知道"这件事做过, 结果是什么, 要细节自己去取".

结论行由 `ToolObservation` 派生, **不手写格式** —— ADR-0031 §背景第 3 条记过一次
手写副本漂移的教训.

### 决策 8: 压缩落成事件, resume 从最后一次压缩起重放

`events.jsonl` 是唯一真相源且 append-only, 而摘要是 LLM 产出的不可复现内容. 因此:

1. 新增 `EventType.CONTEXT_COMPACTED`. payload 记: 摘要正文, 覆盖的 event 区间
   (起止 `event_id`), 用的模型, 压缩级别, 压缩前后估算 token 数.
   摘要正文**进 payload 而不是留引用** —— 它是不可复现的, 引用的目标一旦丢失就
   永远重建不出来. 这与 ADR-0022 计划正文"只留引用"的取舍不同, 理由正是可复现性.
2. `SessionSnapshot` 加 `last_compaction_event_id`.
3. `_rebuild_transcript` 改为: 从最后一条 `CONTEXT_COMPACTED` 起重放, 之前的部分
   用该事件里的摘要顶替.
4. **原始事件一条不删.** 压缩只影响"重建出来的 transcript", 不影响审计. 排查时
   读全量 `events.jsonl` 仍然能看到当初发生的一切.

### 决策 9: `/compact`

手动触发一次二级压缩. 走已有的斜杠命令注册表, 落 `SLASH_COMMAND` 事件.

### 决策 10: 分层归属与模型可读正文

```
domain/context/          ContextBudget, CompactionDraft, DedupKey  (纯值对象)
application/context/     ContextManager (唯一入口), 降级器, 摘要器, 去重表
```

`application/context` 允许 import `application/tools` 的 `ArtifactStore` ——
它是一个 ABC 端口, 实现在 `infrastructure/tools`, 不违反任何现有禁令, 也不让
上下文管理认识任何具体工具实现.

压缩指令, 降级占位文本, "该文件此后被修改过"的通知文案, 结论行模板 —— 全部是模型
可读正文, 按 ADR-0031 进 `domain/prompt/text.py`, 受 `MAIN_AGENT_PROMPT_VERSION`
管辖, `check_prompt_text.py` 在 `make ci` 拦.

## 备选方案

- **只在网关溢出后补救**: 改动最小, 但请求已经组好了, 且要把一条今天是终止性的
  错误路径改成可恢复的, 循环的停止词汇会因此变得含糊.
- **按百分比给每类内容分配 token 预算** (旧详细设计 §6.2 的方案): 看着整齐, 但
  Forge 今天拿不到分类信息 —— transcript 里只有消息, 没有"这条属于文件片段还是
  工具结果"的标签. 要先造一套分类才能按类分配, 而分类本身没有别的消费方.
- **免读缓存 (命中就不读文件)**: 省 IO 不省 token, 而 token 才是稀缺的那一头;
  且要额外承担一致性风险.
- **按会话建 artifact 目录**: 回收简单, 但放弃内容寻址, 同一份大输出会存多份.
- **引用计数 + 会话结束时回收**: 精确, 不会误删还在用的内容, 但要维护一份必须与
  artifact 写入成对原子完成的计数文件, 且回收时机挂在用户几乎不会做的"归档会话"上.

## 影响

- 长回合不再因为读几个文件就整轮失败.
- 跨轮重复劳动显著减少, 但跨轮历史变长 —— 这是决策 1 必须先落地的原因.
- `~/.forge/state/artifacts/` 从无限增长变成 3 天过期回收; 但因为全量落盘, 活跃
  期间的占用会明显上升.
- 一级降级从"无损"变成"3 天内可回取". 超期后 `shell.run` 的历史输出不可再取回.
- `AgentTurnService` 与 `BuiltinAgentLoop` 各增加一个依赖. 压缩逻辑住在独立
  service 里, **不作为 `AgentTurnService` 的私有方法** —— ADR-0028 §背景第 5 条
  批评过 716 行的 `ToolRequestCoordinator`.
- 新增 `artifact.read` 工具与 `ARTIFACT_READ` 能力; 按 ADR-0033 决策 9 属增量扩词汇,
  `CAPABILITY_VOCABULARY_VERSION` 不升, 已有 `always` 规则不失效.
- 顺带修掉 `FsArtifactStore._path_of` 的路径穿越 —— 今天不可达, 但 `artifact.read`
  会让它变成模型可控.
- ADR-0010 的 `LoopAction.request_compaction?` 草稿作废.
- 决策 5 在实现时被推翻: 去重做成无状态之后, `ManualMutationBarrier` 上不新增钩子.
- 顺带删掉 `ContentPart.media_type` 与 `emit_text` 的同名参数 (ADR-0028 规则 C):
  它有值, 但全库没有消费方, 也没有任何调用方传过非默认值; 而 artifact 文件一律
  落 `.txt`, 类型信息没有去处. 决策 6 的全量落盘让这个字段更显眼 —— 每次工具调用
  都会写一次一个没人读的值.
- `docs/02-detailed-design.md` §6 由本 ADR 取代.

## 验收标准

- 一轮内连续读 20 个 16 KiB 文件不触发 `ModelContextOverflowError`.
- 同一文件在未变更的情况下被读两次, 第二次回填的是引用行而非全文.
- 文件在两次读取之间被外部进程修改, 第二次回填全文, 且旧那条的占位文本含变更提示.
- 同一份 transcript 反复整理, 第二次不再产生任何改写 (整理是幂等的).
- mtime 早于 3 天的 artifact 文件在启动扫描后被删除; 3 天内被引用过的不被删除.
- 取一个已被回收的 artifact id, 模型收到明确的"已过期回收"结论, 而不是 `KeyError`.
- `artifact.read` 取回一份被降级的内容, 全程不产生审批提示.
- `artifact.read` 传入含 `..`, 路径分隔符或非十六进制字符的 id 被 `PreparationError`
  拒绝, 且不触碰文件系统.
- `fs.read` 与 `shell.run cat` 指向 `~/.forge/state/artifacts/` 仍然是 Hard Deny.
- 一份 32 MB 的 artifact 能用 `offset` / `limit` 分段取回, 单次调用不整份读进内存.
- `/resume` 一段发生过压缩的会话, 重建出的 transcript 以摘要开头, 且原始
  `events.jsonl` 仍含全部原始事件.
- 压缩指令与占位文本全部位于 `domain/prompt/text.py`, `check_prompt_text.py` 通过.
- `make ci` 全绿.
