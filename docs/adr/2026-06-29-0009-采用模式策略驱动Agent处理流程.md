# ADR-0009：采用规则引擎 + 模式预设驱动 Agent 权限裁决

## 状态

Accepted（2026-07-22 修订：回归规则引擎定位，模式退为预设；对齐 Claude Code 权限模型）

## 日期

2026-06-29（2026-07-21、2026-07-22 多次修订）

## 背景

ForgeCLI 需要从 REPL 直接响应用户输入，演进为由 `AgentTurnService` 管理一次完整 Agent
turn。用户通过自然语言提出需求，Agent 根据当前权限决定应该解释、澄清、生成计划，还是
尝试执行改动。

权限不是简单的 UI 状态，而是 Agent 行为边界：它决定 Agent 在当前 turn 能做什么、不能做
什么、什么时候必须询问人类。LLM 或 `AgentLoop` 只产出候选动作，ForgeCLI 据当前规则裁决。

### 演进说明（2026-07-22）

权限裁决**一开始就应是一个规则引擎**；中途几版把"模式"当成了主结构、把高危拦截当成旁挂
的黑名单，偏离了这个定位。本版校正回来，并对齐 Claude Code 已经过实战的权限模型：

- **裁决核心是规则引擎**：`deny → ask → allow` 优先级，第一个匹配即决定；模式只是往
  allow 集预填内容的**预设**。规则引擎是**唯一的、可移植的主决策层**。
- **OS 用户权限（非 root）是永远在的外墙**，另有一道主动的执行前 deny 拦截。
- **叠加一层 Bash 沙箱做 containment**（决策 14）：对执行命令与模型生成的未知代码，在可用平台
  （macOS Seatbelt / Linux bubblewrap）内隔离执行；Windows 等无沙箱平台**回退到 rule-engine-
  only**。沙箱是互补的纵深防御，不作底座——正因如此，早前"平台相关、太复杂"的顾虑不再成立：
  没有沙箱就回退，可移植性不依赖它。资源以**绑定式**取自宿主（读广去机密、写限工作区、网络默认
  关），越界（联网 / 写区外）**升级为向用户的一次 ask**（on-failure escalation）。
- **补齐命令规范化**：复合命令拆解、进程包装器剥离、命令替换扫描——否则任何黑名单都能被
  `git status && rm -rf ~` 或 `echo "$(rm -rf ~)"` 一行绕过。
- **实现 glob 规则配置语法**（`Bash(npm run *)`、`Read(~/.ssh/**)`、gitignore 式路径锚定）：
  代码库扫描、按路径限制读写都要用到。
- git 写操作**不做硬性限制**，按普通命令走规则；MVP 工具仅内置，不接入 MCP。

## 决策

### 1. 模型只产出候选动作，`AgentTurnService` 是唯一裁决与执行边界

`AgentLoop` / LLM 只能产出候选动作：回复、生成计划、请求编辑文件、请求执行 shell、请求调用
工具、请求继续、请求用户补充信息。`AgentTurnService` 负责裁决、决定是否人类确认、调用
ToolRuntime 执行副作用、写 session events 与 state snapshot。`AgentLoop` 与 LLM provider
不得直接写文件、执行 shell、调用外部工具或写 `events.jsonl`。

规则由 ForgeCLI 强制执行，**不由模型执行**：提示词或 FORGE.md 只影响模型*尝试*什么，不改变
引擎*允许*什么。（这也意味着：用户想约束模型行为——例如"不要自动提交"——可以直接在对话或
项目记忆里说，模型大概率不会请求该动作；但这属于"影响尝试"，安全边界仍以规则为准。）

### 2. 外墙是 OS 用户权限；启动时拒绝 root

不引入沙箱。Agent 以调用者的**普通用户身份**运行，OS 权限挡住系统级灾难（写 `/etc`、
`mkfs`、崩溃系统、动别的用户文件——非 root 一律 Permission denied）。这堵墙免费、跨平台、
永远在。

但它有个洞：保护"系统"、不保护"用户自己的东西"（`rm -rf ~`、`rm -rf ./*` 你自己有权删）。
所以 OS 边界**必须叠加**规则引擎的 deny 拦截（决策 8），不能单独承担安全。可用平台上先在Bash 沙箱（决策 14）做 containment；不可用则只剩本层 + 规则引擎。三者纵深防御。

**整套模型的前提是"不以 root 运行"**：启动校验检测到 root / 管理员身份时**拒绝启动**（而非
降级）并说明原因（Windows 对应管理员提权检测）。一旦以 root 运行，外墙消失，无法再声称安全。

### 3. 裁决是一个规则引擎：`deny → ask → allow`，第一个匹配即决定

每个候选动作按固定优先级求值，**第一个匹配的规则决定结果，规则的具体程度不改变顺序**：

1. **deny**：命中即拒绝，先于一切。宽 deny 会盖过更具体的 allow（deny 不含允许例外）。
2. **ask**：命中即提示人类确认；即使更具体的 allow 也匹配同一动作，ask 仍提示。
3. **allow**：命中即免提示执行。
4. 都不匹配：落到**默认**，由当前模式决定（决策 6）——通常是 ask。

三类规则的来源：

- **deny**：内置高危拦截（决策 8）＋ 用户追加（决策 10 语法）；不可删除内置条目。
- **allow**：内置只读命令集（决策 5）＋ 学习式授权累积（决策 9）＋ 用户追加。
- **ask**：模式预设的默认档落在这里，也可由用户显式 ask 规则强制。

引擎的价值正在于优先级把各条规则统一起来。例：`accept_edits` 下 `rm test.tmp`（区内）命中
文件操作 allow → 执行；但 `rm -rf ~` 先命中高危 deny → 拒绝。同一个 `rm`，结果不同，靠的是
deny 高于 allow，而不是散落的 if 分支。

### 4. 规则匹配前必须规范化解析命令

字符串匹配天然可被组合绕过，规则**必须作用于解析后的结构**，不得对原始命令串做子串匹配：

- **复合命令拆解**：识别分隔符 `&&` `||` `;` `|` `|&` `&` 换行，拆成子命令，**每个独立裁决，
  整条取最严结果**。`git status && rm -rf ~` = [只读 allow, 高危 deny] → deny。
- **命令替换 / 进程替换扫描**：`$(...)`、反引号、`<(...)` 内部内容一并过 deny/ask。
  `echo "$(rm -rf ~)"` 中的删除照样被拦。
- **进程包装器剥离**：`timeout` `time` `nice` `nohup` `stdbuf`、以及无标志的 `xargs`，剥离后
  匹配内层。故 `timeout 30 npm test` 等同 `npm test`。
- **永远提示的 exec 包装器**：`watch` `setsid` `ionice` `flock`，以及带 `-exec` / `-delete`
  的 `find`——不能被前缀 allow 放行。
- **不剥离的环境运行器**：`npx` `docker exec` `devbox run` `mise exec` `direnv exec`——它们把
  参数当命令执行（`devbox run rm -rf .`），必须连内层命令一起匹配，外层前缀不授权内层。
- **安全环境前缀**：`LANG=C`、`NO_COLOR=1` 等只读环境变量前缀在匹配时可忽略。

解析不出结构时：高危 deny 不误伤也不硬拦（由 OS 外墙兜底），未知命令落默认 ask。

### 5. 内置规则集

- **deny（高危，所有模式）**：见决策 8。
- **allow（只读命令集，所有模式免提示）**：`ls cat echo pwd head tail grep find wc which
  diff stat du cd`，以及 git 只读形式 `status diff log show blame`。带写/执行能力标志的命令
  （`sed` `find` `sort` `git` 写形式）在出现**未加引号的 glob** 时仍 ask（glob 可能展开成
  `-delete` 一类）。此集合不可通过配置放宽为更少提示，只能加 ask/deny 收紧。
- **allow（文件操作命令集）**：`mkdir touch rm rmdir mv cp sed`——**仅 `accept_edits` 起、
  且路径在工作区内、非受保护路径**时自动放行（它们的效果等同文件编辑工具）。命中高危 deny
  的（如 `rm -rf ~`）仍被拦，因为 deny 优先级更高。
- **默认 ask**：其余一切，由模式调节。

### 6. 四个模式是规则引擎的预设

模式不表达隔离级别，只决定**默认往 allow 集预填什么**；deny 与 ask 规则横切所有模式。
默认 `accept_edits`。

| 模式 | 在只读集之上追加的 allow | 默认（未匹配动作） |
| --- | --- | --- |
| `plan` | 无（写/执行工具经能力门不进 `tool_catalog`） | —（只读之外都不暴露） |
| `accept_edits`（默认） | 区内文件编辑 ＋ 文件操作命令集 | ask |
| `auto` | 追加：命令执行（测试 / 构建 / 脚本 / git 写等） | ask（动工作区外仍 ask） |
| `full_access` | 追加：动工作区外 | ask（仅高危 deny 兜底） |

- **`accept_edits`（默认）**：文件编辑与文件操作命令（mkdir/touch/rm/mv/cp/sed，区内）自动，
  **python / 其他 shell / `git commit` 等仍逐条询问**（它们不在文件操作集里，落默认 ask）。
- **`auto`**：追加放行命令执行，**含 git 写**（commit/push 等按普通命令走，不再特殊拦截）。
  区别只在动工作区外仍 ask。若用户不想让它自动提交，直接在对话里告知即可（决策 1）。
- **`full_access`**：再放行动工作区外，只剩 OS 非 root 与高危 deny 兜底；不是"全放行"。
- 升到 `auto` / `full_access` 是用户的明确授权。ForgeCLI **不做 CC 那样的分类器模型**逐操作
  审查（需逐次模型调用），auto 是纯规则裁决——更可预测，但不"懂请求范围"。这是 MVP 取舍。
- **`chat` 退役**：诉求由 `plan` 覆盖。`/chat` 改名为 `accept_edits`。`SessionMode` 取值
  `PLAN` / `ACCEPT_EDITS` / `AUTO` / `FULL_ACCESS`。

### 7. 能力门优先于裁决门

- **能力门**：动作在当前模式下**是否存在**——作用于 `LoopInput.tool_catalog`（ADR-0010 §4.1）。
  `plan` 下写/执行工具根本不进模型的工具清单。裸工具名 deny 也从上下文移除该工具。
- **裁决门**：存在的动作走决策 3 的规则引擎。

让模型看不见一个工具，比让它提议后再拒绝有效：不会反复尝试、不浪费 turn、不与用户争辩。

### 8. deny 清单：命令黑名单 + 目录黑名单，任何模式一律拒绝

主动的执行前 deny 闸门，不把危险操作完全交给 OS。命中即拒绝（选择 A：`deny` 而非 CC 的
ask 断路器），`full_access` 也不豁免，配置只允许**追加**、不允许删内置条目。

#### 8.1 命令黑名单（含等价变形）

- 递归 / 强制删除危险目标：`rm -rf|-r|-f` 目标为 `/`、`~`、`$HOME`、`.`、`./*`、`*`、`..`、
  工作区根、或任意工作区外绝对路径。（`rm -rf ./明确子目录` 不在此列。）
- 磁盘 / 设备写入、格式化、擦除：`mkfs*`、`dd of=/dev/*`、写块设备、`shred`、`wipefs`、
  `fdisk`/`parted` 破坏性子命令。
- 权限 / 属主大范围修改：`chmod` / `chown` 带 `-R` 且目标为 `/`、`~`、系统路径。
- 资源耗尽：fork bomb（`:(){ :|:& };:` 等）。
- 从网络管道直接执行：`curl ... | sh`、`wget ... | bash`、`... | bash -`。
- 覆盖 / 重定向到 8.2 受保护路径的 `>` `>>` `tee` `dd`。

注：git 写命令（`reset --hard`、`clean -fd`、`push --force` 等）**不进 deny**——git 写不做
硬性限制，按普通命令走模式规则（决策 6）。

#### 8.2 目录 / 文件黑名单（写 / 删一律拒绝）

重点是**写入即导致后续代码执行**或**泄露/篡改凭证**的路径，不只是"敏感数据"：

- **系统路径**：`/`、`/etc`、`/usr`、`/bin`、`/sbin`、`/boot`、`/sys`、`/dev`、`/lib`。
- **VCS / 钩子（写=埋雷）**：`.git`（尤其 `.git/hooks`）、`.gitconfig`、`.gitmodules`、
  `.husky`、`.pre-commit-config.yaml`、`lefthook.*`。
- **包管理 / 构建（可跑脚本）**：`.npmrc`、`.yarnrc`、`.yarnrc.yml`、`.pnpmfile.cjs`、
  `bunfig.toml`、`gradle-wrapper.properties`、`maven-wrapper.properties`、`.bazelrc`。
- **编辑器 / 容器 / 工具配置**：`.vscode`、`.idea`、`.devcontainer`、`.devcontainer.json`、
  `.ripgreprc`、`pyrightconfig.json`。
- **凭证 / shell 启动文件**：`~/.ssh`、`~/.aws`、`~/.gnupg`、`~/.config`、`~/.kube`、
  `.bashrc`、`.zshrc`、`.profile`、`.envrc` 等。
- **ForgeCLI 自身**：`.forge/`、`events.jsonl`、`state.json`、锁文件。

注意：写 `.git/hooks` 被拦，但普通 git 写命令（commit/push）不拦——前者是"埋可执行的雷"，
后者是正常版本库操作。二者不同。

`full_access` 可跨工作区写，但上述受保护路径仍拦——这是高危 deny 穿透所有模式的体现，也是
"full_access = OS 边界 + 高危拦截"而非"无限制"的准确含义。

#### 8.3 工程约束

- **主动闸门 + OS 外墙两道叠加**：能被变量/编码绕过的部分由 OS 非 root 承接，二者不替代。
- 命中转 observation 交回循环并写 `policy_denied` 事件；关键路径堵死才以
  `LoopStopReason.POLICY_DENIED` 停止本轮。
- 清单必须有单元测试，用例含等价变形（空格、引号、`~` 展开、绝对/相对路径、复合命令、
  `$(...)` 替换内部）。

### 9. 学习式授权：ask 的结果累积成 allow

命中 ask 的动作首次询问，用户选 `once` / `always` / `session` / `deny`（缓解提示疲劳）：

- 归一化键 = `可执行文件 + 第一个子命令`（`npm test`、`git status`、`tree`）。参数不进键，
  但仍须过 deny 与规范化解析（决策 4）。复合命令为每个需批准的子命令各存一条。
- `once`：仅本次；`always`：写项目级配置，落成一条决策 10 语法的 allow 规则（如
  `Bash(npm test *)`；文件路径转义字面量）；`session`：本会话不再问、**只存进程内存**不落盘；
  `deny`：拒绝并转 observation。
- `approval_resolved` 事件记录 scope，供审计与 resume。
- 不采用预先枚举的静态命令白名单（太紧：装新工具就改配置；太松：`npm test` 即任意脚本）。
  允许从 `pyproject.toml` / `package.json` / `Makefile` 探测种子 allow 改善开箱，它是预填的
  allow、不是闸门。

### 10. 规则配置语法：glob 模式与 gitignore 式路径锚定

规则遵循 `Tool` 或 `Tool(说明符)`，喂入决策 3 的引擎。**MVP 即实现**——代码库扫描、按路径限制
读写（如允许读 `src/**` 但拒读 `~/.ssh/**`）都需要它，不缓到后续。

**Bash 命令模式**（`*` 可在任意位置）：

- `Bash(npm run build)` 精确匹配；`Bash(npm run *)` 前缀。空格前的 `*` 强制词边界：`Bash(ls *)`
  匹配 `ls -la` 不匹配 `lsof`；`Bash(ls*)` 两者都匹配。
- `Bash(git * main)` 跨参数匹配；`:*` 后缀等同尾部 ` *`（`Bash(ls:*)` = `Bash(ls *)`）。
- 匹配前先经决策 4 规范化（复合拆解、包装器剥离、替换扫描），规则须匹配每个子命令。裸
  `Bash` deny 从上下文移除工具，`Bash(rm *)` 保留工具但拦匹配调用。

**文件路径模式**（Read/Edit，遵循 gitignore 语义，`*` 匹配单段、`**` 跨目录）：

| 前缀 | 含义 | 例 |
| --- | --- | --- |
| `//path` | 文件系统根绝对路径 | `Read(//etc/**)` |
| `~/path` | 主目录相对 | `Read(~/.ssh/**)` |
| `/path` | 相对于**设置源**（项目根 / 用户配置目录），**非**文件系统根 | `Edit(/src/**)` |
| `path`、`./path` | 当前工作目录相对 | `Read(*.env)` |

裸文件名在任意深度匹配（`Read(.env)` ≡ `Read(**/.env)`）。symlink 检查链接与目标两条路径：
allow 需两者都过，deny 命中任一即拦。

这些规则一并进 deny→ask→allow 引擎；MCP、WebFetch、PowerShell 等工具的规则在**引入对应工具
时**按同一 `Tool(说明符)` 形式补齐（MVP 无这些工具）。

### 11. 工作区边界：文件工具可强制，shell 有沙箱则强制、无沙箱尽力而为；出区读写都裁决

- **结构化文件工具：可强制。** `realpath` 后检查是否落在工作区前缀内，防 `..`、symlink、
  hardlink 逃逸。区外**写**：`accept_edits`/`auto` ask、`full_access` allow。区外**读**（含
  Grep/Glob/`@file`）：ask——防止模型自由读 `~/.ssh/id_rsa`、`/etc/passwd` 并喂进上下文。
  `--add-dir` / `/add-dir` 追加的目录等同工作区内。用户也可用决策 10 的路径规则精确放宽/收紧
  （如 `Read(../sibling-lib/**)` allow）。
- **shell 命令：有沙箱则可强制，无沙箱只能尽力而为。**
  - **有沙箱（决策 14，macOS/Linux）**：shell 及其子进程被 OS 级限制在工作区文件系统内、默认
    断网。`cd /`、变量拼路径、Python/Node 脚本写区外都被 OS 阻断——**这道边界是真的**。
  - **无沙箱（Windows / 未装 bwrap）**：只能静态尽力而为（拦明显的区外绝对路径、`cd` 区外），
    拦不住则跑，由 OS 外墙与高危 deny 兜底。

**无沙箱时不得声称 shell 动作被硬限制在工作区内**——声称给不出的保证比不声称更危险。（无沙箱
时这与 CC 一致：其 Read/Edit deny 也不覆盖 Python/Node 脚本这类任意子进程，需靠沙箱。）

### 12. `auto` / `full_access` 的定位与无人值守

语义是**明确授权的自主执行**。进入时明确提示边界：`auto` 自动执行命令（含 git 写），但动
工作区外仍问；`full_access` 连动工作区外也自动，只剩 OS 非 root 与高危 deny 兜底、以你的凭证
行事。审批超时不得无限阻塞：转 observation 交回循环，告知模型未获批准、可换做法或跳过，收尾
列出被跳过的动作。`auto` / `full_access` 预算按**任务**而非 turn 计算，耗尽为可续跑暂停
（对应 ADR-0010 §12）。

### 13. 模式与内置规则是代码级常量；配置只能收紧

四个模式的预设、能力门、内置 deny/allow 定义写在代码里，不是配置项。用户可配置的只有：学习式
授权累积的 allow、以及用决策 10 语法追加的 allow/ask/deny 规则。

**配置只能收紧、不能放宽内置边界**：不允许让 `plan` 执行 shell、移除内置 deny、关闭 root 校验。
设置优先级遵循 **deny 恒压过 allow**——任一层 deny，其他层无法放行（对齐 CC 的托管设置语义，
为将来的企业/团队策略预留同一模型）。用户 allow 规则可以放行"默认会 ask"的动作（这正是 glob
allow 的用途），但不能放行内置 deny 覆盖的动作。

### 14. Bash 沙箱：可用平台的互补 containment 层

在 OS 非 root 外墙（决策 2）与规则引擎（决策 3）之上，再叠加一层 OS 级沙箱，对**执行命令与
模型生成的未知代码**做 containment。定位是**互补的纵深防御，不作底座**：规则引擎仍是唯一的、
可移植的主决策层，决定 allow/ask/deny；沙箱只限制"真正跑起来的东西"能碰到什么。

**资源来自宿主（绑定式，非空盒）**：沙箱不是从零起的新系统，而是把宿主机的资源**绑定**进来，
这正是 `pytest` / `npm test` 能跑起来的原因——盒内要能看到宿主的 `python`/`node`/`git` 二进制、
系统库、语言工具链。这是 Seatbelt/bwrap 的原生工作方式（启动时设定的静态策略），**不是运行时
向宿主 IPC 请求资源的 broker**（Flatpak portals 那种自建盒外 broker 的方案过重，不采用）。

**沙箱边界策略**：

- **读：广，去机密。** 系统路径、语言库、工具链（含 `~/.cargo`、`~/.pyenv`、`~/.nvm` 等 home
  下的工具链/缓存）可读；但决策 8.2 的机密路径（`~/.ssh`、`~/.aws`、`~/.gnupg`、`.env` 等）
  **deny-read**——不能简单"禁掉整个 home"，否则工具链失效。
- **写：限工作区。** 仅工作区（＋ `--add-dir` 目录）与每会话私有临时目录可写；写区外被 OS 级
  阻断。
- **执行：** 可读即可执行，解释器/二进制正常运行。
- **网络：默认关闭。** 断掉"顺手把代码传出去"。
- 这些边界与规则引擎的 Read/Edit deny、路径 allow 规则**合并**成最终边界（对齐 CC）。

**平台实现（读策略作者方式相反，效果一致）**：

- macOS：Seatbelt（`sandbox-exec` profile）——默认全部可见、`deny` 特定路径，天然**黑名单**，
  "广读去机密"很自然。
- Linux：bubblewrap（`bwrap`，namespaces）——默认空、`--ro-bind` 进来才可见，天然**白名单**，
  广读用 `--ro-bind / /` 再以 tmpfs 盖住 home 机密；`--unshare-net` 断网。
- Windows / 无可用沙箱（如未装 bwrap）：**回退到 rule-engine-only**——只靠决策 3 规则 + OS 非
  root，无 containment。启动时探测沙箱可用性，不可用则明确提示"当前无执行隔离"。

**越界升级为 ask（on-failure escalation，已转正为正式机制）**：这是 `auto` 的"允许命令"如何
安全落地的机制——命令在盒内正常跑、不预先询问；当它**撞到沙箱边界**（要联网、要写工作区外）
而失败时，把这次"越界请求"**升级为向用户的一次 ask**（"该命令需要联网，放行吗？"）。这就是
"沙箱内资源向宿主请求"的落地形态——请求对象是**人**，不是自动 broker。三个作用：bash 能跑
测试（盒内够用）、要越界才打扰、分类判错的代价从"执行了坏事"降到"多问一次"。

**与决策 6 模式梯度的衔接（escalation 只作用于 allow，不覆盖 ask）**：

- `accept_edits`：命令仍按决策 6 **执行前询问**——它的定义就是"下命令前先确认"；批准后命令在
  盒内运行（纵深防御）。escalation 不改变这一档。
- `auto`：命令的"allow"= **盒内直接跑、撞边界才 escalation 升级为 ask**。这正是 `auto` 区别于
  `accept_edits` 的实现：前者"先批准再跑"，后者"盒内自主跑、逃出盒子才问"。
- `full_access`：**预先授权逃出沙箱**（联网、跨工作区），越界不再询问。
- `plan`：只读，命令不执行。

这样四档仍是清晰梯度，沙箱不把 `accept_edits` 塌缩进 `auto`。

**执行流水线（顺序固定，不可颠倒）**：规则引擎与沙箱不是"二选一"，而是**引擎先决策、沙箱再
containment**，一条命令按下述顺序处理：

```text
命令
 └─ 1. 规范化解析（决策 4：复合拆解 / 包装器剥离 / $(...) 替换扫描）
 └─ 2. 规则引擎裁决（决策 3：deny → ask → allow）
        ├─ deny  → 拒绝，根本不进沙箱（转 observation + policy_denied）
        ├─ ask   → 提示人类；拒则停，允则进 3
        └─ allow → 进 3
 └─ 3. 在沙箱内执行（决策 14：读广去机密 / 写限工作区 / 网络关）
        └─ 撞边界（联网 / 写区外）
              └─ 4. escalation：升级为一次 ask
                     ├─ 允 → 放宽该次越界，继续
                     └─ 拒 → 中止该命令，转 observation
```

**为什么顺序不能反（不能"先沙箱、引擎兜底"）**：沙箱允许写工作区，所以 `rm -rf ./*`、往
`.git/hooks` 埋雷、fork bomb 这些**在盒内照样发生**——挡它们的是第 2 步的 deny，不是沙箱。若把
沙箱放前面、引擎当兜底，这些会被放行。deny 必须在命令**进入沙箱之前**先拦掉。

**两层的分工（纵深防御，各自正确）**：

- 引擎回答"要不要做、要不要问"（决策层）；沙箱回答"做了之后能碰到什么"（containment 层）。
- deny 规则在进入沙箱前就拦（高危一律 deny，连沙箱都不进）；显式 ask 规则照旧提示。
- 沙箱是"即使规则判漏、或 prompt injection 骗过模型，跑起来的代码也逃不出盒子"这一层。
- 沙箱只在"作用域"这一个判断上比字符串检查可靠，故决策 11 的工作区边界以沙箱为准、无沙箱
  才退回字符串尽力而为；但"是否高危、是否埋雷、要不要问"沙箱管不了，引擎不可被降级为兜底。
- **它让决策 11 的 shell 工作区边界从"尽力而为"变成"可强制"**——这是引入沙箱最大的收益。

## 附：与 Claude Code 权限模型的对照

本 ADR 对齐 CC 的规则引擎（deny→ask→allow、复合拆解、包装器、替换扫描、只读集、acceptEdits
文件命令集、受保护路径、glob 规则语法与 gitignore 路径锚定），差异点：

- `rm -rf ~` / `rm -rf /`：CC 用 ask 断路器（可批准）；本 ADR 用 **deny**（更硬，选择 A）。
- 沙箱：CC 与本 ADR 一致——可用平台（macOS Seatbelt / Linux bwrap）启用 Bash 沙箱做 containment，
  作互补层；Windows / 不可用时回退到 rule-engine-only（决策 14）。
- auto 分类器：CC 用模型逐操作审查；本 ADR 纯规则裁决。
- git 写：CC 的 acceptEdits 不放行、auto 走分类器；本 ADR **不做硬性限制**，git 写按普通命令
  走模式规则（accept_edits ask、auto/full_access allow）。
- MCP / WebFetch / PowerShell / 托管设置：CC 已支持；本 ADR MVP 无这些工具，规则语法在引入时
  按同一形式补齐。

## 备选方案

- 让 LLM 自行决定执行：破坏权限边界与可测试性，不采用。
- 以模式为主结构、高危拦截旁挂黑名单：偏离规则引擎定位，`A && rm -rf ~` 一类靠散落分支裁决
  易漏，回归规则引擎，不采用。
- 保留 `chat` / `ask` 独立模式：诉求与 `plan` / `accept_edits` 重复，徒增测试路径，不采用。
- 把 OS 沙箱作**底座**（无沙箱即无法交付）：平台相关（Windows 无等价物），会让可移植性依赖
  平台能力，不采用。改为**互补层 + 回退**（决策 14）：可用平台加固，不可用回退到 rule-engine-
  only。曾设计的可逆性风险矩阵不恢复；on-failure escalation 已作为沙箱的正式机制转正（决策 14）。
- 把危险操作完全交给 OS：OS 不拦 `rm -rf ~` / `rm -rf ./*`，必须叠加主动执行前 deny，不采用。
- `rm -rf ~` 用 ask 断路器（CC 做法）：本定位要求更硬的拒绝，采用 deny（选择 A）。
- **对 git 写做硬性限制（如 auto 下强制 ask）**：git 写属正常版本库操作，硬拦会逼用户为一次
  commit 退出 auto；不想自动提交的诉求可由对话约束模型尝试（决策 1），不采用。曾设想的"auto
  下 git 写 ask" 与自动 checkpoint 一并移除。
- **不实现 glob 规则语法（缓到 Alpha）**：代码库扫描、按路径限制读写在 MVP 就需要，采用 b2、
  MVP 即实现。
- **为 MCP 预留接入设计**：不实际接入的预览接口不稳定、易随上游变动，不如不预留；MVP 工具仅
  内置，MCP 待真正接入时再定，不采用预留。
- 以 root / sudo 运行：摧毁 OS 外墙前提，启动即拒绝。

## 影响

收益：

- 规则引擎统一了裁决：deny>ask>allow 优先级 + 命令规范化 + glob 语法，`A && rm -rf ~`、
  `$(rm -rf ~)`、`timeout rm -rf ~` 一类无法靠组合绕过，按路径的读写限制可精确表达。
- 可移植性不依赖平台：规则引擎 + OS 非 root 跨平台且永远在；沙箱是加固层，没有就回退，MVP 在
  任何平台都能交付。
- 沙箱纵深防御：可用平台上把 shell 工作区边界从"尽力而为"变成"OS 级可强制"，未知代码被隔离，
  即使 prompt injection 骗过模型也逃不出盒子。
- 模式退为预设，四档区别真实可测（命令问/跑、出区问/跑），单元测试可覆盖。
- 受保护路径覆盖"写入即执行"类配置（`.git/hooks`、`.npmrc`、pre-commit 等），堵住埋雷面。
- 面收窄：不接入 MCP、不特殊处理 git 写、无自动 checkpoint，实现更简单直接。

代价：

- 需要一个较完整的命令解析器 + glob 匹配器：复合拆解、包装器识别、替换扫描、gitignore 路径
  锚定、只读/文件操作/高危集匹配——是多条决策的共同前置件，须独立排期并有绕过用例测试。
- 沙箱要分平台实现（Seatbelt profile / bwrap 参数）并处理其不可用时的探测与回退；沙箱边界与
  规则路径需合并，两层交互要有测试。
- 安全性在无沙箱平台显式依赖"不以 root 运行"，须有可靠启动校验并向用户说明。
- git 写不硬限 + 无自动 checkpoint：`auto`/`full_access` 下 `git reset --hard` 会丢失未提交
  改动、`git push` 会真的推送——是这两档知情授权语义下的取舍，须在用户文档写明。
- OS 边界不保护用户自有数据（`full_access` 下 `rm -rf ~/其他项目` 会执行，除非命中高危 deny）。
- 无分类器：auto 不能像 CC 那样按"是否超出你的请求范围"审查，只按规则；换取可预测与零额外
  模型调用。

兼容性：

- `/plan` 语义不变；`/act` 映射到默认 `accept_edits`；连续执行切 `/auto`；跨区切 `/full-access`。
- `/chat` 为兼容别名映射到 `accept_edits`。
- `SessionMode` 由 `CHAT/PLAN/ACT` 改为 `PLAN/ACCEPT_EDITS/AUTO/FULL_ACCESS`，默认 `ACCEPT_EDITS`。

## 验收标准

- 以 root / 管理员身份启动时拒绝运行并说明原因。
- 裁决按 `deny → ask → allow` 优先级，第一个匹配即决定；宽 deny 盖过更具体 allow。
- 复合命令按子命令拆解裁决，整条取最严：`git status && rm -rf ~` 被拒。
- 命令替换内部被扫描：`echo "$(rm -rf ~)"` 被拒。
- 进程包装器剥离：`timeout 30 npm test` 与 `npm test` 同判；`watch`/`find -exec` 仍提示；
  `devbox run rm -rf .` 不因外层前缀被放行。
- 内置只读集（`ls cat grep …` + git 只读）在所有模式免提示。
- `accept_edits` 下文件编辑与文件操作命令集（mkdir/touch/rm/mv/cp/sed，区内非受保护）自动，
  **python / 其他 shell / `git commit` 仍确认**；确认支持 once/always/session/deny，session 不落盘。
- `auto` 下命令直接执行（含 git 写）；可检测到的动工作区外仍确认。
- `full_access` 下动工作区外也直接执行，仅 OS 非 root 与高危 deny 兜底。
- 高危 deny（`rm -rf ~`、`rm -rf ./*`、`mkfs`、`dd of=/dev/*`、fork bomb、`curl|sh`、写受保护
  路径含 `.git/hooks`/`.npmrc`/`~/.ssh`/`.forge/`）在**所有模式含 `full_access`**被拒；等价
  变形有测试。git 写命令**不在** deny 内。
- glob 规则生效：`Bash(npm run *)` allow、`Read(~/.ssh/**)` deny、`Read(src/**)` allow 等按
  gitignore 语义与 `//`/`~/`/`/`/`./` 锚定匹配；`Bash(ls *)` 不匹配 `lsof`。
- 出工作区**读**（含 Grep/Glob）默认触发确认，可由 `Read(...)` allow 规则放宽；区内读免提示。
- 经 shell 与经 git 工具的 git 命令得到相同裁决。
- MVP 不接入 MCP：`tool_catalog` 不含 MCP 工具；不存在自动 checkpoint。
- 用户配置无法放宽内置权限、移除内置 deny、关闭 root 校验；deny 恒压过 allow。
- 可用平台（macOS/Linux）下命令与生成代码在沙箱内执行：宿主资源绑定式接入（`python`/`node`/
  工具链可读可执行），读广但机密路径（`~/.ssh` 等）deny-read，写限工作区 + 私有临时目录，网络
  默认关闭；沙箱不可用（Windows / 未装 bwrap）时探测到并提示，回退到 rule-engine-only。
- `auto` 下命令在盒内直接跑、撞边界（联网 / 写区外）时升级为一次 ask（on-failure escalation）；
  `accept_edits` 仍执行前询问（不被沙箱塌缩进 auto）；`full_access` 预授权越界不问。
- 沙箱与规则并存：高危 deny 命令连沙箱都不进；沙箱边界与 `Read`/`Edit` 路径规则合并生效。
- 执行顺序固定为「规范化 → 引擎裁决(deny/ask/allow) → 沙箱执行 → 越界 escalation」，不可颠倒：
  `rm -rf ./*` 即使有沙箱也被第 2 步 deny 拦下，不进沙箱。
- 裁决逻辑位于 application 层，不落在 REPL 或 CLI 渲染层。
