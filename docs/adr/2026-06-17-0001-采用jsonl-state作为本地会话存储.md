# ADR-0001：采用 jsonl + state 作为本地会话存储

## 状态

Accepted

## 日期

2026-06-17

## 背景

ForgeCLI 是本地优先的对话式 CLI Agent，需要支持长任务、会话恢复、审计和人工排查。MVP 阶段不需要复杂查询、多用户共享或服务端事务。

## 决策

MVP 会话存储采用 `events.jsonl` 作为追加式事件日志，`state.json` 作为快速恢复快照，`summary.md` 保存上下文压缩摘要，`artifacts/` 保存长输出和产物。

### 真相源的适用范围 (2026-08-17 补充)

"`events.jsonl` 是唯一真相源, `state.json` 可由它重建"这条约束的范围是**会话状态**, 不是
Forge 的全部持久化状态.

**项目级状态各有自己的存储, 不在 `events.jsonl` 的重建职责内.** 判据是生命周期: 会话状态
随会话创建与结束, 项目级状态跨会话存在. 把项目级状态塞进某一个会话的事件流, 会让"在会话 B
里读会话 A 产生的东西"变成跨文件重放, 而那个会话的日志随时可能被归档或清理.

当前属于项目级状态的有:

| 状态 | 位置 | 相关 ADR |
| --- | --- | --- |
| 学习规则 (`always`) | `~/.forge/state/rules/<workspace_id>.toml` | ADR-0013 |
| 项目配置 | `~/.forge/projects/<project_id>/forge.toml` | ADR-0008 |
| 计划与待办清单 | `~/.forge/projects/<project_id>/plans/` | ADR-0022 |

这些状态**仍然要在会话事件里留下引用与裁决记录** (谁在什么时候改了什么, 人怎么裁的),
用于审计; 但事件 payload 只记摘要与引用, 不复制正文——复制正文就有了两个会漂移的副本,
而事件流是 append-only 的, 漂移之后无法修正.

这条边界一直隐含存在 (学习规则从落地起就是这样), 此处补写清楚, 避免后续实现把项目级状态
误当作会话状态处理.

## 备选方案

- SQLite：查询能力强，但对 MVP 本地对话存储偏重。
- 纯内存：实现简单，但无法恢复和审计。
- 单个 JSON 文件：易读，但并发和中断恢复能力弱。

## 影响

该方案更适合本地调试、人工审查和 Git 管理。代价是复杂查询能力较弱，后续企业审计或服务端化可再引入 SQLite 或其他存储后端。

## 验收标准

- 所有会话事件先写入 `events.jsonl`。
- `state.json` 可由事件日志重建，不作为唯一真相源。
- 长输出不直接写入事件 payload。
- resume 以事件日志校验状态快照。
