# ADR-0062: 采用只读报告型子 Agent: 复用主循环, 派生取消, 按 agent_id 归账

## 状态

Accepted

本文实现概要设计 §2.6 / §7.2 与详细设计 §12 里"首版只做无写权限报告型 Sub-Agent"的
承诺, 并取代详细设计 §12.1 的输入输出字段表: `mode_policy`, `context_slice`,
`allowed_tools`, `output_schema` 不再是每次派发的参数, 由决策 4, 5, 6 定死.
`core/turn.py` 里"为将来 sub agent 预留 `MessageRole.SUB_AGENT`"的说明随本文删除:
子 Agent 的报告以普通 tool result 进父窗口, 不需要新的消息角色.

保留 ADR-0051 的双层循环、ADR-0054 / 0055 的统一工具与权限管线、ADR-0057 的回合边界;
新增子运行约束, 并补齐取消、会话写入与事件分发的并发语义. 本文已进入实现; 以下决策为实现约束, 背景中的代码事实描述修订前的基线.
ADR-0016 的事件信封与 ADR-0011 §11 的用量草稿各加一个 `agent_id` 字段 (决策 2).

## 日期

2026-09-21

## 背景

### 1. 要做的事

主 Agent 在一轮里派发一个措辞明确的任务 (例: "找出所有写 events.jsonl 的地方, 说明
各自的 turn_id 从哪来"). 子 Agent 用自己的上下文窗口搜索, 阅读, 分析代码, 交回一份
报告: 摘要, 发现, 证据 (文件与行号), 建议, 没做完的事. 子 Agent 不改文件, 不起会改
东西的子进程, 不问人. 改动由主 Agent 读过证据之后自己做.

先打通一次派发一个子任务; 再放开同一批里几个子任务并行.

### 2. 循环今天已经是"给两个函数就能跑"

ADR-0051 之后 `BuiltinAgentLoop.run(loop_input, execute=, assemble=)` 是一次查询的
完整生命周期, 它认识的只有两个函数: `execute` 跑一批工具, `assemble` 组一次材料.
主 Agent 的 `AgentTurnService` 给的是走完整安全管线的 `ToolRunner.run` 与读计划,
记忆, FORGE.md 的 `ContextAssembler.assemble`. 子 Agent 给它另外两个函数就够: 一个
只认识只读工具池的 `ToolRunner`, 一个只组子 Agent 提示词的 `assemble`. 循环的控制流
保持原有形状; 身份、请求用途、取消透传和异常收尾仍需改接线.

### 3. 现有设施的复用边界 (对照 2026-09-21 工作区源码)

| 设施 | 今天的假设 | 子 Agent 直接进来会怎样 |
|---|---|---|
| `TurnCancelSource` (`agent/turn_cancellation.py`) | 一个 token: `issue()` 开轮, `clear()` 收轮; 循环经 `cancel_token_factory=cancel_source.current` 每次调模型现读 | 子 Agent 也读 `current()` 的话, 父停子停没问题, 但子 Agent 自己的超时无法只停自己: 停一个就停全部 |
| `BlockingHumanPromptBroker` (`runtime/human_prompt_broker.py`) | 每轮 `begin_turn()` 归零提问计数, `cancel_turn()` 闩住整轮 | 子 Agent 摆的审批卡片与主 Agent 的长得一样, 用户分不清谁在问; 卡片上"本会话始终允许"会经 `set_app_state` 改父的权限上下文; 三个并行子 Agent 能同时摆三张 |
| `ToolRunner` (`tools/runner.py`) | 一个实例一个会话: `observer.bind_turn`, `batches`, `file_history.make_snapshot`, `read_file_state` 都是实例字段 | 子 Agent 每批工具都给父的 `FileHistory` 拍一次快照 (上限 100, 会把父的挤掉); 子读过的文件进父的 `FileStateCache`, 父就能 Edit 一个自己没读过的文件 |
| `AgentRunEventBus`, `UsageRecordDraft`, `RunContext` | 事件与用量按 `(session_id, turn_id)` 归属, 没有第三个 id; 总线的 `_sequences` 计数无锁 | 子 Agent 的 `MODEL_USAGE`, `TOOL_*` 与父的混在一条时间线上分不开; 循环收尾发的 `TURN_COMPLETED` 会被 `tui/run_view.py` 与 `web/src/shared/lib/run/turn.ts` 当成整轮结束; 并行时 sequence 重号 |

另外四个不能由上述字段扩展自动解决的事实:

- `tools/builtin/Bash/bash_permissions.py` 在逐命令只读检查之前, 可按
  `sandbox.auto_allow_bash_if_sandboxed` 直接 allow. default 模式不是只读保证.
- `conversation/summarize.py` 当前没有把取消 token 交给压缩请求; 只改子循环工厂会漏掉它.
- `SessionService._emit` 的序号、事件追加与快照更新没有完整事务锁;
  `AgentRunEventBus` 同步分发, 只锁编号不能保证订阅者接收顺序.
- `runtime/llm_wiring.py` 的 `_budget_reader` 固定按 `TOOL_CALL` 解析模型;
  当前网关没有可复用的会话费用硬上限, 预算治理仍在 backlog.

## 决策

### 决策 1: 一个 `Agent` 工具, 一条子线程, 复用 `BuiltinAgentLoop`

`tools/builtin/Agent/{tool.py, prompt.py}` 新增 `AgentTool`:

```python
input_schema = {description: str (3-5 个词, 给界面看), prompt: str (给子 Agent 的任务)}
is_read_only -> True          is_concurrency_safe -> 阶段 A False, 阶段 B 验证共享依赖后 True (实施清单)
is_destructive -> False       requires_user_interaction -> False
check_permissions -> allow    (子 Agent 的每一次工具调用各自过 has_permissions_to_use_tool)
to_auto_classifier_input -> "" (派发本身与安全无关; 子 Agent 里每次调用各自进记录)
max_result_size_chars = 20_000 (报告超长走 persist_if_needed, 父用 Read 取全文)
```

工具认识不到循环 (`tools` 不得 import `agent`, `scripts/check_arch.py`). 与 `BashTool`
收两个执行器同一个办法: 构造时收一个函数 `run: SubAgentRun`, 类型定义在
`core/agent/sub_agent.py`:

```python
SubAgentRun = Callable[[SubAgentTask, ToolUseContext], SubAgentReport]
```

实现是 `agent/sub_agent/runner.py` 的 `SubAgentRunner.run`, 由组合根
(`runtime/project_runtime.py`) 装配并交给 `build_tool_stack(sub_agent_run=...)`.
它做的事:

```
原子预占本轮派发额度 -> 可取消地等待并行名额 (决策 7)
-> 造身份并绑定本轮资源 (决策 2) -> 派生取消 token (决策 3)
-> 造子 ToolRunner (决策 4, 5) -> 组一次子上下文 (决策 6)
-> 起线程 forge-agent-<agent_id>: loop_factory().run(child_input, execute=, assemble=)
-> 短间隔 join, 取消或到期后等待实际退出 (决策 3)
-> 结算用量、保存窗口 -> 发一次 SUB_AGENT_FINISHED -> 释放并行名额
-> 交回 SubAgentReport 或传播取消
```

`loop_factory` 与主 Agent 是同一个 `BuiltinAgentLoop` 构造: 同一个网关, 同一个
`UsageMeter`, 同一个事件总线, 每个子运行独立的
`builtin_rules(context=window_manager, max_model_calls=子上限)` 实例. 工厂显式接收子 token
和调用上限; 不能原样使用当前闭包 `new_loop()` 中的 `cancel_source.current`.
子 Agent **在自己的线程里跑完, 调用方线程 join 它**, 而不是在调用它的那条线程里直接跑:
`RunContext` 是 contextvars, 循环 `run()` 一开始就 `update_run_context(step=0, ...)`,
在独立线程绑定身份可避免覆盖父的步号与 request_id, 并让调用方检查截止时间.
这不是强制终止线程的机制: 超时只请求协作取消, 收尾约定见决策 3.

不嵌套: 子 Agent 的工具池里没有 `Agent` (决策 5). 一层就够报告型任务用, 深度字段不加.

### 决策 2: 身份是 `(session_id, turn_id, agent_id)`, 主 Agent 的 `agent_id` 为空串

```python
@dataclass(frozen=True)
class SubAgentIdentity:            # core/agent/sub_agent.py
    session_id: str                # 父的
    turn_id: str                   # 父的: 子 Agent 是这一轮的一部分, 不是新的一轮
    agent_id: str                  # f"agent_{uuid4().hex[:12]}", 组合根生成
    parent_tool_call_id: str       # 父窗口里那次 Agent 调用的 tool_call_id
```

子 Agent 没有自己的 `TurnRun.run_id`, 没有自己的 `TurnIdentity`, 不改
`ProjectRuntime.busy` 的含义 (仍是"有一轮在跑"). 它的费用, 取消, 生命周期都归这一轮,
所以 `turn_id` 就是父的; 把它与父区分开的只有 `agent_id`.

`agent_id` 穿过所有今天按 `(session_id, turn_id)` 归属的地方, 缺省 `""` 表示主 Agent:

| 类型 | 字段 | 谁填 |
|---|---|---|
| `LoopInput` (`core/agent/state.py`) | `agent_id: str = ""` | runner 造子输入时填 |
| `LoopView` (`agent/loop/rule.py`) | `agent_id` | 循环从 `LoopInput` 抄; `context_fit` 组压缩请求时带上 |
| `ModelRequest` (`core/model/request.py`) | `agent_id: str = ""` | 循环 `_build_request`; `window_manager.fit` / `summarize` 从调用方收 |
| `UsageRecordDraft` (`core/model/usage.py`) | `agent_id`, 进 `to_payload()` | `UsageMeter` 从 `ModelRequest` 抄 |
| `ToolUseContext` (`core/tool/tool.py`) | `agent_id: str = ""`, `tool_use_id: str = ""` | 子 `ToolRunner.context()` 填前者; `run_tool_use` 第 6 步 `replace()` 出一份带 `tool_use_id` 的再调 `call` (Agent 工具要用它当 `parent_tool_call_id`) |
| `ToolRunObserver.bind_turn` (`core/tool/observer.py`) | 加 `agent_id` 参数 | 子 observer 实例 |
| `AgentRunEvent` (`agent/run_events.py`) | `agent_id: str = ""` | `AgentRunEventBus.publish(agent_id=)` |
| `RunContext` (`common/observability/context.py`) | `agent_id` | runner 在子线程里 `bind(session_id, turn_id, agent_id)` |

`RunContext` 的字段说明写着"封闭的六个"; 第七个进来的理由与那六个相同: 它是能把一行日志
接回某个执行流的全局 id, 不是一次性的业务字段.

### 决策 3: 取消从父 token 派生, `TurnCancelSource` 不动

`common/cancellation.py`:

```python
@dataclass(eq=False)
class CancelToken:
    _cancelled: bool = False
    _parent: CancelToken | None = None

    def child(self) -> CancelToken:            # 父取消子随之取消; 子取消不影响父
        return CancelToken(_parent=self)

    @property
    def cancelled(self) -> bool:
        return self._cancelled or (self._parent is not None and self._parent.cancelled)
```

轮询式检查, 不注册回调: 本仓库的取消一直是协作式的 (网关 `raise_if_cancelled`, 执行链
第 1 步查 `context.abort.cancelled`), 父链上多读一个布尔就够, 不需要 Claude Code 那套
`WeakRef` 监听器.

取消的接线:

- 父 token 就在 `AgentTool.call` 收到的 `context.abort` 上 (`AgentTurnService._run_tools`
  把 `TurnCancelSource.current()` 传给 `ToolRunner.run`, `context()` 挂到 `abort`).
  runner 调 `context.abort.child()` 得到子 token, **不认识 `TurnCancelSource`**.
- 子循环 `cancel_token_factory=lambda: child`, 子 `ToolUseContext.abort = child`.
  `TurnCancelSource` 仍然一轮一个 token, `ProjectRuntime.cancel()` 一行不改: 它取消父
  token, 所有子 token 的 `cancelled` 随之为真, 下一次模型调用抛 `ModelCancelledError`,
  下一次工具调用在执行链第 1 步返回 cancelled.
- runner 按单调时钟计算 deadline, `join` 每次至多 100ms, 每次检查父取消与 deadline.
  到期只取消 child; 父取消则所有 child 随之取消. 停止后不再启动新模型请求或工具.
- `LoopView` 向 `ContextFitRule` 暴露本次取消 token, 经 `WindowManager.fit` / `_evict`
  到 `summarize` 传给 `ModelRequest.cancel_token`; 正常压缩与 overflow 强压都覆盖.
  网关在途请求、重试等待、Bash 子进程与 LSP 等待也必须有取消检查或有限 I/O 超时.
- grace 缺省 30 秒, 是收尾告警阈值, **不是线程强杀或释放名额的时刻**. 超过后记录
  `sub_agent.cleanup_delayed` 并让界面显示“正在停止”; runner 继续短间隔等待实际退出.
  不遗弃 daemon 线程, 不提前发 `SUB_AGENT_FINISHED`, 不允许父轮结算或切换会话.
  项目保持 busy, 关闭流程同样先取消并排空子运行, 再关闭网关、工具与存储资源.
- 首版不承诺对任意不响应取消的第三方调用提供硬截止时间. 持续卡住时用户只能结束进程;
  若产品要求有界强杀, 必须另做进程隔离, 不能用 daemon 掩盖. 因此 300 秒是请求停止的
  时间, 不是保证报告返回的时间.
- 子 Agent 的状态由 runner 判, 不由循环的停止原因判: 父 token 取消 -> `cancelled`;
  runner 自己取消的 -> `timed_out`. 两者在循环里都是 `USER_CANCELLED`, 分不开, 而 runner
  知道是谁按的.
- 状态优先级: 收尾时父 token 已取消则为 `cancelled`; 否则已触发 deadline 则为
  `timed_out`; 其余按循环结果判定. 即使取消之后模型迟到返回正常回答, 也不能改报 completed.
- 子线程通过结果容器传回结果或异常, 不让线程异常静默丢失. 循环提供只在退出后读取的
  终止快照 (窗口、已收集用量、计数), 使异常路径也能结算与保存排查材料. 对无供应商
  usage 的中断请求标记计量不完整, 不伪造为零费用.
- 父 token 已取消时, runner 先等待实际退出并完成收尾, 再由 `AgentTool.call` 抛 `CancelledError`: 执行链第 6 步把它记成
  `status="cancelled"` 并发 `TOOL_CANCELLED`, 与别的工具被打断时一致. 父循环随后调模型
  也会因同一个 token 停在 `USER_CANCELLED`.
- `BlockingHumanPromptBroker` 不动: 子 Agent 不进这条队列 (决策 4).

### 决策 4: 子 Agent 从不问人, 权限视图固定为 default 且没有 allow 规则

子 Agent 的每一次工具调用仍走 `make_can_use_tool` 产出的那个 `can_use_tool`, 走
`has_permissions_to_use_tool` 的统一权限流程. 除受限权限视图外, 执行链增加只读能力
约束, 在权限结果确定后、实际 `call` 前校验最终入参; allow 不能越过这道约束.
`security/sub_agent.py`:

```python
def sub_agent_permission_context(parent: ToolPermissionContext) -> ToolPermissionContext:
    return replace(
        parent,
        mode=PermissionMode.DEFAULT,           # 不随父放宽: accept_edits 会放行工作目录内的 rm/mv,
                                               # bypass 会放行一切, 那就不是只读了
        should_avoid_permission_prompts=True,  # ask 一律成 deny (permissions.py _no_prompt_available)
        always_allow_rules={},                 # 用户的 Bash(pytest:*) 一类不给子 Agent 用
        pre_plan_mode=None,                    # is_auto_mode_active 也看它: 父从 auto 进了 plan 时
                                               # pre_plan_mode 是 AUTO, 不清掉子 Agent 就会进分类器
        stripped_dangerous_rules=None,
    )                                          # deny / ask 规则, 额外工作目录原样保留
```

子 Agent 的 `AppState` 视图 (runner 造, 交给子 `ToolRunner` 的 `get_app_state` /
`set_app_state`):

- `get` 返回父**当前**的 `AppState`, 权限上下文换成上面这份, `denial_tracking` 换成
  子本地那份. 读当前而不是拍快照: 父在忙碌期间改不了模式 (ADR-0057 决策 4), 两者等价,
  而读当前少一处会过期的副本. 此回调绑定派发时的父运行资源, 不跟随以后切换的会话.
  同时将 `sandbox` 替换为 `replace(parent.sandbox, auto_allow_bash_if_sandboxed=False)`,
  保留隔离与路径限制. 关闭自动放行不等于关闭沙箱.
- `set` 只收 `denial_tracking`, 其余一律丢弃并记一条 warning: 子 Agent 改不了模式, 规则,
  目录与沙箱设置. 审批卡片上"始终允许"的建议不会被施加, 因为根本不摆卡片.
- `prompts=PendingHumanPromptService()`: 就算哪条路走到 `context.prompts.ask`, 立刻得到
  `resolved=False`, 审批侧读成拒绝. `AskUserQuestion` 也不在池里.

只读执行约束放在 `ToolUseOptions.read_only = True` (主 Agent 缺省 False), 不靠
`agent_id` 非空来推断权限. 执行链对最终入参调用工具已有的 `is_read_only`; Bash 复用解析器与
`check_read_only_constraints` / `unit_is_read_only`: 无法证明、写文件重定向、未知结构均拒绝;
POSIX 下确切指向系统字符设备 `/dev/null` 的输出重定向允许. 普通 shell 命令按
`;`、换行、`&&`、`||` 和管道解析为分析单元, 不改变实际执行的原始命令.
目录分析保留成功/失败分支: `&&` 仅在成功分支继续, `||` 仅在失败分支继续,
分号后的路径必须在所有可能的工作目录中通过检查. cd 目标必须存在且位于允许目录内.
`cd -`、动态路径、受 CDPATH 影响的路径、管道内 cd 及无法证明的控制结构仍需审批;
不因这次修复放开原有的 `cd` 与 `git` 组合只读限制.
Git 分支/标签的位置参数创建、配置写入、默认 stash 不算只读; 支持经验证的
`sed -n '起始行,结束行p'` 查询. Bash 文件参数与输入重定向复用 Read 的路径权限检查.
其他工具只允许决策 5 的固定白名单. 该校验与普通权限取交集, 不授予额外路径权限,
即使未来某条权限分支返回 allow 也不能放过写命令. 拒绝记录为工具 denied, 不调用工具.

于是能过的只有: `Read` / `Glob` / `Grep` / `LSP` 在允许路径内的调用, 以及
`read_only_validation` 证明为只读的 `Bash` 命令 (`bash_permissions` 第 7 步, default 下
直接放行). 其余全部 deny; 需要审批的使用 `_no_prompt_available`, 只读约束失败明确说明原因; 子 Agent 的系统提示词
要求把被拒的命令或路径原样写进报告的"未完成"一节, 由主 Agent 在有人可问的主回合里自己做.

`mode=DEFAULT` 顺带决定了子 Agent **不经过 auto 模式分类器**
(`is_auto_mode_active` 看的是 mode): 报告型任务不该为"要不要问"再花模型调用.
父在 `plan` 模式时子 Agent 也是 default, 裁决本来就相同 (`core/permissions.py`).

### 决策 5: 子 `ToolRunner` 是父的受限副本, 读过的文件不回流

`tools/runner.py` 加一个工厂:

```python
def sub_agent_runner(parent: ToolRunner, *, identity, app_state, observer, prompts) -> ToolRunner
```

| 字段 | 子取值 | 为什么 |
|---|---|---|
| `base_tools` | 父的 `base_tools` 里名字在 `SUB_AGENT_TOOLS = ("Read", "Glob", "Grep", "LSP", "Bash")` 的; 再经 `assemble_tool_pool` 过父的 deny 规则 | 白名单而不是"所有 `is_read_only` 的": Bash 的只读随入参变, `AskUserQuestion` / `plan_read` 只读却不该给; 将来新加的工具缺省不进子池 |
| `read_file_state` | `parent.read_file_state.clone()` (`FileStateCache` 加 `clone()`) | 在父缓存锁内克隆独立容器与容量/LRU 状态; 子读不增加父的 Edit 资格. 父若此前已读过文件, 不强制再读; 逐条复核报告仍是提示词要求 |
| `file_history` | `None` (字段类型改成 `FileHistory | None`; None 时 `run` 不拍快照, `track_file_edit` 是一个抛 `RuntimeError` 的函数) | 池里没有会写文件的工具, 拍快照只会挤掉父的 |
| `observer` | 新的 `EventBusToolRunObserver(bus)`, `bind_turn(session_id, turn_id, agent_id)` | 事件带 `agent_id` (决策 8); 父的 observer 实例不被子改绑 |
| `prompts` | `PendingHumanPromptService()` | 决策 4 |
| `get_app_state` / `set_app_state` | 决策 4 的视图 | |
| `can_use_tool`, `cwd`, `environment`, `workspace_roots`, `internal_paths` | 派发时父运行的 | can_use_tool 仍接收子的受限 context |
| `tool_results_dir` | 固定到本会话的 `tool-results/agents/<agent_id>/` | 模型提供的 tool_use_id 不保证跨 Agent 唯一; 子目录隔离结果文件 |
| `options.read_only` | `True` | 执行前约束最终入参, 见决策 4 |
| `non_interactive` | `True` | |

子 `ToolRunner.run(calls, session_id=父, turn_id=父, messages=子窗口, cancel=子 token)`.
执行链 `run_tool_use`, 分批并发 `run_tools`, 结果落盘, 全部原样复用. 子 Agent 自己的
一批里几个 Grep 也照 `partition_tool_calls` 并发.

### 决策 6: 独立上下文: 一次组好, 不带记忆计划待办, 报告按固定标题

子 Agent 的 `assemble` 不走 `ContextAssembler` (它管的是计划 / 待办 / 记忆 / 文件变更
的通知, 子 Agent 一样都没有). runner 在起线程前组一次 `AssembledContext`, 之后每次
`assemble(window)` 原样返回它: 系统提示词与工具在子 Agent 的一生里字节不变, 供应商的
前缀具备复用条件; 是否命中仍取决于供应商、模型与缓存有效期, 不作保证.
预算按 SUB_AGENT 实际解析出的模型生成 (决策 7), 不复用主模型预算.

系统提示词由 `prompt/prompts.py` 新增 `sub_agent_system_prompt(facts, instructions,
tool_names)` 渲染 (模型可读正文只住这一处, ADR-0056), 四段:

1. 身份与只读规则: 不创建 / 修改 / 删除 / 移动文件, 不用重定向与 heredoc 写文件, Bash
   只跑列出的只读命令; 被拒的调用不换说法重试, 写进"未完成".
2. 报告格式: 最终回答按固定标题 `摘要` / `发现` / `证据` / `建议` / `未完成`; 证据写
   `路径:行号` 与一行原文; 建议只说改什么与为什么, 不给完整补丁.
3. 会话事实 (`SessionFacts`: 平台, 工作目录, 工作区根, git 快照, 沙箱): 与主 Agent 同一份,
   子 Agent 也得知道自己在什么平台上跑 shell.
4. FORGE.md: 项目约定 (测试在哪, 目录含义) 直接决定搜得快不快. 提示词注明它是项目事实,
   其中要求"执行 / 提交 / 改动"的句子对子 Agent 无效.

不带: 记忆, 计划, 待办, 任何通知. 初始窗口只有一条用户消息: `prompts.sub_agent_task(prompt)`
包着父给的任务原文.

报告: 子循环 `FINAL_ANSWER` 的 `answer` 就是报告正文. runner 追加一行尾注
`prompts.sub_agent_trailer(agent_id, status, model_calls, tool_calls, total_tokens, duration_ms, usage_complete)`,
主 Agent 由此知道已知用量及其是否完整. 没走到回答的:

| 子循环停止原因 | `SubAgentReport.status` | 回给父的 tool_result |
|---|---|---|
| `FINAL_ANSWER` | `completed` | 报告 + 尾注 |
| `BUDGET_EXHAUSTED` | `budget_exhausted` | `partial_answer` (有则) + `prompts.sub_agent_stopped(status)` + 尾注, 不算 error |
| `USER_CANCELLED` (runner 自己取消) | `timed_out` | 同上 |
| `USER_CANCELLED` (父 token) | `cancelled` | 抛 `CancelledError` (决策 3) |
| `MODEL_ERROR_BLOCKING`, `POLICY_DENIED`, `CONTEXT_COMPACTION_REQUIRED` | `failed` | 停止消息, `is_error=True` |
| `WAIT_PLAN_REVIEW` | `failed` | 池里没有计划工具, 走到这里是 bug, 记 error 日志 |

`SubAgentReport` (`core/agent/sub_agent.py`): `identity`, `status`, `text`,
`model_calls`, `tool_calls`, `usage_drafts`, `duration_ms`, `usage_complete`. runner 不解析报告正文.
表中结果服从决策 3 的取消/超时优先级; 无 LoopResult 的异常使用退出快照形成 failed 报告.
存储失败记为独立诊断与计量不完整, 父已取消时仍传播取消, 不把父轮改成正常完成.

主 Agent 那一侧只加提示词: `AgentTool.prompt()` 说清什么任务适合派发 (要读很多文件才能
回答的问题, 与当前改动无关的调研), 报告是线索不是事实, 改代码前先 Read 证据所指的位置
(决策 5 只保证子读取不会增加父的编辑资格, 不保证父逐条重新读取证据). 主 Agent 系统提示词的工具指引段加一句何时用 `Agent`.

### 决策 7: 预算按子 Agent 定, 用量记在父轮上并带 `agent_id`

预算, 首版常量加环境变量覆盖, 与 `FORGE_MAX_TOOL_USE_CONCURRENCY` 一个写法; 进
`forge.json` 设置段等真有人要调再加:

| 项 | 缺省 | 在哪生效 |
|---|---|---|
| 单个子 Agent 循环模型调用上限 | 30 | `builtin_rules(max_model_calls=)` -> 子的 `ModelBudgetRule`; 到点 `BUDGET_EXHAUSTED` |
| 单个子 Agent 时限 | 300 秒 | runner 单调时钟 deadline (决策 3); 从取到并行名额起算, 含初始化, 排队不算 |
| 一轮里的子 Agent 总数 | 8 | runner 按 `(session_id, turn_id)` 在锁内检查并预占; 超过返回额度错误, 不起线程 |
| 同时在跑的子 Agent | `FORGE_MAX_SUB_AGENT_CONCURRENCY`, 缺省 4 | runner 的 `BoundedSemaphore`; 超出的等, 等待期间每秒看一次父 token |

工具调用次数不单独设上限, 与主循环同 (`model_budget.py` 的注释). 子 Agent 窗口撑满时
`ContextFitRule` 照常压缩, 那次 `COMPACT` 调用的草稿进子的账本. 30 次遵循现有
`ModelBudgetRule` 的循环调用口径, 不包含压缩请求与网关内部重试; 不是总 HTTP 请求数、
token 或费用硬上限.

`AgentTool.validate_input` 只校验参数, 不检查或修改配额. runner 先检查父取消, 再原子
预占派发额度; 等并行名额时可取消. 预占后排队取消或启动失败仍消耗本轮一次额度,
防止失败重试绕过总数限制. 并行名额只在实际持有时释放, 且已启动线程必须退出后才能
释放. 本轮停止后拒绝新派发, 所有已预占调用返回、子运行退出后清理该轮计数.
额度不足由 core 中的 SubAgentLimitError 表达, AgentTool 转为 is_error=True 的工具结果,
使用 prompts.sub_agent_limit(n), 不创建虚假的子身份或生命周期事件.
阶段 A 并行数固定 1; 阶段 B 才启用缺省 4 和环境变量覆盖. 所有限值必须为正有限值.

用量归属:

- 子循环的 `TurnLedger` 收齐草稿 (父 `turn_id` 与子 `agent_id`), 通过 `LoopResult`
  或异常终止快照交给 runner. runner 在实际退出后统一结算, 取消也不能跳过.
  `usage_sink` 显式绑定派发时的 `session_id`, 经 `SessionService.record_usage` 写入,
  校验当前会话身份一致, 不使用可漂移的 `self.session` 回调. 用量不经 ToolResult 回传.
- `SessionService` 新增实例级可重入锁, 完整覆盖序号分配、事件追加、内存快照替换和
  state.json 写入; 会话切换与其他快照修改也遵守同一锁. 只锁 JsonlEventStore.append
  不够. 这是线程间串行化, 不宣称文件系统多文件原子事务. I/O 失败沿现有故障通道
  暴露, 不重复提交已落盘草稿、不静默丢账; 不支持崩溃后恢复子运行.
- 每个 runner 只有一个收尾者, 按 request_id 去重结算已获得的草稿, 然后保存排查材料、
  发一次结束事件. 存储失败保留诊断与 failed 结果 (父取消优先), 仍在 finally 释放并行名额.
  `SUB_AGENT_FINISHED` 与排查材料带 `usage_complete`, 区分已知用量合计与完整费用.
- “本轮合计”在同一 session 下按 turn_id 汇总父子持久化草稿; 展示须核对实际消费路径,
  不能假定仅写 USAGE_RECORDED 就自动更新现有父轮面板. 子事件按 agent_id 分组,
  不能一边累加 MODEL_USAGE 一边又把 SUB_AGENT_FINISHED 合计重复加入.
- 当前网关没有会话费用硬上限. 首版仅提供调用次数、派发数、并发数与协作式时限,
  并展示用量; 费用/token 总预算另列后续工作, 不作为现有守卫复用.
- `RequestOrigin` 加 `SUB_AGENT = "sub_agent"` (`benefits_from_thinking` 归入"要思考"),
  子循环 `_build_request` 用它代替 `TOOL_CALL` / `CHAT`. 它是子 Agent 真有的产出方
  (ADR-0028 规则 C), 用途是让用户经 `ModelOverridesService` 给子 Agent 单独绑一个便宜的
  模型, 与 Claude Code 给 Explore 配小模型是同一件事.
- `LlmRuntime.context_budget` 改为按 origin 读取, 主调用显式使用 TOOL_CALL, 子调用
  使用 SUB_AGENT, 与模型选择共用 resolver. 子运行开始时固定模型选择与预算, 本轮内
  不允许配置变更使二者分离; 未知窗口保持 None, 不猜主模型窗口.
- 压缩请求继续使用 `origin=COMPACT`, 可使用自己的模型覆盖; agent_id 仍属于子运行.
  origin 描述用途, agent_id 描述归属. 压缩输入也需适配其实际模型窗口, 不把当前
  `_MAX_FLATTENED_CHARS` 当成所有模型都适用的预算; 取消 token 同样透传.

### 决策 8: 事件带 `agent_id`, 子 Agent 的生命周期事件由 runner 发

- `AgentRunEventBus.publish(agent_id="")`, `AgentRunEvent.agent_id`; `_sequences` 的
  编号与分发统一串行化: 总线使用锁保护待分发队列与唯一 drainer, publish 在锁内分配
  sequence 并入队, drainer 在锁外逐条调用订阅者. 订阅回调再次 publish 只入队,
  当前事件分发完成后再处理, 不递归打乱顺序. 空队列与 drainer 交接在同一锁内完成.
  sequence 仍按 `(session_id, turn_id)` 编号; 所有订阅者与 JsonlRunStore 接收严格有序.
  订阅者异常继续隔离; drain/flush 纳入项目关闭流程, 不依赖 publish 返回即已完成投递.
  JsonlRunStore 带 agent_id 落盘. 不只锁 `_sequences`, 也不让多个发布线程同时进订阅者.
- 新增开始与结束事件: `SUB_AGENT_STARTED` (`SubAgentStartedPayload(description, parent_tool_call_id)`),
  `SUB_AGENT_FINISHED` (`SubAgentFinishedPayload(status, model_calls, tool_calls,
  total_tokens, duration_ms, detail, usage_complete)`), runner 发, 带 `agent_id`.
  STARTED 在子线程真正进入时发; 每个 STARTED 恰好对应一个 FINISHED. 启动前失败
  通过父工具错误返回, 不伪造子运行. FINISHED 在线程退出并尝试完成持久化后发出.
- 超过 grace 仍未退出时发一次 `SUB_AGENT_STOPPING`, 界面据此显示正在停止; 这不是终态.
- `LoopEventPublisher.start_turn(session_id, turn_id, agent_id)`: `agent_id` 非空时
  `start_turn` / `turn_finished` **不发** `TURN_*`, 只记日志. `MODEL_*`, `TOOL_*`,
  `DECISION_SUMMARY`, `CONTEXT_COMPACTED` 照发, 带 `agent_id`.
- 消费方 (`tui/run_view.py`, `runtime/event_hub.py`, `web/src/shared/lib/run/`) 最低要求
  是不误判: `agent_id` 非空的事件不改变整轮的状态; 阶段 B 起在界面上折进对应的 `Agent`
  工具调用下面.
- 子 Agent 结束时 runner 把子窗口写到 `sessions/<session_id>/agents/<agent_id>.json`
  (ADR-0026 的 JSON): 排查"它为什么得出这个结论"要看它读了什么. 只是排查材料, 不是恢复
  真相源, `/resume` 不读它. 正常、超时、取消及异常均保存退出快照, 包括状态、
  已知用量与计量完整性; 压缩后的窗口不能还原所有已淘汰原文, 文档不承诺完整 transcript.
  不新增 `EventType`: 报告在父的 tool_result 里, 而 tool_result
  本来就不重放 (`_rebuild_window` 的说明), 与别的工具一致.

### 决策 9: 与 Claude Code 的差异

| 事 | Claude Code | 本文 | 理由 |
|---|---|---|---|
| 后台子 Agent (`run_in_background`, `SendMessage`, 完成通知) | 有 | 没有 | 报告型任务的结果只在派发它的那一轮有用 |
| 子 Agent 类型 (`subagent_type`, `.claude/agents/*.md`) | 多种 + 用户定义 | 一种, 无 `subagent_type` 参数 | 第二种出现时再加参数 (ADR-0028 规则 C); 定义放 `agent/sub_agent/definitions.py`, 今天只有 `EXPLORE` |
| fork (共享父前缀缓存) | 有 (`forkSubagent.ts`) | 没有 | 派发的是独立任务, 子窗口从任务一句话开始, 没有前缀可共享 |
| 模式与 allow 规则 | 沿用父的 (bypass / acceptEdits / auto 优先); 异步才 `shouldAvoidPermissionPrompts` | 固定 default, 剥 allow 规则, 一律不问人 | 只读是子 Agent 自己的属性, 不随父放宽 |
| CLAUDE.md | Explore 不带 | 带 FORGE.md | 项目约定直接决定搜索效率; 提示词说明其中的动作要求无效 |
| 报告 | 自由文本 | 固定五个标题 | 给模型阅读的输出约定; 界面展示原文, 不解析标题作控制协议 |
| 子 Agent 的 hooks, MCP, 记忆, 待办 | 有 | 没有 | 本仓库没有这些设施或子 Agent 用不到 |
| 运行方式 | async generator, 消息作为 progress 上报 | 一条线程, 事件经总线带 `agent_id` | 本仓库的循环是同步的, 事件已有总线 |

## 实施清单

按依赖顺序推进, 每步独立提交并完成对应回归, 集成后 `make ci` 通过. 实施前工作区没有
`tests/` 目录; 本次已建立核心回归测试, 不能将“没有收集到测试”当作验证成功.

**阶段 A: 一次一个, 完整生命周期.**

1. **取消与退出快照**: `CancelToken.child()`; LoopView、ContextFitRule、WindowManager
   与 summarize 贯穿取消 token (含 overflow); 循环提供退出后可读快照. 覆盖模型、
   压缩、工具在途取消与异常后已有用量保留. 维持原有循环控制流.
2. **身份与模型选择**: 决策 2 的字段全链路透传; `ToolUseOptions.read_only` 主缺省 False;
   `RequestOrigin.SUB_AGENT`; 按 origin 读取 ContextBudget, 子运行固定选择与预算;
   COMPACT 保持独立用途与子 agent_id, 输入裁剪适配实际压缩模型.
3. **事件与存储**: 两种子生命周期事件; 子事件不发 TURN_*; 总线有序队列与 drainer;
   SessionService 完整写入锁及绑定会话身份的 usage_sink. 支持异常/取消的单次结算,
   明确计量不完整和 I/O 错误. 前后端与存储兼容旧记录缺省 agent_id.
4. **权限与子工具池**: 受限 AppState、关闭沙箱 Bash 自动放行、执行前只读约束;
   白名单、PendingHumanPromptService、独立 observer、缓存克隆、可空 FileHistory;
   按 agent_id 隔离结果目录. 用沙箱开启场景验证写命令不能绕过.
5. **提示词与报告**: 子系统提示词、任务包装、尾注及错误提示; 主提示词增加派发指引;
   固定标题只作阅读约定, 界面无需依赖解析成功.
6. **runner 与配额**: SubAgentTask/Identity/Status/Report/Run; 每轮原子额度预占,
   可取消排队, 阶段 A 并行数固定 1; 短间隔 join、deadline、grace 告警、实际退出后
   结算/保存/结束事件/释放. 线程启动失败、初始化失败和排队取消均有 finally 清理.
7. **工具与组合根**: AgentTool(run=), validate_input 仅校验参数;
   build_tool_stack(sub_agent_run=); 参数化 loop_factory 接收 child token 与调用上限.
   装配可用“用时读”, 但一次派发捕获并绑定会话、工具、结果目录、网关与预算等资源,
   子运行中不跟随当前会话漂移. 项目关闭先取消并排空, 再释放共享服务.
8. **展示与文档**: 子流式文本不混入父回答, 子事件不改变整轮状态; 超 grace 显示正在
   停止; 本轮用量按 session/turn 汇总且不重复计费. 更新详细设计 §12、代码阅读线路、
   core/turn.py 预留说明与 ADR 索引. 本文修订不代表这些实现已经完成.

**阶段 B: 有限并行.**

9. 先验证共享依赖并发: 网关/凭证池/计量、Bash 执行器、LSP 池、事件订阅者与会话存储.
   已有锁的组件保留其串行边界; 若存在共享可变状态竞争, 先修复再开放并行.
   Agent.is_concurrency_safe=True 会与其他连续 safe 工具混批, 验收同时覆盖该情形.
10. 开启 FORGE_MAX_SUB_AGENT_CONCURRENCY (缺省 4), Agent.is_concurrency_safe=True;
    验证额度原子性、排队取消、并发结果目录隔离、事件交付顺序及状态快照一致性.
    一批多个 Agent 的结果仍按请求顺序回填.
11. 前后端将子事件折进对应 Agent 工具调用, 用量按 agent_id 拆分; 验证三个并行
    子 Agent 中途停止全部排空, 主轮终态最后发出且只发一次.

## 备选方案

- **子 Agent 用一个独立的 `AgentTurnService` 加一个旁支会话.** 会带进会话事件, 计划,
  记忆, FORGE.md 刷新点, 通知这一整套, 每一样对报告型任务都是多余的, 而且要解释"旁支
  会话的 turn 编号与主会话怎么对". 循环只要两个函数, 就只给两个函数. **不采用.**
- **像 ADR-0061 那样发一次结构化请求, 不给工具.** 搜代码就是要反复 Grep 与 Read,
  一次请求做不到. **不采用.**
- **`TurnCancelSource` 改成按 `agent_id` 登记多个 token.** 父 token 已经在
  `context.abort` 上, 派生一个子 token 比登记表少一处状态, 也不必让 runner 认识
  `ProjectRuntime` 的设施. **不采用.**
- **子 Agent 与父共用 `ToolRunner`, observer 与 `FileStateCache`.** 快照互相挤, 事件
  串线, 父能改自己没读过的文件. **不采用.**
- **子 Agent 的审批卡片冒泡到父的队列 (Claude Code 的 `bubble`).** 报告型子 Agent 该问的
  只有"读工作区外的文件"与"跑不在只读表里的命令"两类, 都可以由主 Agent 在主回合里做;
  代价是并行时多张卡片, 以及卡片上的"始终允许"改到父的权限上下文. 将来有必须问人的
  子 Agent 类型时再单独设计. **不采用.**
- **子 Agent 沿用父的模式 (Claude Code 的做法).** 父在 accept_edits 时子 Agent 的 Bash
  能在工作目录里 rm / mv, 父在 bypass 时能做一切; "只读"就只剩提示词在守. **不采用.**
- **一起做后台子 Agent.** 要加任务登记, 完成通知注入窗口, 跨轮的取消与费用归属; 全是
  这份 ADR 之外的机制, 而报告型任务不需要. **不采用.**
- **子 Agent 的报告用 JSON schema 经 `complete_structured` 收.** 子 Agent 是带工具的
  循环, 最后一次回答走的是普通 tool calling; 固定标题够主 Agent 用, 少一种解析失败.
  **不采用.**

## 影响

**好处.**

- 主 Agent 能把"读二十个文件才能回答"的调研交出去, 自己的窗口只进一份报告; 并行几个
  子 Agent 可缩短独立调研的墙钟时间, 实际收益受模型延迟、限流与共享工具锁影响.
- 只读由三道机制守: 池里没有写工具; 权限视图固定 default 且没有 allow 规则, ask 一律
  deny; Bash 只放 `read_only_validation` 证明只读的命令. 提示词只是第四道.
- 子读取不会授予父新的编辑资格; 主 Agent 仍需按提示词复核报告证据.
- 复用既有取消、计量与事件设施, 增加父子 token、运行身份、串行写入与有序分发.

**代价.**

- 决策 2 那张表要动十来个类型的签名, 每一处都是加一个缺省为空串的字段, 但都要改.
- 派发一次至少一次子模型调用; 子 Agent 读到的内容主 Agent 看不到, 报告漏了主 Agent 就
  得再读一次. 尾注与 `SUB_AGENT_FINISHED` 让费用看得见, 提示词要求主 Agent 只在值得时
  派发.
- 子 Agent 被拒的调用要主 Agent 补做, 多一个来回.
- 一条子线程一份子窗口, 并行 4 个时增加四份窗口与缓存; 上下文预算并非进程内存硬上限.
- 协作取消不能强杀卡住的线程; 为避免跨轮遗留执行, 超 grace 仍保持 busy 等待收尾.
- 会话写入、事件分发与共享依赖需要并发验证, 不能只给类型补字段就开放阶段 B.

**兼容性.** 主循环控制流、会话事件类型与 `/resume` 的恢复语义保留; 主 Agent 的
read_only 默认 False、agent_id 默认空串. 循环快照、压缩取消、预算读取接口、
SessionService 锁、事件分发与界面用量聚合均需修改并回归验证. `events.jsonl` 的 `usage_recorded` 多一个字段, 旧记录读出来 `agent_id` 为空.
`AgentRunEvent` 多一个字段, 旧 `runs` 文件同理.

## 验收标准

以下测试使用假网关、可控阻塞点与临时工作区, 不依赖真实模型耗时或真实付费请求.

- **依赖与兼容**: AgentTool 不 import agent, SubAgentRunner 不 import runtime;
  架构检查通过. 旧 usage/runs 记录缺 agent_id 时按主 Agent 读取; 主 Agent 默认
  read_only=False, 既有权限、取消、恢复与费用展示回归通过.
- **只读权限**: 父模式覆盖 default/plan/accept_edits/auto/bypass, 沙箱覆盖开启/关闭;
  无显式 deny 规则时 rm/mv、写重定向与无法证明只读的 Bash 均被拒, Edit/Write 不在池中;
  允许路径下 git log 可执行. 父的 allow 规则对子无效, deny/ask 仍生效;
  注入返回 allow 的权限替身仍不能绕过最终入参只读校验. 工作区内容保持不变.
- **交互隔离**: 子调用不新增任何人工提示, 不发带子 agent_id 的 APPROVAL_REQUESTED;
  子 set_app_state 不能修改父权限、目录或沙箱. 不要求混批中父工具自己的审批队列为空.
- **缓存与结果隔离**: 子新读文件不进入父缓存; 父此前未读过该文件时直接 Edit 被拒.
  父此前已有合法读取记录不被清除. 两个子 Agent 使用同一 tool_use_id 落盘长输出,
  得到不同目录, 原文互不覆盖且可读取.
- **取消贯穿**: 父取消子随之取消, 子取消父不受影响; 普通请求、自动压缩、overflow
  压缩、重试等待与工具执行都使用对应 token. 子工厂不能读取当前父 token 替代 child.
- **正常超时**: deadline 到点请求取消, 响应取消的假执行器在 grace 内退出;
  timed_out 报告在退出并收尾后返回. 父取消则子终态 cancelled, 父轮 USER_CANCELLED.
- **延迟收尾**: 假执行器超过 grace 不退出时只显示正在停止, 保留 busy 和并行名额,
  不发 FINISHED、不切会话、不启动新一轮. 解除阻塞后恰好收尾一次; 父 TURN_* 在全部
  子运行结束后出现. 不用真实睡眠 300 秒测试该行为.
- **失败收尾**: 初始化/启动失败不伪造 STARTED; 已启动运行异常有终止快照、已知用量
  与一次 FINISHED. 用量或排查材料写入失败可见, 不静默宣称成功, 不泄漏名额.
  进程强制退出不承诺完整计量或子运行恢复.
- **额度**: 达到 30 次循环调用后不能再发起第 31 次循环请求, 需要继续时返回
  budget_exhausted; 第 30 次本身正常回答仍可 completed. 压缩与网关重试另按实际计量.
  并发争抢本轮最后一个派发额度时只允许一个预占成功; 第 9 次被 runner 拒绝,
  validate_input 无配额副作用. 排队取消/启动失败按决策 7 消耗额度并完成资源清理.
- **模型与窗口**: 父模型大窗口、子覆盖小窗口时按子模型预算触发压缩; 压缩调用按
  COMPACT 模型限制裁剪输入. 主请求 origin 不变, 子普通请求为 SUB_AGENT,
  子压缩为 COMPACT; 二者均带子 agent_id 和父 turn_id.
- **用量**: 同一 session/turn 持久化用量等于父及所有子已获得的草稿之和;
  子 FINISHED.total_tokens 等于该子去重草稿合计. 取消/异常保留已知用量, 无 usage
  的在途取消明确 usage_complete=False. 面板不会重复累计结束事件与 MODEL_USAGE.
- **存储并发**: 多个子运行同时结算, 会话 event_id 唯一且落盘有序, state.json 的
  last_event_id 指向最后成功事件; 不出现旧快照回写覆盖. 会话身份不符时拒绝写入.
- **事件交付**: 并发发布及订阅回调再次发布时, 每个订阅者与 JsonlRunStore 实际收到的
  同轮 sequence 严格递增且无重号; 订阅者异常不影响其他订阅者. 关闭时排空待分发事件.
  子不发 TURN_COMPLETED/CANCELLED/FAILED, 父恰好发一条终态; 子文本不混入父回答.
- **上下文与材料**: 子系统提示词与工具在相邻调用中保持字节稳定, 不断言供应商缓存
  命中. 正常/超时/取消/异常退出均尝试保存 agents/<agent_id>.json; 内容是退出窗口与
  诊断元数据, 不宣称保留已压缩原文; /resume 不读取它.
- **阶段 B**: 通过同步屏障证明三次 Agent 调用实际重叠执行, 避免只靠墙钟阈值判断;
  达到并发上限时后续调用排队, 取消排队不启动线程; 结果按请求序返回. 同批父只读
  工具与子 Agent 混合执行时, 事件、缓存与文件结果保持正确归属.

## 实现记录 (2026-09-21)

阶段 A 与有限并行阶段 B 已接线, 默认并发数 4。主要实现差异与落点：

- 模型选择通过内部 `ModelRequest.resolved_model` 固定到派发快照, 预算由同一快照构造;
  网关仍执行原有调用管线。子普通请求不进入响应缓存, 供应商前缀缓存不受影响。
- 执行前只读检查复用工具的 `is_read_only`, 白名单集中于 `core/agent/sub_agent.py`;
  首版只有这一份定义, 未单独建立仅含一个常量的 definitions.py。
- 增加 `SUB_AGENT_STOPPING` 支持延迟收尾展示; 开始/结束事件仍是生命周期配对依据。
- 凭证池及冷却存储、响应缓存和熔断状态补齐互斥; 模型网络调用本身不串行化。
  LSP 保留已有客户端锁, Bash 执行器的进程与输出预算按调用创建。
- 工具并发线程复制 contextvars, 子工具日志与事件都保留 agent_id。
- 回归使用假网关和临时目录, 包括真实主循环派发/读工具/返回报告、沙箱开启只读检查、
  取消/超时/配额、模型快照、压缩归属、有序事件和并发会话写入。前端补充 reducer 测试。
  未用真实供应商进行付费端到端验证; 协作取消不承诺强制终止卡住的第三方调用。
