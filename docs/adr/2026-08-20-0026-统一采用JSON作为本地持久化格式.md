# ADR-0026：统一采用 JSON 作为本地持久化格式

## 状态

Accepted

## 日期

2026-08-20

## 背景

Forge 的落盘格式长期是两套并行的：会话事件与状态用 JSON（`events.jsonl` / `state.json`
/ 恢复清单），而配置、项目索引、学习规则、计划与待办用 TOML（经 `tomlkit`）。

选 TOML 的原始理由是"人机共编"：用户会手写 `llm.toml`，`tomlkit` 的 round-trip 能保住
用户写的注释与排版。这条理由在终端时代成立，但两件事让它失效了：

1. **ADR-0025 之后，配置的主入口是 Web 控制面**，不是手写文件。设置页、模型页、工作区
   授权页都在改这些文件，用户手写并保留注释的场景已经不是主路径。
2. **两套格式各带一套解析与写入代码。** `toml_io` + 五个 `Toml*Store` 与
   `session/json_io` + 两个 Json store 并存，各有一套"读不到怎么办""怎么原子写"的实现。
   同一个仓库里回答两遍同一个问题，两边迟早会不一致。

附带的第三点：`tomlkit` 的文档模型（`Table` / `InlineTable` / `AoT`）会渗进 store 的实现，
读写两端都要在值对象与 tomlkit 容器之间来回转换，比 `dict` 多一层没有收益的间接。

## 决策

**Forge 自身的全部持久化改为 JSON，删除 tomlkit 依赖与全部 TOML 读写代码。**

1. 新增 `infrastructure/json_io`，承担所有持久化文档的解析、序列化与原子写；解析与 IO
   失败统一翻成 `ConfigReadError`。`infrastructure/session/json_io` 保留自己的读取入口，
   因为它把失败翻成 `SessionStateError`——两处的错误语义不同，合并只会让调用方分不清该
   catch 什么。
2. 落盘文件重命名：`config.toml` → `config.json`，`llm.toml` → `llm.json`，
   `forge.toml` → `forge.json`，`projects/index.toml` → `index.json`，
   学习规则 `<workspace_id>.toml` → `.json`，计划 `r<N>.toml` → `r<N>.json`，
   计划索引与待办同理。计划的 `r<N>.md` 派生视图不变。
3. store 类随之更名：`TomlConfigStore` → `JsonConfigStore`，`TomlLlmConfigStore` →
   `JsonLlmConfigStore`，`TomlProjectIndexStore` / `TomlProjectConfigStore` →
   `Json*`，`TomlLearnedRuleStore` → `JsonLearnedRuleStore`，
   `TomlModelOverridesStore` → `JsonModelOverridesStore`。
4. **不做迁移，不读旧文件。** 旧的 `.toml` 留在磁盘上不会被读取，也不会被删除；用户在
   Web 里重新配置一次即可。这是 MVP 阶段的显式取舍。
5. `pyproject.toml` 与 `.claude/` 等 Python 生态与工具链文件仍是 TOML——它们不是 Forge
   的持久化，格式由外部标准决定，不在本决策范围内。

写入语义保持不变：读出整份文档 → 局部修改 → 先写临时文件再 `replace`。因此
`forge.json` 里 `ConfigService` 与 `JsonModelOverridesStore` 各写各的键，互不覆盖，与
原来 round-trip 的效果一致。丢掉的只有注释——JSON 没有注释，而配置的说明本来就该在
文档与 Web 界面里，不在用户机器上某个文件的注释里。

## 影响

- 用户已有的 `~/.forge/*.toml` 与项目 `forge.toml` 不再生效，需要重新配置一次。
- `llm.json` 仍然可以手写，只是不能写注释。
- 依赖减少一个（`tomlkit`）。
- ADR-0005 / ADR-0008 / ADR-0013 / ADR-0022 里关于"TOML"的表述由本 ADR 取代；那些 ADR
  的决策本身（应用配置与项目配置分离、规则只存哈希、计划分文件存放）都不受影响——它们
  约束的是**存什么**，不是**用什么格式存**。

## 验收标准

- 仓库内不再出现 `tomlkit` 依赖与 `import tomlkit`。
- `forge` 首启能写出 `config.json` / `projects/index.json` / `forge.json` 并正常读回。
- 计划、待办、学习规则、模型配置的读写往返测试全部通过。
- `make ci` 全绿。
