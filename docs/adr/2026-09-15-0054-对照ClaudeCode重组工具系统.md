# ADR-0054: 完全仿照 Claude Code 重写工具系统

## 状态

Proposed (2026-09-15; 2026-09-16 起工作区里有一版实现, 见"影响"末段)

取代 ADR-0004 (将工具系统作为一等运行时) 全部, ADR-0029 (按动作重组工具模块),
ADR-0044 (把工具实现的机械动作上收到统一管线), ADR-0015 (首次破坏性写入屏障与独立
工作区恢复机制), 以及 ADR-0027 里"执行前复核文件状态绑定"的部分. 权限侧的对应改动在
ADR-0055, 两份 ADR 一起生效.

## 日期

2026-09-15

## 背景

### 借鉴对象与"完全仿照"的含义

2026-03-31 Claude Code 的 TypeScript 源码随 source map 发布到 npm, 本地有一份
(`../claude-code-analysis/`, 源码在 `src/`, 分析在 `analysis/`). 下面提到它的文件时,
路径相对 `claude-code-analysis/src/`.

本文的口径是**同一套设计换一种语言写**: 同样的 `Tool` 协议成员与缺省值, 同样的执行链
与每一步的失败形状, 同样的并发分批, 同样的结果落盘, 同样的内置工具与它们对协议问题的
回答. 与 Claude Code 不同的地方只有最后一节那一张表, 表外的一律以 Claude Code 为准;
本仓库既有 ADR 与本文冲突时以本文为准.

### Claude Code 的工具系统

| 组成 | 文件 | 做什么 |
|---|---|---|
| 协议对象 | `Tool.ts:362` `Tool`, `Tool.ts:757` `buildTool` | 一个工具要回答的全部问题; 缺省值保守 (`isConcurrencySafe` / `isReadOnly` / `isDestructive` 都是 false) |
| 执行上下文 | `Tool.ts` `ToolUseContext` | 工具池, 权限上下文的读写, `abortController`, `readFileState`, 当前消息 |
| 工具池 | `tools.ts:193` `getAllBaseTools`, `:271` `getTools`, `:345` `assembleToolPool` | 内置清单 (按开关增减), 按 deny 规则过滤, 与 MCP 工具合并去重 |
| 执行链 | `services/tools/toolExecution.ts:337` `runToolUse`, `:599` `checkPermissionsAndCallTool` | schema 校验 -> `validateInput` -> PreToolUse hook -> 权限 -> `call` -> PostToolUse hook -> `tool_result` |
| 调度 | `services/tools/toolOrchestration.ts:91` `partitionToolCalls` | 按 `isConcurrencySafe` 分批, 并发上限 10 |
| 结果落盘 | `utils/toolResultStorage.ts` | 超过 `maxResultSizeChars` (上限 50000) 存文件, 回给模型 2000 字节预览与路径 |
| 读过的文件 | `utils/fileStateCache.ts` `FileStateCache` | Read 记下内容与时间戳, Edit / Write 据此要求"先读再改"并发现读后被改 |
| 文件历史 | `utils/fileHistory.ts` | 每条 assistant 消息一个快照, `/rewind` 回退 |
| hook | `services/tools/toolHooks.ts` | 用户配置的 PreToolUse / PostToolUse 命令, 能 allow / deny / ask / 改入参 / 加上下文 |
| 内置工具 | `tools/<Tool>/` | `<Tool>.ts` 协议对象, `prompt.ts` 给模型的说明, `UI.tsx`, 其余是只有这个工具用的函数 |

安全属性由**工具自己**回答: `isReadOnly(input)`, `isDestructive(input)`,
`isConcurrencySafe(input)`, `checkPermissions(input, context)`. 框架只做两件事: 按固定
顺序问, 以及把回答变成模型看得到的 `tool_result`. 权限的通用部分 (规则, 模式, 询问) 在
`utils/permissions/`, 每个工具认识它并调用它 —— Edit 直接判 `mode === 'acceptEdits'`
(`utils/permissions/filesystem.ts:1205`), Bash 自己解析命令与匹配规则
(`tools/BashTool/bashPermissions.ts`).

### 本仓库现状与要删掉的东西

本仓库的工具系统建在另一套前提上 (ADR-0004): 工具不认识安全, 只在 `prepare` 里交出
一份 `ToolPlan` (能力集合, 触达路径, 目标封闭度), 安全模块按能力分派分析器裁决, 签发
`ExecutionAuthorization`, `ToolRuntime.execute` 校验之后才调 `perform`. 由此派生的概念:
`ToolSpec.declared_capabilities` (能力上界), `TargetDeclarationAbility` /
`TargetResolution` (目标封闭度), `Capability` 闭集, `PlanEffects`, `AnalysisSubject`,
`FileStateBinding`, `validate_narrowing`, `ToolCatalog.catalog_snapshot_hash`,
`ResourceGovernor`, `ArtifactPolicy` 溢写与 `artifact_read` 工具.

这一套的代价是每个工具要先把"自己会碰什么"翻译成一份中间事实, 安全模块再把它翻译回
"要不要问人"; 两次翻译各有一张词汇表, 加一种判断要两边同时改. Claude Code 没有中间
事实: 工具直接回答"要不要问人", 框架只管顺序. 本文按后者重写, 上面列的概念全部删除,
不保留兼容层.

## 决策

### 1. `Tool` 协议: 与 `Tool.ts` 同一组成员, 同一组缺省值

`tools/tool.py`:

```python
class Tool(ABC):
    # ---- 给模型的说明 ----
    name: str                                  # 稳定名, 见决策 2
    input_schema: Mapping[str, object]         # JSON Schema; 缺 zod, 用 jsonschema 校验
    output_schema: Mapping[str, object] | None = None
    strict: bool = False                       # 发给模型时置 strict
    def description(self, input, options) -> str      # 随入参变 (Bash 用 input.description)
    def prompt(self, options) -> str                   # 长说明, 进系统提示词的工具段

    # ---- 运行控制 ----
    max_result_size_chars: int                 # 必填. 超过就落盘 (决策 5)
    def is_enabled(self) -> bool: return True
    def interrupt_behavior(self) -> InterruptBehavior: return InterruptBehavior.BLOCK
    def requires_user_interaction(self) -> bool: return False

    # ---- 安全属性 (缺省全部保守) ----
    def is_concurrency_safe(self, input) -> bool: return False
    def is_read_only(self, input) -> bool: return False
    def is_destructive(self, input) -> bool: return False
    def is_search_or_read_command(self, input) -> SearchOrRead | None: return None
    def get_path(self, input) -> str | None: return None
    def prepare_permission_matcher(self, input) -> Callable[[str], bool] | None: return None
    def check_permissions(self, input, context) -> PermissionResult:
        return PermissionAllow(updated_input=input)    # 与 buildTool 缺省同: 安全来自每个工具覆盖它

    # ---- 校验与规范化 ----
    def validate_input(self, input, context) -> ValidationResult: return ValidationResult(ok=True)
    def backfill_observable_input(self, input: dict) -> None: pass   # 在副本上补派生字段, 幂等
    def inputs_equivalent(self, a, b) -> bool: return a == b

    # ---- 展示 ----
    def user_facing_name(self, input) -> str: return self.name
    def get_activity_description(self, input) -> str | None: return None
    def get_tool_use_summary(self, input) -> str | None: return None

    # ---- 执行 ----
    @abstractmethod
    def call(self, input, context, can_use_tool, parent_message, on_progress=None) -> ToolResult
    @abstractmethod
    def map_tool_result_to_block(self, output, tool_use_id) -> ToolResultBlock
```

配套类型 (`tools/tool.py`):

```python
@dataclass(frozen=True)
class ValidationResult:          # validateInput 的返回
    ok: bool
    message: str = ""
    error_code: int = 0
    behavior: str = ""           # "ask": 校验失败但应作为 ask 而不是错误呈现 (Edit 用)
    meta: Mapping[str, object] = MappingProxyType({})

@dataclass(frozen=True)
class ToolResult:                # call 的返回
    data: object
    new_messages: tuple[ChatMessage, ...] = ()
    context_modifier: Callable[[ToolUseContext], ToolUseContext] | None = None

class ToolUseContext:            # 执行上下文总线, 一次 turn 内共用
    options: ToolUseOptions      # tools (当前工具池), model, debug, non_interactive, commands
    abort: CancelToken
    read_file_state: FileStateCache
    file_history: FileHistory
    messages: Sequence[ChatMessage]
    def get_app_state(self) -> AppState          # 含 tool_permission_context
    def set_app_state(self, update) -> None
    cwd, environment, workspace_roots            # 原 ExecutionContext 里还有用的三项
    executor: CommandExecutor                    # 起子进程 (带围栏)
    prompts: HumanPromptService                  # ask_user 与审批共用 (ADR-0043)
```

成员对照, 只列有出入的:

| Claude Code | 本仓库 | 说明 |
|---|---|---|
| `inputSchema` (zod) / `inputJSONSchema` | `input_schema` (JSON Schema) | Python 没有 zod; 校验用 jsonschema, 错误文本按 `formatZodValidationError` 的形状拼 |
| `renderToolUseMessage` 等 5 个界面方法 | 无 | 展示由运行事件流承担 (ADR-0016); 事件 payload 里带 `user_facing_name` / `get_activity_description` / `get_tool_use_summary` 的返回 |
| `toAutoClassifierInput` | 无 | 没有分类器 (ADR-0055 差异表) |
| `isMcp` / `mcpInfo` / `shouldDefer` / `alwaysLoad` | 无 | 没有 MCP 与延迟加载; 接 MCP 时按 `assembleToolPool` 的规则加回 |
| `call` 是 async, 返回 Promise | 同步方法, 并发批走线程池 | 决策 4 |

其余成员一一对应, 缺省值同 `TOOL_DEFAULTS`.

### 2. 工具池: `get_all_base_tools` / `get_tools` / `assemble_tool_pool`

`tools/pool.py` 三个函数, 与 `tools.ts` 同名同序:

```python
def get_all_base_tools() -> tuple[Tool, ...]           # 内置总表, 按开关增减 (LSP 要 lsp.enabled)
def get_tools(permission_context) -> tuple[Tool, ...]  # 去掉整工具 deny 规则命中的, 去掉 is_enabled() 为假的
def assemble_tool_pool(permission_context, external_tools=()) -> tuple[Tool, ...]
    # get_tools + 外部工具 (先按 deny 规则过滤) -> 各按名字排序 -> 按名字去重, 内置优先
```

`find_tool_by_name(tools, name)` 认主名与 `aliases`.

**工具名用 Claude Code 的名字**: `Read`, `Edit`, `Write`, `Glob`, `Grep`, `LSP`, `Bash`,
`TodoWrite`, `AskUserQuestion`. 理由有两条: 权限规则的写法 `Bash(git commit:*)`,
`Edit(src/**)` 与 Claude Code 的设置文件逐字相同, 用户手里的规则能直接搬; 模型对这几个
名字与它们的入参形状已经很熟. 本仓库自有的工具 (`plan_read`, `plan_write`,
`todo_set_status`, `memory_write`, `memory_forget`) 保留原名. 名字的合法形状放宽为
`[A-Za-z][A-Za-z0-9_]*`. 旧名进 `aliases`: `Read` 认 `file_read` 与 `fs_read`, `Grep`
认 `search_text`, `Bash` 认 `shell_run`.

`ToolCatalog` 与 `catalog_snapshot_hash` 删除. 模式不再决定目录: plan 档下写工具照样在
池里, 请求了就按 ADR-0055 的规则 ask —— 与 Claude Code 同 (它的 plan 模式靠系统提示词
说明加权限层的 ask, 不从池里摘工具).

### 3. 执行链: `run_tool_use`, 九步, 每一步的失败都是一条 `tool_result`

`tools/execution.py::run_tool_use(tool_use, context, can_use_tool, parent_message)`, 与
`checkPermissionsAndCallTool` 同序:

| # | 步骤 | 失败时回给模型的 `tool_result` (`is_error=True`) |
|---|---|---|
| 1 | `find_tool_by_name` | `No such tool available: <name>` |
| 2 | jsonschema 校验 `input_schema` | `<tool_use_error>InputValidationError: <字段与原因>\</tool_use_error>` |
| 3 | `tool.validate_input(input, context)` | `<tool_use_error><message></tool_use_error>`; `behavior="ask"` 的校验失败同样作为错误回流, 只是措辞是"请先 ..." |
| 4 | `backfill_observable_input` 在副本上跑; 副本给 hook 与权限看, 原件给 `call` | 无 |
| 5 | PreToolUse hook (决策 6) | hook deny: `<hook 的 reason>`; hook 报错: 照常继续 |
| 6 | `can_use_tool(tool, input, context)` (ADR-0055 决策 4) | deny: `<decision.message>`; ask 之后用户拒绝: `The user doesn't want to proceed with this tool use. The tool use was rejected (eg. if it was a file edit, the new_string was NOT written to the file). STOP what you are doing and wait for the user to tell you how to proceed.` |
| 7 | `tool.call(input, context, can_use_tool, parent_message, on_progress)` | 异常经 `classify_tool_error` 归成一句, `is_error=True`; 取消是 `Tool execution was cancelled` |
| 8 | PostToolUse hook | hook 的 `additional_context` 追加成一段文字; 不能改结果 |
| 9 | `map_tool_result_to_block` -> 超长落盘 (决策 5) -> `tool_result` | 无 |

第 6 步允许 `updated_input` (权限层或 hook 改过的入参) 顶掉原件, 之后 `call` 用它 ——
Claude Code 的 `getUpdatedInputOrFallback`. 一次 `tool_use` 只产生一条 `tool_result`,
`tool_use_id` 对应; 中间事件 (进度, 权限询问) 走运行事件流.

删除的: `ToolRequestCoordinator`, `ToolRuntime`, `CoordinatorToolDispatcher`,
`ToolObservation` 与 `ObservationKind` 十四种结论. Claude Code 只有一种失败形状 ——
`is_error` 的 `tool_result` 加一句话, 模型按话的内容决定下一步.

### 4. 调度: 按 `is_concurrency_safe` 分批, 并发上限 10

`tools/orchestration.py`:

```python

    # 连续为 True 的合成一批 (concurrent), 其余各自一批 (sequential).
def run_tools(tool_uses, context, can_use_tool, parent_message) -> Iterator[ToolUseUpdate]

    # 结果按完成序发出, 靠 tool_use_id 对应; context_modifier 攒到整批结束后按序施加.
```

与 `partitionToolCalls` / `runTools` 同. 循环 (`agent/loop/builtin_loop.py`) 的
`_run_batch` 把一整批 `tool_calls` 交给 `run_tools`, 不再逐个 `execute`; ADR-0051 的
"循环只认识一个入口"照旧, 入口从 dispatcher 换成 `run_tools`.

`Read` / `Glob` / `Grep` / `LSP` 回答 `True`; `Bash` 回答 `is_read_only(input)`; 其余
`False`. 线程安全要补的: `AgentRunEventBus.publish`, `FileStateCache`, `FileHistory`,
`LspServerPool` 各加锁.

### 5. 结果落盘, 读过的文件, 文件历史

**结果落盘** (`tools/result_storage.py`, 对应 `toolResultStorage.ts`): `tool_result` 的
文本超过 `min(tool.max_result_size_chars, 50_000)` 时写到
`~/.forge/projects/<id>/sessions/<session>/tool-results/<tool_use_id>.txt`, 回给模型
前 2000 字节的预览, 包在 `<persisted-output>` 里并附路径, 模型用 `Read` 读全文.
`max_result_size_chars` 为无穷的工具 (Read) 永远不落盘 —— 落盘之后让模型再用 Read 读
一遍是循环. 取代 `ArtifactPolicy`, `FsArtifactStore` 与 `artifact_read` 工具.

**读过的文件** (`tools/file_state.py`, 对应 `fileStateCache.ts`): LRU, 100 条 / 25 MB;
每条 `FileState(content, timestamp, offset, limit, is_partial_view)`. `Read` 写它,
`Edit` / `Write` 的 `validate_input` 读它: 没读过 -> "File has not been read yet. Read it
first before writing to it."; 读后文件的 mtime 变了且内容不同 -> "File has been modified
since read ... Read it again". 这是 Claude Code 对 TOCTOU 的全部处理, 本仓库照做, 不再
有 `FileStateBinding` 与执行前统一复核.

**文件历史** (`tools/file_history.py`, 对应 `fileHistory.ts`): `Edit` / `Write` 落盘前
调 `file_history.track_edit(path)` 备份原件; 每条 assistant 消息开始时
`make_snapshot(message_id)`; `/rewind` 回到某条消息之前的文件状态; 快照上限 100.
取代 ADR-0015 的 `RecoveryCoordinator` 与 `/undo`. Bash 改的文件不在历史里 —— 与
Claude Code 同.

### 6. hook: PreToolUse / PostToolUse, 用户配置的外部命令

`tools/hooks.py`, 对应 `toolHooks.ts`. 配置在 `forge.json` / `config.json` 的 `hooks`
段, 形状与 Claude Code 的 `settings.json` 同:

```json
{"hooks": {"PreToolUse": [{"matcher": "Bash", "hooks": [{"type": "command", "command": "./scripts/check.sh"}]}]}}
```

`matcher` 按工具名匹配 (正则); hook 命令从 stdin 读 JSON (`tool_name`, `tool_input`,
`cwd`, `session_id`), 退出码 0 通过, 2 是 deny (stderr 是给模型的理由); stdout 里的
JSON 可以带 `permissionDecision` (allow / deny / ask), `updatedInput`, `additionalContext`.
hook 的 allow **不**越过 deny / ask 规则 (`toolHooks.ts:324` 的不变量): hook 说 allow
之后仍然过一遍 `check_rule_based_permissions`. 超时缺省 10 分钟
(`TOOL_HOOK_EXECUTION_TIMEOUT_MS`), 每条 hook 可以自己配 `timeout` (秒); 超时按没表态算.

### 7. 内置工具: 与 Claude Code 同名, 同入参, 对协议问题给同样的回答

| 工具 | 入参 | `is_read_only` | `is_concurrency_safe` | `max_result_size_chars` | `check_permissions` |
|---|---|---|---|---|---|
| `Read` | `file_path`, `offset?`, `limit?`, `pages?` | True | True | 无穷 | `check_read_permission_for_tool` |
| `Edit` | `file_path`, `old_string`, `new_string`, `replace_all?` | False | False | 100_000 | `check_write_permission_for_tool` |
| `Write` | `file_path`, `content` | False | False | 100_000 | `check_write_permission_for_tool` |
| `Glob` | `pattern`, `path?` | True | True | 100_000 | `check_read_permission_for_tool` (对 `path`) |
| `Grep` | `pattern`, `path?`, `glob?`, `type?`, `output_mode?`, `-n?`, `-i?`, `-A?` / `-B?` / `-C?` / `context?`, `multiline?`, `head_limit?`, `offset?` | True | True | 20_000 | `check_read_permission_for_tool` (对 `path`) |
| `LSP` | `operation`, `filePath`, `line`, `character`, `query?` | True | True | 100_000 | `check_read_permission_for_tool` |
| `Bash` | `command`, `timeout?` (毫秒, 缺省 120000, 上限 600000), `description?`, `run_in_background?`, `dangerously_disable_sandbox?` | `check_read_only_constraints` | `= is_read_only` | 30_000 | `bash_tool_has_permission` |
| `TodoWrite` | `todos` | False | False | 100_000 | 缺省 allow |
| `AskUserQuestion` | `questions` | True | False | 100_000 | 缺省 allow; `requires_user_interaction=True` |
| `plan_read`, `plan_write`, `todo_set_status`, `memory_write`, `memory_forget` | 不变 | `plan_read` True, 其余 False | 同左 | 100_000 | 缺省 allow |

各工具的 `validate_input` 与 `call` 照 Claude Code 的实现写, 要点:

- **`Read`**: `validate_input` 查 read deny 规则, 拒二进制扩展名, 拒会阻塞的设备文件;
  文件总大小上限 256 KB (超了报错, 让模型用 `offset` / `limit`); 缺省 2000 行, 单行
  超 2000 字符截断; 输出每行 `行号→内容`; `call` 之后写 `FileStateCache`. 空文件给一条
  系统提醒而不是空串.
- **`Edit`**: `validate_input` 依次: `old_string == new_string` 报错; edit deny 规则;
  文件大小上限; 文件不存在 (`old_string` 为空视为新建, 否则报错并给 "Did you mean"
  建议); 未读过 / 读后被改 (决策 5); `find_actual_string` 做引号归一化后定位; 多于一处
  且 `replace_all` 为假报错并要求更多上下文. `call` 施加, 写盘保留原编码与换行, 更新
  `FileStateCache`, 记文件历史. 保留本仓库的 `matching.py` 容差层 (行尾空白, 缩进偏移)
  放在 `find_actual_string` 之后 —— 这是差异表里的一条.
- **`Write`**: 已存在的文件要求先读且未被改; 父目录按需建; 记文件历史.
- **`Glob`**: `path` 必须存在且是目录; 结果按 mtime 从新到旧, 超过上限截断并提示.
- **`Grep`**: 调 `rg`, 入参与 Claude Code 的 GrepTool 一致 (三种 `output_mode`,
  `head_limit` 缺省 250); 没装 rg 时 `validate_input` 报错说明用 `Bash grep`.
- **`LSP`**: 九种 `operation`, 位置 1 起算; 服务器池按语言各养一个, 项目关闭时关掉.
- **`Bash`**: `is_read_only` 由 `read_only_validation.py` 回答 —— 一张只读命令表
  (`ls`, `cat`, `git status`, `git log` 等) 加逐命令的安全参数校验, 带 `cd` 与 `git` 的
  复合命令不算只读; `check_permissions` 见 ADR-0055 决策 5; `call` 经 `CommandExecutor`
  起子进程 (围栏, ADR-0030), `run_in_background` 起后台任务返回 `backgroundTaskId`;
  stdout / stderr 合并超 30_000 字符落盘.
- **`AskUserQuestion`**: 经 `HumanPromptService` 摆卡片 (ADR-0043 不变).

目录布局与 Claude Code 一致, 一个工具一个目录:

```
tools/builtin/<Tool>/
├── __init__.py       只有 docstring
├── tool.py           <Tool>Tool: 协议对象的全部成员          (= <Tool>.ts)
├── prompt.py         DESCRIPTION 与 PROMPT                    (= prompt.ts)
└── <helpers>.py      只有这个工具用的函数
```

`Bash/` 下与 Claude Code 同名的内部模块: `bash_permissions.py`, `read_only_validation.py`,
`mode_validation.py`, `path_validation.py`, `bash_security.py`, `sed_validation.py`,
`should_use_sandbox.py`, `destructive_command_warning.py`, `utils.py`. `Edit/` 下
`utils.py` (`find_actual_string`, `apply_edit`), `constants.py`; `Read/` 下 `limits.py`;
`LSP/` 下 `schemas.py`, `formatters.py`, `symbol_context.py`, 以及本仓库已有的
`client.py`, `pool.py`, `servers.py`.

给模型的说明 (`prompt.py`) 按 Claude Code 的原文翻译, 不另起草: 那些说明与工具的行为
是一起调出来的.

### 8. 与 Claude Code 的差异

| 差异 | 理由 |
|---|---|
| 没有界面渲染方法, 展示走运行事件流 | 本仓库的终端与 Web 都是事件流的消费方 (ADR-0016), 工具不认识界面 |
| 没有 `toAutoClassifierInput`, 没有 auto 模式分类器 | 见 ADR-0055 差异表 |
| 没有 MCP, 没有延迟加载 / ToolSearch, 没有 `StreamingToolExecutor` | 本仓库没有这三个前提 (MCP 客户端, 工具多到要搜, 边收边跑的模型网关); `assemble_tool_pool` 留了 MCP 的位置 |
| `call` 是同步方法, 并发批走线程池 | Python 与同步的模型网关 |
| `Edit` 的定位多一层容差 (行尾空白, 整块缩进偏移) | 本仓库的实测: 这一层省掉大半的"定位失败 -> 重读 -> 再失败"; 命中时如实回报 |
| `Bash` 的子进程经围栏 (ADR-0030 的 `FencePolicy` + `CommandExecutor`) | 这就是 Claude Code 的 sandbox (`utils/sandbox/`), 只是实现在本仓库已经有了 |
| 工具名之外的自有工具 (`plan_*`, `todo_set_status`, `memory_*`) | Claude Code 的对应物是 EnterPlanMode / ExitPlanMode 与 auto memory, 本仓库的计划评审流程 (ADR-0023 / ADR-0038) 不在本文范围 |

## 备选方案

- **保留 `ToolPlan` 与能力分派, 只补协议成员** (本文上一稿): 两套判断并存 —— 工具回答
  `is_read_only`, 分析器再从计划推一遍能力; 每加一种判断改两处. 用户的决定是不保留.
- **工具名沿用 `file_read` / `shell_run`**: 规则文件与 Claude Code 不通用, 模型要重新
  学一遍名字与入参; 只省下改事件与前端里的名字.
- **保留 `ObservationKind` 十四种结论**: 模型看的是文字, 循环按 kind 分流的那几条
  (人拒绝了不许换说法重试) 由 Claude Code 的那句固定措辞承担 —— 它就是给模型的指令.

## 验收标准

- `Tool` 的每个非抽象成员都有与 `TOOL_DEFAULTS` 相同的缺省值; 一个只实现 `call` 与
  `map_tool_result_to_block` 的工具能注册并按"不并发, 非只读, 缺省 allow"跑通.
- `run_tool_use` 对未知工具, schema 不过, `validate_input` 不过, hook deny, 权限 deny,
  用户拒绝, `call` 抛异常, 取消, 八种情形各回一条 `is_error` 的 `tool_result`, 文字与
  决策 3 的表一致, 且每次只有一条.
- 一轮里 `[Read, Glob, Edit, Grep]` 分成 `[Read, Glob]`, `[Edit]`, `[Grep]` 三批, 第一批
  两个 `call` 在不同线程上跑; `Bash ls` 与 `Bash rm x` 分别落在并发批与串行批.
- `Edit` 一个没读过的文件报 "File has not been read yet"; `Read` 之后外部改动再 `Edit`
  报 "modified since read"; `Read` 之后 `Edit` 成功并出现在 `/rewind` 的快照里.
- `Bash` 输出 40_000 字符时 `tool_result` 是 2000 字节预览加路径, 文件在
  `tool-results/` 下; `Read` 输出再长也不落盘.
- `forge.json` 里的 PreToolUse hook 退出码 2 时模型收到 stderr 的文字, 工具没有执行;
  hook 说 allow 但 `Bash(rm:*)` 在 deny 规则里时仍然 deny.
- 九个同名工具的 `input_schema` 与 Claude Code 对应工具的 `inputSchema` 字段集相同.
