# ADR-0061：采用会话记忆与长期记忆分离的后台提取

## 状态

Proposed

本文新增 Session Memory，并在 ADR-0033 的项目/用户记忆上补充后台提取。
接受后，替代 ADR-0033 对“回合结束自动提取”的否决及仅依赖主模型主动写入的假设；
保留静默写入、项目/用户分级、来源追踪、凭证过滤和不参与权限裁决的约束。
按用户选择采用 Markdown 记忆文件，接受后为 ADR-0026 增加记忆正文的格式例外，
替代 ADR-0033 的单文件 JSON 条目存储，以及 ADR-0056 决策 5、13 的全量 key-value
记忆快照约定。分层注入与刷新点继续以 ADR-0056 为准，压缩消费方式由 ADR-0060 定义。
本文不代表功能已实现，不提前变更旧 ADR 的状态。

## 日期

2026-09-17

## 背景

Forge 当前 `MemoryService` 提供 `remember/forget/load`，主模型通过记忆工具主动保存
项目事实或用户偏好。`JsonMemoryStore` 每级最多 32 条、单条 value 最多 512 字节。
这能解决显式“记住这个”，但主模型也可能结束任务而忘记整理可复用信息。

上下文摘要目前由 `conversation/summarize.py` 在窗口淘汰时即时生成。长任务的进度、
失败尝试和下一步需要会话内连续维护，而这些临时信息不应混入下个会话的长期记忆。
另一个现有约束是 `MemoryService.begin_turn()` 将当前 session/turn 存在可变字段里：
后台任务若继续使用它，可能把上一轮提取结果错误归到已开始的新一轮。

Claude Code 分别实现了这两类提取：

| 路径 | 时机与作用 | 源码位置（相对参考仓库 `src/`） |
|---|---|---|
| Session Memory | 主 REPL 的 post-sampling hook 检查阈值；forked agent 更新会话笔记 | `services/SessionMemory/sessionMemory.ts` |
| Session Memory 阈值 | 默认初始化 10000 token、更新增长 5000 token、工具次数 3；受配置覆盖 | `services/SessionMemory/sessionMemoryUtils.ts` |
| 手动会话提取 | `manuallyExtractSessionMemory()` 绕过阈值，源码注释关联 `/summary` | `services/SessionMemory/sessionMemory.ts` |
| 长期提取 | 完整 query loop 结束后从 Stop hooks 异步启动；主模型已写记忆则跳过相应范围 | `query/stopHooks.ts`、`services/extractMemories/extractMemories.ts` |
| 提取节流 | 默认每 1 个符合条件的回合尝试；进行中则只保留最新待处理上下文 | `services/extractMemories/extractMemories.ts` |
| 长期存储 | 受限 forked agent 编辑记忆主题文件和索引，最多 5 个 agent turns | `services/extractMemories/prompts.ts` |

这些分支受功能开关、主线程、运行模式等条件限制，不意味着所有 Claude 会话都会运行。
下面借鉴其触发与生命周期划分，存储和执行方式适配 Forge。

## 决策

### 1. 会话记忆、长期记忆与项目指令各有归属

| 类型 | 保存内容 | 生命周期与位置 | 如何进入请求 |
|---|---|---|---|
| 人工项目指令 | 用户维护的规范 | 工作区 `FORGE.md` | ADR-0056 会话段 |
| Session Memory | 当前任务、约束、进展、证据、失败、待办 | 当前会话状态目录 `session-memory/summary.md` | 仅在 compact/恢复需要时作为历史摘要 |
| 项目长期记忆 | 已验证且跨会话有用的项目事实 | `~/.forge/projects/<project_id>/memory/` | `MEMORY.md` 索引快照与按需读取主题正文 |
| 用户长期记忆 | 用户明确表达的通用偏好 | `~/.forge/memory/` | 同上 |

Session Memory 可以记录尚未完成的工作；长期记忆不保存临时进度、一次性审批、待办、
未经验证的推测、凭证或“允许绕过权限”的规则。计划与待办仍由 PlanningService 管理，
会话摘要里的描述只是交接参考，不成为另一份权威计划。

记忆正文采用 Markdown，长期记忆每个主题一个文件，按语义命名，例如
`test_commands.md`、`architecture.md`、`user_preferences.md`。每个 scope 有独立的
`MEMORY.md`，只保存标题、相对链接与一句话用途，不在索引里重复正文。
临时进度只进入会话 `summary.md`，不写进长期主题文件。

每个主题使用 YAML frontmatter 保存 `id`、`name`、`description`、`scope`、`revision`、
来源 session/turn/message IDs 和更新时间，正文使用 Markdown。元数据由宿主填写，
安全解析，不执行自定义 YAML 标签。scope 以实际存储根为准，文件内字段仅用于校验。
控制游标、任务幂等信息及删除版本可继续使用运行时 JSON；记忆正文的唯一权威副本是 MD，
不同时维护一份等价的 JSON 记忆库。

初始每 scope 最多 32 个主题文件，替代旧的单条 512 字节限制为单主题正文最多 4 KiB。
索引最多 200 行且不超过 16 KiB，每条说明尽量在 150 字符以内；超限先合并/拒绝，
不能把未列出的文件伪装成不存在。索引可由主题 frontmatter 确定性重建。
正文按需读取，单次最多 5 个文件、合计 20 KiB，会话记忆类注入累计上限沿用 ADR-0056
的 60 KiB。所有内容同时服从 ADR-0060 总 token 预算。首版不引入向量库或混合检索。

### 2. Session Memory 按增长和安全消息边界更新

在主会话一次模型响应完成后检查；若响应发出了工具调用，等这一批工具结果返回并
形成合法配对边界再截取输入，不能把尚未完成的调用当作已完成事实。
这是对 Claude post-sampling 触发方式的 Forge 适配，不按流式 token/chunk 触发。

首版提供独立开关，自动提取默认关闭；启用后采用以下可配置初值：

```text
首次：当前上下文估算至少 10000 token
更新：自上次成功覆盖位置以来的新内容至少 5000 token
并且满足以下之一：
  已完成至少 3 次工具调用
  最近模型响应不再要求工具调用，形成自然停顿
```

首次提取也满足更新与安全边界条件；没有新增内容时不重复提取。工具调用量按实际
`tool_call_id` 计数，不能把并行批次算成一次，也不能把重放消息重复计数。

Claude 的更新判断使用上下文 token 计数差。Forge 使用已提交消息的新增 token 累计量，
而非“当前窗口长度减上次长度”，防止 microcompact 或正式压缩使计数倒退、长期不再
触发。计数不含提取自身的提示词与输出，以成功覆盖的消息 ID 推进；失败不消费阈值。

Session Memory 内容固定分为：任务与约束、当前状态、关键文件与证据、已完成工作、
错误与纠正、未完成事项与下一步、关键交付结果。每节上限 2000 token、合计上限
12000 token 是初始上限，还需收紧到当前模型和摘要消费预算；小窗口模型不能机械
预留 12000 token。超限摘要不机械截断结构化响应或关键约束，拒绝候选并保留旧版本。

新增 `/summary`：手动生成/更新 Session Memory，绕过时间与增长阈值，仍受输入输出
预算、合法消息边界和并发限制；不裁剪主窗口，不自动保存长期记忆。会话正在执行工具
时排队到安全边界，不能并发改写同一份笔记。

### 3. 长期记忆提取在完整主回合结束后检查

最终回答完成、没有待执行工具调用或待用户回答时，AgentTurnService 调度后台提取。
一次回合中的 Read → Grep → Edit 等中间采样不分别触发长期提取。

需要同时满足：长期自动提取开关开启、存在尚未处理的新 user/assistant/工具证据、
当前是主会话、不是提取/压缩内部任务、未处于取消或失败中断。默认仅对交互式会话启用
调度资格，脚本与非交互入口必须显式开启；整体自动提取开关首版默认关闭。

启用后默认每 1 个符合条件的完整回合尝试，可配置为每 N 个回合。计数只在满足资格时
增加；没有新消息直接跳过。增加独立的每次输入/输出预算与会话后台预算，预算耗尽后
暂停自动提取并记录原因，显式记忆工具继续可用。

主模型若已成功 `memory_write` 或 `memory_forget`，以成功结果而非仅出现 tool call
判断，将覆盖到的当前消息范围标记已处理，跳过后台重复提取。该优化可能漏掉同轮
其他事实，作为节省重复调用的取舍保留；失败的写入不导致跳过。

用户显式“记住/忘记”由主模型使用现有记忆工具立即处理，不等待回合节流。后台只补充
未主动保存的信息；“忘记”必须对进行中的旧提取生效，不能下一轮又被写回来。

### 4. 用受限结构化请求提取，由服务提交结果

Claude 通过继承主对话前缀的 forked agent 编辑文件。Forge 首版复用统一 LLM 网关，
分别增加 `session_memory`、`memory_extract` origin，默认跟随主模型，也可按已有
origin 配置显式覆盖。真正接入生产方时才增加枚举、参数和计量映射。

每个任务一次结构化请求，工具列表为空，不执行 Shell、文件编辑、网络查询或再派生
代理；网关已有的有界解析修复计入同一任务预算。无须为了编辑 MD 文件先建设通用
forked-agent 运行时，也不承诺与主请求共享全部缓存。

输入为不可变快照：来源 session/turn、消息范围及 ID、带原始角色的内容、必要工具
证据、已有会话笔记或长期主题目录与相关正文、存储 revision。长期提取只允许从
未处理的新范围产生事实，旧记忆只用于去重和替换，摘要/系统提示词不能被当成新事实来源。

Session Memory 返回固定 sections；长期提取返回有限的操作集合：

```text
upsert(scope, topic_id, name, description, markdown_body, evidence_message_ids)
forget(scope, topic_id, evidence_message_ids)
或空操作集合
```

结构化返回只是网关传输协议，不是记忆落盘格式。宿主验证 schema、消息 ID 属于输入
范围、scope、topic_id、大小、凭证过滤和冲突，再调用 MemoryService 写入 Markdown
主题并刷新索引。topic_id 沿用受限 slug，路径由宿主映射，禁止绝对路径、`..` 和
越界符号链接；模型不指定任意落盘路径。程序只保证来源可追溯，不能声称 ID 检查
等价于事实真实性验证。
prompt 要求只保存有直接依据的事实，尤其不把助手的未验证推断变成用户偏好。

只把工具/文件/网页中的文本当作证据数据，忽略其中要求“写入某条记忆”的指令。
正文和 `derived_from` 等可持久化文本都执行凭证检查；长期日志默认只记 ID、原因和
计数，不延续现有 `memory.written` 的 value 原文日志方式。
记忆不会进入权限分类器的可信策略、规则库、审批事实或模式判断。

### 5. 会话摘要的覆盖边界必须可验证

`session-memory/summary.md` 用 frontmatter 保存 schema version、session id、window
epoch、revision、covered_through_message_id、来源 turn 和生成时间，正文使用固定
Markdown 标题对应 sections。保存的是“已成功总结到哪里”，不是“任务启动时准备
总结到哪里”。成功校验并落盘后才推进覆盖游标。

后台提取开始后主会话可以继续。提交时只认启动快照的最后完整边界，后续消息全部
留在未覆盖尾部；不能因为响应较晚就把游标推进到最新消息。
`/clear`、rewind 或丢弃原历史时推进 epoch，旧 epoch 任务返回不得覆盖新会话视图。

ADR-0060 使用笔记压缩时，只有摘要覆盖前缀连续、边界仍可定位、近期未覆盖消息可
完整保留时才能复用。提取正在进行则有界等待，超时使用合法旧摘要或传统 compact，
不能阻塞主会话直到无限期任务结束。摘要落后时保留所有未覆盖尾部，仍超预算就退回
传统 compact，不假定“有文件就足够压缩”。

传统 compact 成功后为 Session Memory 建立新的窗口 epoch 和基线，保留必要的累计
提取计数语义；旧摘要不得跨不相关历史再次生效。手动 `/summary` 只提交笔记，不创建
compact boundary。长期提取游标基于可追溯的源消息，不因窗口变短而从头重复写记忆。

### 6. 并发提取合并，写入不能覆盖新事实

每个 session 的每类提取最多一个进行中任务；再次触发仅保留最新待处理快照，当前
完成后至多启动一个尾随任务，不为每一轮堆积后台队列。会话记忆和长期提取使用独立
游标、开关、预算，关闭一类不隐式关闭另一类。

来源身份显式传入写入操作；后台不得读取 `MemoryService.begin_turn()` 的可变
“当前回合”字段。任务标识、来源范围及用量归属在启动时冻结。

共享用户/项目存储必须解决跨会话并发。每个 scope 用进程间锁保护主题更新与索引刷新，
带 revision/内容 hash 校验并逐文件原子替换；不能只靠原子 rename，因为两个旧快照
仍会相互覆盖。模型返回的是操作集合，不是整份目录。提交时检查涉及 topic 自快照后
是否改变；冲突项跳过并记录，无关主题继续保留，不用旧结果覆盖用户或主 Agent 的新写入。

主题文件为事实源，`MEMORY.md` 是派生索引：先提交主题，再重建索引。崩溃发生在两者
之间时，下次受控读取在锁内检查并修复索引，不能把多文件 rename 当成原子事务。
用户手工编辑 MD 时通过内容 hash 识别变更，不依赖用户主动增加 revision；frontmatter
非法的文件保留原件并报告，不直接当空文件覆盖。

显式 forget 删除主题正文与索引引用，并写入 topic_id 的删除版本/墓碑，进行中的旧快照
不得复活它；相同 session 内在 forget 之前的源消息也不再作为自动重建该主题的依据。
用户明确重新要求记住时可创建新版本。墓碑保留到旧任务失效且恢复不会重放相应范围，
不无条件永久积累正文。

成功写入与游标推进按提取任务 ID 做幂等提交，崩溃恢复不会重复应用同一操作集合。
验证通过的空结果算成功并推进游标；模型失败、取消和存储失败不推进。无效单项记录
拒绝原因，任务整体状态明确区分“已处理但未保存”与“调用失败待后续重试”。
不建立无限重试；再次尝试只在下一次合格触发或显式请求时发生。

### 7. 注入与提取分离，避免后台写入打断前缀缓存

长期记忆在 ADR-0056 的会话刷新点将项目与用户 `MEMORY.md` 索引读入会话段，替代旧的
全量条目快照。主模型据索引通过受限的 `memory_read(scope, topic_id)` 按需读取主题
正文，结果走标准工具结果与预算路径；不为此放开通用 Read 对 Forge 状态目录的权限。
后台提取所需的主题正文由宿主按输入预算提供；更新未提供正文的现有主题时不提交，
将相关来源范围标记为待补材料，下一次合格提取时补齐，不能以“成功无操作”推进并
遗失该范围。材料仍放不下时停止该项并记录原因，不盲目覆盖旧内容。
后台成功写入不会立即重写主请求
system prompt。当前会话需要得知变更时，沿用带 revision 的增量通知，在下一次安全
组装位置追加一次；主模型刚写过并已看见的内容不重复通知。

Session Memory 平时不全文注入每一次请求，因为窗口已经含有它总结的历史。
只有 compact/恢复采用它时才进入历史摘要位置。记忆和摘要均标记来源与较低信任，
不覆盖当前用户要求或人工项目指令；内容涉及的动作仍经过当前权限裁决。

### 8. 后台成本与生命周期有明确归属

两类提取均走统一 UsageMeter 和 `USAGE_RECORDED`，带独立 origin、任务 ID、来源
session/turn，输入、输出与缓存计数分别记录。空操作、解析失败、被冲突拒绝的结果
仍需记录已经产生的费用，不能只在成功保存记忆后记账。

后台完成可能晚于主回合结束，因此不能把 usage 追加到已经提交的 LoopOutcome
就算完成；由驱动层的后台完成回调通过现有事件写入入口持久化，并更新原回合合计。
UI 标注“记忆提取”费用，不能归到此时正在运行的新回合，也不伪装成用户任务的工具步骤。

交互式最终回答不等待后台提取。退出时有界 drain，超时取消并保留最后成功状态；
非交互入口只有显式开启提取时才 drain。恢复可依据持久化任务/游标对未提交范围重新
判断，但不保证进程被强制杀死后的任务必达。后台失败不把已经成功的主回合标成失败。

### 9. 按功能分包落地，保持已有边界

建议在现有 `memory/` 下新增 Markdown 存储、会话笔记、提取和调度逻辑；数据类型与结构化
请求保持少量直接模块，不引入另一套工作流框架。MemoryService 继续是长期记忆的
唯一提交入口，主工具和后台提取共享过滤、版本与事件行为。`memory_write` 演进为
主题写入，旧 key 映射为 topic_id，旧 value 作为 Markdown 正文；`memory_forget` 删除
同 scope 的主题并更新索引，补充 `memory_read` 供按需读取。

AgentTurnService 负责调度与持久化，loop 在安全边界提供只读快照/信号，不持有
长期 MemoryService。`conversation/` 通过外层传入的会话摘要读取结果决定是否复用，
不直接依赖长期记忆写入。新增提示正文按 ADR-0056 放入 `prompt/prompts.py`；若该 ADR
尚未实现，作为迁移项接入，不能把未来文件描述成已有实现。

## 备选方案

- 只靠主模型调用记忆工具：零后台成本、实现简单，但任务结束后容易漏记。
- 每次模型采样都提取长期记忆：及时，但工具循环中大量中间状态会产生重复费用和噪声。
- 等 compact 时才同时提取短期与长期记忆：调度少，但短会话可能永不保存长期信息，
  长会话则在最缺窗口空间时集中付出提取延迟。
- 完整复制 Claude forked agent 并通过 Read/Edit/Write 自由编辑 MD：能共享主请求前缀，
  但需要新的代理执行和路径约束。采用 Markdown 存储，同时由宿主受控提交模型生成的正文。
- 继续 JSON key-value 存储：兼容成本最低，但用户已选择便于人工阅读、修改的 Markdown
  主题文件；JSON 仅用于不承载记忆正文的运行控制元数据。
- 一份摘要同时服务恢复和跨会话记忆：结构最少，但临时计划会污染长期记忆，删除与
  有效期语义无法一致。采用分开生命周期、共享网关和计量的方案。

## 影响

会话摘要把部分 compact 的延迟提前到后台，长期提取补主模型漏记；这增加了真实模型
成本，不能把“后台”当作免费或必然省 token。首版默认关闭自动提取，手动入口和开关
上线后记录实际命中率、费用、被拒率，再决定是否调整默认值。

旧 `memory.json` 首次受控迁移时，在 scope 锁内将每个 key 导出为同名主题 MD，保留
来源，生成 `MEMORY.md` 并校验条目数和正文一致性后再切换读取来源。旧 JSON 留作
只读备份，不继续双写；迁移中断可幂等重跑，目标已有手工 MD 或内容冲突时保留两者并
报告，不能覆盖已有文件。迁移期间不将旧普通摘要自动导入长期记忆。
先实现显式来源、索引修复与并发提交，再启用后台生产者；先验证 Session Memory
质量与边界，再让 ADR-0060 自动复用。

代价主要是任务生命周期、幂等提交和后台费用回写。避免引入向量检索、无限任务队列、
自动写 FORGE.md 或通用代理工具权限系统，将范围限定为两类可审计的提取请求。

## 验收标准

- 会话笔记为 `summary.md`，长期正文为主题 MD、`MEMORY.md` 仅含索引，frontmatter
  保留来源；无等价 JSON 正文双写。旧 JSON 迁移幂等、不丢条目、不覆盖手改文件。
- Session Memory 与长期记忆的文件、游标、开关、预算和 origin 独立，任务进度不进入
  长期记忆；记忆不成为权限分类器的可信输入。
- 初始化 10000、新增 5000、工具 3 次/自然停顿的边界有用例；窗口裁剪后增长计数不倒退。
- `/summary` 绕过自动阈值但不裁剪窗口；`/compact` 不隐式调用长期提取。
- 仅完整且合格的主回合触发长期提取，普通工具循环、子任务、提取自身、失败中断不触发。
- 主模型成功写/忘记可抑制重复提取，失败调用不能；显式 forget 后旧任务不能复活条目。
- 结构化提取无执行工具，来源 ID、schema、大小、凭证及元信息检查一致，空结果合法。
- 提取中继续对话只覆盖启动快照；clear/rewind 后旧任务无效，摘要边界找不到时禁止复用。
- 跨会话并发写不同主题不丢文件，同主题的过期提取不覆盖新事实或人工修改；原子替换
  之外还有 scope 锁和冲突检查，崩溃后不会重复提交同一任务，索引可从主题重建。
- 单类任务运行中多次触发只合并出一个最新尾随任务；退出有界等待，失败不影响主回答。
- 后台完成后的费用归原回合，空/拒绝/失败结果不漏账，Session Memory 被复用不重复收费。
- 记忆索引只在刷新点/增量通知注入，主题通过 memory_read 按需读取；路径逃逸被拒，
  会话笔记不在每次请求重复注入，恢复保留来源与信任标注。
- 实现阶段更新详细设计、数据格式说明和相关边界测试；旧文件与未开启功能的会话可继续使用。
