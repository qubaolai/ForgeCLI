# ADR-0021：采用失败向安全的默认值与端到端事实接线

## 状态

Accepted（2026-08-10 实现）

本 ADR 不引入新的安全层, 而是修正 ADR-0004 / 0013 / 0015 已落地实现中的两类系统性缺陷:
**默认值写反了方向**, 以及**安全关键事实只声明了一半**. 同时收回 ADR-0013 §6.2 关于
"结构化 argv" 的一条承诺。

## 日期

2026-08-10

## 背景

ADR-0004 / 0013 / 0014(非沙箱条款) / 0015 / 0016 落地之后, 对工具系统, HITL 与 Shell
安全引擎做了一轮针对性审计。结论不是"某一层没做", 而是两个反复出现的形态。

### 形态一: 默认值写向了危险

安全判定大量以"命令名 -> 类别"的表为依据, 而表外的默认值决定了漏一项的代价。审计发现
表外默认值被写成了乐观的一侧:

- `_effects_of` 对不在写/删/移清单里的命令, 默认把位置参数按**读取**记录。于是
  `java -jar app.jar` 被判成"只读了 app.jar", `sed -i`、`chmod 777`、`tar -x` 同理。而
  恢复层用 `mutates_workspace` 决定要不要建恢复点, 所以这些命令连恢复点都没有。
- 选项匹配用 token 相等比较规范选项名。`bash -lc 'rm -rf /'` 认不出 `-c`, 内层根本没被
  解析, Hard Deny 看不到 `rm -rf /`, 整条命令拿到 ALLOW —— 而 `status.complete` 为真,
  是自信地判错。
- 以命令名为键的表不做基名归一。`/bin/rm`、`/usr/bin/sudo`、`cmd.exe` 绕过每一张表。
- 生产装配在没有配置 gateway 时回落到测试用的 `FakeSafetyClassifier`, 它默认返回
  LOW / allow。"没接分类器"于是变成"分类器说没问题"。

这一类的共同点: 缺陷不会报错, 只会让某一层再也看不到它本该拦住的东西。

### 形态二: 事实只声明了一半

更普遍的一类是字段定义了、注释解释了它保障什么, 而**生产方或消费方缺一头**:

| 字段 | 缺的那头 |
|---|---|
| `ApprovalPresentation.script_content` | 生产方要求 `ScriptSubject`, 而无任何工具产出它 |
| `HitlApprovalView.unresolved_reason` | 无人传值, 于是 `closed` 恒为真 |
| `presentation_hash` / `approval_presentation_hash` | 两头皆无 |
| `RiskReport.recommendation` / `.capabilities` | 零消费方 |
| `WorkspaceGrants` 的 READ/WRITE 分级 | `as_roots()` 摊平, 只读授权实际可写 |
| `normalized_input["argv"]` | 零生产方 |
| `ExecutionContextRef.filesystem_view_version` | 有两头, 但生产方每次调用换值, 使校验不可用 |
| `RecoveryPolicy.retention_seconds` | 无执行点 |

其中 `filesystem_view_version` 那条影响最大: 它进 `plan_hash`, 而每次调用新建的文件系统
视图带一个时间戳版本, 于是 plan_hash 永不重复 —— 学习规则 (`always`) 从来没有命中过,
用户每次都被重新询问, 而且不报错。

### 形态三: 声称可恢复而实际不可恢复

`FULL` 策略只列工作区顶层一层, 而顶层多为目录; 目录进 `_store_preimage` 后
`read_bytes` 吞掉 `OSError` 返回 `b""`。checkpoint 于是记下"空内容的哈希"并标着
`recoverability=FULL`。同时复制式 preimage 按文件保存旧内容, 真实仓库轻易超过预算, 于是
最需要恢复保障的那类命令 (`npm test`, `make`) 被直接拒绝执行。

## 决策

### 1. 表外默认值一律指向"无法证明"

新增 `domain/security/shell/effects.py`, 把散落在分析器里的命令语义知识收敛为一处
`EffectKind` 判定, 并把表外默认值定为 `UNPROVEN`:

```text
DELETE / MOVE / WRITE / READ / RUNS_CODE   已知语义
UNPROVEN                                   不认识 = 不知道它碰什么
```

`UNPROVEN` 的后果由三处同时表达, 缺一处就等于没表达:

1. 位置参数仍按读取记录 (受保护路径检查要看得到 `cat ~/.ssh/id_rsa`), 但**这不是完整
   清单**;
2. 目标集合标 `DYNAMIC` —— 封闭的语义是"这就是全部目标", 而这里连它写不写都不知道;
3. 新增 `DecisionReason.UNPROVEN_EXECUTABLE` 落 ASK。

同一份知识里另外两条与"表"无关的补充: 条件写按参数判定 (`sed` 不写而 `sed -i` 写,
`sort -o` 写), `git` 按子命令分流 (复用只读子命令这份既有知识, 而不是把整个 git 归到
某一边)。

**判据是漏一项的代价**: 从"静默放行"变成"多问一次"。清单仍然会漏, 这一点不变。

### 2. 选项按语法族匹配, 命令名先归一

选项匹配不再比较 token, 而是按四种语法族解析: POSIX 短选项聚合 (`-lc`)、GNU 附加值
(`--eval=X`)、PowerShell 唯一前缀缩写与 `:` 分隔、cmd 大小写不敏感且 `/c` 之后整行都是
命令。取值选项按解释器分别声明 —— 不声明会把 `python -mc x` 误判成内联代码 (它其实是
`-m c`)。

命令名统一经 `normalize_executable` 取基名并去 Windows 可执行后缀, 查表一律用它;
`unit.executable` 保持原样写法, 供 PATH 解析与身份哈希使用。**两者必须分开**: `/bin/rm`
与 `rm` 对规则是同一个判据, 但不是同一个文件。

### 3. 分析事实必须端到端接线, 且以工具声明上界为界

- 分析器恢复一个先前被收缩掉的能力时, 界是**工具 spec 声明的上界**
  (`AnalysisFindings.declared_capabilities`), 不是收缩后的计划 —— 拿后者当界会得到恒等
  交集, 后一个分析器新发现的事实被静默丢掉。
- 工具的声明上界必须**真的**是上界: 界外的事实即便被发现也无处安放。
- 脚本正文以 `ScriptSnapshot` 形式从分析器一路带到审批与学习规则。三个下游都要"分析读过
  的那一份", 谁都不能自己再读一次文件 —— 那是又开一个 TOCTOU 窗口。
- 审批界面逐字展示要执行的代码与要写入的内容。只给路径等于让用户批准一个他没读过的文件;
  工具层不能依赖安全模块, 所以内容经中立的 `ContentPreview` 从 `ToolPlan` 交出。
- 视图哈希两头接通: 批准时记下 `presentation_hash`, 重验后**重新渲染视图**再比一次, 通过
  才进 `ExecutionAuthorization`。这一层覆盖 `ApprovalBinding` 覆盖不到的东西 —— 脚本文件
  在审批期间被换掉时命令串没变, `plan_hash` 也就没变。

### 4. plan_hash 只绑定"这次调用是什么", 不绑定"这一次的环境"

`compare=False` 的字段一律不进哈希 (`canonical()` 统一跳过)。`filesystem_view_version`
标为 `compare=False`: 它是一次调用内部"prepare 与执行用同一份视图"的凭据, 属于环境而不是
身份。

### 5. 恢复保障的判据是"能不能写", 不是"推导出了目标"

- 分析器在"可能写但推不出目标"时声明写能力, 恢复层才看得到 `npm test` 与 `java -jar`。
- 反向也要成立: `ls` 声明了 EXECUTE_SHELL 却确定不写, 不该触发全工作区快照。
- `_store_preimage` 校验目标是普通文件且读到的字节数等于文件大小, 任一不满足抛
  `RecoveryUnavailableError`。**绝不落一个空 preimage。**
- `FULL` 优先使用写时复制快照 (新增 `WorkspaceSnapshotBackend`): APFS `clonefile` 与
  btrfs / XFS reflink 把代价从"复制内容"变成"复制元数据"。实测 512 MB 单文件快照 9 ms,
  整份复制 943 ms。有快照就不再逐文件保存 preimage, 逐文件预算也不再适用。
- 可用性**靠实测**而不靠平台判断: 同一台机器上工作区与快照目录可能在不同卷, 那时克隆直接
  失败。用 `cp -c` / `--reflink=always` 而不是 `auto`, 因为后者会在不支持时静默退化成整份
  复制 —— 一次"快照"悄悄写掉几个 GB, 而我们本来想在那种情况下退回逐文件 preimage。
- 拿不到快照后端时退回逐文件 preimage 并照常过预算; 该拒绝的仍然拒绝, 但**绝不假装成功**。
- `retention_seconds` 由 `prune_expired` 执行: 快照占的磁盘接近零, 但 inode 不是零。

### 6. 无法自证的能力走 Mandatory Ask

`CREDENTIAL_ACCESS` / `EXTERNAL_IRREVERSIBLE_EFFECT` / `UNKNOWN` 落 ASK 时置
`mandatory=True`。不置位的话它只是普通 ASK, 而普通 ASK 会被学习规则抬成 ALLOW —— "读凭证
永远需要人类在场"和 ADR-0013 §4.1 的逐次批准都会在用户点过一次 `always` 之后失效。

模式预算分支不再覆盖分析器给出的具体理由。`shell.run` 在 plan 与 accept_edits 下必然超
预算, 覆盖会让 `PARSE_INCOMPLETE` / `CLASSIFIER_UNAVAILABLE` / `SCRIPT_EXECUTION` 永远不
出现在审计与界面上, 而 `_UNLEARNABLE_REASONS` 也就永远匹配不到它们。

"分析没做完"与"分类器说别自动跑"一律不可学: 否则一次退让会变成永久放行。

### 7. 只保留原始 Shell 入口, 收回结构化 argv 承诺

ADR-0013 §6.2 写着"之后生成的是不会被 shell 二次展开的结构化 argv"。**收回这条承诺**,
并删除对应的半成品 (`parse_argv`, `shell_run` 里读 `normalized_input["argv"]` 的分支)。

理由不是"暂时没实现", 而是**在当前工具形态下它不可能成立**: 把展开结果写回
`normalized_input` 之后仍旧交给 `sh -c`, shell 会把拼回去的串重新解析一遍, 字段值里的
`$`、反引号、`;`、`&&`、glob 全部重新生效。要让冻结成立, 执行必须自己按结构执行 (argv
直接 spawn, 管道由执行器建 fd, 重定向由执行器自己 open), 整条链路里不出现 shell; 而
`shell.run` 的入参就是一条 shell 命令串, 自己执行就得实现一遍 shell 语义。

因此 `shell.run` 明确承认自己是不透明入口: 展开结果只用于裁决与审批展示, glob 在执行时
会被 shell 再展开一次, 两次展开之间的窗口**由恢复点兜住, 不由 `target_set_hash` 假装
消除**。

结构化执行如果要做, 应当是新增 `process.run` / `script.run` 两个工具, 而不是给
`shell.run` 加一条第二路径。`shell.run` 本身要保留 —— 堵死降级路径只会让模型绕行 (写脚本
文件再执行, 或把逻辑塞进 `python -c`), 风险搬到连解析器都没有的地方。

### 8. 未接线的符号一律删除, 不留作"扩展点"

判据是"零生产方或零消费方"。本轮删除: `RuleKind` 及其映射表 (与 `PolicyEngine.decide`
分支顺序并存的第二份优先级编码)、`AgentRiskChoice` / `AgentRiskResponse`、`ScriptSubject`、
`NetworkSubject`、`ApprovalPresentation.normalized_command`、
`RecoveryPolicy.max_checkpoint_seconds` / `max_total_store_bytes`、
`WorkspaceGrants.writable` / `readable`。

**没人走过的分支是未经测试的代码, 而它看起来像经过测试的。** `ScriptSubject` 正是审批界面
看不到脚本正文的根因。将来需要时重新加是十行的事, 而留着的代价是每个读代码的人都以为它
在工作。

有守卫的预留不在此列: `SnapshotStrategy.OVERLAY` 保留, 因为 `available` 会拦下它且选中会
明确报错 —— 那是"有守卫的预留", 不是"静默的死路"。

## 备选方案

- **方案 A：继续补清单条目。** 给 `_INLINE_FLAGS` 补 `-lc`、`-ic`、`-ec`……给 `_INTERPRETERS`
  补 `java`、`osascript`。优点是改动最小。缺点是补不完: 要补的是短选项的幂集, 而"会执行
  任意代码的程序"这个集合没有闭包。每一次漏项的代价仍然是静默放行。**否决。**
- **方案 B：改用结构化工具替代 `shell.run`。** 只提供 `process.run` / `script.run`, 彻底
  消除解析歧义。优点是解析层的缺陷整类消失。缺点是模型会绕行 —— 写脚本文件再执行, 或把
  shell 逻辑塞进 `python -c`, 风险搬到看不见的地方; 而且这是新功能而非缺陷修复。**作为后续
  方向保留, 本 ADR 不采纳为替代品。**
- **方案 C：把 FULL 恢复的预算调大。** 把 `max_checkpoint_files` 提到十万。优点是一行。
  缺点是复制式 preimage 真的要复制十万个文件的内容, 时间与磁盘都不可接受, 而"保护了一部分"
  比明确拒绝更糟。**否决, 改为引入写时复制快照。**
- **方案 D：把未接线字段留作扩展点并加注释。** 优点是将来接入时不用重新设计形状。缺点正是
  本次审计的主要发现: 注释描述的是接线完成后的设计, 而代码停在一半, 每个读者都会以为它在
  工作。**否决。**

## 影响

### 收益

- 消除四类可实际触发的 Hard Deny 绕过 (`bash -lc`、`sh -ec`、`/bin/rm`、`/usr/bin/sudo`)。
- 学习规则 (`always`) 首次真正可用。
- `FULL` 恢复从"真实仓库里通常不可用"变成"通常可用", 且不再声称可恢复而实际为空。
- 审批界面首次展示要执行的代码与要写入的内容。
- 子进程输出有真实的内存上界 (此前 `communicate()` 先全量读入, 一条 `yes` 可在超时前耗尽
  内存)。

### 代价

- **询问次数明显上升。** UNPROVEN 命令、Mandatory Ask 的 never-auto 能力、未配置 gateway
  时的脚本执行, 三者都会落 ASK。安全上是正确的方向, 但**确认疲劳本身就是安全问题** ——
  一个会话问四十次会让人变成橡皮图章。建议实际运行一段时间统计 ASK 频率, 再决定是否往
  `effects.py` 里显式声明常用工具的影响范围。
- UNPROVEN 命令目前无法沉淀成学习规则 (目标集合不封闭 → `can_learn` 拒绝)。降噪只有两条
  路: 显式声明该工具的影响范围, 或上沙箱 (ADR-0019)。
- 不支持写时复制的卷上, "可能写到工作区任何位置"的命令仍会被拒绝执行。错误信息给出可行动
  的两条出路 (写明确目标, 或把工作区放到支持 reflink / clonefile 的卷上)。
- `spec_hash` 变化 (`shell.run` 与 `git.read` 的声明都改了), 已有的学习规则与未完成审批
  全部失效。这是设计意图。

### 兼容性

- `git.read` 的 `stash` / `branch` / `remote` 从"允许并用禁止清单过滤参数"改为"按子命令的
  参数白名单"。`git stash`(裸)、`git branch <name>`、`git remote add` 现在被拒绝 —— 它们
  分别改写工作树、创建 ref、改 `.git/config`, 本就不属于只读工具。
- `/add-dir` 的只读授权不再可写。此前只读与读写授权在裁决层面没有区别。
- 删除的符号见决策 8。主仓同步时一并删除。

## 验收标准

- `make ci` 全绿 (`poetry check` + `ruff` + `ruff format` + `mypy --strict` + `arch` +
  `pytest`)。
- 每一条修复都有回归测试, 断言对象是"曾经真实放行的那个输入", 而不是中间结构。新增 8 个
  测试文件共 103 条。
- 表外默认值的方向有测试钉住: 不认识的命令归 UNPROVEN 且目标集合不封闭; 确定只读的命令
  仍走只读快速路径 (修复不该把一切都打成未知)。
- 恢复层有测试证明"目录不会产生静默的空 preimage"、"FULL 递归到子目录"、"纯读取不需要
  checkpoint"、"过期快照被清理"。
- 快照后端在不支持写时复制的卷上退回逐文件 preimage, 且该退路有测试覆盖。
- 审批视图哈希覆盖脚本正文与写入内容, 且相同视图哈希稳定 (否则重验会把所有审批变成死
  循环)。
- ADR-0013 §6.2 的"结构化 argv"一句需按决策 7 修订。
