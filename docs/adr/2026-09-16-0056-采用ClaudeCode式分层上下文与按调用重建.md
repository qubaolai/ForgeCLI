# ADR-0056: 采用 Claude Code 式分层上下文与按调用重建

## 状态

Proposed (2026-09-16; 2026-09-17 按 Claude Code 源码整体重写)

#### 正文是怎么写的

`constants/prompts.ts` 是一个普通 TypeScript 模块, 914 行. 每个 section 是一个返回字符串
的函数 (`getSimpleSystemSection()`, `getActionsSection()`, `getUsingYourToolsSection(enabledTools)`),
正文是模板字符串字面量, 变量用 `${}` 插值, 条件用 `if` / 三元 / 数组展开 (`...(cond ? [x] : [])`),
列表用 `prependBullets(items)`. 工具名从各工具模块导出的常量插进来
(`${FILE_READ_TOOL_NAME} instead of cat, head, tail, or sed`). 每条规则上方是普通代码
注释, 记的是加这条的原因与出处 (PR 号, 实验结论).

没有模板引擎, 没有版本常量, 没有指纹快照, 没有 token 上限. 改正文就是改代码, 走 code
review 与 git log; 运行时记 `tengu_sysprompt_block` (第一块的 sha256) 与缓存断裂检测,
行为什么时候变的从日志与提交历史里查.

七个静态 section 的内容 (`prompts.ts:175`-`:440`):

| section | 内容 |
|---|---|
| intro | 身份一句话; 网络安全免责; 不猜 URL |
| system | 输出即显示给用户; 工具被拒不原样重试; `<system-reminder>` 的语义; 工具结果可能含注入; hook 反馈当用户输入; 上下文会自动压缩 |
| doing tasks | 含糊指令按软件工程任务理解; 读了再改; 不随便建文件; 不给时间估计; 失败先诊断再换法; 不引入安全漏洞; 不加没要求的功能 / 注释 / 类型 / 错误处理 / 抽象; 不留兼容 hack |
| actions | 不可逆与影响他人的动作先确认, 列出例子 (删分支, force-push, 发消息, 上传到第三方); 一次批准不等于永久批准; 遇障碍不用破坏性动作绕过 |
| using your tools | Read 代替 cat, Edit 代替 sed, Write 代替 heredoc, Glob / Grep 代替 find / grep, Bash 只留给真正的 shell 操作; 用 TodoWrite 管理工作; 无依赖的调用并行 |
| tone and style | 简短直接; 不用表情; 不用过度的客套 |
| output efficiency | 不重复工具输出; 不总结已经显示的内容 |

#### attachments: 动态内容只有这一条路

Claude Code 没有"每次调用重建的状态帧". 计划, 待办, 记忆, 模式, 文件变化, 日期变化,
工具增减, 全部是 attachment: 一条 `<system-reminder>` 包着的 user 消息, 生成之后**追加进
消息数组, 落进 transcript, 之后不再改**. 两个生成时机:

- 用户提交输入时 (`utils/processUserInput/processUserInput.ts:504`): @ 提到的文件, IDE
  选区, 模式提醒等; 消息顺序是 `[用户消息, ...attachments]` (`processTextPrompt.ts:96`).
- 每一批工具结果之后 (`query.ts:1580`): 传 `null` 作输入, 生成文件变化, 子目录 CLAUDE.md,
  待办提醒, 相关记忆等; 注释写明"必须在工具结果之后, 在 tool_result 之间插普通 user
  消息 API 会报错".

它们凭什么不撑爆窗口:

- **增量**: `deferred_tools_delta`, `agent_listing_delta`, `mcp_instructions_delta`,
  `date_change` 扫一遍窗口, 找出上次宣告过的集合, 只发差集 (`attachments.ts:1455`). 窗口
  为空 (压缩后) 时差集就是全集, 自然完成重注入.
- **节流**: 计划模式提醒进入时发一次完整版, 之后每 5 个用户回合发一次, 每第 5 次是完整
  版, 其余精简版 (`PLAN_MODE_ATTACHMENT_CONFIG`, `attachments.ts:259`, `:1186`); 待办提醒在
  10 条 assistant 消息 (即 10 次模型调用) 没写过待办之后发一次, 再隔 10 次
  (`TODO_REMINDER_CONFIG`, `:3266`). 计数**从窗口里数出来**, 不另存计数器, 压缩之后自动
  归零.
- **预算**: 相关记忆每个文件 4 KB, 每次最多 5 个, 每会话累计 60 KB, 累计量同样扫窗口
  得出 (`RELEVANT_MEMORIES_CONFIG`, `attachments.ts:279`).
- **事件触发**: `edited_text_file` 只在模型读过的文件 mtime 变了且 diff 非空时发, 正文
  只有变化的片段 (`getChangedFiles`, `:2063`); `nested_memory` 只在首次触达某个子目录的
  文件时发那个目录的 CLAUDE.md.

#### 什么不在 system prompt 里

三样东西被有意挡在 system prompt 外面, 理由都是缓存:

- **权限模式**. plan / auto 模式的说明是 attachment (`plan_mode`, `auto_mode`, 退出时
  `plan_mode_exit` / `auto_mode_exit`). 换模式只多一条消息, 前缀不动.
- **日期**. 会话起始日期在第一条 user 消息里; 跨天时一条 `date_change` attachment.
- **CLAUDE.md**. 第一条 user 消息, 会话级快照; 会话中改了它, 要到 `/compact` 或 `/clear`
  才重读.

静态段连"当前有哪些 agent 可用"都挪了出去 (`agent_listing_delta` 的注释: 这个清单原先
嵌在 AgentTool 的描述里, 占全部缓存写入的 10.2%).

### 本仓库现状

提示词侧 (`prompt/`): 正文在 `templates/` 下的 16 份 Jinja2 模板 (`blocks/` 六块,
`headings`, `runtime/`, `state/`, `notices/` 六组 macro, `classifier/`), 由
`template_renderer.py` 的 `render_block` / `render_runtime` / `render_state` /
`render_notice` / `render_classifier` 五个入口渲染; `system_prompt_builder.py` 把五个静态
块与 FORGE.md 编成 `PromptSnapshot` (`core/prompt_blocks.py`); FORGE.md 与状态帧用
`sentinels.py` 的整行分隔符围起来并转义正文里的同形行. 配套的纪律: `PROMPT_TEXT_VERSION`
与指纹快照测试 (改一个字要升版本改快照), `PROMPT_STATIC_BUDGET = 994` token 的只降不升
上限, "提示词里不出现任何工具名", `blocks/` 每条规则前必须有 `{# why: #}` 注释并有测试
查, `scripts/check_prompt_text.py` 扫描全部 .py 禁止含中文的字面量流向模型消息.

上下文侧 (`conversation/`, `core/agent/state.py`, `agent/turn_service.py:236`): `policy`
(策略块 + FORGE.md) 与 `runtime_context` (运行事实 + **当前模式**) 拼成 `system_prompt`;
`tools` 每次调用重新渲染; `messages` 是窗口加一条每次调用重建的状态帧 (计划, 待办, 记忆),
状态帧不进窗口, 不落事件日志. 每次调用重读 FORGE.md, 计划, 待办, 记忆.

逐条对照 Claude Code, 这些设计站不住:

1. **模板引擎买不到东西.** 正文里的条件与槽位, Python 的 f-string 与 `if` 就够了.
   Jinja2 带来的是: 一套 `render_*` 入口, `StrictUndefined`, `FunctionLoader`, `SINKS` 白
   名单, `{# #}` 注释与指纹的分离规则, 以及"要知道模型看到什么, 得在 .py 与 .md.j2 之间
   来回跳". Claude Code 914 行一个文件, 从上到下读完就是模型看到的全部.
2. **994 token 的静态上限把提示词钉在 Claude Code 十分之一的长度.** 上限的理由是"防
   腐化", 而 Claude Code 的静态段证明: 读了再改, 失败先诊断, 不加没要求的注释与抽象,
   不可逆动作先确认, 如实报告 —— 这些具体的工作规则是模型行为质量的主要来源, 每一条都
   在那份源码里带着 PR 号与实验结论. 一个只准放 994 token 的提示词放不下它们.
3. **"不出现工具名"与 Claude Code 相反.** 它的 using your tools 一节全是工具名: Read
   代替 cat, Edit 代替 sed, Bash 只留给 shell 操作, 无依赖的调用并行. 这一节解决的是
   "模型什么都用 Bash 干"这个具体问题, 工具描述里写不了 (描述只说自己, 不说别人).
4. **版本常量与指纹快照让改正文变成一件有摩擦的事.** 改一句话要升版本, 改快照, 跑测试;
   结果是正文冻结在落地那一天. git 本身就是版本; 行为什么时候变的, 从日志里的 sha 与
   提交历史查.
5. **模式在 system prompt 里.** 换一次档, 整条请求的前缀作废. 工具池只按 deny 规则过滤
   (`tools/pool.py:50`), 不随模式变, 没有任何东西要求模式进前缀.
6. **状态帧每次重建, 追加在末尾, 不进窗口.** 接 Anthropic 式显式断点时, 断点打在最后一
   条消息 (帧) 上, 下一次调用的消息序列里没有那条帧, 上一次写的缓存条目找不到 —— 每次
   调用整段未命中. 模型看到的内容不在事件日志里, `/resume` 回放不出它当时看到了什么.
7. **FORGE.md 与记忆每次调用重读.** 模型 Edit 一次 FORGE.md, 下一次调用前缀从 system
   prompt 开头作废; 而它刚在 tool_result 里看过自己写的内容.
8. **通知没有增量, 节流与预算.** 状态帧每次全量, 计划与待办没变也每次重发.

质量门禁: 当前工作树 `poetry check`, 源码编译与核心模块导入冒烟通过; `ruff` 报 59 项,
架构检查因工具包直接依赖安全包失败, mypy 报 63 项新旧工具协议不一致, pytest 收集到 0
个用例. 仍在迁移中.

## 决策

### 1. 正文只有一个 Python 模块: `prompt/prompts.py`

对应 `constants/prompts.ts`. Forge 撰写的, 会进模型上下文的文字**全部**在这一个文件里:
系统提示词的每个 section, 窗口通知, 压缩指令, auto 模式分类器的 system prompt. 唯一的
例外是工具描述, 留在各工具的 `tools/builtin/<Tool>/prompt.py` (对应 `tools/<Tool>/prompt.ts`):
描述只在该工具在池里时才进请求, 与工具住在一起才能跟着工具增删.

形状:

```python
SYSTEM_PROMPT_DYNAMIC_BOUNDARY = "__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__"

def get_system_prompt(pool: tuple[Tool, ...], facts: SessionFacts) -> tuple[str, ...]:
    static = (_intro(), _system(), _doing_tasks(), _actions(), _tone_and_style(), _output_efficiency())
    session = resolve_sections((
        session_section("using_your_tools", lambda: _using_your_tools(pool)),
        session_section("env_info", lambda: _env_info(facts)),
        session_section("workspace_instructions", lambda: _workspace_instructions(facts.forge_md)),
        session_section("memory", lambda: _memory(facts.memory)),
        session_section("git_status", lambda: _git_status(facts.git)),
    ))
    return tuple(s for s in (*static, SYSTEM_PROMPT_DYNAMIC_BOUNDARY, *session) if s)

def _using_your_tools(pool: tuple[Tool, ...]) -> str | None:
    names = {t.name for t in pool}
    items = [
        f"读文件用 {READ_TOOL_NAME}, 不用 cat / head / tail / sed" if READ_TOOL_NAME in names else None,
        ...
    ]
    return _section("使用工具", items)

def notice_mode(mode: PermissionMode, *, full: bool) -> str: ...
def notice_todo_reminder(todos: tuple[TodoItem, ...]) -> str: ...
COMPACT_PROMPT = """..."""
```

- 正文是 Python 字符串字面量; 变量用 f-string; 条件用 `if` 与 `None` 过滤; 列表用
  `_bullets(items)`; 工具名从各工具模块的 `NAME` 常量插入, 不手写.
- 每个 section 函数返回 `str | None`, `None` 表示整节不出现 (没有 FORGE.md 就没有那一节,
  不渲染一个写着"(无)"的标题).
- 每条规则上方一行普通注释, 记加这条的原因 (删掉它之后哪个错误动作会出现, 或出处). 这
  是写法要求, 不由测试强制.
- 改正文就是改代码: 走 review 与 git log. **没有**版本常量, **没有**指纹快照测试,
  **没有** token 上限. 成本可见但不设限: 每次组装的日志记静态段 sha256 与各 section 的
  token 估算 (决策 12).
- 提示词可以引用工具名, 可以按池里有哪些工具增减句子 (那些句子在会话段, 见决策 2).

删除: `prompt/templates/` 整个目录, `template_renderer.py`, `system_prompt_builder.py`,
`sentinels.py`, `errors.py` (`PromptBudgetExceeded`), `core/prompt_blocks.py`
(`PromptBlock` / `PromptBlockId` / `PromptSnapshot`), `conversation/runtime_view.py`,
`conversation/state_view.py`, `scripts/check_prompt_text.py`, `PROMPT_TEXT_VERSION`,
`PROMPT_STATIC_BUDGET`, jinja2 依赖. 分隔符转义随 `sentinels.py` 一起删: FORGE.md 是
用户自己的项目文件, 工作区信任 (ADR-0008) 已经回答了"信不信它", 转义防的是用户对自己
的提权.

### 2. 一次请求的形状: 四个位置, 变更源决定位置

| 位置 | 内容 | 变化时机 | 请求里的槽位 |
|---|---|---|---|
| [1] 工具目录 | 工具 schema | 会话级字节锁定 (决策 8) | `tools` |
| [2] 静态段 | intro, system, doing_tasks, actions, tone_and_style, output_efficiency | 包版本 | `system_prompt` 前半 |
| [3] 会话段 | using_your_tools (随池), env_info (平台, shell, cwd, 工作区根, 沙箱, 模型, 会话起始日期), FORGE.md 快照, 记忆快照, git 快照 | 会话刷新点 (决策 7) | `system_prompt` 后半 |
| [4] 窗口 | 用户, 助手, tool call, tool result, 通知 | 只追加; 撞高水位批量淘汰 | `messages` |

没有状态帧. 它承载的内容按决策 5 变成窗口里的通知.

六个静态 section 与 Claude Code 同名同题, 正文按本仓库的工具集与中文重写, 不逐句翻译.
`AssembledContext.system_prompt` 把 [2] [3] 用空行拼成一条; 边界标记只给传输层看:
OpenAI-compatible adapter 拼接时去掉它; 接显式断点的 adapter 时, 断点打在边界之前与最后
一条消息上. [2] 与 [3] 各算一个 sha256 进 `context.assembled` 日志.

模式, 日期变化, 计划, 待办, 文件变化都不在 [2] [3] 里. [3] 只放"整个会话内不该变, 变了
就该重来一遍"的事实.

### 3. section 按名缓存, 打破缓存要写理由

对应 `systemPromptSections.ts`:

```python
def session_section(name: str, compute: Callable[[], str | None]) -> Section: ...
def uncached_section(name: str, compute: Callable[[], str | None], reason: str) -> Section: ...
def resolve_sections(sections: tuple[Section, ...]) -> tuple[str | None, ...]: ...
def clear_section_cache() -> None: ...
```

缓存是会话级的 dict, `resolve_sections` 命中就不调 `compute`; `clear_section_cache` 只在
决策 7 的刷新点调. 现在没有任何 section 需要 `uncached_section`, 留这个入口是为了让
"每轮重算"必须显式写出理由, 而不是悄悄把一个每轮变的值塞进前缀.

### 4. 模式说明是窗口里的通知, 不进 system prompt

`notice_mode(mode, full=...)` 每档一段, 完整版与精简版两种.

- 回合开始时模式与上一条模式通知不同 (含会话第一个回合): 随这一回合的用户消息发一条
  完整版, 并入同一条 user 消息.
- 模式没变: 每 5 个用户回合随用户消息发一条精简版, 每第 5 条发完整版. 数回合的方法与
  Claude Code 相同: 从窗口末尾往前数不带 tool_result 的 user 消息, 遇到上一条模式通知
  为止.
- 退出 plan / auto 档: 一条退出通知, 说明现在能做什么.

模式切换只在回合边界生效 (ADR-0057), 所以通知总是与用户消息同一条, 不会落在
tool_result 之间.

### 5. 计划, 待办, 记忆以通知进窗口

原则: **模型已经在窗口里看过的内容不再发**. 计划与待办的绝大多数变化由模型自己用
`plan_write` / `TodoWrite` / `todo_set_status` 造成, tool_result 里已经有新状态.

需要发通知的只有三种情形:

- **外部改动**: 用户在 Web 控制面改了待办, 计划评审给出结论, 另一个进程写了记忆.
  `PlanningService` / `MemoryService` 各带一个 revision; 每批工具结果之后与用户消息提交
  时比一次上次发过的 revision (记在通知本身的元数据里, 扫窗口取), 变了就发一条带当前
  内容的通知.
- **提醒**: 待办清单非空且连续 10 次模型调用没有任何待办工具调用, 发一条带当前清单的
  提醒; 之后再隔 10 次. 记忆不提醒. (Claude Code 清单为空也提醒, 是在催模型用 TodoWrite;
  本仓库不催.)
- **重注入**: 压缩之后与恢复之后 (决策 9, 决策 11), 窗口里没有这些内容, 整份发一遍.

记忆: 会话开始时的条目进 [3] 会话段; 会话中 `memory_write` 新写的条目模型自己刚看过,
不再发; 下一个刷新点并入 [3].

`AssembledContext.state_frame` 字段与 `to_request_messages()` 里追加帧的逻辑删除.

### 6. 通知的统一形状

Forge 注入窗口的所有文字 (模式, 计划, 待办, 记忆, 文件变化, 日期变化, 工具增减, 子目录
FORGE.md, 压缩占位, 恢复占位, 循环规则的引导) 用同一个包裹标记 `<system-reminder>`,
静态段 system 一节用一句话说明它的语义 (与 `prompts.ts:190` 那句话对应). 不再各自发明
`--- BEGIN CURRENT STATE ---` 之类的标记.

- 通知是 `ChatMessage(role=USER)`, 带 `meta=True`: 界面不显示, 事件日志保留 (决策 11
  要回放它).
- 只在两个位置注入: 随用户消息 (排在用户文本之后, 同一条消息), 或在一批工具结果之后
  (并入含 tool_result 的那条 user 消息). 不在 tool_result 之间插独立的 user 消息.
- 每种通知有一个类型名; 通知的元数据带类型与 revision. 增量与节流都从窗口里同类型的
  上一条推出来, 不另存计数器. 压缩淘汰掉旧通知, 计数自然归零.
- 预算三个数值, 常量集中在 `prompts.py` 顶部: 单条通知上限 4 KB (超出截断并注明), 单次
  注入合计 20 KB, 记忆类通知每会话累计 60 KB, 到量停发. 数值取自 Claude Code, 没有本
  仓库的实测之前不改.
- 正文是 `prompts.py` 里的 `notice_*` 函数, 收结构化参数, 返回包好的字符串.

### 7. 会话段的刷新点

[3] 在六个时刻重算 (调 `clear_section_cache`): 会话开始, 压缩之后, 恢复之后, `/clear`,
用户显式 `/reload`, 以及 ADR-0047 报告 FORGE.md 变化且来源不是本 Agent 时的下一回合
开始. 其余时刻每次调用组出来的 [3] 字节相同.

- FORGE.md 会话中被改: 模型 Edit 的它自己看过, 不重读; 用户在编辑器改的, 下一回合开始
  重读一次 (Claude Code 要等到 `/compact` 或 `/clear`, 用户改了 CLAUDE.md 之后经常要
  手动 `/clear`; 本仓库有 ADR-0047 的来源归因, 能只在用户改时付一次前缀作废的代价).
- 子目录 FORGE.md: 首次读或改某个目录下的文件时, 那个目录 (向上到工作区根为止) 的
  FORGE.md 以通知发一次, 之后不再发.
- 日期: 会话起始日期在 [3]; 每批工具结果之后比一次本地日期, 跨天发一条 `date_change`
  通知.
- git 快照: 分支, 主分支, `status --short` 截 2000 字符, 最近 5 条提交; 文字里说明这是
  会话开始时的快照, 之后不更新, 要看现状用 `Bash`.

### 8. 工具目录会话内字节稳定

- 工具描述与 input_schema 首次渲染后按会话缓存 (`tools/runner.py:89` `tool_schemas`
  现在每次重渲染); 描述里不许有每轮变的内容 (当前模式, 时间, 其他工具的清单).
- 池只随 deny 规则与配置 (`/reload`) 变. 变了: 新目录进 `tools`, 同时发一条通知列出
  增减的工具名, 让模型知道为什么某个工具没了.
- 不变量 (可测): 同一会话相邻两次调用的 `tools` 字节相同, 除非两次之间有一条工具增减
  通知.

### 9. 只在写入期控制结果体积; 压缩后重注入

- 工具结果分短摘要, 结构化字段和可选正文. 短摘要与模型继续推理所需的结构化字段进窗口;
  超长正文落盘 (ADR-0054 决策 5), 窗口里留稳定引用与"正文已落盘"的事实.
- 窗口平时只追加; 达到高水位时在合法 tool call 配对边界整体淘汰到低水位, 不逐条滑动,
  不回头改写已发送的消息.
- 摘要只处理会话历史, 不压缩也不覆盖静态段, 当前用户目标, 当前模式, 沙箱边界和未决
  安全结论. 被淘汰的用户约束按有限预算逐字保留, 摘要内容标记为模型生成的历史转述.
  压缩指令 `COMPACT_PROMPT` 在 `prompts.py`, 与 Claude Code 的 compact prompt 同一结构:
  先禁工具, 再要 `<analysis>` 与 `<summary>` 两段.
- 预算计算覆盖 system prompt, 工具 schema 与窗口的总和; 模型窗口未知时不猜一个更小的
  窗口来主动丢数据.
- **压缩后重注入**, 摘要之后紧跟一组通知, 顺序固定: 模式通知 (完整版), 当前计划与待办,
  最近读过且仍存在的文件 (只发 `ToolUseContext.read_file_state` 里有的, 最多 5 个, 每个
  截到 5k token, 合计 50k token), 然后 [3] 会话段刷新 (决策 7). 与 Claude Code 的
  `buildPostCompactMessages` 同一顺序.
- 不做 microcompact 式的原地清理: 本仓库的工具结果正文在写入期就不进窗口, 窗口里没有
  可清的东西.

### 10. 区分"回合冻结"与"调用刷新"

- 一次 turn 冻结 session id, turn id, 权限模式, 沙箱边界和本回合的工具执行上下文. 当前
  排队中的工具调用不能因为外部切换模式而改变语义.
- 每次模型调用前重新做的只有两件事: 按决策 5, 6, 7 的增量检查组 [4] 的通知; 算预算.
  [1] [2] [3] 在刷新点之外不重算.
- `AgentTurnService` 负责提供材料, Agent loop 只依赖 `assemble()` 和 `execute()` 两个
  边界, 不直接读取计划, 记忆, 权限或文件系统.

### 11. 恢复必须"可重建且不假装完整"

会话恢复以事件日志和外部事实源重建, 不把 `state.json` 当成唯一真相源:

- 用户 / 助手消息与通知从事件日志恢复, 通知按原位置回放 (它们是模型当时看到的内容).
- [3] 按恢复时的事实重算; 恢复时的 FORGE.md 与恢复前不同, 正文就不同, 这是对的.
- 压缩摘要及不可复现的人类回答持久化正文.
- 工具结果至少恢复其稳定摘要, 结构化状态和落盘引用; 正文已回收或不具备重放条件时, 显式
  标记"历史正文不可用", 不让模型误以为从未执行过.
- 恢复之后走一次决策 9 的重注入.
- 恢复后的上下文重新经过同一预算, 信任分层和模式边界, 不把历史中的工具结果, 项目文件
  或模型摘要提升为系统指令.

### 12. 上下文可观测, 但默认不泄露原文

每次组装记录 [1] [2] [3] 三个 sha256, 各 section 的 token 估算, 通知类型与条数, 淘汰与
恢复结果. info 级别不记录完整 prompt, 文件正文, 凭证或环境敏感值; debug 级可把整条请求
落 JSONL (对应 `dumpPrompts.ts`), 沿用现有脱敏和权限边界.

**缓存断裂检测**: 三个 sha256 与上一次比, 变了但两次之间没有刷新点也没有工具增减通知,
warn 一条带哪一层变了, 并把两版正文的 diff 写到会话目录; `ModelUsage.cached_input_tokens`
相对上一次骤降时同样 warn. 这是 `promptCacheBreakDetection.ts` 的做法, 用来抓"谁又把
每轮变的东西放进了前缀". 静态段没有 token 上限, 它的长度靠这里的数字被看见.

### 13. 与 Claude Code 的差异

| 差异 | 理由 |
|---|---|
| FORGE.md 在 system prompt 会话段, 不做第一条 user 消息 | 缓存经济上两者相同 (都在 tools 之后, 历史之前); 少一种消息形状 |
| 用户改了 FORGE.md, 下一回合重读会话段 | 有 ADR-0047 的来源归因, 只在用户改时作废一次前缀; Claude Code 要等 `/compact` / `/clear` |
| using_your_tools 在会话段 (边界之后), 不在静态段 | 它随池变; Claude Code 把它放静态段是因为它的池几乎不变, 本仓库 deny 规则会摘工具 |
| 记忆是 key-value 条目, 整份进会话段, 没有按相关性检索的记忆通知 | 本仓库记忆量小; 检索通道另议 |
| 文件变化通知沿用 ADR-0047: 只报路径, 下一回合开始交付; 不做每批工具结果后比 mtime 发 diff 片段 | 有了 `read_file_state` 之后可以重议, 不在本文 |
| 没有 override / custom / append system prompt | 本仓库没有把提示词交给外部编排的场景 |
| 没有 microcompact | 正文不进窗口, 没有可清的 |
| 没有 skill / agent / MCP 相关的 section 与通知类型 | 本仓库没有这三样 |
| 待办清单为空时不提醒 | Claude Code 的提醒是在催模型用 TodoWrite; 本仓库不催 |
| 通知预算的数值直接取 Claude Code 的 | 没有本仓库实测; 有了再改, 改时写进本 ADR |

## 备选方案

- **保留 Jinja2, 只删版本与预算.** 少一次搬家, 但正文仍分散在 16 份文件里, 读模型看到
  什么仍要跨两种语法. 不采用.
- **每个 section 一个 .py 文件.** 找是好找, 但"这几句彼此矛盾没有"看不出来; Claude
  Code 一个 914 行的文件从上到下读完就是全部. 不采用.
- **保留末尾状态帧, 在帧之前再打一个缓存断点.** 帧仍不进事件日志, 恢复回放不出模型看
  到的内容; 每次调用重发全量计划与待办. 不采用.
- **模式留在 system prompt.** 换档是用户的日常操作, 每次作废整个窗口. 不采用.
- **保留静态 token 上限, 只是调大.** 上限的问题不在数字, 在于它让"加一条有理由的规则"
  变成要先删一条的谈判; 可见 (决策 12) 比设限管用. 不采用.
- **完全复制 Claude Code 的供应商专用消息格式.** 本仓库复制的是位置, 时机与形状; 消息
  的协议表示由 adapter 决定.

## 验收标准

- `prompt/` 下没有 `.md.j2`, 仓库里没有 `jinja2` 的 import; 搜索含中文的字符串字面量流
  向 `TextBlock` / `ToolResultBlock` 的构造, 只在 `prompt/prompts.py` 与
  `tools/builtin/*/prompt.py` 里出现.
- `get_system_prompt` 对同一个池与同一份事实返回字节相同的元组; 池里没有 `TodoWrite`
  时 using_your_tools 里没有那一句; 没有 FORGE.md 时没有 workspace_instructions 一节.
- 连续两次调用之间没有刷新点时, [1] [2] [3] 三个 sha256 相同; 换档之后三个 sha256 仍然
  相同, 窗口里多一条模式通知.
- plan 档连续 12 个用户回合: 第 1 回合一条完整版, 第 6 与第 11 回合各一条精简版, 其余
  回合没有模式通知 (第 26 回合才是下一条完整版); 退出时一条退出通知.
- 待办非空且连续 10 次模型调用没有待办工具调用时收到一条提醒, 之后 10 次调用内不再
  收到.
- 通知总是与用户消息或 tool_result 在同一条 user 消息里; 任何 tool call 与其 tool_result
  之间没有独立的 user 消息.
- 用户在编辑器改了 FORGE.md, 下一回合 [3] 的 sha256 变化且日志里有刷新点记录; 模型自己
  Edit 了 FORGE.md, [3] 不变.
