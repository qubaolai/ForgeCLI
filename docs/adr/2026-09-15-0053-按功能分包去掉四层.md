# ADR-0053: 按功能分包, 去掉 domain/application/infrastructure/interfaces 四层

## 状态

Accepted (2026-09-15 实现, 分支 `refactor/package-by-feature`)

取代 ADR-0002 (采用轻量 DDD 分层架构) 的目录结构部分. ADR-0028 (抽象收敛判据) 与
ADR-0004 §2 / ADR-0016 §4.3 / ADR-0033 / ADR-0041 / ADR-0043 定下的几条互斥边界原样保留,
只是从"层"改写成"包". 旧 ADR 正文里的路径不逐一改写, 以本文末尾的对照表为准.

## 日期

2026-09-15

## 背景

### 四层在这个代码库里换来的东西不对等

迁移前 `src/forgecli/` 368 个 `.py` 文件 46.3k 行, 分成 `domain/` (10.8k), `application/`
(20.7k), `infrastructure/` (5.1k), `interfaces/` (8.8k), `shared/` (0.9k), 66 个包目录.

1. 30 个 ABC 里 20 个只有一个实现, 全部是 `infrastructure/` 里的 JSON / JSONL / 文件系统
   读写类 (`ConfigStore` -> `JsonConfigStore`, `MemoryStore` -> `JsonMemoryStore`,
   `PlanStore` -> `FsPlanStore`...). 每一对是两个文件, 两个目录, 一处装配代码; 它们存在的
   唯一理由是 `application` 不得 import `infrastructure` 这条层规则.
2. 一个业务概念散在 4-5 个目录. session 在 `domain/session/`, `application/session/`,
   `infrastructure/session/`, `interfaces/tui/`, `interfaces/web/routers/sessions.py` 五处;
   memory 这种小功能也是 `domain/memory` + `application/memory` + `infrastructure/memory`
   + `tools/builtin/memory_tools.py` 四处.
3. 这条层规则保护的 `infrastructure/` 只有 5k 行 (11%), 而"同一个概念找三个目录"和
   "改一个 store 方法要动 ABC + 实现 + 装配"是每天都在付的成本.

### 直接并包不成立: domain 有一半是跨包词汇

第一版设想是把 `domain/X` + `application/X` + `infrastructure/X` 直接并成 `X/`. 用脚本
按包重算 import 图之后发现这会产生 19 对包级双向依赖 (`tools<->security`,
`agent<->conversation`, `execution<->workspace`, `llm<->prompt`...). 原因是 `domain/` 里
有一半模块被两个以上功能包共用: `domain/tool/plan.py` 被 security, recovery, workspace,
agent 四个包 import; `domain/intents.py` 被六个包 import; `domain/workspace/boundary.py`
被六个包 import. 这些不能拆进任何一个功能包.

所以最终布局比"传统三层"多一个底层词汇包 `core/`: 它装的是原 `domain/` 里被跨包引用的
那一半 (39 个文件, 3.7k 行), 另一半回到各自的功能包. 另有 4 个原本不在 `domain/` 的文件
为了无环也要下沉: `shared/serialization.py` (它认识 `ThinkingEffortName`),
`application/llm/gateway/token_estimator.py` (prompt 与 llm 互相 import 的唯一原因),
`interfaces/exit_codes.py` (tui / web 与 cli 互相 import 的唯一原因),
`interfaces/full_access_gate.py` (它 import `tui.chooser` 与 `tui.console`, 只能住 tui).

## 决策

### 1. 顶层布局: 21 个包, 按功能命名

```
src/forgecli/
├── cli.py               Typer 入口 (原 interfaces/app.py)
├── common/              错误基类, 取消令牌, JSON 读写, 日志, 退出码, 分发版本号
├── core/                跨包共用的词汇: 消息, 模式, 模型请求/响应, 工具计划, 执行画像
│   ├── agent/  context/  execution/  model/  tool/
├── settings/            配置键, 路径, 有效配置, forge.json 读写, 启动期读配置
├── project/             项目身份, 信任与索引
├── llm/                 模型配置, 选模, 目录; gateway/ 网关; adapters/ 供应商 HTTP
├── conversation/        上下文组装, 窗口维护, 摘要
├── prompt/              系统提示词构建, 模板渲染, templates/
├── agent/               一轮对话 (外层), 运行事件总线, 过程记录; loop/ 内层循环与 rules/
├── tools/               工具规约, 注册, 执行; builtin/ 内置工具; pipeline/ 请求管线
├── execution/           命令执行器, 环境探测; sandbox/ 平台围栏
├── security/            能力分析, 策略, 授权, 审批, 学习规则; shell/ 纯解析; analyzers/
├── workspace/           边界, 文件系统视图, 变化监测, 忽略规则
├── recovery/            检查点, 写前保护, 快照
├── session/             会话记录, 续写, 删除, 落盘
├── planning/            计划与待办
├── memory/              长期记忆
├── human_interaction/   审批与提问共用的人机提示通道
├── runtime/             组合根: ProjectRuntime, 装配, 事件集线, 人机提示 broker
├── tui/                 终端交互式会话; commands/ 斜杠命令
└── web/                 本机 Web 控制面; routers/; static/ (构建产物)
```

包内文件约定: 原来靠目录名区分的三种东西, 现在靠文件名区分. 值对象与纯函数按原名平铺;
业务流程叫 `service.py` 或原名; 落盘类叫 `*_store.py` / `catalog.py`, 与原 ABC 文件合成
一个; 起子进程 / 探测 / 发网络请求的放 `*_probe.py`, `adapters/`, `sandbox/`.

### 2. 依赖方向: 11 层拓扑 + 11 条互斥, 由 `scripts/check_arch.py` 守

| 层 | 包 |
|---|---|
| L0 | `common`, `human_interaction` |
| L1 | `core`, `memory` |
| L2 | `settings`, `project`, `prompt`, `workspace`, `planning` |
| L3 | `llm`, `security`, `recovery` |
| L4 | `conversation`, `execution`, `session` |
| L5 | `tools` |
| L6 | `agent` |
| L7 | `runtime` |
| L8 | `tui` |
| L9 | `web` |
| L10 | `cli` |

一个包只能 import 比自己层级低的包. 这张表是从迁移后的 import 图算出的拓扑序, 写死是
为了让新加的一条反向 import 立刻被认出来.

同层互斥 (旧规则逐条改写, 加一条新的):

| 规则 | 出处 |
|---|---|
| `tools` ↛ `security`, 例外 `tools.pipeline` (它是装配点) | ADR-0004 §2, §5 |
| `security` ↛ `tools` | ADR-0004 §2 |
| `agent.loop` ↛ `llm.gateway.default_gateway` | ADR-0028 A1 |
| `conversation` ↛ `llm.gateway.default_gateway` | ADR-0028 A1 |
| `llm.gateway` ↛ `llm.adapters` (新增; `ModelProvider` ABC 的存在理由) | ADR-0028 A1 |
| `memory` ↛ `security` | ADR-0033 决策 3 |
| `conversation` ↛ `security` | ADR-0041 |
| `agent.loop` ↛ `memory` | ADR-0010 |
| `tools.pipeline` ↛ `agent` | ADR-0016 §4.3 |
| `human_interaction` ↛ `security`, ↛ `core.tool` | ADR-0043 决策 3 |

第三方按包归属: `rich` 只在 `tui` / `web` / `cli`; `prompt_toolkit` 只在 `tui`; `typer`
只在 `cli`; `fastapi` / `starlette` / `sse_starlette` / `uvicorn` 只在 `web`; `httpx` 只在
`llm.adapters`; `openai` / `anthropic` / `requests` 任何地方不许出现. 模块级 import 图
无环的检查原样保留.

丢掉的保证: "application 不得 import infrastructure"原来是机器守的, 它保证业务逻辑不碰
磁盘. 现在 `memory/service.py` 可以直接 import 同包的 JSON 读写. 没有补一条弱版本的
I/O 白名单检查; 需要时再加.

### 3. 单实现 ABC 删除, 保留 10 个

删除 20 个 (`scripts/check_abstractions.py` 的判据在新布局下逐个点名): `ConfigStore`,
`LlmConfigStore`, `ModelOverridesStore`, `ProjectConfigStore`, `ProjectIndexStore`,
`CredentialPool`, `CredentialResolver`, `ProviderSettingsSource`, `ProjectInstructionReader`,
`ArtifactStore`, `FileSystemView`, `WorkspaceSnapshotProvider`, `LearnedRuleStore`,
`RecoveryStore`, `WorkspaceSnapshotBackend`, `EventStore`, `SessionCatalog`, `StateStore`,
`PlanStore`, `MemoryStore`. 抽象方法上的 docstring 转移到实现方法; 调用方的类型标注改成
具体类.

保留 10 个, 各有理由: `Tool`, `CapabilityAnalyzer` 是开放扩展点 (A3); `SandboxProvider`
(3), `CommandExecutor` (2), `HumanPromptService` (2), `ModelCatalogService` (2),
`AgentRunEventSubscriber` (3) 有多个实现 (A2); `LlmGateway`, `ToolRunObserver`,
`ModelProvider` 各守一条上表的互斥边界 (A1).

### 4. 与初版对照表的三处偏差

- `interfaces/runtime/human_interaction/broker.py` 去 `runtime/human_prompt_broker.py`
  而不是 `human_interaction/`: `HumanPromptService` 的另一个实现
  `PendingHumanPromptService` 是空实现, 不算 A2; broker 留在 `runtime` 才构成 A1.
- `application/agent_loop/run_events.py` 改名 `agent/loop/event_publisher.py`
  (类名就是 `LoopEventPublisher`), 避免与 `agent/run_events.py` 同名.
- `application/context/transcript.py` 改名 `conversation/split_points.py` (只有
  `safe_split_points`), 避免与 `agent/loop/transcript.py` 同名.

## 备选方案

- **按技术角色分层** (`models/ services/ stores/ adapters/ api/ cli/`): 只是把四个横向
  目录改了名字, session 仍然散在五处. 这种布局在有 ORM 和数据库的 Web 应用里才成立,
  ForgeCLI 落盘的是 JSON / JSONL 文件, `stores/` 与 `adapters/` 的分界没有依据.
- **纯功能分包, 不留 core/**: 见背景, 19 对双向依赖, 不成立.
- **从零重写**: 46k 行里的价值是 shell 解析器, 能力分析器, 补丁工具这些逻辑, 层只是
  文件夹名. `git mv` + import 改写 + 合并单实现 ABC 就能到达目标布局; 重写在结构上得
  不到任何额外的东西, 只会把已经验证过的行为重新引入一遍 bug.

## 影响

- 包目录 66 -> 38, `.py` 文件 368 -> 320 (其中 38 个是 `__init__.py`), 46.3k -> 45.3k
  行. 行数降得不多: `domain/` 那 10.8k 行几乎原样搬进 `core/` 与功能包. 省的是"同一个
  概念找三个目录"和"改一个 store 方法要动三处".
- `pyproject.toml`: console script 改 `forgecli.cli:main`; 打包清单里的模板与静态资源
  路径跟着改. `web/vite.config.ts` 的 outDir 与 `.gitignore` 同步.
- `docs/06-代码阅读线路.md` 与 ADR-0002 ~ ADR-0052 正文里的路径全部过期, 以本文对照表
  为准. 阅读线路的重写另开任务.
- 三个提交: 平移与合并 (428 个文件, git 认出 294 个 rename), 删 ABC (95 个文件), 本 ADR.
- 迁移前 `make ci` 已经不是绿的 (`session/service.py` 里标题提示词的中文字面量违反
  check_prompt_text, `uvicorn` / `wcmatch` 违反 check_deps, 同一行超长), 本次不修.

删掉的 ABC 及其唯一实现. 旧包的 `__init__.py` 一律删除, 新包各建一个只有 docstring 的;
例外是带代码的 `agent/loop/rules/__init__.py` (规则表) 与 `web/routers/__init__.py`
(ROUTERS 表), 它们随包平移.
