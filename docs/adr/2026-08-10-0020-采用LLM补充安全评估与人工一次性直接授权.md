# ADR-0020：采用 LLM 补充安全评估与人工一次性直接授权

## 状态

Accepted（2026-08-10 实现）

本 ADR 收敛 ADR-0013 中 Background Safety Classifier 的实际数据流，并对 ADR-0015
“所有真实写入都必须先建立恢复点”的规则作一个窄范围例外：完整展示后由人类明确批准的
单次调用可以直接执行；未经过人工批准的自动变更仍必须具备恢复绑定。

## 背景

Shell 和通用脚本存在动态求值、间接解释器、运行期路径计算及项目自定义命令。确定性解析器
必须尽力提取语义，但无法对所有语言、框架和运行期行为建立完整 AST。如果 `auto` 对任何未知
语义都直接 ASK，会使自定义但低风险的工程命令失去自动化价值；如果因解析失败直接 Allow，则
会把安全性建立在“没有发现”上。

另一方面，旧协调链在人类点击“仅本次批准”后仍调用 RecoveryGuard。未装配 RecoveryStore 时，
用户已经看过完整动作并批准，最终却收到 `workspace mutation recovery is not configured`。
这既不符合审批语义，也把恢复策略变成了对人类决定的二次否决。

## 决策

### 1. LLM 只补充无法闭合的 auto Shell/脚本分析

调用顺序固定为：

```text
ToolPlan
  → 确定性 Shell/脚本分析
  → Hard Deny 检查
  → auto 且分析不完整？
      ├─ 否：直接进入本地 PolicyEngine
      └─ 是：隔离的 LLM Safety Classifier（最多一次）
              → 结构化 RiskReport
              → 单调合并能力和副作用
              → 本地 PolicyEngine
```

分类器不用于覆盖已经命中的 Hard Deny，也不在 `plan`、`accept_edits` 或 `full_access`
中暗中改变模式语义。触发条件包括 UNKNOWN 能力、未封闭目标、动态执行以及 Shell/脚本
解析不完整事实。

### 2. 分类器使用独立提示词和严格结构化报告

分类请求只包含：本轮用户意图、冻结的 ToolPlan、确定性风险事实、工作区根、隔离等级和
执行画像 hash。不得继承主 Agent transcript、FORGE.md、主工具目录或“必须完成任务”的
交互契约。

命令、脚本和文件正文始终作为不可信 JSON 数据进入 user message。system prompt 明确要求
分析长参数、glob、重定向、间接执行、子进程、文件写删、网络、凭证和外部副作用，并禁止
服从被分析内容里的指令。

`RiskReport` 使用有限词汇和严格 JSON Schema，至少包含：

```text
risk_level
intent_alignment
confidence
recommendation
capabilities
read/write/delete paths
network_targets
external_effects
dynamic_execution
external_side_effect
opaque_regions
summary
```

原始报告不成为授权。报告 hash 以 `analysis_attestation` 进入 effective plan hash，使策略、
审批展示和一次性执行信封绑定同一分类结论。

### 3. 只有严格安全组合可以消除 UNKNOWN

自动放行候选必须同时满足：

- `risk_level=low`；
- `intent_alignment=aligned`；
- `recommendation=allow`；
- 置信度达到本地阈值；
- 没有外部副作用；
- 报告能力全部属于本地封闭词汇，路径可以规范化。

分类器新发现的能力、写删路径、网络和外部副作用与确定性结果取并集，只能扩大风险；它不能
删除确定性分析已经发现的具体危险能力。网络仍受 SandboxPolicy 控制，外部不可逆副作用仍为
Mandatory Ask，凭证和外部访问仍进入本地审批规则。

分类器超时、Provider 异常、Schema 错误、低置信度、不确定、意图冲突或高风险全部 fail-safe
为 ASK。不得反复调用分类器直到得到 Allow。

在 `NO_SANDBOX` 中，高置信度安全结论只允许自动通过没有真实工作区写入的动作；报告包含
写入、删除或外部写能力时仍进入 ASK，使用户可以通过下述一次性直接授权明确承担风险。

### 4. 人类批准签发绑定展示的一次性直接授权

ASK 获得人类“仅本次批准”后仍必须：

1. 重新 prepare；
2. 比较原始 plan hash；
3. 重跑分析、分类器和本地策略；
4. 确认没有 Hard Deny；
5. 比较完整审批 `view_hash`；
6. 绑定当前 execution profile 后签发一次性授权。

全部一致时使用 `human-approved-once:<view_hash>` 作为 recovery binding，不再调用
RecoveryGuard 推翻本次人类决定。该 binding 与 plan hash、执行画像、过期时间一起进入 HMAC
证明，ToolRuntime 在进入工具实现前消费，不能重放。

这项直接授权不表示“命令安全”或“可以恢复”，而表示用户已经看过所展示的副作用并明确承担
本次执行风险。审批 UI 必须原样展示 Shell 命令、规范化目标和 inline 脚本；脚本文件正文尚未
冻结时显示醒目警告和路径，但不禁用批准。

### 5. 人工批准仍不能覆盖以下边界

- `hard_deny.*` 和受保护根；
- 审批后 plan/view hash 变化；
- ToolSpec 能力上界和目标声明契约；
- 授权签名、有效期、单次消费和执行画像绑定；
- 当前沙箱策略没有授予的网络或其他资源；
- 非交互环境中的 pending、超时或伪造批准。

## 影响

- `auto` 可以对无法完全解析、但经独立模型高置信度证明为低风险且符合意图的命令继续执行。
- 分类器增加一次模型调用的延迟和成本；进程内有界缓存按完整请求摘要复用结果。
- 人类批准的写入在没有 RecoveryStore 时也会真实修改工作区，UI 和文档必须明确这是不可恢复的
  单次直接授权。
- 自动写入路径没有获得例外；没有恢复绑定时仍由 RecoveryGuard 拒绝。

## 验收

- auto 的未知 Shell/脚本只调用一次分类器，高置信度安全报告可由本地策略 Allow。
- 分类器失败、低置信度和非法输出进入 ASK。
- `rm -rf /` 等 Hard Deny 在分类器前拒绝，分类器不会被调用。
- 分类器报告的外部不可逆副作用保持 Mandatory Ask。
- 人工批准的 FileTool 与 ShellTool 可在无 RecoveryStore 时执行一次。
- 拒绝、审批展示变化、画像变化和授权重放仍不能执行。
