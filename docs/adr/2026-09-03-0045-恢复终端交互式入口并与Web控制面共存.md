# ADR-0045：恢复终端交互式入口并与 Web 控制面共存

## 状态

Accepted

## 日期

2026-09-03

## 背景

ADR-0025 决策 1 修订二 (2026-08-29) 把终端入口整体删除, 裸 `forge` 成为唯一启动路径。
那次删除算清了一笔账: 决策 2 与决策 33 要求"斜杠命令能改的每一项配置 Web 都要有入口",
于是**每一个配置面都实现了两遍** —— CLI 五个菜单加五个命令, Web 一套设置页与路由。
两份实现共用 application 服务, 但表单, 文案与校验时机各写各的, 改一处漏一处不会报错。

那笔账没有算错。它算的是**当时那份实现**的成本, 不是"终端入口"这件事本身的成本。删除
同时留下了自己写明的代价:

- SSH / tmux 场景没有替代方案。端口转发 (`ssh -L 8765:127.0.0.1:8765`) 不是同一件事,
  也不适用于完全没有图形环境的场合。
- 一个只能靠浏览器驱动的编码 Agent, 在"用另一个终端窗口顺手问一句"这种最高频的用法上
  是缺席的。

本 ADR 把终端入口加回来, 但**不重复上一次的错误**: 不再让两个入口各自持有一份配置面的
实现。做法是把两条入口共用的东西上收到 `interfaces/runtime`, 并把文案与字段清单收到它们
各自的定义处 —— 终端与 Web 都只是照着同一份声明渲染。

本变更**不改变 Agent 行为**: 循环, 裁决, 审批语义, 恢复与 session schema 一字不改。

## 决策

### 1. `forge --cli` 是一个参数, 不是子命令; 默认仍是 Web

裸 `forge` 继续启动本地 Web 控制面 (ADR-0025 决策 1)。`forge --cli` 进终端交互式会话。

写成参数而不是子命令: 两条路启动的是同一个产品, 只是交互面不同, 而子命令会让人以为
它们是两件事 —— 上一次 `forge cli` 正是以子命令的形态存在, 也正是那个形态让"另一套
实现"显得理所当然。

`--port` 与 `--open` 只对 Web 有意义, 带着它们进 `--cli` 直接报用法错误 (退出码 2)。
静默忽略会让人以为 `forge --cli --port 9000` 起了一个监听 9000 的什么东西。

### 2. 组合根上收到 `interfaces/runtime`, 两条入口共用一份

`ProjectRuntime`, `ProjectRuntimeRegistry`, `build_project_service` 从
`interfaces/web/runtime.py` 移到 `interfaces/runtime/project_runtime.py`;
`WebApprovalBroker` 移到 `interfaces/runtime/approval.py` 并改名
`BlockingApprovalBroker`; `WebEventHub` 移到 `interfaces/runtime/event_hub.py` 并改名
`RunEventHub`。

改名不是整理: 一个叫 `WebEventHub` 的类被终端会话订阅, 下一个读它的人会去找那条不存在
的 HTTP 路径。名字里的 `Web` 曾经是事实, 现在是谎话。

让 `interfaces/tui` 去 import `interfaces/web` 是另一条路, 不选它的理由是装配: 那样起一个
终端会话会跟着装配 FastAPI, sse-starlette 与静态资源检查, 而它一个都用不上。

ADR-0025 决策 3 本来就写着"LLM 和工具组合根移到 `interfaces/runtime`, CLI/Web 共用"。
这一条只是把当时没搬完的那部分搬完。

### 3. `InputOrigin.CLI_USER`: 只标"谁说的", 不带任何权限

终端提交的 turn 取 `InputOrigin.CLI_USER`, Web 的仍是 `WEB_USER`。两者在裁决与提示词上
没有任何差别。分开记是因为它进 `events.jsonl`: 事后回看一条会话时,"这句话是在浏览器里
说的还是在终端里说的"是查不回来的事实, 合成一档就等于把它丢了。

**人工 Shell (`#`) 不回来。** ADR-0017 的那条信任通道随 `TTY_USER` 一起删除, 本 ADR 不
恢复它。需要在工作区里亲手敲命令的用户自己开一个终端 —— 那样 Forge 观察不到, 也不需要
失效屏障。`ManualMutationBarrier` 保持删除状态。

### 4. 输入面用 prompt-toolkit

> **2026-09-04 修订.** 本条原文是"不新增运行时依赖: Rich + 标准库 `readline`",
> 理由是"输入行要的是历史, 行编辑与 Tab 补全, 标准库的 `readline` 三样都有, 而换来的
> 只是补全菜单的样式"。那句话有两处错:
>
> 1. **`readline` 在这台机器上根本没生效。** macOS 的 CPython 链的是 libedit
>    (`readline.backend == "editline"`), 而 `parse_and_bind("tab: complete")` 是 GNU
>    readline 的语法 —— 在 libedit 上它是个静默的空操作。也就是说"已经有 Tab 补全"
>    这个前提是假的, 而它不会报错, 只会让 Tab 按下去什么都不发生。
> 2. **"只是样式"低估了差距。** 要的不是补全菜单的样式, 是一个能用 ↑↓ 走, 每行带一句
>    说明的命令菜单。`readline` 画不出它: 它的补全显示是一列候选词, 挂不上说明, 也没有
>    可导航的高亮。
>
> 所以 `prompt-toolkit (>=3.0,<4.0)` 加回 `[project].dependencies`。这不是"当初不该
> 删" —— ADR-0025 修订二删掉的是 6,627 行终端实现, 那笔账没有算错, 依赖只是跟着走的。
> 这次单独把依赖加回来, 换的是下面这些具体行为。

输入面由三个模块承担:

- `interfaces/tui/prompt.py::ForgePrompt` —— 带边框的多行输入框。用底层 `Application`
  而不是 `PromptSession.prompt()`: 后者只能渲染"前缀 + 输入"一行, 画不出边框, 也放不下
  一个整行宽的命令菜单。代价是方向键 / 退格这些默认按键要用 `load_key_bindings()` 手动
  挂上。
- `interfaces/tui/tty.py::KeyReader` —— 只取 prompt-toolkit 的**输入**部分 (跨平台
  raw mode 与 vt100 解析), 循环与渲染仍是我们自己的。菜单与审批卡片是 `rich.Live` 就地
  重绘的, 交给 `Application` 画意味着重写六百多行交互代码。
- `interfaces/tui/select.py::select_one` —— 单层单选: ↑↓ 移动, Enter 确认, 数字键直选,
  Esc 取消。所有菜单 (模式, 模型, 恢复点, 计划, 审批) 走同一个。

行为约定:

- 输入 `/` 即出现全宽命令菜单, 每行是命令名 + 一句说明; ↑↓ 移动, Enter 选中, Esc 关闭。
  说明这一列不能省: 用户记不住 `/gateway` 和 `/config` 的分工, 而菜单是他唯一看得到
  说明的地方。
- 菜单没打开时 Tab / Shift-Tab 沿预设的权限梯度切模式, **两端截断不回绕**。它的唯一
  视觉反馈是输入框右下角那一行, 所以那一行必须带当前模式 —— 否则这个键按下去屏幕上
  什么都不会变, 而它改的是 Forge 能不动手做什么。
- 历史落盘在 `~/.forge/cli-history`。`ForgePrompt` 直接 `app.exit(result=...)` 提交,
  绕过了平时顺手记历史的 `validate_and_handle()`, 所以要显式 `append_to_history()`。
- 拿不到真终端时 `select_one` 抛 `SelectUnavailable`, 调用方退回"打印选项 + 读一个
  编号"。回退路径必须自己把选项打出来 —— 交互路径上那是 `select_one` 画的, 少了它就是
  在问"请选择 [1/2/3]"却没说 1/2/3 是什么。
- **菜单自己管"放不下"**, 不指望终端滚动: 选项多于一屏时按可见窗口滚动 (光标居中,
  两端贴边), 并标出上下各还有几项。`rich.Live` 不滚动 —— 画得比屏幕高就是把顶上的
  选项顶出可视区, 而那几行**不会**进滚动历史 (Live 每帧原地重画), 用户往上翻只能翻到
  菜单出现之前的东西。每帧现算可见行数, 因为拉窗口是常事。
- 同理, 菜单前面不放长表格。`/config` 原先先打一张带多行说明的表 (九个配置项能铺满
  三十行) 再打菜单, 在二十四行的终端上正好把"改哪一项"连同菜单一起顶出屏幕。说明改成
  选中之后单独打, 表里只留名字, 当前值与归属。

### 5. 只有主线程往终端写

turn 跑在 `ProjectRuntime` 起的后台线程里, 事件由那个线程产生, 但渲染必须回到主线程。
`RunEventCollector` 是一个只管收的订阅者, `TerminalRunView` 是只在主线程调用的画笔。

这不是风格偏好: 两个线程同时 print 会把流式正文和审批卡片搅在一起, 而审批卡片正是用户
要读着做决定的东西。

主循环因此是"轮询 + 画"而不是"阻塞等结果": 它要一边把新事件画出来, 一边看审批 broker
有没有人在等, 一边接住 Ctrl-C。阻塞在任何一件事上, 另外两件就都停摆。

### 6. 时间线的渲染约定

- 流式正文用 soft wrap 逐段落地, 不重排也不加前缀。Rich 默认按自己算出的宽度断行, 而
  两次 print 之间它并不知道上一段停在第几列 —— 没有 soft wrap, 一句话会被切成碎片。
- 结构化行 (工具, 裁决, 计划, 待办) 之前先收掉正文那一行, 否则工具名会接在半句话后面。
- `DECISION_SUMMARY` 不单独占一行, 挂在它解释的那一步上 (与 ADR-0025 决策 32 修订同因)。
- 自动放行的裁决不占行; 要人点头或直接拒了的必须看得见。
- **没有执行过的调用也要有一行。** 工具名不存在, prepare 失败, 被拒或没等到批准都不会
  发 `TOOL_STARTED` —— 时间线上不补这一行, 一次被拒的调用在终端上什么都不会留下, 而
  模型下一步的行为正是被它决定的。
- `side_effect_unknown` 单独标 (ADR-0016 §10.1):"没成功"与"没发生"是两回事。
- 思考只报状态不报内容 (ADR-0016 §6)。
- 压缩烧掉的用量单独标 (ADR-0037): 它不发 `MODEL_STARTED`, 不标出来, 合计对不上"模型
  N 次"。

### 7. 审批: 同一份 payload, 且 Ctrl-C 不等于拒绝

终端卡片画的是与 Web 同一份 `ApprovalView.to_payload()`。同一次调用在两条入口看到的目标,
脚本正文与可选范围逐字一致 —— 各画各的话, 终端上少列一个目标不会有任何东西报错。
有一条用例拿真的 `ApprovalView` 造 payload 再渲染, 钉住这条对应关系。

**无等待超时**, 与 broker 语义一致 (ADR-0025 决策 7): 终止条件只有用户做决定, 用户停止
这一轮, 进程退出三个。

**Ctrl-C 判成"停止这一轮", 不判成拒绝。** 判成拒绝, 模型会收到一条用户从来没说过的
拒绝并据此往下走, 而用户以为自己只是把这一轮停了。

### 8. 斜杠命令表与 Web 面板一一对应, 由用例钉住

ADR-0025 决策 2 说"斜杠命令能改的每一项配置 Web 都要有入口"。终端入口回来之后, 反过来
也要成立, 否则又会长出"只能在某一边改"的配置。

`tests/tui/test_commands.py` 里有一张 Web 面板 -> 命令的对照表, 少一条就红:

| Web 面板 | 终端命令 |
| --- | --- |
| 模式菜单 | `/mode` |
| 常规配置页 | `/config` |
| 当前模型选择器 / 用途覆盖 | `/model` |
| thinking 开关与强度 | `/thinking` |
| 网关运行时 (缓存, 熔断, 重试) | `/gateway` |
| 安全页工具清单 | `/tools` |
| 学习规则与清理 | `/rules` |
| 工作区授权 | `/dirs` |
| 项目中心 | `/projects` |
| 计划目录 / 待办 | `/plan` / `/todo` |
| 恢复页 / 撤销 / 恢复层状态 | `/checkpoints` / `/undo` / `/recovery` |
| 状态页 | `/status` |
| 会话列表与恢复 | `/sessions` / `/resume` / `/new` |

`/config` 额外把"模型与供应商"和"网关运行时"两项列进菜单, 转到 `/model` 与 `/gateway`。
模型与供应商不在 `config_keys.SCHEMA` 里 (它们住 `llm.json`, 各有各的校验), 但用户是
照着 Web 的设置页来找的, 而那一页把"常规"和"模型"放在同一个地方 —— 只列 SCHEMA 的话,
一个来 `/config` 找"添加供应商"的人会得出"这个 CLI 加不了供应商"的结论。

**表单字段一个都不手抄。** 常规配置读 `config_keys.SCHEMA` 的 `title` / `help` /
`choices`; 模型标准字段读 `STANDARD_FIELDS`, 供应商字段读 `PROVIDER_FIELDS`, 网关运行时
字段读那三个 settings dataclass 的当前取值。抄一份的话, 加一个字段不会有任何东西报错,
只会让它在终端里编不了。

### 9. 档位文案上收到 domain

`SANDBOX_OPTIONS`, `APPROVAL_OPTIONS`, `MODE_PRESETS` 与 `stance_label()` 进
`domain/intents`, 与 `ConfigKey.label` / `help` 同一个理由: 同一个档位在终端菜单和网页上
叫不同的名字, 两边都不会报错, 只会让用户以为它们是两个开关。

> **已知遗留**: `web/src/App.tsx` 里仍有一份 `sandboxOptions` / `approvalOptions` /
> `modePresets` 的副本, 本次没有动它 —— 改它要动 1855 行 React 与它的用例, 而收益是把
> 一份已经正确的文案换成从接口取。下一次动 Web 那块时把它指向后端, 副本随之删除。
> 在那之前, 改档位文案要改两处。

### 10. 两条入口取同一把项目锁, 用同一套退出码

CLI 与 Web 取的是同一把项目级 `forge.lock`。这不是限制, 是前提: 计划, 会话事件与恢复点
都不加文件锁, 正因为这把进程锁保证了同一项目只有一个 Forge 进程。抢不到的一方以
`PROJECT_LOCKED` (6) 退出并打印占用者 pid —— 两条路用同一个码, "另一个 Forge 在跑"与
对方是哪种入口无关。

`ExitCode.NO_TTY` (4) 重新有产出方: `forge --cli` 要求 stdin/stdout 都是 TTY。审批, 菜单
与计划评审都要读人的输入, 没有终端就没有人能回答, 而一个读不到输入的会话只会静静挂在
那里等。码位一直留在表里, 没有漂移过。

### 11. `resolve_plan_review` 返回 outcome 而不是 bool

终端要把 `PlanReviewOutcome.message` 原样打给用户 (它会说清"同意并执行"顺带升了档);
Web 只判真假。让终端自己再拼一句"计划已批准", 同一件事就有了两种说法。

### 12. 明确不做的

- **`/runs` 处理过程回看不做。** Web 需要它是因为刷新页面会丢掉正在展开的过程
  (ADR-0025 决策 26); 终端的滚屏本身就是那份记录。
- **不提供 PTY 或任意命令入口**, 与 ADR-0025 决策 6 一致。Agent 的 `shell_run` 照常经过
  能力分析, 审批, 恢复屏障, 授权与沙箱。
- **不做 Web 那样的进程内过程归档**: 事件缓冲不是恢复真相源 (ADR-0016 §9), 会话正文继续
  由 transcript 提供, `/resume` 只重放用户与助手的消息, 不拼一份假的过程出来。

## 兼容性

- `~/.forge/projects`, `events.jsonl`, `state.json`, 计划, 学习规则与恢复数据不迁移。
- `user_message.payload.origin` 新增取值 `"cli_user"`。老事件缺失或取别的值时按既有读取
  逻辑处理 —— 没有任何地方把 origin 解析回枚举。
- 输入历史落在 `~/.forge/cli-history` (跟着 `FORGE_CONFIG_DIR` 走), 不污染工作区。
- `interfaces/web/runtime.py` / `events.py` / `approval.py` 三个模块路径消失, 类名
  `WebEventHub` / `WebApprovalBroker` 消失。它们没有跨进程契约, 只有 import 方受影响。
- ADR-0025 决策 1 修订二的"终端入口整体删除"由本 ADR 取代; 它对**那一份实现**的判断
  仍然成立, 本 ADR 不恢复那份实现。
- ADR-0017 的人工 Shell 保持删除状态, 不随本 ADR 回来。

## 验收标准

- `forge` 仍启动 Web 控制面; `forge --cli` 进终端会话; `forge cli` 子命令不存在;
  `--version` 不启动任何东西; 退出码原样传出 (`tests/test_entrypoint.py`)。
- `forge --cli` 在非 TTY 下以 `NO_TTY` (4) 退出并说清原因, 不挂着等输入。
- 当前目录未信任时先问一次再信任; 拒绝也能进会话, 用 `/projects` 另选。
- 相同输入, 配置与工作区状态下, 终端入口产生与 Web 相同的 Agent/tool/policy/session 结果。
- 工具审批与计划评审可在终端完成; Ctrl-C 停止这一轮而不放行, 也不判成拒绝。
- 模型正文流式落地, 工具阶段按事件顺序显示; 终态给出耗时, 模型/工具次数与 token 合计。
- 没有执行过的工具调用在时间线上仍然有一行。
- 对照表里的每一块 Web 面板都有对应的终端命令 (`tests/tui/test_commands.py`)。
- 终端审批卡片渲染的是真的 `ApprovalView.to_payload()`, 不是手写字典
  (`tests/tui/test_approval_prompt.py`)。
- 斜杠菜单只在 `/` 开头且还没写参数时出现; 候选带一句说明; 选中替换的是已输入的
  那一截而不是接在后面 (`tests/tui/test_prompt.py`)。
- 提示行在窄终端上整组丢弃而不是截断半个按键名。
- 选项多于一屏时菜单按窗口滚动并标出上下还剩几项; 二十四行的终端上 `/config`
  的表格加菜单不溢出 (`tests/tui/test_select.py`)。
- `/config` 的菜单里能进到模型与供应商 (`tests/tui/test_commands.py`)。
- `make ci` 全绿。
