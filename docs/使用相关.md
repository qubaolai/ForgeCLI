# 配置内容

## 环境变量

配置文件存储根目录可以通过环境变量`FORGE_CONFIG_DIR`指定, 如果未指定, 则用户主目录下的 ~/.forge;

## 日志与可观测性 (ADR-0035)

日志与指标的开关都是**配置项**, 在 `/config` 的"常规配置"与 Web 设置页的"常规"标签里
各是一行, 改完写进 `~/.forge/config.json`. 这几项原先是 `FORGE_LOG_*` 环境变量 ——
环境变量在设置面板里看不见也改不了, 于是"面板显示 info, 实际按 debug 在写"这种状态
没有任何界面能解释.

| 配置项 | 名称 | 取值 | 说明 |
|---|---|---|---|
| `logging.level` | 日志级别 | `debug` / `info` / `warn` | 下次启动生效 |
| `logging.console` | 日志同时写终端 | 是 / 否 | 默认否: CLI 的活动区独占终端, 往 stderr 打日志会把画面戳花 |
| `logging.directory` | 日志目录 | 目录路径 | 留空使用系统临时目录中的 Forge 私有运行目录 |
| `logging.max_value_chars` | 日志单值截断长度 | 整数 | `0` 表示不截断; 留空用内置上限 |
| `logging.include_http` | 日志包含 HTTP 库 | 是 / 否 | 把 httpx / uvicorn 的日志收进同一个文件, 与 Forge 自己的记录在同一条时间线上 |
| `telemetry.enabled` | 运行指标采集 | 是 / 否 | 默认否. 关掉时各阶段的计数与耗时不采集, `/diagnostics` 的阶段读数为空 |

改完 `logging.*` 需要重启 forge: handler 在进程启动时就装好了.

## 日志

默认写入系统临时目录的 `forge-<用户标识>/run-<随机标识>/logs/`。
启动时只清理超过 7 天且不再占用的日志、中间产物、工具结果等临时子目录，
不删除整个运行目录、历史项目或会话记录，未知文件保留。活跃运行不受清理影响；
退出时刷新保留期。清理范围限定为临时运行目录下的 `logs/`、`artifacts/`、
`sandbox-*/`，以及其项目下的 `file-history/` 和会话下的 `tool-results/`、
`diagnostics/`、`agents/`（子代理临时报告）；遍历时不跟随符号链接。
显式指定 `logging.directory` 时仍使用该目录，保留最近 20 个日志文件。
用 `/diagnostics` 查看当前日志路径，将下面的 `<日志目录>` 替换为实际目录。
`forge-latest.log` 指向该目录中的本次日志:

```bash
tail -f "<日志目录>/forge-latest.log"
```

每行的形状是 `时间 级别 模块 [线程] 事件名 键=值 键=值`, 一条记录一行, 所以可以直接 grep.
常用的几条:

```bash
# 某一轮从头到尾
grep 'turn=turn_0007' "<日志目录>/forge-latest.log"

# 所有非零退出的子进程
grep 'shell.exited' "<日志目录>/forge-latest.log" | grep -v 'exit_code=0'

# 模型侧的失败与重试
grep -E 'llm\.(failed|rate_limited|auth_failed|transport_retry)' "<日志目录>/forge-latest.log"

# 被安全策略拒掉的工具调用
grep 'pipeline.denied' "<日志目录>/forge-latest.log"
```

`debug` 级别额外写整段提示词 (`prompt.text`), 模型回复原文 (`model.response.text`),
工具输出 (`tool.output`), 子进程 stdout/stderr (`shell.output`) 与 HTTP payload.
它们每条几千字, 所以默认级别 `info` 不写.

**日志不脱敏**: 工具入参, 命令 argv 与环境变量, 模型请求与回复原文都原样写. 唯一的例外是
API key 的值 —— 记的是它的引用名与哈希前缀 (`credential=OPENAI_API_KEY
credential_fingerprint=3f9a1c04`). 把日志贴给别人之前请自己先看一眼: 工作区里的文件内容
在里面.

## 诊断读数

终端里:

```text
/diagnostics
```

Web 控制面:

```text
GET /api/v1/diagnostics
```

两边读的是同一份读数: 日志级别与文件路径, 各阶段的耗时分位数与计数, 以及按
provider/model 的模型调用统计 (调用数, 重试, 错误分类, 延迟分桶, cache 命中).
`/diagnostics --reset` 把计数与耗时清零, 从当前时刻重新量一次 (不影响日志文件).
